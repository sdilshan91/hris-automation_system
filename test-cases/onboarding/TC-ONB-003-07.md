# TC-ONB-003-07: Employee cannot revert a completed task to pending (only HR can reopen)

## 1. Test Objective
Verify BR-3: once the employee marks a task "completed", they cannot revert it to "pending"; the system rejects the revert attempt and the task remains "completed". Reopening is reserved for HR (out of scope for the employee self-service flow).

## 2. Related Requirements
- User Story: US-ONB-003
- Acceptance Criteria: AC-3
- Business Rules: BR-3

## 3. Preconditions
- Employee "Alex Reed" authenticated in tenant `acme`.
- Task "Read handbook" (TK10) is already "completed" by Alex.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| task | TK10 (completed) | by Alex |
| revert target status | pending / in-progress | disallowed for employee |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In the UI, view the completed task TK10 | No "reopen"/"mark pending" control is available to the employee (BR-3). |
| 2 | Attempt to revert TK10 to "pending" via API (status transition request) | Rejected (403/409 or validation error); status remains "completed" (BR-3). |
| 3 | Attempt to re-complete or change comment on TK10 in a way that reverts state | Rejected; completion timestamp + actor unchanged. |
| 4 | Re-GET the task | Still "completed"; progress unchanged. |
| 5 | Confirm HR-reopen boundary | HR reopen capability is out of scope here (separate HR flow) — note as deferred, do NOT assert HR reopen in this employee test. |

## 6. Postconditions
- TK10 remains "completed"; no employee-initiated revert succeeds; progress unaffected.

# TC-ONB-002-01: Assign 5-task template to new hire creates 5 task instances (happy path)

## 1. Test Objective
Verify the primary success flow of AC-1, AC-2 and FR-2: an authenticated HR Officer opens an employee profile with no onboarding checklist, picks an active template containing 5 tasks, and confirms assignment. Five task instances are created, each with `due_date = date_of_joining + due_offset_days`, status `pending`, the resolved responsible party, and `tenant_id` from session context (FR-7). An audit event is recorded (FR-8).

## 2. Related Requirements
- User Story: US-ONB-002
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-3, FR-7, FR-8
- Business Rules: BR-2
- Data Requirements: onboarding_checklist_instance + nested onboarding_task_instance

## 3. Preconditions
- HR Officer "Maya Cole" is authenticated within tenant `acme` with the `Onboarding.Manage` permission.
- The Onboarding/Offboarding module is enabled for the tenant's subscription plan.
- Employee "Alex Reed" exists in `acme`, status `active`, `date_of_joining = 2026-07-01` (future), with `reporting_manager_id` set, and has NO active onboarding checklist.
- An active template "Standard Engineer Onboarding" with exactly 5 tasks (varied responsible parties and due_offset_days) exists in `acme`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| employee_id | Alex Reed's uuid | exists in tenant, no active checklist |
| template_id | "Standard Engineer Onboarding" uuid | active, 5 tasks |
| date_of_joining | 2026-07-01 | future date |
| Task A | Sign NDA / responsible HR / offset 0 | due 2026-07-01 |
| Task B | Provision laptop / responsible IT / offset -2 | due 2026-06-29 (pre-joining) |
| Task C | Welcome meeting / responsible Manager / offset 1 | due 2026-07-02 |
| Task D | Complete profile / responsible Employee / offset 3 | due 2026-07-04 |
| Task E | Security training / responsible IT / offset 5 / mandatory | due 2026-07-06 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open Alex Reed's employee profile and click "Assign Onboarding Checklist" | The system shows the active templates filtered for this employee (AC-1); "Standard Engineer Onboarding" is selectable. |
| 2 | Select the template; observe the preview/timeline | 5 tasks are previewed, each showing title, responsible-party badge, and a calculated due date (date_of_joining + offset). |
| 3 | Confirm the assignment; observe `POST /api/v1/onboarding/assignments` | Request carries the `acme` tenant bearer; response 201 Created with `{ checklist_instance_id, employee_id, tasks: [...5] }`. |
| 4 | Inspect the persisted checklist instance row | One `onboarding_checklist_instance` for Alex Reed, status active, `tenant_id` = acme set from session (FR-7), audit columns populated (FR-8). |
| 5 | Inspect the persisted task instance rows | 5 `onboarding_task_instance` rows, each `status = pending`, `due_date = date_of_joining + due_offset_days` (Task B = 2026-06-29, Task E = 2026-07-06), each with a resolved responsible party (FR-3) and the same `tenant_id`. |
| 6 | Inspect the audit log | A checklist-assignment audit event records actor (Maya Cole), employee, template, and timestamp (FR-8). |

## 6. Postconditions
- Alex Reed has exactly one active onboarding checklist with 5 pending task instances, correctly dated and tenant-scoped; no rows written for any other tenant.

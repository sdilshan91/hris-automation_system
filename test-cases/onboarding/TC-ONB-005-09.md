# TC-ONB-005-09: Authorization — HR permission required to initiate / approve clearance / complete offboarding; XSS/SQLi in free-text neutralized

## 1. Test Objective
Verify the security requirements: initiating offboarding, approving clearances, and completing offboarding all require the appropriate HR/department permission; unauthenticated (401) and under-privileged (403) callers are denied with no side effects. Free-text fields (notes, clearance remarks) are sanitized against XSS/SQL injection.

## 2. Related Requirements
- User Story: US-ONB-005
- Acceptance Criteria: AC-1, AC-3, AC-4
- Functional Requirements: FR-5, FR-9
- Cross-cutting: authentication, role-based authorization, input sanitization

## 3. Preconditions
- Tenant `acme` has: an HR Officer (Offboarding.Manage), a regular employee (no offboarding permission), and an unauthenticated client.
- An offboarding instance for E300 exists with pending clearance tasks.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| no token | (none) | expect 401 |
| employee token | regular employee | expect 403 |
| xss payload | `<script>alert(1)</script>` | in notes / remarks |
| sqli payload | `'; DROP TABLE offboarding;--` | in remarks |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Call initiate-offboarding with no token | 401 Unauthorized; no instance created. |
| 2 | Call initiate-offboarding as a regular employee | 403 Forbidden; no instance created (AC-1). |
| 3 | As a regular employee, attempt to approve a department clearance | 403 Forbidden; clearance status unchanged (AC-3). |
| 4 | As a regular employee, attempt "Complete Offboarding" | 403 Forbidden; employee not terminated, account still active (AC-4, FR-5). |
| 5 | As HR, submit notes/remarks containing the XSS payload | Stored/escaped as inert text; rendered literally in the dashboard, no script execution (sanitization). |
| 6 | As HR, submit remarks containing the SQLi payload | Treated as a literal string via parameterized queries; no SQL executed; row persisted with literal text. |
| 7 | Inspect the audit log after the denied attempts | Denied privileged actions did not mutate state; audit reflects no unauthorized completion (FR-9). |

## 6. Postconditions
- Only authorized HR/department roles can act; injection payloads are neutralized; no unauthorized state change.

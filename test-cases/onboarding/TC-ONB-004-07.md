# TC-ONB-004-07: issue_date cannot be in the future (boundary / negative)

## 1. Test Objective
Verify the issue_date validation: an issuance with a future issue_date is rejected; today's date is accepted (inclusive boundary); a past date is accepted. Validation is enforced server-side, not only in the date picker.

## 2. Related Requirements
- User Story: US-ONB-004
- Functional Requirements: FR-1 (form captures issue_date)
- Data Requirements: assets[].issue_date — "Cannot be in the future"

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`; server date is 2026-06-17.
- Employee E600 has a pending asset_issuance task; an available asset is selected.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| future date | 2026-06-18 | tomorrow — invalid |
| today | 2026-06-17 | boundary — valid (inclusive) |
| past date | 2026-06-10 | valid |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Issue an available asset with issue_date=2026-06-18 (future) | Rejected (422); "Issue date cannot be in the future"; no assignment occurs. |
| 2 | Issue with issue_date=2026-06-17 (today) | Accepted; issuance persisted with today's date (inclusive boundary). |
| 3 | Issue another asset with issue_date=2026-06-10 (past) | Accepted; past issue dates allowed. |
| 4 | Bypass the UI and POST a future issue_date directly to the API | Same 422 rejection — validation is server-side, not picker-only. |

## 6. Postconditions
- Only today/past issue dates produced assignments; future-dated request rejected with nothing persisted.

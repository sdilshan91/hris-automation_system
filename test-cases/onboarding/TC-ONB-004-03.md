# TC-ONB-004-03: Double-assignment rejected — asset already assigned to another employee, current-holder message shown

## 1. Test Objective
Verify AC-3 and BR-1: an asset can be assigned to only one employee at a time. Attempting to issue an asset that is already "assigned" to another employee is rejected, and the message names the current holder: "This asset (Serial: XYZ) is currently assigned to [Employee Name]. Please return it first or select a different asset."

## 2. Related Requirements
- User Story: US-ONB-004
- Acceptance Criteria: AC-3
- Business Rules: BR-1
- Functional Requirements: FR-3, FR-4

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- Asset LAP-100 (serial SN-100) is already in "assigned" status, linked to employee "John Doe" (E300).
- Employee "Sara Lee" (E301) has a pending asset_issuance task.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| employee_id | E301 | the new target |
| asset | LAP-100 / serial SN-100 | already assigned to E300 (John Doe) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Attempt to issue LAP-100 to E301 and save | 409/422; rejected — no change to LAP-100 (BR-1). |
| 2 | Inspect the error message | Exactly: "This asset (Serial: SN-100) is currently assigned to John Doe. Please return it first or select a different asset." (AC-3). |
| 3 | Inspect the register | LAP-100 still status="assigned", assigned_employee_id=E300 (unchanged); E301 has no new linkage (FR-4). |
| 4 | Confirm the gate is server-side | Same rejection returned when the request is replayed via API directly (not only a UI guard, FR-3). |

## 6. Postconditions
- LAP-100 remains assigned to E300; E301 received no asset; no audit "assigned" event for E301.

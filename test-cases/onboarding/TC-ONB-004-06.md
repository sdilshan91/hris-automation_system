# TC-ONB-004-06: Acknowledgment upload — signed PDF stored at tenant-isolated path; >10MB / bad MIME rejected; malware-scan seam

## 1. Test Objective
Verify FR-6 and NFR-4: a signed acknowledgment receipt (PDF/JPEG/PNG, <= 10 MB) can be attached to the issuance record and is stored at a tenant-isolated object-storage path; files over 10 MB or of a disallowed MIME type are rejected; the malware-scan seam is exercised before persistence.

## 2. Related Requirements
- User Story: US-ONB-004
- Functional Requirements: FR-6 (attach acknowledgment document)
- Non-Functional Requirements: NFR-4 (<= 10 MB, scanned for malware)
- Dependencies: File & Document Management (Technical Doc S26)

> PLATFORM NOTE: Object-storage backend (Azure Blob / S3 / MinIO) and the tenant-first key shape are the contract under test; key shape mirrors the established onboarding convention `{tenantId}/onboarding/{employeeId}/assets/{assetId}/{filename}`. Live ClamAV malware scanning is CONDITIONAL/deferred (same family as TC-ONB-003-05) — step 4 exercises the scan SEAM with an EICAR test file; flag to caller if ClamAV is not yet wired.

## 3. Preconditions
- HR Officer authenticated in tenant `acme` (tenantId T-acme) with `Onboarding.Manage`.
- Employee E500 has an issuance in progress for asset ASSET-500; object storage available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| valid file | receipt.pdf, 1.5 MB, application/pdf | within limit, allowed MIME |
| expected key | T-acme/onboarding/E500/assets/ASSET-500/receipt.pdf | tenant-first path (NFR-4) |
| oversize file | big-receipt.pdf, 11 MB | exceeds 10 MB |
| bad MIME | payload.exe, application/octet-stream | disallowed type |
| EICAR file | eicar.pdf (EICAR test string) | malware-scan seam |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Attach receipt.pdf (1.5 MB) to the ASSET-500 issuance and save | Accepted; issuance record stores the acknowledgment file reference (FR-6). |
| 2 | Inspect object storage | File stored at `T-acme/onboarding/E500/assets/ASSET-500/receipt.pdf` — tenant id is the first segment (NFR-4). |
| 3 | Attempt to upload big-receipt.pdf (11 MB) | Rejected with a size-limit error; nothing stored (NFR-4). |
| 4 | Attempt to upload payload.exe (disallowed MIME) | Rejected with an invalid-file-type error (allowed: PDF/JPEG/PNG); nothing stored. |
| 5 | Upload eicar.pdf to exercise the malware-scan seam | Scan hook invoked before persistence; infected file rejected/quarantined (NFR-4). (CONDITIONAL: if live ClamAV not wired, assert the scan seam is called and flag to caller.) |
| 6 | Confirm acknowledgment is optional | Saving an issuance WITHOUT an acknowledgment document succeeds (FR-6 is "allow attaching", not mandatory). |

## 6. Postconditions
- Valid receipt stored at the tenant-isolated path and referenced by the issuance; oversize/bad-MIME/infected files rejected with nothing persisted.

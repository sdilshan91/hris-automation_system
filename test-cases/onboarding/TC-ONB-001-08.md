# TC-ONB-001-08: Input sanitization — XSS/SQL-injection payloads in template/task fields (security)

## 1. Test Objective
Verify free-text fields (template_name, description, task title/description, category) are stored and rendered safely: script payloads are neutralized on render (no XSS), SQL-injection payloads are parameterized (no SQL execution / EF parameterization), and stored values are not silently corrupted.

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-2, FR-3
- Cross-cutting: input sanitization (XSS, SQL injection)

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.

## 4. Test Data
| Field | Payload | Notes |
|-------|---------|-------|
| description | `<script>alert(document.cookie)</script>` | XSS probe |
| tasks[0].category | `IT'); DROP TABLE onboarding_template;--` | SQLi probe |
| tasks[0].title | `<img src=x onerror=alert(1)>` | XSS probe |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Save a template with the XSS payload in description and a task title | 201 Created; the value is stored as literal text. |
| 2 | Reopen the template in the builder and on any read view | The script does NOT execute; it renders as escaped text (Angular interpolation auto-escapes). No alert fires. |
| 3 | Save a task with the SQLi category payload | 201 Created; the `onboarding_template` table still exists and is intact; the payload is stored verbatim as a category label (EF parameterizes — no SQL executed). |
| 4 | Query the stored rows | Stored values equal the submitted payloads (not stripped/mangled), confirming neutralization is at render time, not silent data loss. |

## 6. Postconditions
- No script execution, no SQL executed; payloads safely stored and escaped on display.

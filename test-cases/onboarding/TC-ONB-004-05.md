# TC-ONB-004-05: Available-status gate — cannot issue an asset not in "available" status

## 1. Test Objective
Verify FR-3 and FR-4: an asset must be in "available" status before it can be issued. Attempts to issue an asset whose status is "assigned", "returned", or "disposed" are rejected, and only an "available" asset transitions to "assigned" on a successful issuance.

## 2. Related Requirements
- User Story: US-ONB-004
- Functional Requirements: FR-3 (validate "available" before issuance), FR-4 (set "assigned" on issuance)
- Business Rules: BR-1, BR-4 (returned -> available/disposed)

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- Assets exist in each status: AV-1 (available), AS-1 (assigned), RT-1 (returned), DP-1 (disposed).
- Employee E400 has a pending asset_issuance task.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| employee_id | E400 | |
| AV-1 | status=available | issuable |
| AS-1 | status=assigned | not issuable |
| RT-1 | status=returned | not issuable (FR-3) |
| DP-1 | status=disposed | not issuable (FR-3) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Issue AV-1 (available) to E400 | Accepted; AV-1 -> status="assigned", linked to E400 (FR-4). |
| 2 | Attempt to issue RT-1 (returned) to E400 | Rejected (409/422); status-gate error — asset not available (FR-3); RT-1 unchanged. |
| 3 | Attempt to issue DP-1 (disposed) to E400 | Rejected (409/422); DP-1 unchanged (FR-3). |
| 4 | Attempt to issue AS-1 (assigned) to E400 | Rejected — covered by the double-assignment / current-holder path (see TC-ONB-004-03); AS-1 unchanged (FR-3, BR-1). |
| 5 | Confirm the gate is server-side | API replay of each rejected case returns the same status-gate rejection (not a UI-only filter). |

## 6. Postconditions
- Only AV-1 became "assigned"; RT-1, DP-1, AS-1 unchanged.

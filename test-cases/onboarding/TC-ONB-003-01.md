# TC-ONB-003-01: New hire completes 3 of 5 tasks -> progress 60%, completion timestamp + actor + audit recorded

## 1. Test Objective
Verify the happy path of AC-1, AC-3, FR-2, FR-4 and FR-8: a new hire marks 3 of 5 assigned Employee-role tasks complete; each completed task records status="completed", completion timestamp, and the acting employee as actor; the overall progress recalculates to 60% (3/5); the HR Officer notification intent is raised; and each completion is written to the tenant audit log.

## 2. Related Requirements
- User Story: US-ONB-003
- Acceptance Criteria: AC-1, AC-3
- Functional Requirements: FR-2, FR-4, FR-8
- Dependencies (deferred delivery): US-NTF-001 (in-app SignalR), US-NTF-002 (email)

> PLATFORM NOTE: AC-3 says HR is "notified via SignalR". Real-time delivery is owned by Notifications (US-NTF-001/002). This test asserts the onboarding side: the HR notification intent (outbox) is raised on completion; end-to-end SignalR receipt is deferred (covered fully by TC-ONB-003-04 step 5).

## 3. Preconditions
- Employee "Alex Reed" has an active user account linked to their employee record in tenant `acme` and is authenticated.
- A checklist of exactly 5 Employee-role tasks (none requiring document upload) is assigned and all are "pending".

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| total tasks | 5 | all Employee-role, pending |
| tasks completed | 3 (e.g. Read handbook, Sign policy, Setup profile) | via Mark Complete |
| expected progress | 60% | 3/5 completed |
| comment (optional) | "Done" on one task | FR-2 optional comment, max 500 chars |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Authenticate as Alex Reed; GET the personalized checklist | 200; 5 pending Employee-role tasks for this employee only (FR-1 boundary asserted in TC-ONB-003-02). |
| 2 | Mark task 1 complete via `POST /api/v1/onboarding/tasks/{taskInstanceId}/complete` (no attachment) | 200; status="completed"; `completed_at` set; `completed_by` = Alex Reed; progress = 20% (FR-2, AC-3, FR-4). |
| 3 | Mark task 2 complete with optional comment "Done" | 200; comment persisted (<=500 chars); status="completed"; progress = 40%. |
| 4 | Mark task 3 complete | 200; progress recalculated to 60% (3/5) (FR-4). |
| 5 | Inspect the notification outbox | An HR Officer notification intent row exists per completed task (or batched) carrying tenant_id=acme (AC-3; delivery deferred to US-NTF). |
| 6 | Inspect the tenant audit log | Three task-completion audit events recorded with actor=Alex Reed, timestamp, and task ids; all tenant-scoped (FR-8). |
| 7 | Re-GET the checklist / dashboard | Progress shows 60%; the 3 tasks show "completed" with completion timestamps; 2 remain "pending". |

## 6. Postconditions
- 3 of 5 task instances are "completed" with timestamp + actor; progress = 60%; HR notification intents queued; 3 audit events written; all tenant-scoped to acme.

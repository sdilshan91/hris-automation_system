# TC-ONB-001-10: Deactivate / reactivate template — soft status toggle (FR-7 / BR-4)

## 1. Test Objective
Verify FR-7 and BR-4: deactivating a template flips `is_active` to false WITHOUT deletion; a deactivated template no longer appears in the "assign to new hire" selection but remains visible in the template list for historical reference. Reactivation restores eligibility.

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-2
- Functional Requirements: FR-7
- Business Rules: BR-4
- Data Requirements: is_active (boolean, default true)

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- An active template "Standard Engineer Onboarding" exists in tenant `acme`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Template | Standard Engineer Onboarding | active |
| Action | Deactivate, then Reactivate | soft toggle |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In the template list, toggle the template to Deactivated | Response success; the template row still exists with `is_active = false` (soft toggle — NOT deleted, FR-7). |
| 2 | Open the "assign onboarding to new hire" selection | The deactivated template is NOT offered for assignment (BR-4). |
| 3 | Return to the template list | The deactivated template is STILL listed (e.g. with an "Inactive" badge) for historical reference (BR-4). |
| 4 | Confirm no rows deleted | Task rows and the template row remain in the DB; only `is_active` changed; audit `updated_at`/`updated_by` populated (FR-8). |
| 5 | Reactivate the template | `is_active = true`; the template reappears in the assignment selection. |

## 6. Postconditions
- Template can be toggled inactive/active without data loss; assignment eligibility follows `is_active`.

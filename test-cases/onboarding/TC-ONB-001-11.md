# TC-ONB-001-11: Template creation API within 500 ms P95 (NFR-1)

## 1. Test Objective
Verify NFR-1: the template-creation API responds within 500 ms at the 95th percentile under representative load, for a realistic template payload (multiple categories and tasks) on a tenant with existing templates (so the per-tenant uniqueness check is exercised against non-trivial data).

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-2
- Non-Functional Requirements: NFR-1
- Note: requires a performance-representative environment (warm app + representative DB). On a non-representative dev box, record observed numbers and flag as indicative only — do NOT relax the threshold.

## 3. Preconditions
- A performance-representative environment with the API warmed (JIT/connection pool primed).
- Tenant `acme` pre-seeded with ~200 existing templates so the uniqueness check runs against real data.
- A test harness (e.g. k6/JMeter) issuing concurrent `POST /api/v1/onboarding/templates` requests.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Payload | template + 3 categories + 8 tasks | representative size |
| Concurrency | sustained representative RPS | per harness config |
| Sample size | >= 200 successful creates | for a stable P95 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm the API, then run the create-template scenario at target concurrency | All requests return 201 (unique names per iteration). |
| 2 | Record server-side latency per request | Capture full distribution (P50/P95/P99). |
| 3 | Compute P95 | P95 of create latency <= 500 ms (NFR-1). |
| 4 | Inspect outliers | P99 reviewed; any breach is reported with the trace, not silenced. |

## 6. Postconditions
- A latency report (P50/P95/P99) recorded; P95 meets the 500 ms SLA or the breach is reported to the caller.

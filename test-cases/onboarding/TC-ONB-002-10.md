# TC-ONB-002-10: Input sanitization on ad-hoc task fields (XSS / SQLi neutralized)

## 1. Test Objective
Verify input safety for the free-text fields available during assignment and modification (ad-hoc task title/description, override notes). Malicious payloads (XSS, SQL injection) are stored/escaped as inert data and never executed when rendered in the timeline/task list or persisted, and do not corrupt queries.

## 2. Related Requirements
- User Story: US-ONB-002
- Acceptance Criteria: AC-2, AC-4
- Functional Requirements: FR-5
- Cross-cutting: input sanitization

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- Employee with an active checklist exists, ready to receive an ad-hoc task.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS payload | `<script>alert('x')</script>` | in ad-hoc task title |
| HTML-attr payload | `"><img src=x onerror=alert(1)>` | in ad-hoc task description |
| SQLi payload | `'; DROP TABLE onboarding_task_instance;--` | in a free-text field |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Add an ad-hoc task with the XSS payload as title and save | 2xx; payload stored as literal text. |
| 2 | Render the checklist timeline/task list in the UI | The script does NOT execute; the payload displays as escaped text (Angular interpolation escapes by default). |
| 3 | Add a task with the SQLi payload in a free-text field | Treated as literal data via parameterized queries (EF Core); the `onboarding_task_instance` table is intact; no error. |
| 4 | Re-read the stored values | Values returned verbatim/escaped, not interpreted; the database schema is unchanged. |

## 6. Postconditions
- Malicious payloads are inert in both storage and rendering; no schema or data corruption.

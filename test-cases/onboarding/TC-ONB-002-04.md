# TC-ONB-002-04: Modify assigned checklist — add ad-hoc task, change due date, soft-delete non-mandatory; mandatory cannot be removed

## 1. Test Objective
Verify AC-4, FR-5, FR-6 and BR-3: after assignment, HR can add an ad-hoc task not in the original template (due date = today + offset), modify the due date of an individual task, and soft-delete a non-mandatory task; a mandatory task cannot be removed. Each modification writes an audit record (AC-4, FR-8).

## 2. Related Requirements
- User Story: US-ONB-002
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5, FR-6, FR-8
- Business Rules: BR-3

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- Employee "Alex Reed" has an active checklist with 5 tasks; at least one is mandatory (Task E "Security training") and at least one is non-mandatory (Task D "Complete profile").
- Today's date is 2026-06-17.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| ad-hoc task | "Order business cards" / offset 2 / non-mandatory | due = today + 2 = 2026-06-19 |
| task to re-date | Task C "Welcome meeting" -> 2026-07-10 | manual due-date override (FR-6) |
| task to soft-delete | Task D "Complete profile" (non-mandatory) | allowed |
| task removal attempt | Task E "Security training" (mandatory) | must be blocked (BR-3) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the assigned checklist for Alex Reed and add ad-hoc task "Order business cards" with offset 2 | Task added; due date = today (2026-06-17) + 2 = 2026-06-19 (added tasks dated from today per AC-4); status pending; an audit record is written. |
| 2 | Change Task C "Welcome meeting" due date to 2026-07-10 and save | Due date updated to 2026-07-10 (FR-6); audit record captures the change. |
| 3 | Soft-delete Task D "Complete profile" (non-mandatory) | Task is soft-deleted (marked deleted, row retained); it no longer appears in the active task list; audit record written (AC-4). |
| 4 | Attempt to remove Task E "Security training" (mandatory) | The action is blocked with a clear message that mandatory tasks cannot be removed (BR-3); no delete is recorded. |
| 5 | Attempt the mandatory removal via direct API `DELETE /api/v1/onboarding/assignments/{id}/tasks/{taskE}` | Server rejects (422/409) — mandatory removal is enforced server-side, not just in the UI (BR-3). |
| 6 | Re-read the checklist | Contains original tasks minus the soft-deleted Task D, plus the new ad-hoc task; Task E still present; Task C shows the new due date. |

## 6. Postconditions
- The active checklist reflects: added ad-hoc task (dated from today), re-dated Task C, soft-deleted Task D, retained mandatory Task E; each change is auditable.

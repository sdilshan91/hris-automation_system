# TC-ONB-003-10: Self-service authorization — employee acts only on their own tasks

## 1. Test Objective
Verify FR-1, FR-2 and FR-7 authorization: the employee can view and complete only their own assigned tasks. Any attempt to read or complete another employee's task instance (same tenant) is rejected, and unauthenticated access is denied. Also verify free-text comment input is sanitized against XSS/SQLi.

## 2. Related Requirements
- User Story: US-ONB-003
- Acceptance Criteria: AC-2, AC-3
- Functional Requirements: FR-1, FR-2, FR-7

## 3. Preconditions
- Employee "Alex Reed" (E123) and a second employee "Bo Kim" (E456) both in tenant `acme`, each with assigned tasks.
- Alex is authenticated; Bo's task TK-BO-1 exists.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| own task | TK10 (Alex) | allowed |
| other-employee task | TK-BO-1 (Bo) | must be denied |
| XSS payload | `<script>alert(1)</script>` in comment | must be neutralized |
| SQLi payload | `'; DROP TABLE onboarding_task_instance;--` | must be parameterized/inert |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Alex, GET the checklist | Only Alex's own task instances returned; Bo's tasks never appear (FR-1). |
| 2 | As Alex, `POST .../tasks/{TK-BO-1}/complete` | 403 Forbidden (or 404 not-disclosing); Bo's task unchanged (FR-7). |
| 3 | As Alex, attempt to read Bo's task instance by id | Denied/empty; no cross-employee data leakage. |
| 4 | Call the completion endpoint unauthenticated | 401 Unauthorized; no state change. |
| 5 | Complete TK10 with an XSS payload in the comment | Stored encoded/sanitized; rendered inert in the UI (no script execution). |
| 6 | Submit the SQLi payload in the comment | Treated as literal text via parameterized queries; no SQL executed; table intact. |

## 6. Postconditions
- Employee can only act on their own tasks; cross-employee and unauthenticated actions blocked; injection payloads neutralized.

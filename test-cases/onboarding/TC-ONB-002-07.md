# TC-ONB-002-07: Past joining date — due dates calculated from today (BR-4)

## 1. Test Objective
Verify BR-4 (with FR-2): if the employee's `date_of_joining` is in the past, task due dates are calculated from today's date + due_offset_days instead of from the past joining date, so no instance is created already overdue purely due to a backdated join.

## 2. Related Requirements
- User Story: US-ONB-002
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2
- Business Rules: BR-4

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- Today's date is 2026-06-17.
- Employee "Pat Vega" exists in `acme` with `date_of_joining = 2026-06-07` (10 days ago) and no active checklist.
- An active template with tasks at offsets 0, 3, and 5 exists.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| date_of_joining | 2026-06-07 | 10 days in the past |
| today | 2026-06-17 | calculation base per BR-4 |
| Task offset 0 | due 2026-06-17 | from today, not 2026-06-07 |
| Task offset 3 | due 2026-06-20 | from today |
| Task offset 5 | due 2026-06-22 | from today |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Assign the template to Pat Vega | 201 Created; task instances created. |
| 2 | Inspect each task's due date | Due dates are today (2026-06-17) + offset (2026-06-17, 2026-06-20, 2026-06-22), NOT joining date + offset (BR-4). |
| 3 | Confirm none is spuriously overdue | No task instance has a due date before today purely because the join date was backdated. |
| 4 | Contrast control: assign to an employee with a FUTURE joining date | For the future-join employee, due dates use date_of_joining + offset (FR-2) — confirming BR-4 applies only when joining date is past. |

## 6. Postconditions
- Pat Vega's task instances are dated from today + offset; future-join employees remain dated from joining date + offset.

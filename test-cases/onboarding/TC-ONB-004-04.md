# TC-ONB-004-04: Unique asset_tag (and serial if provided) per tenant — duplicate rejected

## 1. Test Objective
Verify BR-3: an asset_tag must be unique within the tenant, and a serial_number must be unique within the tenant when provided. Attempting to create an asset with a duplicate asset_tag (or duplicate serial) in the same tenant is rejected; the same tag/serial is allowed in a different tenant.

## 2. Related Requirements
- User Story: US-ONB-004
- Business Rules: BR-3
- Functional Requirements: FR-2
- Data Requirements: assets[].asset_tag (unique per tenant), assets[].serial_number (unique per tenant if provided)

## 3. Preconditions
- HR Officer authenticated in tenant `acme`.
- An asset with asset_tag LAP-DUP (serial SN-DUP) already exists in tenant `acme`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| existing asset (acme) | asset_tag LAP-DUP, serial SN-DUP | already in register |
| new asset (acme) — case A | asset_tag LAP-DUP | duplicate tag |
| new asset (acme) — case B | asset_tag LAP-NEW, serial SN-DUP | duplicate serial |
| new asset (tenant globex) | asset_tag LAP-DUP, serial SN-DUP | should be allowed (different tenant) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In acme, create/issue an asset with asset_tag=LAP-DUP | Rejected (409/422); duplicate asset_tag within tenant message (BR-3). |
| 2 | In acme, create/issue an asset with a new tag but serial=SN-DUP | Rejected (409/422); duplicate serial_number within tenant (BR-3). |
| 3 | In acme, create an asset with no serial and a unique tag | Accepted — serial is optional; uniqueness only enforced when provided. |
| 4 | In tenant globex, create an asset with asset_tag=LAP-DUP and serial=SN-DUP | Accepted — uniqueness is scoped per tenant, not global (BR-3). |
| 5 | Inspect the register after rejections | No duplicate rows created in acme. |

## 6. Postconditions
- acme register contains a single LAP-DUP / SN-DUP; globex may independently hold the same tag/serial.

# TC-ONB-002-03: Duplicate assignment triggers replace/merge prompt; one active checklist enforced

## 1. Test Objective
Verify AC-3 and BR-2: assigning a checklist to an employee who already has an active onboarding checklist surfaces the warning "This employee already has an active onboarding checklist. Do you want to replace it or add additional tasks?" with replace and merge options. Replace creates a new version (the previous instance is superseded) so that at most one active checklist exists; merge appends tasks to the existing active checklist.

## 2. Related Requirements
- User Story: US-ONB-002
- Acceptance Criteria: AC-3
- Business Rules: BR-2
- Functional Requirements: FR-2

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- Employee "Alex Reed" already has ONE active onboarding checklist (from a prior assignment) with 5 task instances.
- A second active template "Extended Engineer Onboarding" with 3 tasks exists.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| employee_id | Alex Reed's uuid | already has active checklist |
| second template_id | "Extended Engineer Onboarding" uuid | 3 tasks |
| action (path A) | replace | new version supersedes old |
| action (path B) | merge | tasks appended to existing |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open Alex Reed's profile and click "Assign Onboarding Checklist"; select "Extended Engineer Onboarding" and confirm | A warning dialog appears: "This employee already has an active onboarding checklist. Do you want to replace it or add additional tasks?" with Replace and Merge options (AC-3). |
| 2 | (Path A) Choose Replace | The previous active checklist instance is superseded (marked not-active / versioned); a new active checklist instance with the 3 new tasks is created. |
| 3 | Verify active-checklist invariant after Replace | Exactly ONE active `onboarding_checklist_instance` exists for Alex Reed (BR-2); the old one is retained as a prior version, not active. |
| 4 | Reset to a single active checklist; repeat step 1; (Path B) choose Merge | The 3 new tasks are appended to the existing active checklist; original 5 tasks remain. |
| 5 | Verify active-checklist invariant after Merge | Still exactly ONE active checklist for Alex Reed, now holding 8 task instances (BR-2). |
| 6 | Attempt to bypass the prompt by calling `POST /api/v1/onboarding/assignments` directly with the second template | Server enforces the same rule: returns a conflict/clarification response requiring replace|merge intent — no silent second active checklist is created. |

## 6. Postconditions
- Alex Reed has at most one active onboarding checklist after either branch; the replaced instance is preserved as an inactive prior version.

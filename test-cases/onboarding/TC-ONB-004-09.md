# TC-ONB-004-09: Authorization — Onboarding.Manage required to issue; 401/403 deny, no record created

## 1. Test Objective
Verify that asset issuance and asset-register mutation require the `Onboarding.Manage` permission. Unauthenticated requests are rejected with 401; authenticated users without the permission are rejected with 403; in neither case is an asset issued or modified.

## 2. Related Requirements
- User Story: US-ONB-004
- Functional Requirements: FR-1, FR-4
- Business Rules: BR-6
- Cross-cutting: authentication + role-based authorization

## 3. Preconditions
- Tenant `acme` with an available asset and an employee with a pending asset_issuance task.
- A user WITHOUT `Onboarding.Manage` (e.g. a plain Employee) and an anonymous client are available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| issuance endpoint | POST /api/v1/onboarding/assets/issue | requires Onboarding.Manage |
| unauthenticated | no/expired bearer token | expect 401 |
| under-privileged | Employee role, no Onboarding.Manage | expect 403 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | POST an issuance with no/expired token | 401 Unauthorized; no asset issued. |
| 2 | POST an issuance as an authenticated user lacking Onboarding.Manage | 403 Forbidden; no asset issued (FR-4, BR-6). |
| 3 | Attempt to modify/return an asset as the under-privileged user | 403 Forbidden; asset unchanged. |
| 4 | POST the same issuance as an HR Officer WITH Onboarding.Manage | 200/201; issuance succeeds (positive control). |
| 5 | Inspect the register after the denied attempts | No asset created or status-changed by the unauthorized/unauthenticated callers. |

## 6. Postconditions
- Only the authorized HR Officer's issuance persisted; denied callers left the register unchanged.

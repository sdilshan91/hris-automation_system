# TC-ONB-001-06: template_name length boundaries (3 and 200) and due_offset_days = 0 (boundary)

## 1. Test Objective
Verify the data-requirement boundaries via equivalence-partition edge values: `template_name` accepts exactly 3 and exactly 200 characters and rejects 2 and 201; `tasks[].title` accepts 3 chars; `tasks[].due_offset_days = 0` is accepted (BR-3 lower bound). Both client and server enforce the limits.

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-1, AC-2
- Business Rules: BR-3
- Data Requirements: template_name (min 3, max 200), tasks[].title (min 3, max 200), tasks[].due_offset_days (>= 0)

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- No name collisions for the boundary values used.

## 4. Test Data
| Field | Value | Expected |
|-------|-------|----------|
| template_name = 2 chars | "On" | Reject |
| template_name = 3 chars | "On1" | Accept |
| template_name = 200 chars | "A" x 200 | Accept |
| template_name = 201 chars | "A" x 201 | Reject |
| tasks[0].title = 3 chars | "Foo" | Accept |
| tasks[0].due_offset_days | 0 | Accept (same-day) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Save a template with a 2-char name + 1 valid task | Rejected with a min-length (3) validation error, client and server. |
| 2 | Save with a 3-char name + 1 valid task (title 3 chars, due_offset_days 0) | 201 Created; persisted exactly as entered; due_offset_days = 0 accepted (BR-3). |
| 3 | Save with a 200-char name + 1 valid task | 201 Created; full 200 chars stored, not truncated. |
| 4 | Save with a 201-char name | Rejected with a max-length (200) validation error, client and server. |

## 6. Postconditions
- Only the in-range boundary templates (3 and 200 chars) persisted; out-of-range attempts wrote nothing.

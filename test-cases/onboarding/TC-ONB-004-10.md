# TC-ONB-004-10: Input sanitization + tenant_id from session — XSS/SQLi in asset free-text neutralized; client tenant_id ignored

## 1. Test Objective
Verify FR-7 and the data-validation rules: free-text asset fields (brand, model, notes) carrying XSS/SQLi payloads are stored/rendered safely (no script execution, no SQL injection), notes respects its 500-char max, and tenant_id is always set from the session context — a client-supplied tenant_id is ignored.

## 2. Related Requirements
- User Story: US-ONB-004
- Functional Requirements: FR-7 (tenant_id from session on all asset records)
- Data Requirements: assets[].notes (max 500 chars), free-text fields

## 3. Preconditions
- HR Officer authenticated in tenant `acme` (resolved tenantId T-acme) with `Onboarding.Manage`.
- An available asset and employee E700 with a pending issuance task.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| notes (XSS) | `<script>alert('x')</script>` | must not execute |
| brand (SQLi) | `'; DROP TABLE assets;--` | must not inject |
| notes (boundary) | 500 chars / 501 chars | 500 ok, 501 rejected |
| client tenant_id | T-globex (spoofed) | must be ignored — session wins |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Issue an asset with the XSS payload in notes | Stored safely; rendered as inert text (escaped/encoded) — no script execution in the assets view. |
| 2 | Issue with the SQLi payload in brand | Treated as a literal string via parameterized queries; the assets table is intact; no error/leak. |
| 3 | Submit notes of exactly 500 chars, then 501 chars | 500 accepted; 501 rejected with a length-validation error. |
| 4 | POST an issuance with a spoofed `tenant_id`=T-globex in the body | tenant_id is taken from the session (T-acme); the spoofed value is ignored — the asset is stamped T-acme (FR-7). |
| 5 | Inspect the persisted record | tenant_id=T-acme; free-text fields safely encoded. |

## 6. Postconditions
- Malicious payloads neutralized; tenant_id always = session tenant regardless of client input.

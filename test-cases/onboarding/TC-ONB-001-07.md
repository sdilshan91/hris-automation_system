# TC-ONB-001-07: Onboarding.Manage authorization required (negative / security)

## 1. Test Objective
Verify the precondition and FR-5 authorization gate: only a user holding the `Onboarding.Manage` permission may create a template. Authenticated users WITHOUT the permission are denied (403); unauthenticated requests are rejected (401). A denied attempt creates no template.

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-1 (precondition), AC-2
- Functional Requirements: FR-5
- Cross-cutting: authentication + role-based authorization

## 3. Preconditions
- Tenant `acme` exists.
- A user "Ravi" in `acme` is authenticated but holds only an Employee role (no `Onboarding.Manage`).
- An HR Officer "Maya" in `acme` holds `Onboarding.Manage`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Unauthorized user | Ravi (no Onboarding.Manage) | expect 403 |
| Unauthenticated | no bearer token | expect 401 |
| Authorized user | Maya (Onboarding.Manage) | expect 201 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Ravi, attempt `POST /api/v1/onboarding/templates` with a valid body | Response 403 Forbidden; no template row created. |
| 2 | In the UI as Ravi, look for the "Create Checklist Template" action | The action is hidden/disabled (defense-in-depth); the API still enforces 403 regardless of UI state. |
| 3 | Send `POST /api/v1/onboarding/templates` with no/expired bearer token | Response 401 Unauthorized; no template row created. |
| 4 | As Maya (Onboarding.Manage), send the same valid body | Response 201 Created — confirms the gate denies only the unauthorized callers, not the privilege itself. |

## 6. Postconditions
- No template created by unauthorized/unauthenticated callers; the authorized HR Officer can create one.

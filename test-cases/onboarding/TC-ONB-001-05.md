# TC-ONB-001-05: Negative due_offset_days rejected (negative)

## 1. Test Objective
Verify BR-3 and the data requirement `tasks[].due_offset_days >= 0`: a task with a negative due offset is rejected, server-side, with a field-level validation error.

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-2
- Business Rules: BR-3
- Data Requirements: tasks[].due_offset_days (>= 0)

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| template_name | Offset Validation | valid |
| tasks[0].title | Collect ID | valid |
| tasks[0].due_offset_days | -1 | violates BR-3 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the builder, add one task, set due_offset_days to -1, click Save | The numeric input rejects/flags the negative value; Save is blocked with an inline error. |
| 2 | Send `POST /api/v1/onboarding/templates` with `tasks[0].due_offset_days = -1` directly | Response 400/422 with a field-level error on `due_offset_days` (must be >= 0, BR-3); no template persisted. |
| 3 | Re-send the same payload with `due_offset_days = 0` | Response 201 — 0 is valid (same-day-as-joining, BR-3) and confirms only the negative value was the failure. |

## 6. Postconditions
- No template with a negative due offset persisted; the boundary value 0 is accepted.

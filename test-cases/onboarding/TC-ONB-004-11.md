# TC-ONB-004-11: Asset issuance API <= 600 ms P95

## 1. Test Objective
Verify NFR-1: the asset issuance API responds within 600 ms at the 95th percentile under representative load and data volume, including the atomic multi-asset transaction path.

## 2. Related Requirements
- User Story: US-ONB-004
- Non-Functional Requirements: NFR-1 (<= 600 ms P95), NFR-5 (atomic transaction)

> PLATFORM NOTE: NFR-1 (<= 600 ms P95) must be measured in a performance-representative environment (prod-like DB, realistic asset-register sizes, warmed caches). On a dev box, record indicative numbers and flag the environment caveat — do NOT relax the 600 ms threshold to pass.

## 3. Preconditions
- Tenant `acme` seeded with a realistic asset register (thousands of assets) and many employees.
- HR Officer authenticated; load-test tooling available (k6/JMeter); indexes present on asset_tag, serial_number, status, assigned_employee_id, tenant_id.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| endpoint | POST /api/v1/onboarding/assets/issue | write path |
| load profile | sustained concurrent issuances (single + 3-asset batch) | representative |
| SLA | P95 <= 600 ms | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm caches; run a sustained issuance load (mix of single-asset and 3-asset bulk submissions) | Requests succeed (200/201); assets assigned atomically (NFR-5). |
| 2 | Capture the latency distribution | P95 response time <= 600 ms (NFR-1). |
| 3 | Inspect query plans for the issuance transaction | Uniqueness/availability checks and the tenant filter use indexes; no full scans degrading P95. |
| 4 | Record environment context | Note hardware/DB sizing; if not prod-representative, flag indicative-only and do NOT relax the threshold. |

## 6. Postconditions
- Issuance P95 meets the 600 ms SLA (or indicative numbers recorded with an environment caveat).

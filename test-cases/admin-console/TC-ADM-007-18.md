# TC-ADM-007-18: [DEFERRED] Redis workflow-definition cache + evaluation/load performance (NFR-1/2/3)

## 1. Test Objective
Verify the deferred non-functional requirements: NFR-2 — workflow definitions cached in Redis at `t:{tenantId}:workflows:{entityType}` and invalidated on edit; NFR-1 — the workflow editor (incl. approver suggestion list) loads within 2s; NFR-3 — workflow evaluation (determining the next step for a request) completes under 100ms.

## 2. Related Requirements
- User Story: US-ADM-007
- Non-Functional: NFR-1 (editor < 2s), NFR-2 (Redis cache + invalidation), NFR-3 (evaluation < 100ms)

## 3. Preconditions (NOT satisfiable in the current build)
- Redis is NOT wired on this platform (same family as US-ADM-001..006 / Payroll / Leave deferred Redis). Definitions are read tenant-filtered from the DB; any cache-invalidation call no-ops gracefully.
- NFR-1/NFR-3 timing assertions require a performance-representative environment.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| cache key | `t:{tenantId}:workflows:{entityType}` | target key, not yet wired |

## 5. Test Steps (deferred)
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Read a workflow definition twice | (When Redis lands) second read served from `t:{tenantId}:workflows:{entityType}`; key is tenant-scoped. |
| 2 | Edit the workflow | Cache key invalidated; next read repopulates. |
| 3 | Measure editor load with approver list | P95 < 2s (NFR-1) in a perf-representative env. |
| 4 | Measure evaluator next-step resolution | < 100ms (NFR-3). |

## 6. Postconditions
- DEFERRED. Today: definitions always read tenant-filtered from the DB; the pure evaluator's correctness is covered (TC-ADM-007-12/-13/-14). Cache key `t:{tenantId}:workflows:{entityType}` is the documented target.

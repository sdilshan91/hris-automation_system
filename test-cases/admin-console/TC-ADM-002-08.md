# TC-ADM-002-08: Tenant detail view shows operational fields (status/plan/owner/created/last-activity/Hangfire)

## 1. Test Objective
Verify the REAL subset of AC-4: clicking a tenant on the dashboard opens a detail view showing tenant status, plan, owner, creation date, last-activity timestamp, and that tenant's background-job (Hangfire) status. (The 24h error/latency trend charts and top-errors grouping from AC-4 are Deferred — TC-ADM-002-16.)

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5 (per-tenant job status)
- Data Sources: `tenant`, `tenant_lifecycle_event`, Hangfire storage

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- Tenant "Acme" exists with a known status, plan, owner, creation date, recent activity, and at least one Hangfire job.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Tenant | acme | detail subject |
| status | active | from `tenant` |
| plan | Growth | from subscription plan |
| owner | owner@acme.com | TenantOwner |
| created | known date | from `tenant.created_at` |
| last activity | recent timestamp | from activity/audit source |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | On the dashboard tenant table, click "Acme"; observe `GET /api/v1/admin/monitoring/tenants/{id}` | 200 with the tenant detail payload; the detail view opens. |
| 2 | Read the identity/operational fields | Shows status = active, plan = Growth, owner = owner@acme.com, creation date, and a last-activity timestamp. |
| 3 | Read the per-tenant background-job status | Acme's Hangfire job status (e.g. queued/processing/failed for this tenant) is shown (FR-5). |
| 4 | Note the Deferred widgets | The 24h error-rate chart, 24h latency chart, and top-errors panel render a "Not available — requires observability pipeline" placeholder (covered in TC-ADM-002-16), not fabricated data. |
| 5 | Confirm a Monitoring.TenantViewed audit record is implied | Opening this detail is auditable (asserted in TC-ADM-002-11). |

## 6. Postconditions
- Tenant detail shows accurate operational fields; deferred analytics are placeholdered. A `Monitoring.TenantViewed` audit record is written.

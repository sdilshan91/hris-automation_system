# TC-ADM-005-04: Invite a brand-new global user — user + invited membership + 72h token + email dispatch (happy path)

## 1. Test Objective
Verify AC-2 / FR-2 / Test-Hint "Invite new user": inviting an email that does not yet exist globally creates a new `users` record, a `user_tenant` membership with `status = 'invited'`, a `user_invitation` with a one-time hashed token (72-hour expiry), assigns the selected roles, dispatches the invitation email (log-only seam today — delivery is TC-ADM-005-19), and surfaces the invite in the Pending Invitations tab. The action is audited (NFR-2).

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2
- Business Rules: BR-1, BR-5 (limit checked, not breached here)
- Test Hints: Invite new user

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme; Acme has spare plan capacity (active count < `MaxEmployees`).
- Email "alex.new@example.com" does NOT exist in the global `users` table.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| email | alex.new@example.com | new global user |
| role_ids | [Employee, Manager] | one or more roles |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, `POST /api/v1/admin/users/invitations` with `{ email, role_ids }` | 201/200; success response with the new invitation. |
| 2 | Query `users` | A new global user row exists for alex.new@example.com. |
| 3 | Query `user_tenant` for Acme | A membership exists with `status = 'invited'`, tenant = Acme. |
| 4 | Query `user_tenant_role` | Rows for both selected roles, with `assigned_at`/`assigned_by = Dana`. |
| 5 | Query `user_invitation` | One row: `status = 'Invited'`, a HASHED token stored (not plaintext), `expires_at = now + 72h`, tenant = Acme. |
| 6 | Inspect the email/dispatch seam | An invitation email targeting alex.new@example.com is dispatched (log-only today; delivery deferred to TC-ADM-005-19). |
| 7 | `GET /api/v1/admin/users/invitations?status=invited` (Pending Invitations) | The new invitation appears with email, invited roles, invited-at, expires-at. |
| 8 | Query `audit_log` | A user-invite entry with actor=Dana, action, IP, timestamp, before/after (NFR-2). |

## 6. Postconditions
- A pending invitation exists for Acme; no email duplication; no other tenant affected.

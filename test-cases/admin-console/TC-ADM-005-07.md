# TC-ADM-005-07: Bulk CSV invite — 5 valid + 2 invalid rows → per-row results, valid rows succeed

## 1. Test Objective
Verify AC-2 / FR-3 / Test-Hint "Bulk CSV invite": uploading a CSV with columns `email,role` containing 5 valid and 2 invalid rows creates 5 invitations and returns 2 per-row errors, WITHOUT the invalid rows blocking the valid ones. Validation is per-row (bad email format, unknown role, duplicate-of-existing-member, blank email).

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2, FR-3
- Test Hints: Bulk CSV invite

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme; plan has capacity for at least 5 more users.
- CSV header: `email,role` (role = comma-separated role names).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| valid row 1 | v1@acme.io,Employee | ok |
| valid row 2 | v2@acme.io,"Manager,HR Officer" | multi-role ok (BR-7) |
| valid row 3 | v3@acme.io,Employee | ok |
| valid row 4 | v4@acme.io,Manager | ok |
| valid row 5 | v5@acme.io,Auditor | ok |
| invalid row A | not-an-email,Employee | malformed email |
| invalid row B | v6@acme.io,Wizard | unknown role |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /api/v1/admin/users/invitations/bulk` (multipart CSV) | 200/207 multi-status; a per-row result list. |
| 2 | Inspect the result payload | 5 rows reported `success` (with created invitation refs); 2 rows reported `error` with row index + reason ("invalid email", "unknown role: Wizard"). |
| 3 | Query `user_invitation` for Acme | Exactly 5 new invitations (v1..v5); none for `not-an-email` or v6. |
| 4 | Confirm valid rows were NOT blocked | All 5 valid invitations exist despite the 2 invalid rows in the same file. |
| 5 | Query `audit_log` | The bulk invite is audited (actor=Dana, count succeeded/failed). |

## 6. Postconditions
- 5 pending invitations created from one upload; the 2 invalid rows produced row-scoped errors only.

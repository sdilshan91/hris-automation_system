# TC-ADM-002-05: DB and Redis health indicators reflect real dependency state (Redis "not configured" honored)

## 1. Test Objective
Verify AC-1 / FR-6: the dashboard shows DB and Redis health as discrete status indicators sourced from the readiness check, and that when no Redis is wired the indicator shows an explicit "not configured" state rather than a fabricated healthy/green. Also verify a degraded DB propagates to the platform-health roll-up.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-1
- Functional Requirements: FR-6
- Data Source: `/health/ready`

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- Ability to control dependency state for the test environment (DB reachable/unreachable; Redis configured/not-configured).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Scenario A | DB up, Redis configured & up | both healthy |
| Scenario B | DB up, Redis NOT configured | Redis -> "not configured" |
| Scenario C | DB down/degraded | DB -> down; roll-up degraded/down |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Scenario A: load the dashboard | DB indicator = healthy (green); Redis indicator = healthy (green); roll-up = healthy. |
| 2 | Scenario B: with no Redis wired, load the dashboard | Redis indicator explicitly shows `not configured` (neutral), NOT green; DB stays healthy; roll-up reflects only required dependencies (a not-configured optional Redis does not force "down"). |
| 3 | Scenario C: make the DB readiness check fail, reload | DB indicator = down (red); the platform-health roll-up reflects the worst dependency (degraded or down). |
| 4 | Confirm indicators trace to `/health/ready` | The displayed states match the `/health/ready` payload — no independent/fabricated status. |

## 6. Postconditions
- Health indicators faithfully mirror dependency readiness; absent Redis is shown as not-configured.

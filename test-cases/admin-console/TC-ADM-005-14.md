# TC-ADM-005-14: Force password reset — ALL refresh tokens across tenants revoked, password_changed_at nulled, reset email, audited

## 1. Test Objective
Verify AC-5: "Force Password Reset" revokes ALL of the target user's refresh tokens across ALL tenants (the password is a global credential), nullifies `password_changed_at` to force a reset, dispatches a password-reset email (log-only seam — delivery TC-ADM-005-19), and audits the action. Because the credential is global, this is the one user action whose token revocation is deliberately cross-tenant (contrast with deactivation in TC-ADM-005-11/-12).

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-5
- Non-Functional: NFR-2 (audit)

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Target user "Sam" has memberships in Acme AND Beta, with live refresh tokens/sessions in BOTH.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| target user | sam | dual-tenant |
| action | force-password-reset | global credential |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, `POST /api/v1/admin/users/{sam}/force-password-reset` (confirm) | 200/204 success. |
| 2 | Query `users` for Sam | `password_changed_at` is NULL (forces reset on next login). |
| 3 | Query Sam's refresh tokens across ALL tenants (Acme + Beta) | ALL revoked/invalidated — not just Acme (global credential). |
| 4 | As Sam, attempt to refresh/use any existing session in Beta | Rejected — token revoked despite Dana acting from Acme. |
| 5 | Inspect the email/dispatch seam | A password-reset email to Sam is dispatched (log-only; delivery deferred TC-ADM-005-19). |
| 6 | Query `audit_log` | A force-reset entry: actor=Dana, action, IP, timestamp, before/after (NFR-2). |

## 6. Postconditions
- Sam must reset their global password; every session everywhere is dead until they do.

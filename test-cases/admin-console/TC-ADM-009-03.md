# TC-ADM-009-03: Unique-code enforcement — second plan with same code rejected (incl. archived code reuse)

## 1. Test Objective
Verify FR-3 + BR-5 + the "Unique code" Test Hint: the `code` field is unique across all plans. Creating a second plan with an existing code is rejected. The code cannot be reused even after the original plan is archived (BR-5).

## 2. Related Requirements
- User Story: US-ADM-009
- Functional Requirements: FR-3 (code unique + immutable)
- Business Rules: BR-5 (code not reusable, even if archived)
- Test Hints (Unique code)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.
- A plan with code `growth` already exists.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| existing code | growth | active |
| duplicate attempt | growth | second create |
| archived code | starter (then archived) | reuse attempt after archive |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Pat, POST create a plan with code `growth` (different name/limits) | 409/400 — rejected with a "code already exists" validation error; no second row created. |
| 2 | Archive the `starter` plan (is_active=false) | 200; starter archived. |
| 3 | POST create a NEW plan with code `starter` | 409/400 — rejected; the code remains taken by the archived plan (BR-5). |
| 4 | Inspect plans list | Exactly one plan per code; no duplicates created by the rejected attempts. |

## 6. Postconditions
- No duplicate or reused-code plans created.

# TC-ADM-003-13: Audit attribution — actions during impersonation carry impersonator id + session id in both logs

## 1. Test Objective
Verify AC-2 / FR-3: every action performed during an impersonation session is attributed to the impersonator. Tenant-scoped audit rows written during the session carry `ImpersonatorUserId`, `ImpersonationSessionId`, and `IsImpersonationAction=true`; the corresponding system AuditLog entries carry the same attribution; and the session's `actions_count` increments per action.

## 2. Related Requirements
- User Story: US-ADM-003
- Acceptance Criteria: AC-2
- Functional Requirements: FR-3, FR-4
- Test Hints: Happy path (verify action logged in both tenant + system audit with correct impersonator attribution)

## 3. Preconditions
- An Active impersonation session (Olivia impersonating Bob in Acme) with `actions_count=0`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| impersonator | Olivia | imp_actor_id |
| target user | Bob | sub of imp token |
| actions | one read + one benign write (full session) | both should be attributed |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | With the imp token, perform a read action that produces an audit row | A tenant audit row is written with `ImpersonatorUserId`=Olivia, `ImpersonationSessionId`=session id, `IsImpersonationAction=true` — even though the acting `sub` is Bob. |
| 2 | Inspect the matching system AuditLog entry | Same impersonator attribution + session id recorded at the system level. |
| 3 | Perform a benign write action (full session) | A tenant audit row with the same impersonator attribution is written. |
| 4 | Query `impersonation_sessions.actions_count` | Incremented to reflect the actions performed (FR-4). |
| 5 | Compare against a NON-impersonated action by Bob himself (control) | A normal action by Bob has `IsImpersonationAction=false` and no impersonator id — attribution only appears for impersonated actions. |

## 6. Postconditions
- All impersonated actions are unambiguously attributable to the impersonator across both audit trails; actions_count reflects activity.

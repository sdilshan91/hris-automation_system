# TC-ADM-008-11: Export respects filters, masks sensitive values, and self-audits "AuditLog.Export"

## 1. Test Objective
Verify AC-4 / BR-4 / FR-4: exporting the audit log (CSV or JSON) produces a file containing ONLY the records matching the currently applied filters, with sensitive field values masked as `***REDACTED***`. The export action itself writes a new `audit_log` row with `Action = "AuditLog.Export"` (to prevent silent data exfiltration). This covers the SYNCHRONOUS small-dataset path; the async >10k Hangfire + emailed-link path is DEFERRED (TC-ADM-008-19). (Test Hints — Export audit; Sensitive field masking.)

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-4
- Functional Requirements: FR-4 (masked), FR-5 (synchronous small-export path; async path deferred)
- Business Rules: BR-4 (export is itself audited)

## 3. Preconditions
- Dana (`TenantAdmin`, Acme) authenticated.
- Acme `audit_log` has rows; a filter (e.g. action="Leave.Approve") is applied that selects a small subset (< 10,000 rows).
- At least one selected row contains a `bank_account_number`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| applied filter | action=Leave.Approve | export must respect it |
| format | CSV, then JSON | both formats tested |
| sensitive value | bank_account_number=1234567890 | must be masked in file |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Apply filter action=Leave.Approve; click Export (CSV) | A CSV file is generated synchronously and available for immediate download. |
| 2 | Inspect file rows | Contains ONLY the Leave.Approve rows (respects the active filter), not the full table. |
| 3 | Inspect sensitive columns/values | bank_account_number appears as `***REDACTED***`, never the raw value. |
| 4 | Repeat as JSON | JSON export respects the same filter + masking. |
| 5 | Query the audit log after export | A new row exists with Action="AuditLog.Export", actor=Dana, tenant=Acme, timestamp ~now. |
| 6 | Confirm export-audit content | The export-audit row records the requesting actor (and ideally the filter/format) — no silent exfiltration. |

## 6. Postconditions
- Exactly one new `AuditLog.Export` row added for Acme; no other audit rows mutated.

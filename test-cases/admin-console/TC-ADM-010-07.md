# TC-ADM-010-07: Audit log export as JSON Lines (audit_log.jsonl)

## 1. Test Objective
Verify FR-5: the tenant's audit log is exported as `audit_log.jsonl` in JSON Lines format — one valid JSON object per line, one line per audit record — and is tenant-scoped (only Acme's audit rows).

## 2. Related Requirements
- User Story: US-ADM-010
- Acceptance Criteria: AC-2
- Functional Requirements: FR-5 (JSON Lines audit export, one record per line, all fields)

## 3. Preconditions
- Acme has a known number of audit_log rows (e.g. N rows) including before/after detail rows.
- A FULL export of Acme has Completed.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| acme_audit_rows | N | known count for assertion |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open `audit_log.jsonl` and count lines | Line count == N (one record per line; the manifest row_count for audit_log also == N). |
| 2 | Parse each line as JSON independently | Every line is a standalone valid JSON object (true JSONL, not a JSON array). |
| 3 | Inspect a record that had a before/after change | The record includes its fields including before/after content. |
| 4 | Inspect every record's tenant attribution | All records belong to Acme — none from another tenant (cross-tenant covered in TC-ADM-ISO-028). |

## 6. Postconditions
- No state change.

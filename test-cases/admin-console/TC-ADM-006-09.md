# TC-ADM-006-09: Localization — unsupported language (and invalid format/timezone/currency) rejected

## 1. Test Objective
Verify FR-4: localization input is validated against the system-supported languages list; an unsupported language code is rejected with 400 and the tenant default is unchanged. Also verify rejection of an unsupported/garbage date format, time zone, or currency code (no silent acceptance of an unrenderable value).

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4
- Business Rules: BR-5

## 3. Preconditions
- Tenant Admin "Dana" authenticated at `acme.yourhrm.com`; a known-good localization baseline exists.
- The platform ships English + at least one supported secondary language; `xx` is NOT in the supported list.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| unsupported language | "xx" | not in supported list → reject |
| invalid date format | "QQ-WW-ZZ" | not a recognized format token |
| invalid timezone | "Mars/Olympus" | not a valid IANA zone |
| invalid currency | "ZZZ" | not a valid ISO 4217 code |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `PUT` localization with `default_language = "xx"` | 400; "unsupported language" error; tenant default unchanged. |
| 2 | `PUT` with an invalid date format token | 400; rejected; unchanged. |
| 3 | `PUT` with `time_zone = "Mars/Olympus"` | 400; rejected; unchanged. |
| 4 | `PUT` with `currency = "ZZZ"` | 400; rejected; unchanged. |
| 5 | `GET` localization after rejects | Equals the baseline; no audit row for rejected attempts. |

## 6. Postconditions
- Tenant localization unchanged; only supported/valid values can be persisted.

# TC-ADM-006-14: Authorization — only TenantAdmin/TenantOwner may modify settings; others denied

## 1. Test Objective
Verify BR-1: every settings-mutation endpoint (org profile, branding, localization, password policy, session policy) requires the `TenantAdmin` or `TenantOwner` role. A regular Employee/Manager in the tenant is denied (403), and an unauthenticated request is rejected (401). Read endpoints follow the platform's read-authorization contract; writes are admin-only.

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-1..AC-4 (all guarded by authz)
- Business Rules: BR-1 (TenantAdmin/TenantOwner only)

## 3. Preconditions
- Acme tenant with: Dana (`TenantAdmin`), Olivia (`TenantOwner`), Em (`Employee`, no admin role), plus an unauthenticated client.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| admin roles | TenantAdmin, TenantOwner | allowed |
| denied role | Employee/Manager | 403 |
| no token | unauthenticated | 401 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana (TenantAdmin), `PUT` org profile | 200; allowed. |
| 2 | As Olivia (TenantOwner), `PUT` branding primary color | 200; allowed. |
| 3 | As Em (Employee), `PUT` each settings endpoint (org/branding/localization/password policy/session policy) | 403 each; no change persisted. |
| 4 | Unauthenticated, `PUT` any settings endpoint | 401; no change. |
| 5 | As Em, `PUT` password policy | 403; the password policy is unchanged. |
| 6 | Confirm audit | No audit rows written for the denied/unauth attempts (or a denied-access audit if the platform records those — but never a settings-change row). |

## 6. Postconditions
- Settings mutated only by admin roles; non-admin and unauthenticated writes blocked.

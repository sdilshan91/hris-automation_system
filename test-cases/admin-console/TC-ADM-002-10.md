# TC-ADM-002-10: Monitoring views expose only aggregates/operational fields — no tenant PII

## 1. Test Objective
Verify AC-5 / BR-2: monitoring views (dashboard overview, tenant usage table, tenant detail) expose only aggregate counts and operational fields (employee COUNT, status, plan, owner email, timestamps, job counts). They MUST NOT expose employee-level PII such as employee names, national IDs, addresses, or salaries from any tenant.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-5
- Business Rules: BR-2
- Test Hints: monitoring shows only aggregate data, never PII

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- At least one tenant has employees with known PII (names, salaries) seeded.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Tenant | acme | has employees w/ PII |
| Allowed fields | employee COUNT, status, plan, owner email, created, last activity, job counts | aggregates/operational |
| Forbidden fields | employee names, salaries, national IDs, addresses | tenant PII |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Capture the raw JSON of `GET /api/v1/admin/monitoring/overview` | Payload contains only counts/health/job aggregates — no employee records, no names, no salaries. |
| 2 | Capture the raw JSON of the tenant usage table response | Each tenant row carries the employee COUNT and limit, not an enumeration of employees; no PII fields present. |
| 3 | Capture the raw JSON of `GET /api/v1/admin/monitoring/tenants/{id}` | Detail carries status/plan/owner-email/created/last-activity/job-status only; no employee names/salaries/national IDs. |
| 4 | Grep all three payloads for seeded PII values (a known employee name and salary) | Zero matches — the PII strings appear nowhere in any monitoring response. |
| 5 | Inspect the rendered UI for the same tenant | Only aggregates/operational fields are displayed; no employee-level PII is rendered. |

## 6. Postconditions
- No employee PII is exposed via any monitoring view or API. Only aggregates/operational fields are surfaced.

# TC-ADM-004-09: Data-deletion job fires — per-tenant data hard-deleted, tenant row retained as Terminated with PII redacted, audit retained, lifecycle 'terminated'

## 1. Test Objective
Verify AC-4 / FR-3: when the scheduled data-deletion Hangfire job fires (grace expired or triggered manually), all per-tenant business data is hard-deleted within a transaction in dependency order, the `tenant` row is RETAINED with `status = Terminated` and PII fields redacted (not deleted), audit logs are retained per the retention policy, a `tenant_lifecycle_event` with `event_type = 'terminated'` is written, and the operation is recorded in `system_audit_log`.

## 2. Related Requirements
- User Story: US-ADM-004
- Acceptance Criteria: AC-4
- Functional Requirements: FR-3, FR-7
- Non-Functional: NFR-4 (atomic, no partial state)
- Test Hints: Data deletion

## 3. Preconditions
- Tenant "Acme" is in `Terminating` status with populated per-tenant business data (employees, leave, attendance, payroll, settings, user_tenant memberships).
- The data-deletion job for Acme can be triggered manually (force-run) for the test.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| tenant_id | acme-tenant-uuid | terminating |
| business tables | employees/leave/attendance/payroll/tenant_setting/user_tenant | hard-delete targets |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Trigger the Acme data-deletion job | Job runs to completion. |
| 2 | Query each per-tenant business table for `tenant_id = Acme` | Zero rows — all per-tenant business data hard-deleted (children before parents; transactional). |
| 3 | Re-read the `tenant` row for Acme | Row STILL EXISTS; `status = Terminated`; PII fields (owner name/email, billing email, etc.) redacted/nulled per FR-3 — NOT deleted. |
| 4 | Query the retained audit/log tables for Acme | Audit logs are retained per the retention policy (not purged with business data). |
| 5 | Query `tenant_lifecycle_event` | A `event_type = 'terminated'` row is written. |
| 6 | Query `system_audit_log` | A deletion-completed entry exists (FR-7 / AC-4). |
| 7 | Simulate a mid-deletion failure (inject fault), then inspect state | Transaction rolls back atomically — no partial deletion; the job is safely retried by Hangfire (NFR-4 atomicity). |

## 6. Postconditions
- Acme's business data is gone; its tenant row persists as `Terminated` with PII redacted; audit history is intact; deletion is fully audited.
- NOTE: file-storage (blob) deletion of documents/resumes/payslips per §10 is DEFERRED — no blob storage is wired (see TC-ADM-004-19).

# TC-ADM-008-16: Detail diff view — added/modified/removed fields highlighted (FE-verified)

## 1. Test Objective
Verify FR-3 / AC-3: the audit detail DIFF VIEW (computed on the FRONTEND from the `before`/`after` JSON returned by the API) highlights changed fields — added (green), removed (red), and modified (yellow) — with old and new values shown. (Test Hints — Diff view: change an employee name "John" -> "Jane"; verify the diff shows old and new values correctly.) This is FE-verified.

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-3 (diff highlight of changed fields)
- Functional Requirements: FR-3 (visual diff between before/after, computed FE-side)

## 3. Preconditions
- Dana (`TenantAdmin`, Acme) authenticated in the running SPA.
- Acme has an Employee.Update audit row: `before` = `{"first_name":"John","title":"Analyst"}`, `after` = `{"first_name":"Jane","department":"HR"}` (title removed, department added, first_name modified).

## 4. Test Data
| Field | before | after | Expected highlight |
|-------|--------|-------|--------------------|
| first_name | John | Jane | modified (yellow) |
| title | Analyst | (absent) | removed (red) |
| department | (absent) | HR | added (green) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the audit list; click the Employee.Update row | The detail side panel opens with a diff view. |
| 2 | Inspect first_name | Shown as modified — old "John" and new "Jane" both visible, highlighted as a change. |
| 3 | Inspect title | Shown as removed (red) — present in before, gone in after. |
| 4 | Inspect department | Shown as added (green) — absent in before, present in after. |
| 5 | Inspect a sensitive field if present | Masked value `***REDACTED***` is what the diff renders (no raw sensitive value leaks into the FE). |
| 6 | Keyboard + screen reader | Diff panel is keyboard-navigable; color coding has a non-color cue (icon/label) per WCAG 2.1 AA. |

- No state change.

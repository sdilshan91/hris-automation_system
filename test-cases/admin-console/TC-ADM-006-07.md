# TC-ADM-006-07: Primary brand color — hex validated server-side; FE derives complementary shades

## 1. Test Objective
Verify AC-2/FR-3: the primary brand color is accepted as a validated hex value, persisted to `branding.primary_color`, and the frontend derives complementary shades (dark/light/contrast text) into CSS custom properties so buttons/links/sidebar reflect the new color (Test Hint). Invalid hex is rejected.

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-2
- Functional Requirements: FR-3
- Non-Functional: NFR-2 (server-side validation), NFR-4 (audit)
- Test Hints: "Set a primary color; verify CSS custom properties are updated and buttons/links reflect the new color."

## 3. Preconditions
- Tenant Admin "Dana" authenticated at `acme.yourhrm.com`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| valid hex (6) | `#1E88E5` | accepted |
| valid hex (3) | `#0AF` | accepted if 3-digit supported, else reject consistently |
| invalid — no `#` | `1E88E5` | reject per validator contract |
| invalid — bad chars | `#ZZZZZZ` | reject |
| invalid — wrong length | `#12345` | reject |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `PUT` branding with `primary_color = #1E88E5` | 200; `branding.primary_color` persisted; audited. |
| 2 | Load a tenant page (FE) | CSS custom properties for primary + derived dark/light/contrast shades are set; buttons, links, sidebar reflect `#1E88E5`. |
| 3 | `PUT` invalid hex variants (no `#`, bad chars, wrong length) | 400 each; `primary_color` unchanged. |
| 4 | `GET` branding after rejects | Value remains the last valid color. |

## 6. Postconditions
- `branding.primary_color` holds a valid hex; FE renders derived shades; invalid attempts rejected and unaudited.

# TC-ADM-002-03: Per-tenant employee usage gauge — 100% breach flag (max_employees=5, 5 employees)

## 1. Test Objective
Verify the upper quota boundary of AC-2 for the employee usage gauge. With `max_employees = 5` and the 5th active employee created, the tenant's employee gauge reads 100% and the tenant is flagged as BREACHED (red), distinct from the 80% warning state.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2, FR-3
- Business Rules: BR-4 (95% threshold also triggers an alert)
- Test Hints: max_employees=5, 5 employees -> 100% breach

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- Tenant "Acme" on a plan with `max_employees = 5`, currently at 4 employees (from TC-ADM-002-02), about to add the 5th.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Tenant | acme | usage subject |
| max_employees | 5 | plan limit |
| Active employees | 5 | 5/5 = 100% |
| Expected gauge | 100% | red breach band (95-100%) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create the 5th active employee in Acme (or seed to 5), then refresh the Monitoring dashboard | Acme's employee gauge recomputes. |
| 2 | Read the employee gauge value | Reads 5 / 5 = 100%. |
| 3 | Read the gauge color/indicator | Red BREACH band; tenant flagged as breached. |
| 4 | Verify Acme appears in the quota-breach queue | Acme is listed in the breach queue at 100% severity (top), ahead of warning-only tenants (FR-3). |
| 5 | (Boundary cross-check) Verify the 95% threshold flag | At 95% of any limit, BR-4 marks the tenant for an alert; for max_employees=5 the discrete steps are 4=80% and 5=100%, so confirm the breach queue includes both the 80%+ warning tier and the 100% breach tier sorted by severity. |

## 6. Postconditions
- Acme renders at 100% breach and tops the breach queue. State documented for downstream alert tests.

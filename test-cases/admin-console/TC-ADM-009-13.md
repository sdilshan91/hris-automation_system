# TC-ADM-009-13: Audit completeness — create/edit/archive/delete-attempt/override all logged with before/after

## 1. Test Objective
Verify NFR-3: every plan-management operation is logged to the system audit log with full before/after state. Sweep across create, update, archive, delete-attempt (rejected), and override create/update/delete and confirm each writes an audit entry with actor, action, before/after, and timestamp.

## 2. Related Requirements
- User Story: US-ADM-009
- Non-Functional Requirements: NFR-3 (all operations audited with full before/after state)
- Acceptance Criteria: AC-2, AC-3, AC-4, AC-5 (each names auditing)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.
- A clean audit baseline for the plan(s) under test.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| ops swept | create, update, archive, delete-attempt, override create/update/delete | all audited |
| audit fields | actor, action, before, after, timestamp | full envelope |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create plan `temp` | Audit "SubscriptionPlan.Create": after=full plan, before=null, actor=Pat, ts. |
| 2 | Update `temp` (change max_employees) | Audit "SubscriptionPlan.Update": before {max_employees:old}, after {max_employees:new}. |
| 3 | Archive `temp` | Audit "SubscriptionPlan.Archive": before {is_active:true}, after {is_active:false}. |
| 4 | Attempt DELETE a referenced plan (rejected) | Whether or not a rejected op is audited is consistent with the platform convention; at minimum the rejection is observable and no state changed. |
| 5 | Create/update/delete a `plan_limit_override` | Each override mutation writes an audit entry with tenant_id, limit_key, value, expires_at before/after. |
| 6 | Inspect every entry | All carry actor, action, before/after, and timestamp — no operation is unaudited. |

## 6. Postconditions
- Every executed plan/override mutation is auditable end-to-end.

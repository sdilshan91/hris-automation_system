# TC-ADM-005-16: Invitation expiry (72h) blocks acceptance; Resend issues a NEW token that works (BR-6)

## 1. Test Objective
Verify BR-6 / AC-2 / Test-Hint "Invitation expiry": an invitation token is valid for 72 hours. Accepting after expiry is rejected (and the invitation marked `Expired`). Resend generates a fresh token (invalidating the old one) and resets the 72h window; the new token accepts successfully. Also covers Revoke making an outstanding invitation unusable.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-2
- Business Rules: BR-6
- Test Hints: Invitation expiry

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- A pending invitation exists for "late@acme.io" with `status = Invited`, `expires_at = created + 72h`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| invite | late@acme.io | Invited |
| time advance | +73h | past 72h window |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Advance system/clock (or expiry-sweep job) past 72h, then attempt to accept the original token | Rejected as expired; invitation `status` resolves to `Expired`. |
| 2 | As Dana, `POST /api/v1/admin/users/invitations/{id}/resend` | 200; a NEW hashed token is generated; `expires_at` reset to now + 72h; `status = Invited`. |
| 3 | Attempt to accept using the OLD (pre-resend) token | Rejected — the previous token is invalidated by resend. |
| 4 | Accept using the NEW token within 72h | Succeeds; membership transitions `invited` -> `active`; roles applied; invitation `status = Accepted`. |
| 5 | Create another invite, then `POST .../invitations/{id}/revoke` and attempt to accept | Acceptance rejected; invitation `status = Revoked`. |
| 6 | Query `audit_log` | Resend and revoke actions audited (actor=Dana, timestamps). |

## 6. Postconditions
- Expired/revoked invitations are unusable; resend cleanly re-enables onboarding via a fresh token.

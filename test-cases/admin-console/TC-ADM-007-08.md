# TC-ADM-007-08: FR-5 validation — non-positive SLA values rejected

## 1. Test Objective
Verify FR-5 (third clause): SLA values must be positive integers. A step with `sla_hours <= 0` (0 or negative) or a non-integer is rejected; no definition is persisted. The lowest valid boundary (1) is accepted.

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-2 (creation validity)
- Functional Requirements: FR-5 (SLA positive integer), FR-2 (sla_hours)

## 3. Preconditions
- Dana (`TenantAdmin`) at Acme `active`; valid approver refs available; plan limit not reached.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| sla=0 | step sla_hours=0 | invalid (boundary below positive) |
| sla=-5 | step sla_hours=-5 | invalid (negative) |
| sla=1 | step sla_hours=1 | valid (lowest positive boundary) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | POST create workflow with a step sla_hours = 0 | Rejected (HTTP 400/422); error indicates SLA must be a positive integer. Nothing persisted. |
| 2 | POST create workflow with a step sla_hours = -5 | Rejected; nothing persisted. |
| 3 | POST create workflow with a step sla_hours = 1 | 201; accepted (positive boundary). |

## 6. Postconditions
- Only the positive-SLA workflow persists; no zero/negative-SLA definition exists.

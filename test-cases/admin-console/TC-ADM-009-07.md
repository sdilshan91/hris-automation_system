# TC-ADM-009-07: Edit plan propagation — limits read live so existing tenants benefit immediately; before/after audited

## 1. Test Objective
Verify AC-3 + the "Edit plan propagation" Test Hint (upward path): editing an existing plan's `max_employees` (100 -> 200) updates the plan record and, because limits are read from the plan at runtime, existing tenants on that plan immediately benefit from the increased limit (can create more employees). The edit is audited with before/after values.

> NOTE: The DOWNWARD path of the Test Hint — "edit limit downward, existing data preserved but new creations blocked when over limit" — is BR-4 and depends on each module's create-time limit check; that retroactive-block behavior is captured in the DEFERRED/conditional TC-ADM-009-16. This TC asserts the propagation mechanism (live read) + the upward effect + audit.

## 2. Related Requirements
- User Story: US-ADM-009
- Acceptance Criteria: AC-3
- Functional Requirements: FR-1 (update), FR-2 (limit fields)
- Non-Functional Requirements: NFR-3 (before/after audit)
- Test Hints (Edit plan propagation — upward)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.
- Plan `growth` has `max_employees=100`.
- Tenant "Acme" is provisioned on `growth`; `Tenant.MaxEmployees` is derived from the plan; Acme has 100 active employees (at limit).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| plan | growth | |
| max_employees before | 100 | Acme at limit |
| max_employees after | 200 | edit upward |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Acme tenant admin, attempt to create the 101st employee (before the edit) | Rejected — Acme at the 100 limit. |
| 2 | As Pat, PUT update `growth` max_employees=200 | 200; plan record updated to 200. |
| 3 | As Acme tenant admin, create the 101st employee (after the edit) | Succeeds — the increased limit is in effect immediately because Acme's employee-limit check reads the plan/derived limit live (no manual re-provision needed). |
| 4 | Inspect system audit log for the edit | Entry "SubscriptionPlan.Update": actor=Pat, before {max_employees:100}, after {max_employees:200}, timestamp. |
| 5 | (Optional) Confirm affected-tenant notification dispatch | If implemented, a plan-change notification dispatch to affected tenant admins is enqueued (delivery is US-NTF; see TC-ADM-009-15 for propagation/cache nuance). |

## 6. Postconditions
- Plan limit is 200; Acme can grow past 100; edit audited.

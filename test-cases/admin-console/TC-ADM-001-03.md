# TC-ADM-001-03: Duplicate subdomain is rejected (including reuse of a terminated subdomain)

## 1. Test Objective
Verify AC-2 and BR-2: the platform rejects a submission whose subdomain is already allocated to an existing tenant, displaying "Subdomain is unavailable" and preventing creation. A subdomain previously allocated to a now-terminated tenant is also rejected (no reuse, to prevent subdomain takeover).

## 2. Related Requirements
- User Story: US-ADM-001
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2
- Business Rules: BR-2

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com` with the `SystemAdmin` role.
- Tenant `acme` already exists (active). Tenant `formerco` previously existed and is now `terminated` (its subdomain remains allocated per BR-2).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Existing active subdomain | acme | already in use |
| Terminated subdomain | formerco | allocated, not reusable (BR-2) |
| Other fields | valid (name, plan, owner, region) | so only subdomain is at fault |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | On the Create Tenant form, type subdomain `acme` and wait for the debounced availability check | The real-time indicator shows a red X and "Subdomain is unavailable" (FR-2). |
| 2 | Submit the form anyway (forcing a server call); observe `POST /api/v1/admin/tenants` | Server-side validation rejects with 400/409 and message "Subdomain is unavailable"; NO new tenant, user, lifecycle event, or audit "created" event is written. |
| 3 | Change the subdomain to `formerco` (terminated tenant) and submit | The request is rejected the same way; the terminated subdomain cannot be reclaimed (BR-2). |
| 4 | Confirm no side effects | `tenant` count unchanged; no welcome email dispatched; no partial rows in `users`/`user_tenant`. |

## 6. Postconditions
- No tenant was created; the existing/terminated subdomains remain owned by their original tenants.

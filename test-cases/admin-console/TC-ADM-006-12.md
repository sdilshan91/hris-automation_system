# TC-ADM-006-12: Password policy ENFORCEMENT — short/non-complex password rejected at next change/reset

## 1. Test Objective
Verify the AC-4 / Test-Hint enforcement contract: after the tenant sets minimum length to 12 (and complexity flags on), a user's next password change/reset is validated against that policy by the password validation service — a 10-character password is REJECTED, and a password missing a required complexity class is rejected; only a compliant password (≥12, meets complexity) is accepted. Enforcement is read from the CURRENT tenant policy, so a tighter policy takes effect immediately for subsequent changes.

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5
- Test Hints: "Set minimum length to 12; attempt to set a 10-character password; verify rejection."

## 3. Preconditions
- Tenant Admin "Dana" has set the Acme policy: min_length 12, require upper/lower/digit/special, history_count 5 (per TC-ADM-006-11).
- User "Noah" is a member of Acme and is performing a password change (or going through reset).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| too short | "Ab1!xyzq" (10 chars) | < 12 → reject |
| missing class | "abcdefghijkl" (12, no upper/digit/special) | fails complexity → reject |
| reused | a password in Noah's last-5 history | history_count → reject |
| compliant | "Abcdef12!@xyz" (≥12, all classes, new) | accept |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Noah, change password to the 10-char value | 400; rejected — below tenant minimum length (12). |
| 2 | Change to a 12-char all-lowercase value | 400; rejected — missing required complexity classes. |
| 3 | Change to a previously-used password (within history_count) | 400; rejected — password-history violation. |
| 4 | Change to the compliant value | 200; accepted; `password_changed_at` updated. |
| 5 | Confirm enforcement source | The validator read Acme's CURRENT policy (a tighter policy set moments earlier applies to this change). |

## 6. Postconditions
- Non-compliant passwords blocked; compliant password set; policy enforced from the live tenant configuration.

# TC-ADM-004-17: Typed-subdomain confirmation gate for termination — wrong/absent subdomain blocks; paste prevented (FE-verified)

## 1. Test Objective
Verify FR-4 / NFR-5: the termination flow requires the operator to TYPE the tenant's exact subdomain to confirm. An incorrect or absent confirmation blocks the action (the FE "Terminate" button stays disabled; if the API receives a request, it rejects on mismatch). Paste into the confirmation field is prevented (NFR-5) — verified at the frontend layer.

## 2. Related Requirements
- User Story: US-ADM-004
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4
- Non-Functional: NFR-5 (paste prevention)
- Test Hints: Typed confirmation

## 3. Preconditions
- System Admin authenticated; in the multi-step termination dialog for active tenant "acme" (subdomain = `acme`).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| correct subdomain | "acme" | unlocks Terminate |
| wrong subdomain | "acmee" / "Acme" / "" | blocks |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In the confirmation field type a WRONG subdomain ("acmee") | The red "Terminate" button remains disabled; submission is blocked. |
| 2 | Leave the confirmation field empty and attempt to submit | Blocked; button disabled. |
| 3 | Type a case-mismatched value ("Acme" when subdomain is "acme") | Blocked unless exact match (confirm exact-match semantics per FR-4). |
| 4 | Type the EXACT subdomain ("acme") | The "Terminate" button enables; submission proceeds to the termination call (cross-ref TC-ADM-004-06). |
| 5 | Attempt to PASTE a value into the confirmation field (FE) | Paste is blocked; the field requires manual typing (NFR-5) — verified in the browser/component test. |
| 6 | (API guard) Send a terminate request whose typed confirmation does not match the subdomain | Server rejects on subdomain mismatch (defense in depth; no Terminating transition). |

## 6. Postconditions
- Termination is gated on an exact, manually-typed subdomain; mismatches never terminate.
- NOTE: FR-4 typed-confirmation and NFR-5 paste-prevention are FRONTEND concerns — steps 1-5 are FE-verified (component/e2e); step 6 is the backend defense-in-depth check.

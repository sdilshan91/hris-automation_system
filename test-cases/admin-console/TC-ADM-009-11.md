# TC-ADM-009-11: Provisioning inherits the plan — tenant.EnabledModules + MaxEmployees derived from the chosen plan

## 1. Test Objective
Verify the "Assign to tenant" Test Hint (and US-ADM-001 dependency): provisioning a new tenant with a chosen plan derives the tenant's `EnabledModules` and `MaxEmployees` (and other governed limits) from that plan. The tenant inherits the plan's enabled modules and limits at provisioning time.

## 2. Related Requirements
- User Story: US-ADM-009
- Functional Requirements: FR-2 (limit/module fields), FR-6 (enabled_modules)
- Dependencies: US-ADM-001 (provisioning)
- Test Hints (Assign to tenant)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.
- Plan `growth` exists: max_employees=100, enabled_modules=["CoreHR","Leave","Attendance","Reporting"] (no Recruitment/Payroll).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| chosen plan | growth | |
| new tenant | beta | provisioned on growth |
| expected MaxEmployees | 100 | derived from plan |
| expected EnabledModules | CoreHR, Leave, Attendance, Reporting | derived from plan |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Pat, provision tenant `beta` selecting plan `growth` | 201; tenant created and linked to `growth`. |
| 2 | Inspect `beta` derived fields | `Tenant.MaxEmployees=100` and `Tenant.EnabledModules` = the plan's enabled_modules (CoreHR, Leave, Attendance, Reporting). |
| 3 | Confirm modules NOT in the plan | Recruitment and Payroll are NOT in beta's EnabledModules (runtime gating that blocks their routes/APIs is deferred — TC-ADM-009-14; here we assert the derived entitlement set). |
| 4 | Confirm the employee limit takes effect | Beta's employee-creation limit reflects 100 (consistent with TC-ADM-009-07's live read). |

## 6. Postconditions
- New tenant inherits plan modules + limits at provisioning.

# TC-ADM-003-07: Impersonation token expiry — session past 60-min ExpiresAt is rejected; token not refreshable

## 1. Test Objective
Verify NFR-2 / AC-3: the impersonation JWT has a hard-capped 60-minute TTL and CANNOT be refreshed. Once `imp_expires_at` (and the session `expires`) has passed, the per-request session middleware rejects any tenant request bearing that token, marks the session `Expired`, and no refresh path issues a new impersonation token from the expired one.

## 2. Related Requirements
- User Story: US-ADM-003
- Acceptance Criteria: AC-3
- Non-Functional Requirements: NFR-2
- Test Hints: Expiry

## 3. Preconditions
- An impersonation session exists. Time can be advanced (mock clock / fast-forward) past the session's `ExpiresAt`, OR a session is seeded with `ExpiresAt` in the past.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| TTL cap | 60 minutes | NFR-2 hard cap |
| Clock advance | +61 minutes | past expiry |
| refresh attempt | call any refresh endpoint with the imp token | must NOT mint a new imp token |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Start a session; confirm `imp_expires_at` <= now + 60 min | TTL is capped at 60 minutes (NFR-2). |
| 2 | Advance the clock to +61 minutes (or use a session with past `ExpiresAt`) | The session's `expires` is now in the past. |
| 3 | With the (now expired) token, call any tenant request | Rejected (401) — per-request middleware enforces expiry; session is treated as Expired. |
| 4 | Query `impersonation_sessions` | `status=Expired` (enforced lazily by the middleware on the expired request). |
| 5 | Attempt to refresh the impersonation token (standard refresh path with the imp token) | No new impersonation token is issued — impersonation tokens are not refreshable; a new session must be initiated. |

## 6. Postconditions
- Expired impersonation sessions are unusable and non-refreshable; continuing support requires a brand-new session.

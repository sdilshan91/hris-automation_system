# TC-ADM-006-11: Password policy — GET+PUT persists structured policy; before/after audited

## 1. Test Objective
Verify AC-4/FR-5: a Tenant Admin reads and updates the password policy (minimum length, complexity flags for uppercase/lowercase/digit/special, history count, max age). The policy persists to the current tenant's password-policy fields and the change is audited before/after. Existing passwords are NOT retroactively invalidated (enforcement at next change is covered by TC-ADM-006-12).

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5
- Non-Functional: NFR-4 (audit)

## 3. Preconditions
- Tenant Admin "Dana" authenticated at `acme.yourhrm.com`; password-policy fields already exist on the Tenant entity (pre-existing columns).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| min_length | 12 | |
| require_uppercase | true | |
| require_lowercase | true | |
| require_digit | true | |
| require_special | true | |
| history_count | 5 | cannot reuse last 5 |
| max_age_days | 90 | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, `GET` password policy | 200; returns the current tenant's policy. |
| 2 | `PUT` the Test Data | 200; all fields persisted to the current tenant. |
| 3 | `GET` again | Every field equals the new value. |
| 4 | Confirm existing users' current passwords still authenticate | No retroactive invalidation; existing logins succeed. |
| 5 | Inspect audit | Before/after entry for the password-policy change, actor = Dana. |
| 6 | `PUT` an out-of-range value (min_length 0 or negative) | 400; rejected; policy unchanged. |

## 6. Postconditions
- The tenant's password policy reflects the new values; existing sessions/passwords intact; audited.

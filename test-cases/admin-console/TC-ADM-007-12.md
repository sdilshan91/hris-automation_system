# TC-ADM-007-12: WorkflowEvaluator — BR-5 conditional step skip/include based on request data

## 1. Test Objective
Verify BR-5 via the PURE, unit-tested `WorkflowEvaluator`: conditional steps are evaluated against the request's data; when a condition is NOT met the step is SKIPPED, and when it IS met the step is included in the resolved approval path. Using the AC-2 workflow (Step 1 unconditional; Step 2 `days_requested > 5`; Step 3 `days_requested > 15`), the evaluator yields the correct ordered set of applicable steps for various request sizes. (Per the Test Hint "Conditional step": a 3-day request skips the `> 5` step.) NOTE: this tests the evaluator FUNCTION directly against a request-data object; invoking it LIVE from a submitted leave request (per-request `WorkflowInstance` creation) is DEFERRED engine work (TC-ADM-007-16/-17) — the evaluation logic itself is fully run-green here.

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-2 (conditional steps)
- Functional Requirements: FR-2 (condition JSON expression)
- Business Rules: BR-5 (conditional steps evaluated at runtime; unmet -> skipped)

## 3. Preconditions
- A workflow definition exists with: Step 1 (no condition), Step 2 (`{"field":"days_requested","operator":">","value":5}`), Step 3 (`{"field":"days_requested","operator":">","value":15}`).
- The `WorkflowEvaluator` is invoked directly with a request-data map.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| req-3 | {days_requested: 3} | below both thresholds |
| req-10 | {days_requested: 10} | above Step 2, below Step 3 |
| req-20 | {days_requested: 20} | above both |
| req-5 | {days_requested: 5} | exactly at `>5` boundary -> NOT met |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Evaluate req-3 (3 days) | Applicable steps = [Step 1] only; Step 2 SKIPPED (3 not > 5), Step 3 skipped. |
| 2 | Evaluate req-10 (10 days) | Applicable steps = [Step 1, Step 2]; Step 3 skipped (10 not > 15). |
| 3 | Evaluate req-20 (20 days) | Applicable steps = [Step 1, Step 2, Step 3]; all conditions met. |
| 4 | Evaluate req-5 (exactly 5 days) | Step 2 SKIPPED — `5 > 5` is false (strict boundary). Applicable = [Step 1]. |
| 5 | Confirm ordering preserved | Returned applicable steps retain `step_order` ascending. |

## 6. Postconditions
- Evaluator is a pure function with no side effects; assertions verify the resolved step set per request size.

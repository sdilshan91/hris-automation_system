# TC-ADM-004-04: Login during suspension — Tenant Admin/Owner allowed (read-only notice); all other users blocked

## 1. Test Objective
Verify AC-2: when a suspended tenant's users attempt to authenticate at `{subdomain}.yourhrm.com`, only Tenant Admin/Owner users are permitted to log in (landing on a read-only suspension notice); every other tenant user is blocked at login with the suspension message.

## 2. Related Requirements
- User Story: US-ADM-004
- Acceptance Criteria: AC-2
- Test Hints: Login during suspension

## 3. Preconditions
- Tenant "Acme" is in `Suspended` status (via TC-ADM-004-01).
- Acme has: a Tenant Admin/Owner user, and a regular Employee user — both with valid credentials.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| admin user | acme-admin (Tenant Admin/Owner) | allowed |
| regular user | acme-employee (Employee) | blocked |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As the Tenant Admin, POST valid credentials to the Acme login endpoint | Login succeeds (limited); session lands on the read-only suspension notice (reason text, Contact Support link, data-export request option per AC-2). No general write API access. |
| 2 | As the regular Employee, POST valid credentials to the Acme login endpoint | Login is blocked with the message "Your organization's account has been suspended. Please contact your administrator." (no token issued). |
| 3 | Confirm credential validity is not the cause | Same regular user logs in normally once the tenant is reactivated (cross-check with TC-ADM-004-10) — confirming the block is suspension-driven, not bad credentials. |

## 6. Postconditions
- Suspension allows only Tenant Admin/Owner login (read-only); all other users are blocked at the door.

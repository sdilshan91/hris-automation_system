# TC-ADM-004-10: Reactivate a suspended tenant — status -> active, suspension fields cleared, login normal, lifecycle 'reactivated'

## 1. Test Objective
Verify AC-5 / FR-5: a System Admin reactivates a `Suspended` tenant. Status reverts to `Active` (or `PastDue` if a payment issue persists), `SuspendedAt`/`SuspendedReason` are cleared, tenant background jobs resume, all users (not just Tenant Admin) can log in normally, a reactivation notification is dispatched, and a `tenant_lifecycle_event` with `event_type = 'reactivated'` is written.

## 2. Related Requirements
- User Story: US-ADM-004
- Acceptance Criteria: AC-5
- Functional Requirements: FR-5, FR-7
- Business Rules: BR-1 (suspended -> active | past_due)
- Test Hints: (reactivate)

## 3. Preconditions
- Tenant "Acme" is `Suspended` (TC-ADM-004-01).
- A regular Acme user (previously blocked at login per AC-2) exists with valid credentials.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| tenant_id | acme-tenant-uuid | suspended |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /api/v1/admin/tenants/{id}/reactivate` | 200/204; success. |
| 2 | Re-read the tenant | `status = Active` (or `PastDue` if payment issue persists); `SuspendedAt` and `SuspendedReason` cleared (null). |
| 3 | As the previously-blocked regular user, log in at the Acme subdomain | Login succeeds; full normal access restored (451 gate lifted). |
| 4 | Issue a tenant write API call | 200 — writes allowed again (no longer blocked). |
| 5 | Query `tenant_lifecycle_event` | One row: `event_type = 'reactivated'`, actor + timestamp. |
| 6 | Inspect notification seam | A reactivation notification to Acme Tenant Admin users is dispatched (log-only; delivery deferred TC-ADM-004-18). |

## 6. Postconditions
- Acme is `Active`; suspension fields cleared; all users log in normally; transition audited.

# TC-ADM-003-14: [DEFERRED] Audit immutability via DB-role UPDATE/DELETE revocation

## 1. Test Objective
Verify NFR-1: audit tables (system AuditLog + tenant audit) are append-only because the application DB role has NO UPDATE/DELETE permission on them — a direct `UPDATE`/`DELETE` against an audit row by the app DB role is denied by the database.

## 2. Related Requirements
- User Story: US-ADM-003
- Non-Functional Requirements: NFR-1
- Test Hints: Audit immutability

## 3. Status — DEFERRED / BLOCKED
**Blocked: platform/infra not implemented.** The DB-role-level GRANT/REVOKE that removes UPDATE/DELETE on audit tables is a deferred database-hardening task in the same family as the deferred PostgreSQL RLS (see US-ADM-001 RLS note). Today, audit immutability is **append-only BY CONVENTION** — the application only ever inserts audit rows and exposes no update/delete path for them, but the DB role itself is not yet restricted at the grant level.

**Expected behavior once implemented:** a raw `UPDATE audit_log SET ...` or `DELETE FROM audit_log` executed via the application's DB role is rejected with an insufficient-privilege error.

**Run-green today instead:** assert at the application layer that no command/handler updates or deletes audit rows (insert-only), and that the start/end audit entries created in TC-ADM-003-01 / -06 / -13 are never modified during a session.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| audit tables | system AuditLog, tenant audit | append-only target |
| app DB role | application connection role | should lack UPDATE/DELETE on audit tables |

## 5. Test Steps (to enable once DB-role hardening lands)
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Using the app DB role, attempt `UPDATE` on an audit row | DENIED — insufficient privilege (NFR-1). |
| 2 | Using the app DB role, attempt `DELETE` on an audit row | DENIED — insufficient privilege. |
| 3 | (Interim, run-green) Verify no app code path mutates audit rows | Confirmed insert-only; existing impersonation audit rows are unchanged across a session. |

## 6. Postconditions
- (Deferred) audit rows are immutable at the DB-role level. Interim: audit rows are immutable by application convention.

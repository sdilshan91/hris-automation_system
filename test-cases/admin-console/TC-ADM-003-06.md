# TC-ADM-003-06: End impersonation session — status Ended, "Impersonation.Ended" audit, subsequent requests rejected

## 1. Test Objective
Verify AC-3: clicking "End Session" (or invoking the end-session command) sets the `impersonation_sessions` row to `Ended` with `ended_at` and an actions summary, writes an "Impersonation.Ended" entry to BOTH audit logs, and causes any subsequent request bearing the now-ended session to be rejected by the per-request session middleware. The end-session command is always allowed (even in a read-only session).

## 2. Related Requirements
- User Story: US-ADM-003
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4
- Business Rules: (none specific)
- Test Hints: (derived from AC-3 lifecycle)

## 3. Preconditions
- An Active impersonation session exists (from TC-ADM-003-01) with a known `imp_session_id` and a non-zero `actions_count` after some activity.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| imp_session_id | active session uuid | to be ended |
| actions performed | >= 1 read before ending | drives actions summary |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | With the impersonation token, perform one read action | 200; `actions_count` increments. |
| 2 | Invoke end-session (banner "End Session" / `POST /impersonation/{id}/end`) | 200; the end-session command is allowed regardless of read-only mode. |
| 3 | Query `impersonation_sessions` for the session | `status=Ended`, `ended_at` set, actions summary/`actions_count` recorded. |
| 4 | Query the system AuditLog | An "Impersonation.Ended" entry exists with impersonator attribution and an actions summary. |
| 5 | Query the tenant-scoped audit | A corresponding end row exists with `ImpersonatorUserId` / `ImpersonationSessionId`. |
| 6 | Replay any tenant request using the same (ended) session token | Rejected (401/403) by the per-request session middleware — the ended session is no longer usable. |

## 6. Postconditions
- Session is terminated; both audit logs record the end; the token can no longer drive tenant requests.

# TC-ADM-010-06: CSV format — UTF-8 BOM, comma delimiter, header row

## 1. Test Objective
Verify FR-3: every CSV in the bundle uses UTF-8 encoding WITH a byte-order mark (BOM), a comma delimiter, and a header row whose columns match the entity field names. (Generation uses AsNoTracking; format correctness is what is asserted here.)

## 2. Related Requirements
- User Story: US-ADM-010
- Functional Requirements: FR-3 (UTF-8 BOM, comma delimiter, headers)

## 3. Preconditions
- A Completed export bundle for Acme (full or partial) is available.
- At least one entity contains a non-ASCII value (e.g. an employee name "José Müller") to validate UTF-8 round-trips.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| non_ascii_name | José Müller | seeded to confirm UTF-8 fidelity |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Read the first 3 bytes of `employees.csv` | They are the UTF-8 BOM `EF BB BF`. |
| 2 | Inspect the first line | A header row of column names matching the entity field names. |
| 3 | Inspect a data row with multiple fields | Fields are comma-separated. |
| 4 | Decode the file as UTF-8 and find the non-ASCII row | "José Müller" round-trips exactly (no mojibake). |
| 5 | Repeat the BOM + header + comma checks on a second CSV (e.g. leave_requests.csv) | Same format holds across all CSVs. |

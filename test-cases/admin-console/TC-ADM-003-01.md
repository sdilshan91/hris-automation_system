# TC-ADM-003-01: Start impersonation session — token claims, Active session row, dual audit logs, notification dispatched (happy path)

## 1. Test Objective
Verify the primary success flow of AC-1: an authenticated System Admin starts an impersonation session against a target tenant user with a valid reason. The system mints a SEPARATE, time-limited impersonation JWT for the target user carrying the impersonation claims, creates an Active `impersonation_sessions` row, writes BOTH a system AuditLog ("Impersonation.Started") and a tenant-scoped audit row with impersonator attribution, and dispatches the tenant-admin notification (log-only seam today — delivery is TC-ADM-003-15).

## 2. Related Requirements
- User Story: US-ADM-003
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-2, FR-4, FR-5
- Business Rules: BR-4
- Test Hints: Happy path

## 3. Preconditions
- System Admin "Olivia Park" is authenticated at `admin.yourhrm.com` with a system-tenant JWT carrying the `SystemAdmin` role.
- Target tenant "Acme" (`status = active`, not system) exists; target user "Bob Lee" has an active `user_tenant` membership in Acme.
- Olivia has NO active impersonation session (BR-3 precondition clear).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| target_tenant_id | acme-tenant-uuid | active, non-system |
| target_user_id | bob-user-uuid | active membership in Acme |
| reason | "Investigating leave-balance bug ticket SUP-4821" | >= 10 chars |
| Initiator role | SystemAdmin | full (not read-only) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Olivia, `POST /api/v1/admin/impersonation/start` with `{ target_user_id, target_tenant_id, reason }` | 200; response carries an impersonation JWT, a redirect URL to the Acme subdomain, and `imp_session_id`. |
| 2 | Decode the returned impersonation JWT | It is a SEPARATE token (not Olivia's admin token); `sub` = Bob's user_id; `tenant_id` = Acme; roles = Bob's roles; and claims `is_impersonation=true`, `imp_session_id`, `imp_actor_id`=Olivia's user_id, `imp_reason`, `imp_readonly=false`, `imp_expires_at` are present. |
| 3 | Assert `imp_expires_at` is <= 60 minutes from now | TTL hard-capped at 60 min (NFR-2). |
| 4 | Query `impersonation_sessions` for `imp_session_id` | One row: impersonator=Olivia, target user=Bob, target tenant=Acme, reason stored verbatim, started_at set, ended_at null, actions_count=0, status=`Active`. |
| 5 | Query the system AuditLog | An "Impersonation.Started" entry exists with impersonator=Olivia, target user/tenant, and session id. |
| 6 | Query the Acme tenant-scoped audit rows | A start row exists carrying `ImpersonatorUserId`=Olivia, `ImpersonationSessionId`=session id, `IsImpersonationAction=true`. |
| 7 | Inspect the notification seam (log/outbox) | A tenant-admin notification for Acme is dispatched containing impersonator name, target user, timestamp, reason (verbatim), and session id reference (AC-4/FR-5 — log-only seam today). |

## 6. Postconditions
- An Active impersonation session exists; the impersonation token is usable against the Acme subdomain; both audit trails record the start with impersonator attribution.

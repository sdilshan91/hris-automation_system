# TC-ADM-008-15: Retention period is VIEW-ONLY for the Tenant Admin (plan-governed)

## 1. Test Objective
Verify BR-5: the Tenant Admin can VIEW the tenant's audit-log retention period (`AuditLogRetentionDays`, surfaced as the "Records retained for {X} days per your plan" indicator) but CANNOT change it — it is plan-governed. Any attempt to set it via the tenant admin surface is rejected (no write path exposed / 403 / 400).

## 2. Related Requirements
- User Story: US-ADM-008
- Business Rules: BR-5 (retention plan-dependent; Tenant Admin views but cannot change)
- Acceptance Criteria: AC-1 (retention indicator on the audit page)

## 3. Preconditions
- Dana (`TenantAdmin`, Acme) authenticated.
- Acme is on a plan with `AuditLogRetentionDays = 365`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| AuditLogRetentionDays | 365 | plan-governed |
| attempted new value | 30 | should be rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, view the audit-log page / retention indicator | Displays "Records retained for 365 days per your plan" (read-only). |
| 2 | Attempt to PUT/PATCH AuditLogRetentionDays = 30 via the tenant admin API | Rejected — no exposed write path for the Tenant Admin (403/400/not-found); value unchanged. |
| 3 | Re-read retention | Still 365 (plan-governed value unchanged). |

## 6. Postconditions
- `AuditLogRetentionDays` unchanged; no state mutation by the Tenant Admin.

# TC-ADM-008-10: Sensitive-field masking — bank account / password hash / MFA secret / national ID redacted recursively

## 1. Test Objective
Verify AC-3 / FR-4: the `SensitiveFieldMasker` redacts the VALUES of sensitive fields to the literal `***REDACTED***` in the audit detail display (and in export — see TC-ADM-008-11). The masked field set is `password_hash`, `mfa_secret`, `bank_account_number`, `national_id`, including their camelCase variants (`passwordHash`, `mfaSecret`, `bankAccountNumber`, `nationalId`). Masking is RECURSIVE — it applies to those keys at any nesting depth in the before/after JSON. (Test Hints — Sensitive field masking: bank account number displayed as `***REDACTED***`.)

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-3 (sensitive values masked)
- Functional Requirements: FR-4 (configurable sensitive-fields list, `***REDACTED***`)

## 3. Preconditions
- Dana (`TenantAdmin`, Acme) authenticated.
- Acme has an audit row whose `after` JSON contains, at the top level AND nested under an object, the sensitive keys with real values:
  - `bank_account_number`: "1234567890", nested `employee.bankAccountNumber`: "9999"
  - `password_hash`: "$2a$...", `mfa_secret`: "JBSWY3DP...", `national_id`: "990101-1234"

## 4. Test Data
| Field | Value (input) | Expected display |
|-------|---------------|------------------|
| bank_account_number | 1234567890 | ***REDACTED*** |
| employee.bankAccountNumber (nested camelCase) | 9999 | ***REDACTED*** |
| password_hash | $2a$10$... | ***REDACTED*** |
| mfa_secret | JBSWY3DP... | ***REDACTED*** |
| national_id | 990101-1234 | ***REDACTED*** |
| first_name (non-sensitive) | Jane | Jane (unmasked) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | GET audit detail for the row | 200; sensitive values returned as `***REDACTED***`. |
| 2 | Inspect top-level bank_account_number | Value is `***REDACTED***`, never "1234567890". |
| 3 | Inspect nested employee.bankAccountNumber | Value is `***REDACTED***` (recursive + camelCase variant). |
| 4 | Inspect password_hash, mfa_secret, national_id | All `***REDACTED***`. |
| 5 | Inspect first_name | Unmasked ("Jane") — only the configured sensitive keys are masked. |
| 6 | Confirm pure masker | Masking is applied at the display/serialization boundary; the raw stored value is never emitted to the client. |

## 6. Postconditions
- No state change; stored audit row is unchanged (masking is presentation-only).

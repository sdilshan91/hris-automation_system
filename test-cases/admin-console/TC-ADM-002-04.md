# TC-ADM-002-04: Quota-breach queue lists tenants by severity on the employee limit (80/95/100%)

## 1. Test Objective
Verify the quota-breach queue (FR-3 / AC-2), built FOR REAL on the employee usage dimension: tenants that have exceeded 80%, 95%, or 100% of their `max_employees` limit are listed and sorted by severity (100% first, then 95%, then 80%). Tenants below 80% are excluded.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-2
- Functional Requirements: FR-3
- Business Rules: BR-4 (95% triggers alert)

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- Multiple tenants seeded at distinct employee-usage ratios against their own `max_employees` limits.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Tenant "full" | 10/10 employees | 100% breach |
| Tenant "near" | 19/20 employees | 95% |
| Tenant "warn" | 8/10 employees | 80% |
| Tenant "ok" | 5/10 employees | 50% — excluded |
| Tenant "unlimited" | 30 employees, MaxEmployees null | unlimited — excluded |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the quota-breach queue (panel/tab) on the Monitoring dashboard | Queue renders with a badge count of 3. |
| 2 | Read the queue ordering | Order is: full (100%), near (95%), warn (80%) — sorted by severity descending (FR-3). |
| 3 | Verify exclusions | "ok" (50%) is absent; "unlimited" (MaxEmployees null = unlimited) is absent — null limit is never a breach. |
| 4 | Verify each entry's content | Each entry shows the tenant, the breached dimension (employees), and the current ratio/percentage. |
| 5 | Confirm only the employee dimension drives the queue today | Storage/API/email dimensions do not contribute (Deferred — TC-ADM-002-18); the queue is computed solely from the employee gauge. |

## 6. Postconditions
- Breach queue accurately reflects the three at-or-over-80% tenants in severity order. No data mutated.

# TC-ADM-007-02: Create 3-step Leave workflow with conditions, SLAs, escalation — v1, audited

## 1. Test Objective
Verify AC-2 / FR-1 / FR-2: a Tenant Admin creates a new Leave approval workflow with three sequential steps — Step 1 Direct Manager (SLA 24h), Step 2 Department Head (conditional: `days_requested > 5`, SLA 48h), Step 3 HR (conditional: `days_requested > 15`, SLA 24h) — with auto-escalation to the next level on SLA breach. A `WorkflowDefinition` record (+ ordered `WorkflowStep` rows) is persisted with all steps, conditions, SLAs, and escalation targets, `version = 1`, and the action is recorded in the tenant `audit_log`. (Per the Test Hint "Create workflow": verify the definition is stored correctly with all steps, conditions, and SLAs.)

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-2
- Functional Requirements: FR-1 (definition fields incl. version=1), FR-2 (step fields: order, approver_type/identifier, sla_hours, escalation_target, condition JSON)
- Business Rules: BR-2 (one active per entity type — see TC-ADM-007-03), BR-1 (authorized role)
- Non-Functional: NFR-4 (audited)

## 3. Preconditions
- Dana (`TenantAdmin`) authenticated at `acme.yourhrm.com`; Acme `active`.
- Approver-eligible users/roles exist: a Manager role, a Department Head, and an HR Officer (US-ADM-005).
- Plan limit `MaxWorkflows` not yet reached.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| name | "Leave Approval" | |
| entity_type | Leave | |
| step1 | order=1, approver_type=LineManager, sla_hours=24, escalation_target=DepartmentHead, condition=null | unconditional |
| step2 | order=2, approver_type=DepartmentHead, sla_hours=48, condition={"field":"days_requested","operator":">","value":5} | conditional |
| step3 | order=3, approver_type=Role(HR), sla_hours=24, condition={"field":"days_requested","operator":">","value":15} | conditional |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, POST create workflow with the Test Data | 201; a `WorkflowDefinition` is created for entity_type=Leave with `version = 1`, `is_active = true`, `created_by = Dana`, `tenant_id` stamped to Acme. |
| 2 | GET the new workflow | Returns 3 ordered steps; each step has the configured `approver_type`/`identifier`, `sla_hours`, `escalation_target`, and `condition` JSON exactly as submitted (step1 condition null; step2 `>5`; step3 `>15`). |
| 3 | Verify SLA values | step1=24, step2=48, step3=24 (all positive integers). |
| 4 | Verify escalation | step1 escalation_target = DepartmentHead persisted. |
| 5 | Inspect tenant `audit_log` | One entry: action = workflow created, actor = Dana, AFTER = workflow definition snapshot, timestamp present. |
| 6 | Confirm tenant scope | Definition is tenant-stamped to Acme; not visible to other tenants (BR-7). |

## 6. Postconditions
- One active v1 Leave workflow exists for Acme with 3 configured steps; one audit row written.

# TC-ADM-005-13: BR-3 — Tenant Admin cannot self-deactivate

## 1. Test Objective
Verify BR-3 / Test-Hint "Self-deactivation prevention": the currently authenticated Tenant Admin cannot deactivate their own membership. The request is rejected, the admin's membership stays `active`, their sessions are untouched, and the attempt is audited.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-4
- Business Rules: BR-3
- Test Hints: Self-deactivation prevention

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme, with an active membership and live session.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user_tenant_id | dana-acme-membership | == the caller's own membership |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, `POST /api/v1/admin/users/{dana}/deactivate` (her own membership) | Rejected (403/409/422) with a self-deactivation-prevented message. |
| 2 | Query Dana's `user_tenant` | Still `active` — unchanged. |
| 3 | Query Dana's refresh tokens | Still valid — not revoked. |
| 4 | Confirm Dana can still operate the console | Session intact; no lockout. |
| 5 | Query `audit_log` | The denied self-deactivation attempt is recorded (actor=Dana, denied, reason BR-3). |

## 6. Postconditions
- Dana remains an active admin; no self-lockout possible.

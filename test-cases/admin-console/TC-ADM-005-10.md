# TC-ADM-005-10: BR-4 — built-in roles are assignable/unassignable but not editable or deletable

## 1. Test Objective
Verify BR-4: built-in roles (`TenantAdmin`, `TenantOwner`, `Employee`, `Manager`, `HR Officer`, `Auditor`) can be assigned and unassigned via the role editor, but the role definitions themselves cannot be edited or deleted by a Tenant Admin. (Custom role creation is out of scope — Phase 2, §10.)

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-3
- Business Rules: BR-4
- Constraints: §10 (custom roles deferred to Phase 2)

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Built-in roles seeded.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| built-in role | Manager | assign/unassign allowed |
| edit attempt | rename "Manager" / change permissions | must be blocked |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Assign Manager to a member, then unassign it | Both operations succeed (assignment is permitted, BR-4). |
| 2 | Attempt to rename or change the permission set of the `Manager` role definition (if any such endpoint is reachable) | Rejected (403/404/405) — built-in role definitions are immutable to a Tenant Admin. |
| 3 | Attempt to delete a built-in role definition | Rejected — built-in roles cannot be deleted. |
| 4 | Attempt to create a custom role | Not available in Phase 1 (out of scope §10) — endpoint absent or returns not-implemented; documented as deferred (see TC-ADM-005-21 note / module deferrals). |

## 6. Postconditions
- Built-in role definitions are intact; only assignment/unassignment was exercised.

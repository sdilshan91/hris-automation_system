# TC-ADM-005-08: Edit roles — assign Manager + HR Officer (replace set), assigned_at/by, before/after audit

## 1. Test Objective
Verify AC-3 / FR-4 / BR-7 / Test-Hint "Role assignment": editing a user's roles replaces the role set with the submitted complete set, persisting `user_tenant_role` rows with `assigned_at` and `assigned_by`. A user may hold multiple roles (Manager + HR Officer, BR-7). The change is recorded in the tenant `audit_log` with before/after state (AC-3, NFR-2). The user's current JWT stays valid until expiry; the next refresh reflects the new roles (verified in TC-ADM-005-18).

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4
- Business Rules: BR-7
- Test Hints: Role assignment

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Target member "Maria" currently holds only the `Employee` role in Acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user_tenant_id | maria-acme-membership | target membership |
| role_ids (new complete set) | [Manager, HR Officer] | replaces Employee |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `PUT /api/v1/admin/users/{user_tenant_id}/roles` with `{ role_ids:[Manager, HR Officer] }` | 200; success. |
| 2 | Query `user_tenant_role` for Maria's membership | Exactly two rows: Manager and HR Officer; the prior `Employee` row removed (set replaced, not merged). |
| 3 | Inspect each role row | `assigned_at` ~now, `assigned_by = Dana`. |
| 4 | Query `audit_log` | One entry for the role change: before = {Employee}, after = {Manager, HR Officer}, actor=Dana, IP, timestamp (NFR-2). |
| 5 | Submit the same set again (idempotency) | 200; no duplicate role rows; no spurious before/after diff if nothing changed. |

## 6. Postconditions
- Maria holds Manager + HR Officer in Acme; the before/after delta is auditable.

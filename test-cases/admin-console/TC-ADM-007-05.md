# TC-ADM-007-05: Plan limit (MaxWorkflows) blocks create with the exact upgrade message

## 1. Test Objective
Verify AC-4 / FR-4: the plan limit `Tenant.MaxWorkflows` is checked before creating a new workflow definition. When the tenant has already reached its `MaxWorkflows` count of ACTIVE/non-archived workflows, the create action is blocked and the system returns the EXACT message: "You have reached the maximum number of workflows ({limit}) for your plan. Please upgrade or archive an existing workflow." (Per the Test Hint: set `max_workflows = 2`, create 2, attempt a 3rd, verify rejection.)

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-4
- Functional Requirements: FR-4 (MaxWorkflows checked before create)
- Business Rules: BR-2
- Related: FR-6 (archived do not count — verified in TC-ADM-007-09)

## 3. Preconditions
- Dana (`TenantAdmin`) authenticated; Acme `active`.
- Acme `MaxWorkflows = 2`.
- Acme currently has 0 workflows.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| MaxWorkflows | 2 | plan limit |
| WF-1 | entity=Leave, 1 valid step | within limit |
| WF-2 | entity=Expense, 1 valid step | within limit |
| WF-3 | entity=Offer, 1 valid step | exceeds limit |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create WF-1 | 201; count = 1 (<= 2). |
| 2 | Create WF-2 | 201; count = 2 (= limit). |
| 3 | Attempt to create WF-3 | Rejected (HTTP 400/422); create action blocked, no WF-3 persisted. |
| 4 | Inspect the error message | Exactly: "You have reached the maximum number of workflows (2) for your plan. Please upgrade or archive an existing workflow." — `{limit}` rendered as the tenant's MaxWorkflows (2). |
| 5 | Confirm count unchanged | Acme still has exactly 2 workflows. |

## 6. Postconditions
- No third workflow created; tenant workflow count remains at the plan limit.

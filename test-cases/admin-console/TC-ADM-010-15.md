# TC-ADM-010-15: Tenant Admin export scoped to own tenant — foreign tenant_id in request IGNORED

## 1. Test Objective
Verify AC-5 / FR-1: for a Tenant Admin, the export is scoped by `ITenantContext` to the authenticated user's tenant. A client-supplied `tenant_id` targeting another tenant is IGNORED (not honored) — the export still produces only the caller's own tenant's data. (Zero-foreign-rows content proof is in TC-ADM-ISO-028; this case asserts the request-parameter contract.)

## 2. Related Requirements
- User Story: US-ADM-010
- Acceptance Criteria: AC-5 (ITenantContext scoping; client tenant_id ignored)
- Functional Requirements: FR-1 (tenant_id implicit from context for Tenant Admin)
- Business Rules: BR-1 (Tenant Admins export only their own tenant)

## 3. Preconditions
- Tenant Admin "Tara" authenticated at `acme.yourhrm.com` (Acme).
- A second tenant "Beta" exists with its own data and tenant_id.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| caller | Tara (Acme TenantAdmin) | |
| injected tenant_id | Beta's tenant_id | should be ignored |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Tara, POST an export with a body/param `tenant_id` = Beta's id | Request is accepted but the injected tenant_id is IGNORED; the ExportRequest is created under Acme (the resolved context), NOT Beta. |
| 2 | Let the job complete and open the bundle manifest | `manifest.json` `tenant_id` = Acme (never Beta). |
| 3 | Spot-check the CSVs | All rows belong to Acme; no Beta data (full content proof in TC-ADM-ISO-028). |
| 4 | Inspect the ExportRequest record | `TenantId` = Acme; storage path = `{acmeTenantId}/exports/...`. |

## 6. Postconditions
- Export produced for Acme only; the cross-tenant parameter had no effect.

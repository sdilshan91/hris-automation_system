# TC-ADM-006-03: Branding — valid PNG logo accepted, stored at tenant-scoped path, URL persisted

## 1. Test Objective
Verify the happy path of branding upload (AC-2/FR-2/NFR-2/BR-6): a Tenant Admin uploads a valid PNG logo; the server validates type via MAGIC BYTES (not extension alone) and size (≤2MB), stores it under the tenant-scoped path `{tenantId}/branding/`, persists the resulting URL to the tenant's `branding.logo_url`, and the UI reflects the new logo on next read. The change is audited.

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2
- Business Rules: BR-6 (tenant-scoped storage)
- Non-Functional: NFR-2 (server-side magic-byte + size validation), NFR-4 (audit)

## 3. Preconditions
- Tenant Admin "Dana" authenticated at `acme.yourhrm.com`; Acme tenant id known.
- Storage is local/stub (real S3/Azure blob NOT wired — see TC-ADM-006-18); the tenant-scoped PATH PREFIX and validation are real.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| logo file | valid PNG, ~300KB | correct magic bytes `89 50 4E 47` |
| accepted types | PNG, SVG | FR-2 logo |
| size limit | ≤ 2MB | FR-2 logo |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, upload the valid PNG as the main logo | 200; server validates magic bytes + size, accepts. |
| 2 | Inspect the storage path | Stored under `{Acme-tenantId}/branding/` (tenant-scoped prefix, BR-6). |
| 3 | `GET` branding settings | `branding.logo_url` points to the stored file. |
| 4 | Reload a tenant page rendering the logo | UI shows the new logo on next read. |
| 5 | Upload a valid SVG as the email logo | 200; accepted (SVG is an allowed logo type). |
| 6 | Inspect the tenant `audit_log` | Before/after entry for the branding change, actor = Dana. |

## 6. Postconditions
- Logo + email logo stored under the Acme branding prefix; `branding.logo_url`/`branding.email_logo_url` persisted; audited.

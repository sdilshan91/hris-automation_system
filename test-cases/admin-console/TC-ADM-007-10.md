# TC-ADM-007-10: BR-6 delete guard — delete allowed only when no in-flight instances

## 1. Test Objective
Verify BR-6: deletion of a workflow definition is allowed ONLY when there are no in-flight workflow instances; otherwise the workflow can only be archived. In the current build the runtime engine that creates per-request `WorkflowInstance` rows is DEFERRED, so NO in-flight instances exist yet — therefore delete of a definition with zero instances succeeds and is hard-removed. The "blocked when in-flight instances exist" branch is asserted at the GUARD level (the delete path checks instance count and falls back to archive) but its positive trigger is documented as runtime-dependent.

## 2. Related Requirements
- User Story: US-ADM-007
- Functional Requirements: FR-6 (archive vs delete)
- Business Rules: BR-6 (delete only with no in-flight instances)
- Non-Functional: NFR-4 (audited)

## 3. Preconditions
- Dana (`TenantAdmin`) at Acme `active`.
- A workflow "WF-Del" exists with zero workflow instances (no request has been routed through it — runtime deferred).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| WF-Del | entity=Expense, in-flight instances = 0 | deletable |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, DELETE "WF-Del" (0 in-flight instances) | 200/204; the definition is removed (hard delete). Audit row written. |
| 2 | GET "WF-Del" | 404 — no longer exists. |
| 3 | (GUARD branch) Confirm the delete path consults in-flight instance count | The delete handler checks the workflow-instance count and only permits hard delete when it is 0; otherwise it returns a "can only archive" rejection. |
| 4 | (DEFERRED — runtime trigger) Delete a workflow WITH in-flight instances -> blocked, archive-only | NOT executable today: per-request `WorkflowInstance` creation is deferred engine work (see TC-ADM-007-16/-17). The guard exists; its positive trigger arrives when the runtime engine lands. |

## 6. Postconditions
- A no-instance workflow is hard-deletable; the in-flight-blocked branch is guard-verified, runtime-trigger deferred.

# TC-ADM-004-13: BR-3 — a terminated tenant cannot be restored

## 1. Test Objective
Verify BR-3 explicitly: once data deletion has completed and the tenant is `Terminated`, the restore endpoint refuses the operation (recovery requires a manual operator/backup process, not the UI/API). This guards against accidental "un-delete" after the irreversible hard-delete.

## 2. Related Requirements
- User Story: US-ADM-004
- Business Rules: BR-3
- Test Hints: Invalid transitions (terminate a terminated tenant)

## 3. Preconditions
- Tenant "Acme" is in `Terminated` status (data already deleted; tenant row retained with PII redacted — TC-ADM-004-09).
- System Admin authenticated.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| tenant_id | acme-tenant-uuid | Terminated |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /api/v1/admin/tenants/{id}/restore` against the Terminated tenant | Rejected (409/400/422) — BR-3 forbids restoring a terminated tenant. |
| 2 | Re-read the tenant | `status` remains `Terminated`; no lifecycle event; no audit row for a successful restore. |
| 3 | Attempt reactivate/suspend/terminate on the Terminated tenant | All rejected (terminated is a terminal state per BR-1). |

## 6. Postconditions
- `Terminated` is terminal; no API transition can revive it; only an out-of-band operator process could.

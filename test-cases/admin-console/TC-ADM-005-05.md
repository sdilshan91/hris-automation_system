# TC-ADM-005-05: Invite an EXISTING global user — no duplicate user, new membership only

## 1. Test Objective
Verify AC-2 / FR-2 / Test-Hint "Invite existing global user": inviting an email that already exists as a global user (e.g., a member of another tenant) does NOT create a duplicate `users` row — it creates only a new `user_tenant` membership (and invitation) in the current tenant. The user's membership/roles in their other tenant are untouched (BR-1).

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2
- Business Rules: BR-1
- Test Hints: Invite existing global user

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- User "sam@globex.com" already exists globally with an active membership in tenant Globex.
- sam@globex.com has NO membership in Acme yet.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| email | sam@globex.com | existing global user (Globex member) |
| role_ids | [Employee] | for Acme |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Snapshot `users` count for sam@globex.com (= 1) and Globex membership state | Baseline recorded. |
| 2 | As Dana, `POST /api/v1/admin/users/invitations` with `{ email: sam@globex.com, role_ids:[Employee] }` | 201/200 success. |
| 3 | Re-query `users` for sam@globex.com | Still exactly ONE global user row — no duplicate created. |
| 4 | Query `user_tenant` | A NEW membership exists for Acme with `status = 'invited'`; the existing Globex membership is unchanged. |
| 5 | Query Globex's `user_tenant_role` for sam | Unchanged — Acme invite did not touch Globex roles (BR-1). |
| 6 | Query `user_invitation` | A new Acme invitation row with hashed token + 72h expiry. |

## 6. Postconditions
- One global user, now with memberships in both Globex (unchanged) and Acme (invited). No cross-tenant side effects.

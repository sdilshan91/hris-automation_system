# TC-ADM-010-12: Download served while Completed & within 72h; expiry/cleanup marks Expired + deletes file

## 1. Test Objective
Verify AC-3 / FR-7 Test Hint ("Download link expiry"): a Completed export is downloadable while now < `ExpiresAt` (72h); after 72h the cleanup job marks the ExportRequest `Expired` and deletes the bundle file, and a subsequent download attempt fails (no longer served). Download events are audited (NFR-4, also TC-ADM-010-14).

## 2. Related Requirements
- User Story: US-ADM-010
- Acceptance Criteria: AC-3
- Functional Requirements: FR-7 (72h expiry + cleanup deletes files)
- Test Hints: "Download link expiry: generate an export, advance time past 72 hours; attempt download; verify the link is expired and the file is deleted."

## 3. Preconditions
- A Completed ExportRequest for Acme with `ExpiresAt = CompletedAt + 72h` and the bundle file present.
- A controllable clock / ability to set `ExpiresAt` in the past for the expiry leg.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| expiry_window | 72h | from completion |
| states | Completed -> Expired | cleanup transition |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | While Completed and now < ExpiresAt, request the download | The bundle ZIP is served (Completed + not expired). |
| 2 | Confirm the download was audited | A download audit row is recorded (see TC-ADM-010-14). |
| 3 | Advance the clock / set ExpiresAt to the past; run the cleanup Hangfire job | ExportRequest status becomes `Expired`; the bundle file is deleted from `{tenantId}/exports/{id}/`. |
| 4 | Attempt the download again after expiry | Not served — fails (e.g. 404/410 "expired"); no file to stream. |
| 5 | Attempt download of a `Failed` or still-`Processing` export | Not served — only Completed-and-unexpired is downloadable. |

## 6. Postconditions
- Expired export's file is gone; status `Expired`; download path closed.

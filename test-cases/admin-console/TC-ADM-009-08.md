# TC-ADM-009-08: Archive plan — is_active=false, excluded from provisioning, existing tenants unaffected, audited

## 1. Test Objective
Verify AC-4 + the "Archive plan" Test Hint: archiving a plan sets `is_active=false`. The archived plan no longer appears as a provisioning option for new tenants, but existing tenants on that plan are unaffected and continue operating with their current limits/modules. The action is logged.

## 2. Related Requirements
- User Story: US-ADM-009
- Acceptance Criteria: AC-4
- Functional Requirements: FR-1 (archive), FR-7 (archiving permitted vs delete blocked)
- Non-Functional Requirements: NFR-3 (audit)
- Test Hints (Archive plan)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.
- Plan `growth` is active with at least one tenant "Acme" assigned.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| plan | growth | active, has tenant Acme |
| is_active before/after | true -> false | archive |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Pat, POST archive `growth` | 200; plan `is_active=false`. |
| 2 | GET the provisioning plan options (assignable plans for a new tenant) | `growth` is NOT listed; only active plans are selectable. |
| 3 | GET the full plans list | `growth` still appears (with archived status) for reference; not assignable. |
| 4 | As Acme tenant admin, operate normally (e.g. create an employee within Acme's limit) | Succeeds — Acme is unaffected by the archive; its derived limits/modules persist. |
| 5 | Inspect system audit log | "SubscriptionPlan.Archive" entry: actor=Pat, before {is_active:true}, after {is_active:false}, timestamp. |

## 6. Postconditions
- `growth` archived, hidden from provisioning, existing tenants intact.

# TC-ADM-005-18: Role change — current JWT stays valid until expiry; next refresh reflects new roles; user-detail view (FR-6)

## 1. Test Objective
Verify the AC-3 token-lifecycle clause and FR-6: after a role edit, the target user's CURRENT access token remains valid until it expires (roles are not force-invalidated mid-token), but the NEXT token refresh issues claims reflecting the updated role set. Also verifies the user-detail view (FR-6) aggregates profile, assigned roles, linked employee, audit trail, active sessions, and invitation history.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4, FR-6

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Member "Maria" is `active` on Acme with a current valid access token and refresh token; currently holds `Employee`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user_tenant_id | maria-acme-membership | target |
| new roles | [Manager] | added via edit |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, edit Maria's roles to add Manager | 200; `user_tenant_role` updated. |
| 2 | Using Maria's EXISTING (pre-change) access token, call an endpoint | Token still accepted until its natural expiry — roles in the live token are unchanged (AC-3: "current JWT remains valid until expiry"). |
| 3 | Trigger Maria's token refresh | New access token issued; its role claims now include Manager (AC-3: "next token refresh reflects the updated roles"). |
| 4 | `GET /api/v1/admin/users/{maria}` (detail view) | Returns profile info, assigned roles (incl. Manager), linked employee record (if any), recent audit trail, active sessions, and invitation history (FR-6). |
| 5 | Confirm detail view is tenant-scoped | Only Acme-context data shown; no other-tenant memberships of Maria leaked. |

## 6. Postconditions
- No data mutated beyond the role edit; the token lifecycle behaves per AC-3.

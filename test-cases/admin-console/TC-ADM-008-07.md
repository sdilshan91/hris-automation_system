# TC-ADM-008-07: Keyword search over before/after JSON change summary

## 1. Test Objective
Verify AC-2 / FR-1 (keyword search): the `search_query` parameter performs a full-text/contains match against the `before`/`after` JSON (the change summary), returning only rows whose change payload contains the keyword, scoped to the current tenant.

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-2
- Functional Requirements: FR-1 (full-text search on before/after JSON)

## 3. Preconditions
- Dana (`TenantAdmin`, Acme) authenticated.
- Acme `audit_log` has a row whose `after` JSON contains `{"first_name":"Jane"}` and other rows that do not mention "Jane".

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| search_query | Jane | matches the after-JSON value |
| search_query (no match) | Zzzzz | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | GET list with search_query = "Jane" | Returns only rows whose before/after JSON contains "Jane". |
| 2 | Confirm exclusion | Rows without "Jane" in the change payload are absent. |
| 3 | GET with search_query = "Zzzzz" | Empty result, no error. |
| 4 | Confirm masking interplay | The keyword search does NOT match against the literal "***REDACTED***" mask such that sensitive values remain non-searchable by raw value (see TC-ADM-008-10). |

## 6. Postconditions
- No state change.

# TC-ADM-001-05: Invalid subdomain formats are rejected (uppercase, special chars, too long, too short)

## 1. Test Objective
Verify AC-5 / FR-1: subdomains that violate the format rules (lowercase alphanumeric + hyphens, 3-50 chars) are rejected by BOTH client-side and server-side validation with a descriptive error, and never create a tenant.

## 2. Related Requirements
- User Story: US-ADM-001
- Acceptance Criteria: AC-5
- Functional Requirements: FR-1

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com` with the `SystemAdmin` role.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Uppercase | `Acme` / `ACME` | uppercase not allowed |
| Special chars | `acme_corp`, `acme.corp`, `acme corp`, `acme!`, `-acme`, `acme-` | only [a-z0-9] + internal hyphens allowed |
| Too long | 51-char string `aaaaaaaaaa...` (> 50) | exceeds max 50 |
| Too short | `ab` (2 chars), `a` (1 char) | below min 3 |
| Empty | `` | required field |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter `Acme` (uppercase) | Client validation flags an error such as "Subdomain must be lowercase alphanumeric with hyphens"; Submit is blocked. |
| 2 | Enter each special-character value in turn | Each is flagged invalid; values with leading/trailing hyphens or non-`[a-z0-9-]` characters are rejected. |
| 3 | Enter the 51-character value | Flagged "Subdomain must be 3-50 characters"; blocked. |
| 4 | Enter `ab` then `a` | Flagged "Subdomain must be at least 3 characters"; blocked. |
| 5 | Leave the subdomain empty and attempt submit | Flagged required; Submit blocked. |
| 6 | For a sample of each class (uppercase, special, >50, <3), bypass the client check and submit; observe `POST /api/v1/admin/tenants` | Server-side validation returns 400 with a descriptive message for every class; NO tenant is created. Client validation alone is not relied upon. |

## 6. Postconditions
- No tenant created for any invalid-format subdomain.

# TC-ADM-001-10: Provisioning completes within the time budget (< 60s target, < 5min SLA)

## 1. Test Objective
Verify NFR-1: end-to-end provisioning — from form submit to welcome-email dispatch — completes within the 60-second target and never exceeds the 5-minute SLA, including under modest concurrent load.

## 2. Related Requirements
- User Story: US-ADM-001
- Non-Functional: NFR-1
- Functional Requirements: FR-3 (atomic transaction), FR-7 (cache populate)

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com` with the `SystemAdmin` role.
- The email service / test SMTP sink is reachable.
- A performance-representative environment (DB + email + cache) is available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Single provision | one valid tenant payload | measure submit -> email dispatch |
| Concurrent batch | 5 distinct valid tenant payloads submitted near-simultaneously | distinct subdomains |
| Measurement | wall-clock from POST to welcome-email enqueue + 201 | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit one valid provisioning request and time it | The 201 response returns and the welcome email is dispatched in under 60s (target). |
| 2 | Repeat for 20 runs; record the distribution | All runs complete < 60s target; the slowest run is well under the 5-minute SLA. |
| 3 | Submit 5 distinct provisions near-simultaneously (concurrent) | Each completes within the SLA with no failures; the atomic transaction (FR-3) and Redis config cache write (FR-7) complete per tenant. |
| 4 | Verify post-provision artifacts for the timed runs | Each created tenant has the full record set (tenant, user, user_tenant, lifecycle event, audit log, dispatched email), confirming the time budget covers a complete provision, not a partial one. |

## 6. Postconditions
- All measured provisions completed within the target/SLA and produced complete tenants.

# TC-ADM-010-05: PII fields INCLUDED in export (national ID, bank account)

## 1. Test Objective
Verify FR-8: while sensitive AUTH fields are excluded (TC-ADM-010-04), PII business fields — national ID and bank account — ARE included in the export. The export is a data-portability artifact (GDPR Art. 20), so the tenant's own PII must be present; the distinction is auth-secrets-out / PII-in.

## 2. Related Requirements
- User Story: US-ADM-010
- Functional Requirements: FR-8 (PII fields included)
- (Schema-doc "clearly marked" portion is DEFERRED — see TC-ADM-010-17)

## 3. Preconditions
- Acme has employees with a known national ID and a known bank account number stored.
- A FULL export of Acme has Completed.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| national_id | known value e.g. `199012345678` | seeded on an employee |
| bank_account | known value e.g. `GB29NWBK...` | seeded on an employee |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open `employees.csv` (or the entity holding bank/national-id) | The national ID and bank account columns are present. |
| 2 | Find the seeded employee's row | The known national ID value is present in the row. |
| 3 | Inspect the bank account value | The known bank account value is present (PII included, not redacted). |

## 6. Postconditions
- No state change; PII confirmed present in the export.

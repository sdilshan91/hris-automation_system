# TC-ADM-007-14: WorkflowEvaluator — condition operators evaluated correctly (>, <, >=, <=, ==, !=)

## 1. Test Objective
Verify the pure `WorkflowEvaluator` correctly evaluates each supported comparison operator in a simple `{field, operator, value}` condition (the Phase-1 expression language; complex AND/OR groups are §10 Phase 2). Each operator is exercised at true, false, and boundary inputs so the condition truth value drives step inclusion deterministically.

## 2. Related Requirements
- User Story: US-ADM-007
- Functional Requirements: FR-2 (condition JSON expression, simple field comparison)
- Business Rules: BR-5 (conditional evaluation)
- Constraint: §10.2 (simple field comparison only; AND/OR deferred to Phase 2)

## 3. Preconditions
- The evaluator accepts a condition object and a request-data map and returns a boolean for step inclusion.

## 4. Test Data
| Operator | Condition | Request field | Expected |
|----------|-----------|---------------|----------|
| > | days > 5 | days=6 / 5 / 4 | true / false / false |
| < | days < 5 | days=4 / 5 / 6 | true / false / false |
| >= | days >= 5 | days=5 / 6 / 4 | true / true / false |
| <= | days <= 5 | days=5 / 4 / 6 | true / true / false |
| == | type == "Sick" | type="Sick" / "Casual" | true / false |
| != | type != "Sick" | type="Casual" / "Sick" | true / false |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Evaluate `>` at 6, 5, 4 | true, false, false (strict). |
| 2 | Evaluate `<` at 4, 5, 6 | true, false, false (strict). |
| 3 | Evaluate `>=` at 5, 6, 4 | true, true, false (inclusive boundary). |
| 4 | Evaluate `<=` at 5, 4, 6 | true, true, false (inclusive boundary). |
| 5 | Evaluate `==` for matching/non-matching value | true / false. |
| 6 | Evaluate `!=` for non-matching/matching value | true / false. |
| 7 | Evaluate a missing field or unknown operator | Handled deterministically per the implementation contract (e.g. condition treated as not-met / validation error) — no exception leaks; assert the documented default. |

## 6. Postconditions
- Each operator's truth table is verified, including inclusive vs strict boundaries.

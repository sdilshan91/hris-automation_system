# TC-ADM-008-12: Auditor role can READ the audit log but CANNOT export (read-only)

## 1. Test Objective
Verify FR-7 / BR-2 / BR-1: the `Auditor` role has read-only access to the audit log — it can list and view detail, but the export endpoint is GATED to `TenantAdmin`/`TenantOwner` and rejects an Auditor with 403. (Test Hints — Auditor role: read access verified; export denied per business rule — the platform resolves the story's open question in favor of DENY.)

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-4 (export gating)
- Functional Requirements: FR-7 (Auditor read-only, cannot export)
- Business Rules: BR-1 (read roles), BR-2 (Auditor read-only — cannot modify any data)

## 3. Preconditions
- "Alex" authenticated at `acme.yourhrm.com` with the `Auditor` role only.
- Acme `audit_log` has rows.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Auditor | Alex (Acme) | read-only |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Alex (Auditor), GET the audit log list | 200; tenant-scoped rows returned (read allowed). |
| 2 | As Alex, GET an audit detail | 200; detail returned with masking applied (TC-ADM-008-10). |
| 3 | As Alex, POST/GET the export endpoint | 403 Forbidden — Auditor cannot export. |
| 4 | Confirm no export-audit row | No "AuditLog.Export" row is created for the denied attempt (no export occurred). |
| 5 | Confirm no other admin access | Auditor cannot reach other admin write functions (FR-7) — e.g. settings PUT returns 403. |

## 6. Postconditions
- No state change; no export produced.

# TC-ADM-008-02: Pagination boundaries — default 50, max 200, oversize clamped/rejected

## 1. Test Objective
Verify FR-1 pagination contract: the default page size is 50; the maximum is 200; a request for more than 200 is clamped to 200 (or rejected with 400 if the implementation validates strictly). Page navigation maintains reverse-chronological order and tenant scope.

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-1, AC-2 (pagination maintained under filtering)
- Functional Requirements: FR-1 (pagination default 50, max 200, sort)

## 3. Preconditions
- Dana (`TenantAdmin`, Acme) authenticated.
- Acme `audit_log` has >= 260 rows with distinct timestamps.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| total rows | 260 | exceeds one max page |
| requested page sizes | (none), 200, 500 | default / max / over-max |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | GET list with no page-size param | Returns 50 rows (default). |
| 2 | GET list with page size = 200 | Returns 200 rows. |
| 3 | GET list with page size = 500 | Page size is clamped to 200 (returns <= 200), OR 400 with a validation message — never returns 500 rows. |
| 4 | GET page 2 (size 50) | Returns the next 50 rows, continuing reverse-chron order with no overlap/gap vs page 1. |
| 5 | Confirm scope on every page | All returned rows belong to Acme only. |

## 6. Postconditions
- No state change.

# TC-ADM-009-15: [DEFERRED] Redis plan cache + <60s propagation via `t:{tenantId}:config` invalidation

## 1. Test Objective
Verify NFR-1 + NFR-4: plan data is cached in Redis and invalidated on any plan update, so plan changes propagate to affected tenants within 60 seconds (via cache invalidation of `t:{tenantId}:config`).

DEFERRED — status: blocked. Redis is NOT wired on this platform (same family as US-ADM-001 FR-7 / US-ADM-006 FR-7). Because limits are read LIVE from the plan/derived fields at runtime (TC-ADM-009-07), propagation is effectively IMMEDIATE today — there is no stale cache to invalidate. This TC documents the target cache key + invalidation contract for when Redis lands; functionally, the live-read path already satisfies the "tenants benefit immediately" requirement of AC-3.

## 2. Related Requirements
- User Story: US-ADM-009
- Non-Functional Requirements: NFR-1 (<60s propagation via `t:{tenantId}:config` invalidation), NFR-4 (plan data cached in Redis, invalidated on update)
- Acceptance Criteria: AC-3 (immediate benefit — satisfied today by live read)

## 3. Preconditions
- (Deferred prerequisite) A Redis distributed cache wired; plan/config cached under `t:{tenantId}:config`; an invalidation hook on plan update.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| cache key | t:{tenantId}:config | target key |
| propagation SLA | <= 60s | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Confirm live-read behavior today | Plan/limit edits take effect immediately on next read (TC-ADM-009-07) — no cache staleness. |
| 2 | (When Redis implemented) Update a plan; observe affected tenants' `t:{tenantId}:config` | The key is invalidated; affected tenants pick up the change within 60s. |
| 3 | Until implemented | Expected behavior: "Not available — Redis cache not wired; propagation is immediate via live reads; `t:{tenantId}:config` invalidation is the target contract once Redis lands." |

## 6. Postconditions

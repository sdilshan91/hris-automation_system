# TC-ADM-007-07: FR-5 validation — invalid/foreign approver reference is rejected

## 1. Test Objective
Verify FR-5 (second clause): all approver references must be valid users/roles in the CURRENT tenant. A step whose `approver_identifier` is a non-existent user/role, or one belonging to a DIFFERENT tenant, is rejected; no definition is persisted. This doubles as an isolation guard — a Tenant B user/role id cannot be referenced as an approver in Tenant A's workflow.

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-2 (creation validity)
- Functional Requirements: FR-5 (valid approver refs), FR-7 (tenant-scoped)
- Business Rules: BR-7 (tenant isolation)

## 3. Preconditions
- Dana (`TenantAdmin`) at Acme `active`; plan limit not reached.
- A valid Manager role exists in Acme; a user `bob@beta` exists only in Tenant Beta.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| step-bad-1 | approver_type=NamedUser, identifier=<random non-existent uuid> | invalid ref |
| step-bad-2 | approver_type=NamedUser, identifier=<bob@beta user id> | foreign-tenant ref |
| step-good | approver_type=Role, identifier=<Acme Manager role id> | valid control |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | POST create workflow with step-bad-1 (non-existent approver) | Rejected (HTTP 400/422); error references invalid approver. Nothing persisted. |
| 2 | POST create workflow with step-bad-2 (Tenant Beta user as approver) | Rejected — the foreign user is not resolvable within Acme's tenant scope (EF query filter); treated as invalid approver. Nothing persisted. |
| 3 | POST create workflow with step-good only | 201; created successfully (control proves rejection is due to the bad refs, not a blanket failure). |

## 6. Postconditions
- Only the valid-approver workflow exists; no workflow references a foreign or non-existent approver.

# TC-ADM-005-09: BR-2 — Tenant Admin cannot remove the TenantOwner role

## 1. Test Objective
Verify BR-2: a Tenant Admin cannot strip the `TenantOwner` role from a user via the role-edit flow. A role-set submission that omits `TenantOwner` for an owner membership is rejected (ownership is changed only via the separate transfer flow). No `user_tenant_role` row for TenantOwner is deleted and the attempt is audited.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-3
- Business Rules: BR-2

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Member "Olivia" is the Acme `TenantOwner` (also holds Employee).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user_tenant_id | olivia-acme-membership | the owner |
| submitted role_ids | [Employee] | omits TenantOwner — attempts removal |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `PUT /api/v1/admin/users/{olivia}/roles` with `{ role_ids:[Employee] }` (no TenantOwner) | Rejected (403/409/422) with a message indicating TenantOwner cannot be removed by a Tenant Admin. |
| 2 | Query `user_tenant_role` for Olivia | TenantOwner role row STILL present; unchanged. |
| 3 | Attempt to add additional roles while KEEPING TenantOwner (e.g. [TenantOwner, Manager]) | Allowed — only REMOVING TenantOwner is blocked, not augmenting other roles. |
| 4 | Query `audit_log` | The blocked removal attempt is recorded (actor=Dana, denied, reason BR-2). |

## 6. Postconditions
- Olivia retains TenantOwner; ownership unchanged outside the dedicated transfer flow.

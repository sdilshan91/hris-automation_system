# TC-RPT-004-08: Concurrency cap -- 3 in-progress exports per user allowed; 4th simultaneous -> 429 / queued / rejected with message (FR-10)

## 1. Test Objective
Verify the per-user concurrency cap of 3 in-progress exports: a user may have up to 3 exports
in-progress simultaneously, and a 4th concurrent request is either rejected (HTTP 429 with a clear
message) or queued behind the cap -- not silently dropped, and never exceeding 3 actively generating.
After one completes, a new export is accepted again. Validates FR-10.

## 2. Related Requirements
- User Story: US-RPT-004
- Acceptance Criteria: AC-2 (async generation)
- Functional Requirements: FR-10 (max 3 concurrent exports per user)
- Test Hint: "Trigger 4 exports simultaneously; verify the 4th is queued or rejected with a message"

## 3. Preconditions
- Tenant A active; `hr1` has `Reports.Export`; Hangfire worker running.
- Four async-eligible report exports (each >= 1000 rows) ready to trigger.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| cap | 3 in-progress per user | FR-10 |
| 4th request outcome | 429 OR queued behind cap | with a user-facing message |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, trigger 3 async exports nearly simultaneously | All 3 accepted; 3 Hangfire jobs in-progress for `hr1` |
| 2 | Trigger a 4th export while the first 3 are still in-progress | 4th is rejected with HTTP 429 (+ message) OR queued behind the cap -- documented behavior, not a silent drop (FR-10) |
| 3 | Confirm actively-generating count | Never more than 3 exports actively generating for `hr1` at once |
| 4 | Allow one of the first 3 to complete | An in-progress slot frees up |
| 5 | Trigger another export | Now accepted (back under the cap of 3) |
| 6 | Confirm the cap is PER-USER, not global | A second user `hr2` can still run their own exports concurrently (cap counted per actor) |
| 7 | If rejected, inspect the response | Carries a clear message (e.g. "Maximum 3 concurrent exports; try again shortly") |

## 6. Postconditions
- No more than 3 concurrent in-progress exports per user; 4th handled per FR-10 with feedback.

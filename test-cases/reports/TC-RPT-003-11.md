# TC-RPT-003-11: Performance — generation P95 < 5s @ 5,000 employees; Redis cache TTL 15min + repeat access (NFR-1, FR-7)

## 1. Test Objective
Verify payroll report generation completes within 5 seconds at P95 for a tenant with up to 5,000
employees (NFR-1), and that report data is cached in Redis with a 15-minute TTL so repeat access is
served from cache (FR-7), with read-replica use where configured (NFR-6). Validates NFR-1, FR-7,
NFR-6.

> CONDITIONAL / DEFERRED INFRA: Redis is a deferred dev-box infra item across this platform (carried
> from US-RPT-001/002 and the Payroll/Leave/Attendance modules). If Redis is wired, assert the
> tenant-prefixed cache key shape + 15-min TTL + repeat-access cache hit + Refresh/invalidation. If
> not wired, assert identical-results-on-repeat and that key derivation includes the tenant prefix.
> The NFR-1 5s threshold is NEVER relaxed to compensate for an absent cache. NFR-1 requires a
> perf-representative environment; on a dev box record indicative numbers only and do not relax the
> threshold.

## 2. Related Requirements
- User Story: US-RPT-003
- Acceptance Criteria: AC-1, AC-2, AC-3 (all heavy aggregations)
- Functional Requirements: FR-7 (Redis cache, TTL 15 min)
- Non-Functional: NFR-1 (<5s P95 @ 5,000 emp), NFR-6 (read replicas if configured)

## 3. Preconditions
- A perf-representative Tenant A with ~5,000 employees and finalized runs across multiple months.
- Load tool able to drive concurrent report generations and record latency percentiles.
- Redis availability state recorded (wired or not) for conditional assertions.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| employee count | 5,000 | NFR-1 ceiling |
| target P95 | < 5,000 ms | per report generation |
| cache key shape | t:{tenantId}:payroll-report:{type}:{paramsHash} | tenant-prefixed (FR-7) |
| cache TTL | 15 min | FR-7 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Generate Run Summary, Department Distribution, Statutory, CTC at 5,000 emp under representative load | P95 generation latency < 5s (NFR-1) for each report type |
| 2 | (Redis wired) Generate, then re-request the SAME report with identical params within 15 min | Second response served from cache (lower latency / cache-hit signal); key = tenant-prefixed shape |
| 3 | (Redis wired) Inspect the cache key | Begins with the tenant prefix (t:{tenantId}:...); no cross-tenant key collision |
| 4 | (Redis wired) Wait past 15-min TTL OR trigger Refresh; re-request | Cache entry expired/bypassed; report re-queried (FR-7 TTL + refresh) |
| 5 | (Redis NOT wired) Re-request identical report | Identical results on repeat; key-derivation logic still includes the tenant prefix; thresholds unchanged |
| 6 | (NFR-6) If read replicas configured, drive heavy reports | Heavy reads routed to replica; latency still meets NFR-1 |
| 7 | Record indicative numbers if on a dev box | Numbers logged as indicative; NFR-1 5s threshold NOT relaxed |

## 6. Postconditions
- Generation within SLA at 5,000 emp; cache behavior verified (or conditional fallback asserted).

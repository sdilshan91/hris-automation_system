# TC-RPT-001-06: Invalid report_type and out-of-tenant department/location filters rejected (negative / validation)

## 1. Test Objective
Verify the report API/UI rejects an unknown `report_type` (must be a valid pre-built report key)
and rejects/ignores `department_ids` or `location_ids` that do not exist in the requesting tenant
(Data Requirements: "Must exist in tenant"). Confirms invalid filter values cannot widen scope or
leak the existence of another tenant's departments/locations.

## 2. Related Requirements
- User Story: US-RPT-001
- Acceptance Criteria: AC-1, AC-2, AC-5
- Functional Requirements: FR-2 (filter validation), FR-7 (tenant context)
- Data Requirements: report_type valid key; department_ids/location_ids must exist in tenant

## 3. Preconditions
- Tenant A active; `hr1` authenticated with `Reports.View.All`.
- Tenant A has department `deptA1`; Tenant B has department `deptB1` (foreign to A).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| invalid report_type | "salary_dump" | not a pre-built key |
| empty report_type | "" | required field |
| foreign department_id | deptB1 | exists only in Tenant B |
| non-existent uuid | random uuid | exists in no tenant |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Request report with report_type = "salary_dump" | 400 Bad Request / validation error: "invalid report type"; no report generated; valid keys not enumerated in a way that leaks internals |
| 2 | Request report with report_type = "" | 400 validation error: report_type is required |
| 3 | Request Headcount Summary with department_ids = [deptB1] (Tenant B's dept) | Request rejected (400/422) OR the filter resolves to zero in-tenant matches -> empty result; in NO case does Tenant B data appear; response does NOT confirm deptB1 belongs to another tenant (treated as not-found within Tenant A) |
| 4 | Request with department_ids = [random non-existent uuid] | Same as step 3: validation rejection or empty in-tenant result; no leakage |
| 5 | Request with location_ids = [foreign/non-existent uuid] | Same handling as department filter — rejected or empty; tenant-scoped |
| 6 | Repeat step 1 via direct API (bypassing UI dropdown) | Server-side validation still rejects (not just client-side) |

## 6. Postconditions
- Invalid inputs rejected/neutralized server-side; no cross-tenant disclosure.

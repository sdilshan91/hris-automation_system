# TC-RPT-005-01: HR dashboard returns the full HR widget set with correct values; each widget carries value + trend + mini chart (AC-1, FR-1/2/3, BR-1)

## 1. Test Objective
Verify that when an HR Officer loads the dashboard, `GET /api/v1/dashboard/widgets` returns
`{role:"hr", greetingName, generatedAt, widgets:[...]}` with the role-appropriate HR widget set
(Total Headcount, Open Positions, Pending Leave Requests, Today's Attendance Rate, Upcoming
Birthdays/Anniversaries, Recent Joiners, Onboarding In Progress, Turnover Rate), and that each widget
carries a numeric `value`, a trend indicator (`trendDirection` + `trendPercentage` + `trendIsPositive`),
and a `miniChart` (sparkline/donut/progress). Anchors to the Test Hint: 50 employees / 5 pending leave /
3 open positions. Validates AC-1, FR-1, FR-2, FR-3, BR-1.

## 2. Related Requirements
- User Story: US-RPT-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1 (role-based HR dashboard), FR-2 (value+label+trend+mini chart), FR-3 (aggregates multiple modules)
- Business Rules: BR-1 (HR sees organizational widgets)

## 3. Preconditions
- Tenant A active; HR Officer `hr1` authenticated within Tenant A.
- Seed data in Tenant A: exactly 50 active employees; 5 leave requests in `Pending` status;
  3 open recruitment positions. Module data exists for attendance/onboarding (assume-all-on, BR-5 deferred).
- DashboardService composes the existing per-module services (Core HR, Leave, Recruitment, Attendance, Onboarding).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| role (derived) | hr | server-derived from `hr1`'s role, not a client param |
| headcount widget value | 50 | matches active-employee count (Test Hint) |
| pending_leave widget value | 5 | matches Pending leave requests (Test Hint) |
| open_positions widget value | 3 | matches open recruitment positions (Test Hint) |
| expected widgetKeys | headcount, open_positions, pending_leave, attendance_rate, upcoming_birthdays, recent_joiners, onboarding_in_progress, turnover_rate | HR set |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, `GET /api/v1/dashboard/widgets` (no `refresh`) | 200; envelope `{role:"hr", greetingName, generatedAt, widgets:[...]}`; `role` is `"hr"` (server-derived) |
| 2 | Inspect `greetingName` and `generatedAt` | `greetingName` is `hr1`'s first name; `generatedAt` is a valid ISO timestamp |
| 3 | Inspect the HR widget set (`widgets[].widgetKey`) | Contains headcount, open_positions, pending_leave, attendance_rate, upcoming_birthdays, recent_joiners, onboarding_in_progress, turnover_rate (BR-1, FR-1) |
| 4 | Read the `headcount` widget | `value == 50`, `label` present; matches active-employee count (Test Hint, FR-3) |
| 5 | Read the `pending_leave` widget | `value == 5` (matches Pending leave requests, FR-3) |
| 6 | Read the `open_positions` widget | `value == 3` (matches open positions, FR-3) |
| 7 | For each widget, confirm the card contract | each has `value`, `label`, a trend indicator (`trendDirection` in up/down/flat + `trendPercentage` + `trendIsPositive`) and a `miniChart{type}` (sparkline/donut/progress) (FR-2) |
| 8 | Confirm the dashboard is read-only | no module data was mutated by loading the dashboard (BR-1) |

## 6. Postconditions
- HR dashboard rendered with correct, tenant-scoped values; no data mutated.

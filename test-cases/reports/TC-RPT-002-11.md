# TC-RPT-002-11: Generation P95 <3s @ 5,000 emp; Redis cache (tenant+type+filter-hash, TTL 5min) + Refresh bypass (NFR-1, FR-7)

## 1. Test Objective
Verify leave/attendance report generation completes within 3s (P95) for a tenant with up to 5,000
employees (NFR-1), that complex attendance aggregations use PostgreSQL views (NFR-6), and that a
repeated identical request is served from Redis (key `t:{tenantId}:report:{type}:{filterHash}`, TTL
5 min) while "Refresh" bypasses the cache (FR-7). Charts render <1s client-side (NFR-3).

> PLATFORM NOTE / CONDITIONAL: (a) NFR-1/NFR-3 thresholds need a perf-representative environment;
> on a dev box record indicative numbers and do NOT relax the 3s / 1s thresholds. (b) Redis is
> deferred dev-box infra — if not wired, assert instead that repeated identical requests return
> identical results, Refresh re-queries the source, and the cache KEY-DERIVATION includes
> `t:{tenantId}` + report type + a hash of the exact filter set. Never relax NFR-1 to compensate for
> an absent cache. (c) NFR-6 PostgreSQL views for attendance optimization are infra-conditional.

## 2. Related Requirements
- User Story: US-RPT-002

## 3. Preconditions
- Tenant A loaded with ~5,000 employees and a full period of leave + attendance data.
- `hr1` authenticated with `Reports.View.All`.
- Redis available (else CONDITIONAL per the note); attendance views in place (else CONDITIONAL).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Generate Attendance Summary (cold) over 5,000 employees; sample many runs | P95 generation time ≤ 3s (NFR-1); record indicative number on dev box |
| 2 | Observe chart rendering time | Charts render ≤ 1s client-side (NFR-3) |
| 3 | Re-run with IDENTICAL filters within TTL | Served from Redis (cache hit) at `t:{tenantId}:report:attendance_summary:{filterHash}`; warm latency < cold |
| 4 | Inspect the cache key | Key embeds tenant id + report type + a hash of the exact filter set (FR-7) |
| 5 | Change one filter value | Different filter-hash -> distinct key -> cache miss (params-sensitive) |
| 6 | Click "Refresh" | Cache BYPASSED; report recomputed from source; entry refreshed |
| 7 | Wait > 5 min TTL, re-run identical | Entry expired -> recompute (TTL honoured) |
| 8 | Confirm attendance aggregation path | Uses PostgreSQL views where configured (NFR-6); document if running without views on dev box |

## 6. Postconditions

# TC-RPT-003-06: Bank Advice reveal — full account requires Payroll.ViewSensitive; writes audit action "PayrollReport.ViewSensitive" (AC-4, FR-6, NFR-3)

## 1. Test Objective
Verify the permission-gated reveal of full bank account numbers: a user WITH `Payroll.ViewSensitive`
can reveal full account numbers, a user WITHOUT it cannot (mask persists / 403 on the reveal path),
and EVERY successful full-account access writes an audit record with the EXACT action string
"PayrollReport.ViewSensitive" (NFR-3 PII audit). Validates AC-4 (reveal), FR-6 (permission-gated
reveal), NFR-3, and the Test Hint "reveal with permission; verify full numbers shown; verify audit
record created with PayrollReport.ViewSensitive".

> NOTE (story mismatch to flag): `Payroll.ViewSensitive` is a NEW permission introduced by
> US-RPT-003 — `PermissionCatalog.cs` today only defines Payroll.View/.View.Own/.Run/.Approve/
> .Configure/.Export, and every current bank-advice endpoint is gated on `Payroll.Export`. Closing
> this AC requires the new permission to be ADDED to the catalog and the reveal endpoint/audit hook
> wired. Tested as the to-be-built behavior.

## 2. Related Requirements
- User Story: US-RPT-003
- Acceptance Criteria: AC-4
- Functional Requirements: FR-6
- Non-Functional: NFR-3 (PII access audited, action "PayrollReport.ViewSensitive")
- Dependencies: US-NTF-004 (audit trail)

## 3. Preconditions
- Tenant A active; both authenticated:
  - `hrSens` — has `Payroll.Export` AND `Payroll.ViewSensitive`.
  - `hrPlain` — has `Payroll.Export` only (no ViewSensitive).
- Bank Advice for latest finalized run available; emp1 full account = 123456789012.
- Audit log accessible (US-NTF-004 / audit-logs endpoint).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| reveal permission | Payroll.ViewSensitive | new permission (US-RPT-003) |
| emp1 full account | 123456789012 | shown only on authorized reveal |
| expected audit action | PayrollReport.ViewSensitive | EXACT string (NFR-3) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hrPlain`, generate Bank Advice; click the "Reveal" eye toggle | Reveal REFUSED — account stays masked (last 4) and/or the reveal/full-export call returns 403; no full account in response/DOM |
| 2 | Confirm NO "PayrollReport.ViewSensitive" audit row is written for the refused attempt | Audit not recorded for a denied/masked view (only successful full access is audited) |
| 3 | As `hrSens`, generate Bank Advice; click "Reveal" | Full account numbers shown (emp1 → 123456789012) |
| 4 | Query the audit log filtered by Tenant A | A row exists with action EXACTLY "PayrollReport.ViewSensitive", actor=hrSens, tenant=A, timestamp ~now |
| 5 | Inspect the audit row detail | Captures who/when and the report+run context (no other tenant's data); is tenant-scoped |
| 6 | As `hrSens`, reveal again | A SECOND "PayrollReport.ViewSensitive" audit row written (each sensitive access audited, not just the first) |
| 7 | Confirm action string is verbatim (case + dot) | "PayrollReport.ViewSensitive" — not "Payroll.ViewSensitive", not lowercased (NFR-3 exact assertion) |

## 6. Postconditions
- Full account revealed only for `Payroll.ViewSensitive`; each successful reveal audited with the exact action name.

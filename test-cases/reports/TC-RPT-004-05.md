# TC-RPT-004-05: Sync/async routing boundary -- 999 rows sync (Completed), 1000 rows async (Queued via Hangfire) (FR-5, boundary)

## 1. Test Objective
Verify the FR-5 routing threshold at its exact boundary: a report with 999 rows is generated
SYNCHRONOUSLY (`status:"Completed"`, no Hangfire job) and a report with 1000 rows is generated
ASYNCHRONOUSLY (`status:"Queued"`, Hangfire job enqueued, SignalR on completion). Validates FR-5 and
the >=1000 inclusive boundary.

## 2. Related Requirements
- User Story: US-RPT-004
- Acceptance Criteria: AC-2, AC-4
- Functional Requirements: FR-5 (<1000 sync; >=1000 async), FR-8

## 3. Preconditions
- Tenant A active; `hr1` has `Reports.Export`; Hangfire worker running.
- Two report variants available: one resolving to 999 rows, one to exactly 1000 rows.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| boundary low | 999 rows | < 1000 -> sync |
| boundary high | 1000 rows | >= 1000 -> async |
| format | csv | reused for both |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, export the 999-row report to CSV | `{status:"Completed", rowCount:999}`; NO Hangfire job enqueued (FR-5 sync) |
| 2 | Confirm the 999-row path returns the file/download directly | Inline completion, no SignalR notification needed |
| 3 | Export the 1000-row report to CSV | `{status:"Queued", rowCount:1000}`; a Hangfire job IS enqueued (FR-5 async, >=1000 inclusive) |
| 4 | Wait for the 1000-row job to finish | SignalR `ReceiveNotification` ready push with download link (FR-8) |
| 5 | Compare boundary behavior | 999 -> Completed/sync; 1000 -> Queued/async; threshold is inclusive at 1000 |

## 6. Postconditions
- 999-row export completed sync; 1000-row export queued async and delivered via SignalR.

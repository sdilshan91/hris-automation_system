# TC-RPT-002-08: Unauthorized user (no Reports.View) blocked 403; unauthenticated 401 (negative/security)

## 1. Test Objective
Verify that a user lacking any reports permission cannot generate leave/attendance reports
(authorization 403), and an unauthenticated request is rejected (401). Validates FR-8 permission
gating and the negative/security path for AC-1–AC-4.

> PLATFORM NOTE: the catalog today exposes `Reports.View` (+ `Reports.Export`). The Team-vs-All
> SCOPE split (AC-4 / FR-8) requires scoped permission variants (`Reports.View.Team` /
> `Reports.View.All`) OR a manager direct-reports data filter to be ADDED — permission-granularity
> gap flagged to the caller. This TC asserts the deny path (no reports permission at all -> 403).

## 2. Related Requirements
- User Story: US-RPT-002
- Acceptance Criteria: AC-1, AC-2, AC-3, AC-4
- Functional Requirements: FR-8 (permission-based access)
- Non-Functional: NFR-2

## 3. Preconditions
- Tenant A active.
- `noPerm` authenticated in Tenant A WITHOUT any `Reports.*` permission.
- A valid HR Officer `hr1` (with `Reports.View.All`) exists as a positive control.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user noPerm | no Reports permission | should be denied |
| user hr1 | Reports.View.All | positive control |
| report_type | leave_utilization | any leave/attendance report |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `noPerm`, call the report endpoint | 403 Forbidden; no report data returned |
| 2 | As `noPerm`, attempt every report type (utilization, balance, attendance, overtime, absenteeism) | 403 on each; no leakage of structure or data |
| 3 | Send an unauthenticated request (no/invalid token) | 401 Unauthorized |
| 4 | Confirm the report UI hides/disables report generation for `noPerm` | No generate action available client-side (defense-in-depth, not the only control) |
| 5 | As `hr1` (positive control), generate the same report | 200 with data — confirms the deny in steps 1–2 is permission-based, not a broken endpoint |

## 6. Postconditions
- Unauthorized blocked 403; unauthenticated 401; authorized succeeds.

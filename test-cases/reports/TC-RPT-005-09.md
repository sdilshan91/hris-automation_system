# TC-RPT-005-09: Unauthenticated request -> 401; a role with no data -> empty/zero-state widgets (not an error) (AC-1/2/3, FR-8)

## 1. Test Objective
Verify the dashboard endpoint's authentication gate and graceful empty-state behavior: an unauthenticated
request returns 401, and an authenticated user whose modules currently have no data receives well-formed
zero-state widgets (value 0 / empty `items[]`) rather than a 4xx/5xx error or a broken card. Validates
AC-1, AC-2, AC-3, FR-8.

## 2. Related Requirements
- User Story: US-RPT-005
- Acceptance Criteria: AC-1, AC-2, AC-3
- Functional Requirements: FR-8 (scoped by session/role; requires a session)

## 3. Preconditions
- Tenant A active.
- A fresh employee `empNew` in Tenant A with NO leave records, NO attendance yet, NO active onboarding journey, and NO pending actions.
- A fresh tenant/role context where HR widgets would aggregate over zero-population data (e.g. a newly provisioned tenant with 0 employees) is available for the zero-state HR check.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| no auth token | -- | expect 401 |
| empNew leave balance | none | zero-state, not error |
| zero-population HR tenant | 0 employees | headcount widget value 0 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `GET /api/v1/dashboard/widgets` with NO Authorization header | 401 Unauthorized; no widget payload (FR-8) |
| 2 | `GET /api/v1/dashboard/widgets` with an expired/invalid token | 401 Unauthorized |
| 3 | As `empNew`, `GET /api/v1/dashboard/widgets` | 200; employee widget set returned with zero-state values (e.g. `leave_balance.value == 0`, `pending_actions.items == []`) -- NOT an error (AC-3) |
| 4 | Confirm zero-state cards are well-formed | each widget still has `label`, a `value` (0), and a `miniChart` (empty/zeroed), not a missing/broken card |
| 5 | On the zero-population HR tenant, load the HR dashboard | `headcount.value == 0`, `open_positions.value == 0`, etc.; 200 with zero-state, no divide-by-zero in `turnover_rate` (AC-1) |
| 6 | Confirm onboarding widget absence is graceful | `empNew` has no active journey -> `onboarding_progress` is omitted or shows a completed/empty state (AC-3 "if active") |

## 6. Postconditions
- Unauthenticated access blocked; empty data renders as zero-state widgets, never as an error.

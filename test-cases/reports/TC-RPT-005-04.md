# TC-RPT-005-04: KPI widget click-through navigates to the module page with pre-applied filter via linkUrl + linkFilters (AC-4, FR-5)

## 1. Test Objective
Verify that each actionable KPI widget exposes a `linkUrl` and `linkFilters` payload and that clicking the
widget navigates to the corresponding module page with the filter PRE-APPLIED. Anchors to the Test Hint:
the Pending Leave Requests widget links to `/leave/requests?status=Pending`. Validates AC-4, FR-5.

## 2. Related Requirements
- User Story: US-RPT-005
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5 (click-through with contextual filters pre-applied)
- UI/UX: S8 (widget cards), Data req (link_url, link_filters)

## 3. Preconditions
- Tenant A active; HR Officer `hr1` authenticated, on the dashboard, with the Pending Leave Requests widget present (value > 0).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| widget | pending_leave | clickable KPI |
| linkUrl | /leave/requests | target module page |
| linkFilters | { status: "Pending" } | pre-applied filter (Test Hint) |
| open_positions linkUrl | /recruitment/positions (or equivalent) | another click-through example |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Inspect the `pending_leave` widget payload | `linkUrl == "/leave/requests"` and `linkFilters` contains `{status:"Pending"}` (AC-4, FR-5) |
| 2 | As `hr1`, click the Pending Leave Requests widget card | the app navigates to `/leave/requests?status=Pending` (filter serialized from `linkFilters`) |
| 3 | Inspect the destination Leave Requests page | the Status filter is already set to "Pending"; only pending requests are listed (AC-4) |
| 4 | Inspect another clickable widget (e.g. `open_positions`) | it carries its own `linkUrl`+`linkFilters` and navigates to the recruitment page with the matching filter |
| 5 | Inspect a non-actionable widget (e.g. a pure sparkline KPI with no drill-through) | `linkUrl` is absent/null and the card is not a navigation target (FR-5 -- click-through only where defined) |
| 6 | Confirm the destination URL is tenant-correct | navigation stays within the current tenant context (no cross-tenant route) |

## 6. Postconditions
- User landed on the filtered module page; dashboard state preserved on back-navigation.

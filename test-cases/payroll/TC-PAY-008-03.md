# TC-PAY-008-03: Direct ReviewPending -> Finalize blocked (must pass >=1 approval step, BR-1); invalid status transitions rejected (state machine, BR-4)

## 1. Test Objective
Verify BR-1 / BR-4 / FR-1: a payroll run MUST go through at least one approval step before it can be finalized -- attempting to Finalize a run that is still ReviewPending (never submitted/approved) is rejected. The approval state machine accepts ONLY the defined transitions (ReviewPending -> AwaitingApproval -> Approved -> Finalized, plus AwaitingApproval -> Rejected -> ReviewPending) and rejects every other transition (e.g., ReviewPending -> Approved, AwaitingApproval -> Finalized, Approved -> AwaitingApproval, Rejected -> Approved).

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-5
- Functional Requirements: FR-1
- Business Rules: BR-1, BR-4
- Test Hints: state-machine unit test

## 3. Preconditions
- Runs available in each tested status (ReviewPending, AwaitingApproval, Approved, Rejected) for tenant acme.
- Default single-step workflow configured (BR-2).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Valid transitions | ReviewPending->AwaitingApproval->Approved->Finalized; AwaitingApproval->Rejected->ReviewPending | BR-4 |
| Invalid transitions | ReviewPending->Finalized, ReviewPending->Approved, AwaitingApproval->Finalized, Approved->AwaitingApproval, Rejected->Approved, Finalized->* | rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | On a ReviewPending run, call Finalize directly (UI Finalize hidden; force via API). | Rejected (409/400) -- a run cannot be finalized without passing >=1 approval step; status stays ReviewPending; no immutability applied (BR-1). |
| 2 | On a ReviewPending run, attempt to set status Approved directly (skip AwaitingApproval). | Rejected -- not a permitted transition; status unchanged (BR-4). |
| 3 | On an AwaitingApproval run, attempt Finalize directly (skip Approved). | Rejected -- Finalize requires Approved (BR-1, BR-4). |
| 4 | On an Approved run, attempt to revert to AwaitingApproval or ReviewPending via API. | Rejected -- not a permitted transition (BR-4). |
| 5 | On a Rejected run, attempt to set Approved directly. | Rejected -- Rejected may only go to ReviewPending after corrections (BR-4). |
| 6 | Walk the valid chain on a fresh run: ReviewPending -> Submit -> AwaitingApproval -> Approve -> Approved -> Finalize -> Finalized. | Each valid transition succeeds; the full chain completes; no invalid transition was needed (BR-1, BR-4). |

## 6. Postconditions
- No run was finalized without an approval step; only the defined state-machine transitions are accepted.

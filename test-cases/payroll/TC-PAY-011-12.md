# TC-PAY-011-12: Distribution UI accessibility + responsiveness -- Send Payslips button, confirmation dialog, real-time progress bar, and the summary card with expandable Sent/Failed/Skipped lists are keyboard-navigable, screen-reader friendly, and responsive 360px-1920px (accessibility / WCAG 2.1 AA)

## 1. Test Objective
Verify the payslip-distribution UI meets WCAG 2.1 AA and is responsive across 360px-1920px: the "Send Payslips" primary button, the pre-send confirmation dialog, the real-time progress bar (sent/total via SignalR), and the post-completion distribution summary card (green/red/amber Sent/Failed/Skipped counts with expandable employee lists and per-employee Re-send / Re-send All Failed actions) are all operable by keyboard alone, announced correctly to screen readers, do not rely on colour alone to convey status, and reflow without loss of content on small screens.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-1, AC-3, AC-4
- Functional Requirements: FR-4 (re-send actions), FR-5 (status), FR-7 (confirmation)
- Standards: WCAG 2.1 AA; UI/UX Notes S8

## 3. Preconditions
- Tenant "acme" Finalized run R with a completed distribution that has a mix of Sent/Failed/Skipped employees (so all summary states render).
- HR Officer authenticated with `Payroll.*.All`.
- Axe (or equivalent) a11y tooling + screen reader (NVDA/VoiceOver) available; viewport set 360-1920px.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Summary state | Sent / Failed / Skipped all > 0 | exercises colour + lists |
| Viewports | 360, 768, 1280, 1920 px | responsive range |
| Contrast | >= 4.5:1 text, >= 3:1 status chips | WCAG 1.4.3/1.4.11 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to "Send Payslips" using Tab only; activate with Enter/Space. | Button is reachable, has a visible focus ring, an accessible name/role=button, and a disabled state announced when the run is non-Finalized. |
| 2 | Open the confirmation dialog ("send to {count} employees...") via keyboard. | Dialog traps focus, has role=dialog + accessible name, Esc cancels, Enter confirms; count is announced; focus returns to the trigger on close (WCAG 2.4.3). |
| 3 | Start a send and observe the progress bar. | Progress bar exposes role=progressbar with aria-valuenow/max; live sent/total updates are announced politely (aria-live) without focus theft. |
| 4 | Inspect the summary card status counts. | Sent/Failed/Skipped are distinguishable by text/icon + label, NOT colour alone (WCAG 1.4.1); contrast meets AA. |
| 5 | Expand the Failed / Skipped lists and reach the Re-send / Re-send All Failed actions by keyboard. | Expanders expose aria-expanded; the lists are keyboard-operable; Re-send buttons have accessible names and are reachable/activatable without a mouse (FR-4). |
| 6 | Run axe at each viewport (360/768/1280/1920). | Zero critical/serious violations; layout reflows, no horizontal scroll trap or clipped content at 360px; the summary lists remain readable. |

## 6. Postconditions
- The full distribution flow (send -> confirm -> progress -> summary -> re-send) is keyboard + screen-reader accessible and responsive with no AA violations.

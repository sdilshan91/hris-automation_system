# TC-PAY-003-01: Initiate monthly payroll run -> 202 + runId + Queued; Hangfire job computes, persists slips, transitions to ReviewPending, notifies HR (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1, AC-2, AC-3 and FR-1..FR-6/FR-8: an authenticated HR Officer with `Payroll.Run` initiates a payroll run for a fully-prepared period; the API synchronously creates a `payroll_run` (status=Queued), enqueues a `ProcessPayrollRunJob`, and returns 202 Accepted with the runId; the Hangfire worker (with restored `ITenantContext`) locks attendance/leave, fetches active employees with salary structures, computes earnings/deductions/LOP/statutory/net per employee, persists one `payroll_slip` (+ `payroll_slip_detail` per component) per employee in batch, writes a run summary (FR-8), transitions the run to ReviewPending, and HR receives an in-app (SignalR) + email notification.

## 2. Related Requirements
- User Story: US-PAY-003
- Acceptance Criteria: AC-1, AC-2, AC-3
- Functional Requirements: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-8
- Business Rules: BR-6 (Queued -> Processing -> ReviewPending)
- Data Requirements: S7 (payroll_run / payroll_slip / payroll_slip_detail; numeric(18,2); tenant_id FK)

## 3. Preconditions
- Tenant "acme" Active, subdomain `acme.yourhrm.com`, Payroll module enabled.
- 3 active employees with assigned salary structures (US-PAY-002); attendance + leave for May 2026 FINALIZED/locked.
- Statutory deduction rules configured (US-PAY-006); Hangfire worker operational.
- No existing non-cancelled payroll_run for May 2026 in acme.
- HR Officer "Maya Singh" authenticated in acme with `Payroll.Run`.

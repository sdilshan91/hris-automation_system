# TC-PAY-011-11: Email content integrity + injection safety + terminated-employee handling -- template variables render correctly, template/recipient fields resist header/HTML injection, and a terminated employee with an email still on file receives their final payslip (security / FR-3 / BR-7)

## 1. Test Objective
Verify FR-3, BR-7 and input-safety: the tenant notification template renders all supported variables correctly ({EmployeeName}, {PayMonth}, {PayYear}, {CompanyName}); template content and the resolved recipient address are safe against email-header injection (CRLF in subject/recipient) and HTML/script injection in the body; and a terminated employee whose final payslip is in the run still receives their payslip email if their email is on file (BR-7). The subject is exactly "Your Payslip for {Month} {Year}" with correct month/year substitution.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2, FR-3
- Business Rules: BR-7 (terminated employee final payslip emailed)
- Non-Functional Requirements: NFR-5 (no amounts; safe content)

## 3. Preconditions
- Tenant "acme" Finalized run R for May 2026 including a TERMINATED employee EMP-TERM whose final-month payslip is in the run and whose email is still on file (BR-7).
- A tenant template variant with a deliberately malicious display-name / template field (CRLF + `<script>`/`<img onerror>`) to test injection handling.
- HR Officer authenticated with `Payroll.*.All`; SMTP sink captures raw headers + body.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Subject template | Your Payslip for {PayMonth} {PayYear} | renders "May 2026" |
| Injection probes | `name\r\nBcc: attacker@evil.com`, `<script>alert(1)</script>` | header + HTML injection |
| EMP-TERM | terminated, email on file, final payslip in run | BR-7 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Send Payslips; inspect the rendered subject + body variable substitution (FR-3, AC-2). | Subject = "Your Payslip for May 2026"; body shows correct {EmployeeName}/{CompanyName}; no unresolved `{...}` placeholders remain. |
| 2 | Inspect raw headers for the recipient with the CRLF-injected display name. | The CRLF/header-injection payload is neutralized -- no injected `Bcc:`/extra headers appear; the message goes only to the intended recipient (header injection blocked). |
| 3 | Inspect the body containing the `<script>`/`<img onerror>` probe. | The payload is encoded/sanitized (rendered inert), not executable HTML; no script/active content delivered (NFR-5). |
| 4 | Verify EMP-TERM received their final payslip email (BR-7). | EMP-TERM gets the email with their own final-month PDF attached; status=Sent -- a terminated employee with an email on file is NOT excluded. |
| 5 | Confirm a terminated employee with NO email on file is Skipped (cross-check with BR-3). | Such an employee is Skipped (consistent with TC-PAY-011-02), payslip still in portal. |

## 6. Postconditions
- Template variables render correctly with the exact subject; header/HTML injection is neutralized; terminated employees with an email on file receive their final payslip.

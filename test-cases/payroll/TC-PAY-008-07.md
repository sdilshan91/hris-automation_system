# TC-PAY-008-07: Return to HR without formal rejection (FR-9); SLA auto-escalation to backup approver (FR-3); approval delegation (FR-6)

## 1. Test Objective
Verify FR-9 / FR-3 / FR-6: the approver can "Return to HR" with specific comments WITHOUT formally rejecting (a distinct action from Reject, BR-4 path differs); if a step's configurable SLA is breached the system auto-escalates to a backup approver; and an approver may delegate their approval authority to another authorized user during their absence.

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-2, AC-3
- Functional Requirements: FR-3, FR-6, FR-7, FR-9
- Non-Functional Requirements: NFR-1
- Business Rules: BR-4
- Data Requirements: S7 (action: Returned, Escalated)

## 3. Preconditions
- A June 2026 run is in AwaitingApproval for acme; approver fin1 (Payroll.Approve), backup approver fin2 (Payroll.Approve), delegate fin3 (Payroll.Approve).
- Step SLA configured (e.g., 24h) with fin2 as the configured backup.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Return comment | "Please attach the variance explanation note for Dept C." | FR-9, mandatory |
| SLA | 24h, backup=fin2 | FR-3 |
| Delegate | fin1 -> fin3 | FR-6 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As fin1, click "Return to HR" WITHOUT a comment. | Blocked -- comments are required for Return (as for Reject); no action taken (FR-9, UI rule). |
| 2 | As fin1, click "Return to HR" WITH a comment. | A history row persists (action=Returned, actor=fin1, comments); HR is notified within 30s; the run is sent back for clarification WITHOUT being marked Rejected -- it is distinct from a formal rejection (FR-9, FR-7, NFR-1). The workflow instance is NOT closed as Rejected (BR-4). |
| 3 | Configure a fresh run's step SLA to a short window and let it elapse without action. | On SLA breach the system auto-escalates: a history row persists (action=Escalated); the backup approver fin2 is notified and may now act on the step (FR-3). |
| 4 | As fin2 (backup), approve the escalated step. | Approval succeeds for fin2 as the escalated approver; recorded with actor=fin2 (FR-3, FR-7). |
| 5 | On a separate run, fin1 delegates approval to fin3 (during absence), then fin3 approves. | The delegation is recorded; fin3 (authorized via delegation) can act on fin1's step; the approval is audited as actor=fin3 acting on behalf of fin1 (FR-6, FR-7). |
| 6 | Confirm a non-authorized user still cannot approve via delegation. | A user without Payroll.Approve (and not delegated) is rejected (FR-6 -- delegation only to authorized users). |

## 6. Postconditions
- Return-to-HR, SLA escalation, and delegation each work and are audited distinctly from Approve/Reject.

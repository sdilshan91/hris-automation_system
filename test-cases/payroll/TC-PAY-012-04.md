# TC-PAY-012-04: Every payroll write logs an audit entry -- create/structure/assignment/statutory/run-events/adjustments/payslip-gen/email all produce the correct standardized action name + resource_type (FR-2 coverage matrix)

## 1. Test Objective
Verify FR-2 and BR-1: perform a representative sequence of payroll write operations across the module and confirm EACH produces an `audit_log` entry with the correct standardized action name and resource_type, with no exceptions. This is the breadth complement to TC-PAY-012-03's depth (a single update's schema).

## 2. Related Requirements
- User Story: US-PAY-012
- Acceptance Criteria: AC-3, AC-4
- Functional Requirements: FR-2, FR-3
- Business Rules: BR-1 (every payroll write logs -- no exceptions)
- Data Requirements: standardized action names (S7 of the story)

## 3. Preconditions
- Tenant "acme" Active; salary components/structures, an employee, statutory rules, and at least one payroll run exist (US-PAY-001..008).
- HR Officer authenticated in acme with `Payroll.*.All`.

## 4. Test Data
| Operation | Expected action | Expected resource_type |
|-----------|-----------------|------------------------|
| Create component | SalaryComponent.Created | SalaryComponent |
| Update component | SalaryComponent.Updated | SalaryComponent |
| Soft-delete component | SalaryComponent.Deleted | SalaryComponent |
| Update structure | SalaryStructure.Updated | SalaryStructure |
| Assign salary | EmployeeSalary.Assigned | EmployeeSalary |
| Update statutory rule | StatutoryRule.Updated | StatutoryRule |
| Initiate run | PayrollRun.Initiated | PayrollRun |
| Approve run | PayrollRun.Approved | PayrollRun |
| Finalize run | PayrollRun.Finalized | PayrollRun |
| Create adjustment | PayrollAdjustment.Created | PayrollAdjustment |
| Generate payslips | PayslipPDF.Generated | PayrollSlip |
| Send payslip emails | PayslipEmail.Sent | PayrollSlip |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Perform each write in the Test Data table in sequence. | Each operation succeeds and writes at least one audit_log entry (BR-1). |
| 2 | Query audit_log for the tenant after the sequence. | Each operation's row carries the EXACT standardized action name + resource_type from the table; no operation is missing an entry. |
| 3 | Verify create actions have null `before`; delete/soft-delete have the expected before/after. | Create -> before is null, after populated; soft-delete -> before populated, after reflects the soft-delete (deleted flag) per S7. |
| 4 | Verify each entry has actor + timestamp + resource_id. | Every row has actor_user_id, timestamp, resource_id set; no null actor on any (see BR-7 for system actions in TC-PAY-012-06). |
| 5 | Confirm no payroll write was silent. | The count of audit entries >= the count of write operations performed; there is no payroll write path that bypasses logging. |

## 6. Postconditions
- One+ audit_log entry per payroll write, each with the correct action name + resource_type; FR-2 breadth covered.

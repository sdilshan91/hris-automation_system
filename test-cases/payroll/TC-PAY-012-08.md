# TC-PAY-012-08: Point-in-time historical payslip preserved -- component/structure changes after a run do NOT alter the run's finalized payslips; history reflects values at run time (snapshot)

## 1. Test Objective
Verify BR-6: historical payslip data is preserved as-is. After a payroll run is finalized, changing a salary component name/value or restructuring does NOT retroactively alter the run's payslips, the run history totals, or the per-run audit timeline -- the historical payslip reflects the values at the time of the run (point-in-time snapshot).

## 2. Related Requirements
- User Story: US-PAY-012
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-6
- Business Rules: BR-6 (point-in-time snapshot), BR-3 (history never deleted)
- Non-Functional Requirements: NFR-5 (7+ year retention)

## 3. Preconditions
- Tenant "acme" Active; a Finalized May 2026 run R whose payslips used component "HRA" labelled "House Rent Allowance" at value 20% with a known per-employee net.
- HR Officer authenticated with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Run | R (May 2026), Finalized | snapshot source |
| Component change | HRA rename + value 20% -> 25% (after R finalized) | post-run mutation |
| Expectation | R's payslips/totals unchanged | BR-6 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Record R's history row (employee count, total net) and one employee's payslip breakdown (HRA line label + amount). | Baseline captured for the finalized run. |
| 2 | After R is finalized, rename HRA to "HRA (Housing)" and change its value 20% -> 25% (US-PAY-001). | The component update succeeds and writes a SalaryComponent.Updated audit entry (TC-PAY-012-03). |
| 3 | Re-open R from history; view the Summary tab and the same employee's payslip. | R's total net + employee count are UNCHANGED; the payslip still shows the HRA line at the OLD label + 20% amount as snapshotted at run time (BR-6). |
| 4 | Confirm the audit timeline for R is unaffected. | R's per-run audit timeline (FR-6) is unchanged; the component-rename audit entry belongs to the component resource, not run R. |
| 5 | Confirm the post-change run (e.g. June 2026) DOES use the new value. | A subsequent run reflects 25%; only future runs adopt the change, historical ones do not. |

## 6. Postconditions
- R's payslips/history/totals reflect run-time values; only future runs use the updated component; nothing historical mutated.

# TC-PAY-003-10: Idempotency-Key prevents duplicate payroll runs on replay; distributed lock blocks concurrent same-tenant+period runs (FR-9 / NFR-2 / NFR-3)

## 1. Test Objective
Verify FR-9, NFR-2, and NFR-3: the payroll trigger endpoint accepts an `Idempotency-Key` header; a replay of the SAME key (e.g. client retry, double-click, network re-send) returns the SAME runId WITHOUT creating a second payroll_run or enqueuing a second job. Concurrent initiate attempts for the same tenant+period are serialized by a distributed lock (NFR-3) so only one run is created. The job itself is idempotent and safely re-runnable (NFR-2).

## 2. Related Requirements
- User Story: US-PAY-003
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-2, FR-9
- Non-Functional: NFR-2 (idempotent job), NFR-3 (distributed lock)
- Data Requirements: S7 (payroll_run.idempotency_key UNIQUE per tenant)

## 3. Preconditions
- Tenant "acme"; a fully-prepared May 2026 period; HR with `Payroll.Run`.

| Idempotency-Key | 22222222-2222-2222-2222-222222222222 | reused on replay |
| Period | May 2026 | same tenant + period |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /api/v1/payroll/runs` (May 2026) with the Idempotency-Key. | 202 Accepted; runId R1 created; one Hangfire job enqueued. |
| 2 | Replay the SAME request with the SAME Idempotency-Key. | 202 (or 200) returning the SAME runId R1; NO second payroll_run row; NO second job enqueued (FR-9; idempotency_key UNIQUE per tenant). |
| 3 | POST a DIFFERENT period with the SAME key. | Rejected (409) OR treated per the documented idempotency contract -- the key is not silently reused to create a different run. |
| 4 | Fire two concurrent initiate requests for May 2026 (different keys, same period). | Distributed lock (NFR-3) serializes them; exactly ONE non-cancelled run exists for the period (the second sees BR-1 conflict 409); no two parallel jobs compute the same period. |
| 5 | Re-enqueue/replay the SAME job (worker-level retry). | Idempotent (NFR-2): no duplicate slips, no double-charged deductions; the run reaches a single consistent ReviewPending state. |

## 6. Postconditions
- Replays and concurrent attempts never create duplicate runs/jobs/slips for a tenant+period; the key is honored per tenant.

# TC-PAY-002-08: Authorization -- only Payroll.*.All may assign salary; others 403

## 1. Test Objective
Verify the authorization contract: salary structure assignment, override, bulk assign, preview, and revision-history read are restricted to users holding `Payroll.*.All` (or Tenant Admin). Users without the permission (e.g., plain Employee, Recruiter, Leave Approver) receive 403 Forbidden and no data is read or written. Authentication is required (401 when unauthenticated).

## 2. Related Requirements
- User Story: US-PAY-002
- Acceptance Criteria: AC-1, AC-2, AC-3, AC-4
- Functional Requirements: FR-1, FR-3, FR-4, FR-5
- Data Requirements: S7

## 3. Preconditions
- Tenant "acme" Active; FT-IN active structure; Ravi Kumar Active.
- Users in acme: Maya (Payroll.*.All), Sam (Employee role only), Rita (Recruiter, no Payroll perm).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Authorized | Maya (Payroll.*.All) | allowed |
| Unauthorized | Sam (Employee), Rita (Recruiter) | denied |
| Unauthenticated | no/invalid bearer | 401 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam (Employee), `POST /api/v1/payroll/employees/{id}/salary`. | 403 Forbidden; no assignment created. |
| 2 | As Sam, `POST .../salary/preview` and `GET .../salary/revisions`. | 403 Forbidden; no breakdown or history returned. |
| 3 | As Rita (Recruiter), attempt bulk assign `POST .../salary/bulk`. | 403 Forbidden. |
| 4 | With no/invalid bearer token, call any salary endpoint. | 401 Unauthorized. |
| 5 | As Maya (Payroll.*.All), perform the same assign/preview/bulk/revisions calls. | All succeed (201/200) -- confirms the deny is permission-based, not a broken endpoint. |
| 6 | Verify a non-Payroll user cannot even read another employee's compensation tab data via the API. | 403; salary data not exposed. |

## 6. Postconditions
- Only Payroll.*.All / Tenant Admin can assign or read salary data; unauthorized callers are blocked with no side effects.

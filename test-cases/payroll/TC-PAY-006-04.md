# TC-PAY-006-04: Tax-slab validation rejects both overlapping ranges AND gaps; only contiguous slabs are accepted

## 1. Test Objective
Verify FR-6 / AC-1: the system validates that tax slabs are contiguous -- it MUST reject configurations with overlapping income ranges and configurations with gaps between slabs, and MUST accept a contiguous set. The inline editor highlights the offending slab(s) (UI/UX); the API returns a 400 with a field-level error identifying the overlap/gap. The first slab must start at 0 and the final slab may be open-ended (slab_to null = unlimited).

## 2. Related Requirements
- User Story: US-PAY-006
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-6
- Data Requirements: S7 (tax_slab: slab_from, slab_to, order_index)

## 3. Preconditions
- Tenant "acme" Active, Payroll enabled, country configured.
- User authenticated as Tenant Admin / `Payroll.*.All` on the Income Tax tab.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Overlap set | [0-250K, 200K-500K, 500K-1M] | 200K-250K overlaps |
| Gap set | [0-250K, 300K-500K, 500K-null] | 250K-300K gap |
| Valid set | [0-250K, 250K-500K, 500K-1M, 1M-null] | contiguous |
| Non-zero-start set | [100K-250K, ...] | first slab must start at 0 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter the overlap set [0-250K, 200K-500K, 500K-1M] and Save. | Rejected with 400; error identifies the overlapping range (200K-250K); the offending row is highlighted red in the inline editor (FR-6). No rule persisted. |
| 2 | Enter the gap set [0-250K, 300K-500K, 500K-null] and Save. | Rejected with 400; error identifies the gap (250K-300K) (FR-6). No rule persisted. |
| 3 | Enter a set whose first slab does not start at 0 ([100K-250K, ...]) and Save. | Rejected with 400; error indicates the first slab must start at 0 (no implicit gap below the first slab). |
| 4 | Enter a set with a duplicate boundary / zero-width slab (e.g. 250K-250K) and Save. | Rejected with 400 (slab_to must be > slab_from for bounded slabs). |
| 5 | Enter the valid contiguous set [0-250K, 250K-500K, 500K-1M, 1M-null] and Save. | Accepted (201/200); 4 contiguous tax_slab rows persisted with correct order_index; no highlight. |
| 6 | Re-fetch and confirm contiguity is enforced on update too. | Editing an existing slab to introduce an overlap/gap is also rejected (validation runs on create AND update). |

## 6. Postconditions
- Only the contiguous slab set is persisted; overlapping/gapped/zero-start sets are never stored.

# TC-PAY-002-07: Bulk assignment of one structure to multiple employees with individual CTCs and a progress indicator

## 1. Test Objective
Verify AC-4 / FR-5: HR uses the bulk assignment feature (multi-select or CSV upload) to assign the same salary structure to multiple employees, each with their individual CTC; all selected employees receive the assignment, a progress indicator shows completion, and per-row validation (inactive structure, sum tolerance) is enforced per employee. Functional correctness at moderate volume; the 500-employee/30s SLA is covered in TC-PAY-002-11.

## 2. Related Requirements
- User Story: US-PAY-002
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5, FR-2, FR-6
- Business Rules: BR-3
- Data Requirements: S7

## 3. Preconditions
- FT-IN active structure available; 10 Active employees with no current assignment exist in acme.
- HR authenticated with `Payroll.*.All`.
- CSV template downloadable.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Structure | FT-IN (active) | applied to all rows |
| Employees | 10 Active | individual CTCs |
| CTCs | 500000, 600000, 720000, ... | per-employee values via spreadsheet paste / CSV |
| One bad row | employee with status Inactive | should fail that row only |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open Bulk Assign (desktop), select FT-IN, paste 10 employee+CTC pairs into the spreadsheet UI (or upload CSV). | Each row shows the employee, CTC, and a derived breakdown preview; rows validate inline. |
| 2 | Include one row for an Inactive employee. | That row flagged invalid (employee not Active) before submit. |
| 3 | Submit bulk assign; observe `POST /api/v1/payroll/employees/salary/bulk`. | A progress indicator advances to completion; response reports per-row success/failure. |
| 4 | Verify results. | The 9 valid employees each have an assignment with their individual CTC and `employee_salary_component` rows stamped `tenant_id`=acme; the invalid row failed without affecting others (partial success contract documented). |
| 5 | Re-run with a row whose component sum violates +/-1 tolerance. | Only that row rejected with sum-mismatch (FR-6); others succeed. |
| 6 | Verify revision history. | A revision row is recorded for each successfully assigned employee. |

## 6. Postconditions
- All valid selected employees have individual-CTC assignments; invalid rows reported and skipped; progress reported to 100%.

# TC-PAY-001-01: HR creates a salary component, creates a salary structure, links components and activates it (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1, AC-3, AC-4 and FR-5: an authenticated HR Officer with `Payroll.*.All` creates a salary component ("Basic Salary", type=Earning, calculation=Fixed) that is stamped with `tenant_id` and appears only in this tenant's component list (AC-1); creates a salary structure ("Full-Time India") (AC-3, FR-2); links multiple components to the structure with per-component overrides and processing order (AC-3, FR-3); reorders components (AC-4); and successfully marks the structure active because it contains at least one earning (FR-5).

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-1, AC-3, AC-4
- Functional Requirements: FR-1, FR-2, FR-3, FR-5
- Business Rules: BR-1, BR-2
- Data Requirements: S7 (salary_component, salary_structure, salary_structure_component; numeric(18,2); tenant_id FK; audit fields)

## 3. Preconditions
- Tenant "acme" exists with status Active or Trial, subdomain `acme.yourhrm.com`, and the Payroll module enabled in its subscription plan.
- At least one active employee exists in acme (for context, not required for configuration).
- HR Officer "Maya Singh" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Payroll.*.All`.
- No salary component with code `BASIC` and no structure with code `FT-IN` currently exist in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Subdomain | acme.yourhrm.com | Active tenant |
| User | Maya Singh (HR Officer) | Has Payroll.*.All |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to `https://acme.yourhrm.com/payroll/settings/components`, click "New Component" | A slide-over panel opens with fields name, code, type, calculation method, default value/percentage, taxability, is_active. |
| 2 | Fill Basic Salary (BASIC, Earning, Fixed, 50000.00) and Save; observe `POST /api/v1/payroll/components` | Request carries `X-Tenant-Subdomain: acme` + bearer; response 201 Created; body has `id` (UUID), `tenant_id` = acme, `default_value` = 50000.00, `created_by` = Maya Singh, audit timestamps. |
| 3 | Inspect the component list | "Basic Salary" appears in acme's list only (AC-1). Verify the persisted `salary_component` row has `tenant_id` = acme and `default_value` stored as numeric(18,2). |
| 4 | Create components HRA (PercentageOfBasic 40) and PF (Formula `basic * 0.12`) the same way | Both created 201 with acme `tenant_id`; PF stores `formula_expression`. |
| 5 | Navigate to `/payroll/settings/structures`, click "New Structure", fill Full-Time India (FT-IN, effective_from 2026-07-01) and Save; observe `POST /api/v1/payroll/structures` | Response 201; body has `id`, `tenant_id` = acme, `is_active` = false (no earning linked yet). |
| 6 | Open the structure, add components BASIC (order 1), HRA (order 2), PF (order 3) with overrides; observe `POST .../structures/{id}/components` | Each link persisted in `salary_structure_component` with `processing_order`, `tenant_id` = acme; the structure's component list shows the inline-editable table. |
| 7 | Drag PF above HRA (reorder) and confirm; observe the reorder request | Processing order persists: BASIC=1, PF=2, HRA=3 (AC-4); reload confirms order survives. |
| 8 | Click "Activate" on the structure; observe `PATCH .../structures/{id}` (is_active=true) | Response 200; `is_active` = true. Because the structure contains an earning (BASIC), activation is allowed (FR-5). |
| 9 | Verify persisted rows | One `salary_structure` row (active) and three `salary_structure_component` rows for acme, all stamped `tenant_id` = acme. |

## 6. Postconditions
- Three salary components (BASIC, HRA, PF) and one active salary structure (FT-IN) with three linked components exist in acme, all tenant-scoped.

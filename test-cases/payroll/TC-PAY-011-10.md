# TC-PAY-011-10: Bulk distribution for 5,000 employees completes within 30 minutes, rate-limited to the configured SMTP cap (e.g. 100/min) without exceeding it (performance / NFR-1 / FR-6)

## 1. Test Objective
Verify NFR-1 and FR-6: bulk payslip email distribution for 5,000 employees completes within 30 minutes while honoring the tenant-configurable SMTP rate limit (e.g. 100 emails/minute) -- the job must throttle so it never bursts past the configured cap, yet still finishes within the SLA. The rate limit is read from tenant config and the job paces sends accordingly; all 5,000 deliveries are attempted and logged.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-1
- Functional Requirements: FR-2, FR-5, FR-6 (rate limit)
- Non-Functional Requirements: NFR-1 (5,000 <= 30 min)
- Note: requires a seeded performance environment + a test SMTP relay that records per-minute throughput.

## 3. Preconditions
- Tenant "acme" Finalized run R with 5,000 employees, all with emails + generated PDFs.
- Tenant SMTP rate limit configured (e.g. 100 emails/min); test SMTP relay accepts mail and records arrival timestamps.
- Seeded performance environment; HR Officer authenticated with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Employees | 5,000 | NFR-1 scale |
| Rate limit | 100/min (tenant-configured) | FR-6 |
| SLA | <= 30 minutes | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Trigger Send Payslips on the 5,000-employee run R; start the timer. | Job enqueued; processing begins; the run summary shows live progress (sent/total). |
| 2 | Monitor per-minute send throughput at the SMTP relay (FR-6). | Throughput never exceeds the configured cap (~100/min) in any rolling minute window; the job paces/throttles rather than bursting. |
| 3 | Measure end-to-end completion time (NFR-1). | All 5,000 deliveries attempted and completed within <= 30 minutes from job start. |
| 4 | Verify `payslip_email_log` completeness. | 5,000 log rows written with terminal status (Sent/Failed/Skipped as applicable); no employee left perpetually Queued. |
| 5 | Re-run with the rate limit raised/lowered in tenant config. | Pacing follows the new configured limit (confirms FR-6 is tenant-configurable, not hard-coded), still within SLA at the higher limit. |

## 6. Postconditions
- 5,000 emails distributed within 30 minutes without exceeding the configured SMTP rate limit; all deliveries logged with a terminal status.

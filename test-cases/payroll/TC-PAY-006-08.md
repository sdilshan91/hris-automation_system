# TC-PAY-006-08: Authorization -- only Tenant Admin / Payroll.*.All may configure statutory rules; others 403, unauthenticated 401

## 1. Test Objective
Verify the authorization model for statutory configuration across AC-1..AC-5: creating/editing/deleting income-tax slabs, social-security rules, exemptions, and fiscal-year versions requires the Tenant Admin role or `Payroll.*.All` permission. Users without it (e.g. plain Employee, an HR role lacking Payroll.*.All, Payroll.Read-only) receive 403; unauthenticated requests receive 401. The Test Calculation (FR-5) read-only preview follows the same configure-permission gate.

## 2. Related Requirements
- User Story: US-PAY-006
- Acceptance Criteria: AC-1, AC-2, AC-3, AC-4, AC-5
- Functional Requirements: FR-1, FR-2, FR-3, FR-7, FR-8
- Non-Functional Requirements: NFR-4 (audit of changes)

## 3. Preconditions
- Tenant "acme" Active, Payroll enabled.
- Users: Tenant Admin (allowed), `Payroll.*.All` holder (allowed), plain Employee (denied), HR role WITHOUT Payroll.*.All (denied), unauthenticated client.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Allowed roles | Tenant Admin, Payroll.*.All | configure |
| Denied | Employee, HR-without-Payroll.*.All | 403 |
| Unauthenticated | no/expired token | 401 |
| Endpoints | statutory-rules, tax-slabs, social-security-rules, exemptions, test-calc | all gated |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Tenant Admin, create a tax-slab rule. | 200/201 success (AC-1). |
| 2 | As a `Payroll.*.All` holder, create an EPF rule and an exemption. | 200/201 success (AC-2, FR-7). |
| 3 | As a plain Employee, POST/PUT/DELETE any statutory config endpoint. | 403 Forbidden on every write; no record created/changed. |
| 4 | As an HR user lacking Payroll.*.All, attempt to configure slabs and to remove a mandatory component (AC-5). | 403 Forbidden; the mandatory-removal block is also enforced independently. |
| 5 | As an unauthenticated client, call any statutory config endpoint. | 401 Unauthorized; no data returned. |
| 6 | As an allowed user, make a config change and verify the audit record. | The change is audit-logged with before/after values + actor (NFR-4); audit store verification owned by the Audit module (S24) -- the enqueue/record is asserted. |

## 6. Postconditions
- Only authorized roles can configure statutory rules; all denied/unauth attempts leave state unchanged and are logged.

# TC-PAY-012-07: Audit-log immutability -- no UPDATE/DELETE on audit_log via the API; any forged modify/delete attempt -> 405/404/not-exposed; append-only enforced (tamper-proof)

## 1. Test Objective
Verify NFR-4 and BR-2: the application exposes NO endpoint to modify or delete audit records. Direct attempts to UPDATE or DELETE an `audit_log` entry through the API return 405 Method Not Allowed / 404 Not Found (endpoint not exposed), and the audit store is append-only and tamper-proof.

## 2. Related Requirements
- User Story: US-PAY-012
- Acceptance Criteria: AC-3, AC-4
- Functional Requirements: FR-2, FR-3
- Non-Functional Requirements: NFR-4 (immutable -- no UPDATE/DELETE via app)
- Business Rules: BR-2 (immutable, tamper-proof, no modify/delete API)

## 3. Preconditions
- Tenant "acme" Active; at least one payroll audit entry A exists with a known audit_log_id.
- Tenant Admin authenticated with audit-view permission; a security tester with API access.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Target | audit_log entry A (known id) | immutability target |
| Methods probed | PUT/PATCH/DELETE on audit routes | NFR-4, BR-2 |
| Expected | 405 / 404 / route not exposed | BR-2 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enumerate the audit API surface (OpenAPI/Swagger). | Only read endpoints (list/filter/export) exist; there is NO create/update/delete endpoint for audit entries (BR-2). |
| 2 | Send `PUT /api/v1/.../audit-log/{A}` and `PATCH` with a modified `after` payload. | 405 Method Not Allowed (route exists read-only) or 404 (route not exposed); entry A is unchanged. |
| 3 | Send `DELETE /api/v1/.../audit-log/{A}`. | 405 / 404; entry A still present and identical. |
| 4 | Attempt to modify an entry indirectly (e.g. by re-running the originating operation). | A NEW append-only entry is written for the new operation; the original entry A is never overwritten (append-only, BR-2). |
| 5 | Re-read entry A after all attempts. | A is byte-identical to its original state (timestamp/actor/before/after/ip/user_agent unchanged); tamper-proof (NFR-4). |
| 6 | Confirm the response leaks no internal detail. | Error responses are generic (405/404), no stack trace / SQL / schema disclosure. |

## 6. Postconditions
- No audit entry can be modified or deleted via the API; the audit_log remains append-only and intact.

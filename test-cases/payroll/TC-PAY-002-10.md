# TC-PAY-002-10: CTC/override/reason fields resist XSS and SQL injection; PII not leaked

## 1. Test Objective
Verify input sanitization on salary-assignment inputs: the revision `reason` free-text field, CSV/spreadsheet bulk paste, and CTC/override numeric fields resist XSS and SQL injection, and malformed numeric input is rejected rather than coerced. Salary data (PII) is not exposed in error messages or logs.

## 2. Related Requirements
- User Story: US-PAY-002
- Functional Requirements: FR-1, FR-4, FR-5
- Non-Functional: NFR-4, NFR-5 (PII at rest)
- Data Requirements: S7

## 3. Preconditions
- FT-IN active structure; Ravi Kumar Active; HR authenticated with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| reason (XSS) | `<script>alert('x')</script>` | must be neutralized |
| reason (SQLi) | `'; DROP TABLE employee_salary_component;--` | must be parameterized/escaped |
| CTC (malformed) | `600000 OR 1=1` / `NaN` / `1e9` | rejected, not coerced |
| CSV cell (formula injection) | `=cmd|'/c calc'!A1` | neutralized on export/import |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Save a revision with reason = `<script>alert('x')</script>`. | Stored escaped/sanitized; the timeline renders it as inert text, no script execution. |
| 2 | Save a revision with reason containing a SQL injection payload. | Persisted as literal text via parameterized query; tables intact; no error leaking schema. |
| 3 | Submit CTC = `600000 OR 1=1`, `NaN`, and `1e9` string. | Each rejected 400 with a validation message; no coercion to an unintended numeric. |
| 4 | Bulk CSV upload containing a formula-injection cell. | Cell treated as data, not a formula; CSV template/export prefixes risky cells to prevent client-side execution. |
| 5 | Inspect error responses and server logs for a failed assign. | No raw salary amounts / employee PII echoed in client error bodies or unmasked logs (NFR-5). |

## 6. Postconditions
- Injection payloads neutralized; malformed numerics rejected; no PII leakage in errors/logs.

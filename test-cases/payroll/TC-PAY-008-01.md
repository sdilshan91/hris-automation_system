# TC-PAY-008-01: Submit for Approval -> AwaitingApproval + approver notified; Approve -> Approved + HR notified; Finalize -> Finalized + immutable (happy path)

## 1. Test Objective
Verify the full single-step approval lifecycle (AC-1, AC-2, AC-5, FR-1, FR-7, FR-8): HR reviews a ReviewPending run summary and clicks "Submit for Approval" -- a workflow instance is created, status -> AwaitingApproval, and the designated approver receives an in-app + email notification (AC-1); the Finance Manager reviews and clicks "Approve" -- status -> Approved and HR is notified (AC-2); HR clicks "Finalize" -- status -> Finalized, all payslip records become immutable, and the run is ready for bank advice + payslip distribution (AC-5, FR-8). Each action writes a `payroll_approval_history` row (FR-7).

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-1, AC-2, AC-5
- Functional Requirements: FR-1, FR-2, FR-7, FR-8
- Non-Functional Requirements: NFR-1, NFR-5
- Business Rules: BR-1, BR-2, BR-4, BR-6
- Data Requirements: S7 (payroll_approval_history)

## 3. Preconditions
- Tenant "acme" Active, subdomain `acme.yourhrm.com`, Payroll module enabled.
- A payroll run for June 2026 exists in ReviewPending status (US-PAY-003) with slips generated (US-PAY-004).
- HR user `hr1` authenticated in acme (initiator; not an approver of this run).
- Finance Manager `fin1` has `Payroll.Approve` permission; default workflow = HR submits -> Finance approves (BR-2).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As hr1, open the run; review the summary card (total gross/deductions/net/statutory + employee count + variance vs previous month); click "Submit for Approval". | A workflow instance is created (default single Finance step); run status -> AwaitingApproval; a `payroll_approval_history` row persists (action=Submitted, step_number=1, actor=hr1, acted_at, ip_address, tenant_id=acme) (AC-1, FR-1, FR-7). |
| 2 | Confirm fin1 is notified. | An in-app notification + email are ENQUEUED to fin1 within 30s (AC-1, NFR-1); the run appears in fin1's "Pending Approvals" queue with a badge count. |
| 3 | As fin1, open the approval review page, review summary + employee list, click "Approve" (optional comment). | Run status -> Approved; a history row persists (action=Approved, actor=fin1, acted_at, ip, comments); HR (hr1) is notified (in-app + email enqueued) (AC-2, FR-7). The "Finalize" action becomes available. |
| 4 | As hr1, click "Finalize". | Run status -> Finalized; all `payroll_slip` records for the run are locked/immutable (FR-8); a history row persists (action=... finalize); the run is flagged ready for bank advice + payslip distribution (AC-5). |
| 5 | Attempt to edit any slip / re-run / re-open the Finalized run. | Rejected -- records are immutable; no mutation succeeds (FR-8, BR-6). |
| 6 | Open the payroll run detail timeline. | The approval history timeline shows Submitted (hr1) -> Approved (fin1) -> Finalized in order with timestamps + actors (FR-7). |

## 6. Postconditions
- The June 2026 run is Finalized and immutable; a complete approval history (Submitted/Approved/Finalize) exists for acme; HR + approver notified at each step.

# TC-PAY-004-05: Failed PDF render -> pdf_status=Failed with logged error, run continues for other employees, and the failure is retryable individually (FR-8)

## 1. Test Objective
Verify FR-7/FR-8: when one employee's PDF render fails (e.g. corrupt/missing logo asset, template error, or a transient blob-write error), that slip is marked `pdf_status=Failed` with the error detail logged, the batch CONTINUES rendering the remaining employees (one bad slip does not abort the whole run), and HR can RETRY just the failed slip individually -- a successful retry flips it to Generated and stores the PDF. No partial/zero-byte PDF is left at the failed slip's path.

## 2. Related Requirements
- User Story: US-PAY-004
- Acceptance Criteria: AC-1 (per-employee generation)
- Functional Requirements: FR-7 (status per slip), FR-8 (failures logged + retryable individually)
- Data Requirements: S7 (pdf_status Failed)

## 3. Preconditions
- Run R (acme, May 2026, ReviewPending) with 3 employees.
- A fault injected for EMP-002 only (e.g. its branding logo asset is unreadable, or first blob write throws).
- HR Maya with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Faulted employee | EMP-002 | render throws |
| Healthy employees | EMP-001, EMP-003 | render OK |
| Expected statuses | Generated / Failed / Generated | FR-7 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run "Generate Payslips" with the EMP-002 fault active. | Job processes all 3; EMP-001 + EMP-003 -> Generated PDFs stored; EMP-002 render fails. |
| 2 | Verify EMP-002 slip state (FR-7/FR-8). | `pdf_status=Failed`; error detail logged (correlation id + exception message); no zero-byte/partial PDF at EMP-002's path; `pdf_generated_at` null or marked failed. |
| 3 | Verify batch did not abort (FR-8). | EMP-001 + EMP-003 are Generated despite EMP-002 failing; run summary shows 2 generated / 1 failed; status bar reflects the failed count. |
| 4 | Remove the fault; on EMP-002's row click "Retry" (individual retry, FR-8). | Only EMP-002 is re-rendered (EMP-001/003 untouched); EMP-002 -> Generated; PDF stored at `{acmeTenantId}/payroll/{R}/{EMP-002}.pdf`; `pdf_generated_at` set. |
| 5 | Verify the status bar after retry. | "3 / 3 generated"; failed count -> 0. |
| 6 | Re-inject the fault and retry again. | Retry returns Failed again with a fresh logged error; idempotent (no duplicate files, no double-counting). |

## 6. Postconditions
- A single render failure is isolated, logged, and individually retryable; the batch completes for healthy employees.

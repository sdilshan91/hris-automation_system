# TC-PAY-008-04: Maker-checker -- the initiator cannot approve their own run; small-team exception relaxes the rule when the tenant has < 2 HR/Finance users

## 1. Test Objective
Verify BR-5 / FR-1: the maker-checker principle blocks the user who initiated/submitted a payroll run from approving that same run, EXCEPT when the tenant has fewer than 2 HR/Finance users (or the tenant has explicitly enabled the small-team relaxation), in which case the initiator may self-approve.

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-2
- Functional Requirements: FR-1, FR-2
- Business Rules: BR-5
- Test Hints: maker-checker unit test

## 3. Preconditions
- Tenant "acme": hr1 (Payroll.Run + Payroll.Approve), fin1 (Payroll.Approve), plus other HR/Finance users (>= 2). Maker-checker enforced (default).
- Tenant "solo": a single HR user soloHR holding both Payroll.Run + Payroll.Approve, < 2 HR/Finance users; small-team exception active.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Initiator | hr1 (also has Payroll.Approve) | submitted the run |
| Different approver | fin1 | allowed |
| Solo tenant | solo / soloHR | < 2 users, exception |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In acme, hr1 submits a run for approval (AwaitingApproval), then hr1 attempts to Approve that same run. | Rejected (403/422) -- the initiator cannot approve their own run; no status change; a maker-checker violation message is shown (BR-5). |
| 2 | In acme, fin1 (a different authorized approver) approves the same run. | Approved succeeds -- a different approver satisfies maker-checker (BR-5, AC-2). |
| 3 | Confirm the rejection in step 1 was evaluated on the SUBMITTER identity, not merely the run creator. | The block is keyed to the actor who submitted the workflow (the "maker"); any other Payroll.Approve user may act (BR-5). |
| 4 | In tenant "solo", soloHR submits a run and then attempts to Approve it. | Allowed -- the small-team exception (< 2 HR/Finance users) relaxes maker-checker; the run is Approved by the same user; the self-approval is still audited (action=Approved, actor=soloHR) (BR-5, FR-7). |
| 5 | Add a 2nd HR/Finance user to "solo" (now >= 2 / exception disabled), submit a fresh run as soloHR, attempt self-approve. | Now blocked -- once the tenant is no longer a small team, maker-checker re-applies (BR-5). |

## 6. Postconditions
- Initiators cannot self-approve in normal tenants; the documented small-team exception is the only path to self-approval and is fully audited.

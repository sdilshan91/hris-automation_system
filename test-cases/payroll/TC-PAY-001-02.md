# TC-PAY-001-02: Edit a salary component updates the definition for future runs; historical payslips unchanged (alternative path)

## 1. Test Objective
Verify AC-2 / FR-1: HR can edit a salary component's name, type, or calculation method; the updated definition is used by all future payroll runs, while historical payslips that already used the prior definition remain unchanged. The write is audit-logged (NFR-5) and the component list cache is invalidated (NFR-1).

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-2
- Functional Requirements: FR-1
- Non-Functional Requirements: NFR-1, NFR-5
- Business Rules: BR-7 (type cannot change after use in a finalized payroll run)

## 3. Preconditions
- Tenant "acme" has an existing component "Transport Allowance" (code TA, Earning, Fixed, 3000.00) that has NOT yet been used in a finalized payroll run.
- HR Officer authenticated in acme with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Component code | TA | Existing |
| New name | Transport & Travel Allowance | Edit |
| New default value | 3500.00 | numeric(18,2) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open component TA in the edit slide-over, change name and default value to 3500.00, Save; observe `PUT /api/v1/payroll/components/{id}` | Response 200; body reflects the new name and `default_value` = 3500.00. |
| 2 | Inspect the audit trail for this component | An update audit entry exists with actor, timestamp, before/after values (NFR-5). |
| 3 | Re-fetch the component list immediately after the write | The list returns the updated value (cache invalidated on write per NFR-1; no stale read). |
| 4 | (Conditional on Payroll Run module) Inspect a historical payslip that previously used TA at 3000.00 | The historical payslip still shows 3000.00 unchanged; only future runs use 3500.00 (AC-2). Marked CONDITIONAL on the Payroll Run/Payslip story existing. |
| 5 | Attempt to change `type` of a component that HAS been used in a finalized run (BR-7) | The system rejects the type change with a validation error; CONDITIONAL on a finalized run existing. |

## 6. Postconditions
- Component TA reflects the edited definition; historical payslips are unchanged; the change is audit-logged.

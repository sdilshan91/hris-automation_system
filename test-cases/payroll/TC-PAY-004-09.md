# TC-PAY-004-09: Generate 5,000 payslip PDFs in <= 5 minutes via parallel batch rendering with configurable concurrency (NFR-1, NFR-3)

## 1. Test Objective
Verify NFR-1 and NFR-3: PDF generation for a 5,000-employee run completes within 5 minutes (as part of the overall 10-minute payroll NFR), and rendering is parallelized in batches with a CONFIGURABLE concurrency (e.g. 10 concurrent renders). Confirm the worker bounds concurrency (does not spawn 5,000 unbounded renders that exhaust CPU/memory), all 5,000 PDFs land at their correct tenant-scoped paths, and per-slip status is recorded. Requires a seeded load environment.

## 2. Related Requirements
- User Story: US-PAY-004
- Acceptance Criteria: AC-1
- Non-Functional Requirements: NFR-1 (5,000 < 5 min), NFR-3 (parallel batch, configurable concurrency)
- Functional Requirements: FR-4 (Hangfire background), FR-5 (storage)

## 3. Preconditions
- Seeded tenant "loadtenant" with a ReviewPending run R5000 of 5,000 employees, each with a payroll_slip.
- Hangfire worker on a representative server; concurrency configured (e.g. 10); blob storage available.
- Test runs on a dedicated/representative environment (not CI default).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Employee count | 5,000 | NFR-1 |
| SLA | <= 5 minutes | NFR-1 |
| Concurrency | configurable, e.g. 10 | NFR-3 |
| Path pattern | {loadtenantId}/payroll/{R5000}/{EMP}.pdf | FR-5 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Trigger "Generate Payslips" on R5000; record start time. | Job starts; status bar shows incremental progress (e.g. "1,250 / 5,000"). |
| 2 | Monitor concurrency during the run (NFR-3). | At most ~N (configured, e.g. 10) renders execute concurrently; concurrency is bounded by the configured value, not unbounded; CPU/memory stay within limits. |
| 3 | Wait for completion; record end time (NFR-1). | All 5,000 PDFs generated; elapsed time <= 5 minutes (P95 over repeated runs). |
| 4 | Verify all outputs landed correctly. | Exactly 5,000 PDFs under `{loadtenantId}/payroll/{R5000}/`; 5,000 slips marked Generated with sizes recorded; zero Failed (or failed ones retryable per FR-8). |
| 5 | Re-run with concurrency changed (e.g. 5 vs 20). | Throughput scales with concurrency; the setting is honored (confirms it is configurable, NFR-3). |
| 6 | Verify each PDF still <= 200KB at scale (NFR-2 cross-check). | Size budget holds across 5,000 renders. |

## 6. Postconditions
- 5,000 PDFs generated within SLA using bounded, configurable parallelism; all stored tenant-scoped.

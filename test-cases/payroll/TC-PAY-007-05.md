# TC-PAY-007-05: Recurring adjustment auto-creates the correct count of future pending records; cancel remaining occurrences works (boundary on recurrence count)

## 1. Test Objective
Verify FR-5 / BR-6 / FR-6: a recurring adjustment (e.g. a 12-month loan deduction) auto-creates the correct number of future pending adjustment records up-front, one per period through the recurrence end; HR can cancel remaining (not-yet-applied) occurrences at any time; on employee separation remaining pending occurrences auto-cancel.

## 2. Related Requirements
- User Story: US-PAY-007
- Functional Requirements: FR-5, FR-6
- Business Rules: BR-6 (recurring auto-creates pending per future period; HR can cancel remaining)
- Data Requirements: S7 (is_recurring, recurrence_end_month/year, status)

## 3. Preconditions
- Tenant "acme"; user with `Payroll.*.All`; Employee X active structure.
- Current period = June 2026.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Recurring deduction | type=Deduction, amount=2000.00, start=2026-07, is_recurring=true, recurrence_end=2027-06 | 12 occurrences (Jul 2026..Jun 2027) |
| Single-month edge | is_recurring=true, start=2026-07, recurrence_end=2026-07 | exactly 1 occurrence |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a recurring Deduction of 2,000/month for Employee X, July 2026 through June 2027, is_recurring=true. | Exactly 12 pending `payroll_adjustment` records are created (one per month Jul 2026..Jun 2027), all status=Pending, each with the correct applicable_pay_month/year (FR-5, BR-6). |
| 2 | Verify the recurrence preview shown before save listed all 12 affected periods. | Preview count == 12, matching the persisted records (FR-5 UI). |
| 3 | Boundary: create a recurring adjustment with start==end (single month). | Exactly 1 pending record is created (no zero, no off-by-one) (BR-6 boundary). |
| 4 | Cancel the remaining occurrences of the 12-month series after, say, 3 have been applied. | The 9 still-Pending occurrences move to status=Cancelled; the 3 Applied ones are untouched (BR-6, FR-6). |
| 5 | Simulate Employee X separation while occurrences remain Pending. | Remaining Pending occurrences are auto-cancelled (status=Cancelled); Applied ones remain (assumption in story S10). |
| 6 | Boundary: attempt recurrence_end earlier than start. | Rejected with a validation error (end must be >= start). |

## 6. Postconditions
- The recurring series materialized the exact number of future pending records; cancellation/auto-cancel left applied records intact.

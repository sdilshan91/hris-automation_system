# TC-PAY-007-12: Adjustments table, New-Adjustment slide-over, bulk-CSV drag-drop, and recurrence preview meet WCAG 2.1 AA + responsive (360-1920); bulk desktop-only

## 1. Test Objective
Verify the UI/UX (story S8) for the Payroll Adjustments surface meets WCAG 2.1 AA: the database-style adjustments table with filters and status badges, the New-Adjustment slide-over form (employee typeahead, type, amount, period, description, file upload), the bulk CSV drag-and-drop area with validation preview, and the recurring-adjustment future-periods preview are all keyboard operable, screen-reader friendly, and colour-contrast compliant; status badges do not rely on colour alone; the layout is responsive 360-1920 with bulk upload gated to desktop.

## 2. Related Requirements
- User Story: US-PAY-007
- Acceptance Criteria: AC-1, AC-3, AC-4
- Functional Requirements: FR-1, FR-2, FR-5
- UI/UX: S8 (table view, slide-over, bulk drop, recurrence preview, Applied tab, mobile)

## 3. Preconditions
- Tenant "acme"; user with `Payroll.*.All`; axe-core / screen reader (NVDA or VoiceOver) available; viewport tooling for 360-1920.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Sample adjustments | mix of Pending/Applied/Cancelled, all 4 types | status badges + Applied tab |
| Recurring config | 12-month series | preview list |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Tab through the adjustments table: filters (Status/Type/Period/Employee), sortable columns, status badges, row actions. | All controls reachable + operable by keyboard; sort/filter state announced; status badges convey state via text/icon, not colour alone (WCAG 1.4.1, 2.1.1). |
| 2 | Open "New Adjustment" slide-over via keyboard; complete the form (employee typeahead, type, amount, period, description, file upload). | Focus moves into the panel and is trapped; every field has a programmatic label; typeahead results are announced (ARIA listbox); Esc closes and returns focus to the trigger (WCAG 2.4.3, 4.1.2). |
| 3 | Trigger validation errors (missing amount, bad file type). | Errors are associated with fields (aria-describedby) and announced to the screen reader (WCAG 3.3.1). |
| 4 | Operate the bulk CSV drag-and-drop area and its validation preview with keyboard only. | A keyboard-accessible file picker alternative exists; the preview table is navigable and per-row errors announced (WCAG 2.1.1). |
| 5 | Open the recurring-adjustment preview of future periods. | The list of affected periods is presented as accessible text and announced; count matches the configured series (FR-5). |
| 6 | Run axe-core on the table, slide-over, and preview. | Zero serious/critical violations; contrast >= 4.5:1 for text (WCAG 1.4.3). |
| 7 | Resize 360px -> 1920px; on 360px attempt bulk upload. | Individual creation works at 360px; the table reflows/scrolls; bulk upload is desktop-only and clearly indicated as unavailable on mobile (S8). |

## 6. Postconditions
- The adjustments UI is WCAG 2.1 AA compliant and responsive; bulk upload gated to desktop.

# TC-PAY-008-09: Authorization -- only Payroll.Approve may approve/reject/return; only the run owner role may submit/finalize; others 403, unauthenticated 401

## 1. Test Objective
Verify FR-1 / FR-7 / NFR-3 authorization: the Approve / Reject / Return-to-HR actions require the `Payroll.Approve` permission; Submit-for-Approval and Finalize require the payroll-run role (Payroll.Run / Payroll.*.All); a user lacking the required permission receives 403; an unauthenticated request receives 401. Authorization is enforced server-side regardless of UI affordances.

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-1, AC-2, AC-3, AC-5
- Functional Requirements: FR-1, FR-7
- Non-Functional Requirements: NFR-3
- Business Rules: BR-5

## 3. Preconditions
- Tenant acme users: hr1 (Payroll.Run), fin1 (Payroll.Approve), emp1 (Employee/Self only, no payroll perms).
- A June 2026 run available in the relevant statuses (ReviewPending / AwaitingApproval / Approved).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Approve/Reject/Return | requires Payroll.Approve | fin1 only |
| Submit/Finalize | requires Payroll.Run / Payroll.*.All | hr1 |
| No-perm user | emp1 | expects 403 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As emp1 (no payroll perms), call Submit / Approve / Reject / Return / Finalize. | Every call -> 403 Forbidden; no status change; no data leaked (FR-1, NFR-3). |
| 2 | As hr1 (Payroll.Run, NOT Payroll.Approve), call Approve / Reject / Return on an AwaitingApproval run. | 403 Forbidden -- approval actions require Payroll.Approve (FR-1). |
| 3 | As fin1 (Payroll.Approve), call Approve on the AwaitingApproval run. | Succeeds -- correct permission (subject to maker-checker BR-5, covered in TC-PAY-008-04) (FR-1, AC-2). |
| 4 | As fin1 (Payroll.Approve, no Payroll.Run), attempt Submit / Finalize. | 403 Forbidden -- submit/finalize require the run role, not the approve role (FR-1). |
| 5 | As hr1, call Submit on ReviewPending and Finalize on Approved. | Both succeed -- correct run-role permission (AC-1, AC-5). |
| 6 | Unauthenticated (no token), call any approval-workflow endpoint. | 401 Unauthorized for all (NFR-3). |

## 6. Postconditions
- Approval actions are gated by Payroll.Approve; submit/finalize by the run role; unauthorized 403; unauthenticated 401 -- enforced server-side.

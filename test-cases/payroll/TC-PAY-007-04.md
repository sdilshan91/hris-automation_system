# TC-PAY-007-04: Adjustment targeting a Finalized period is redirected to the next period as an arrears line referencing the original payslip (Correction/Arrears)

## 1. Test Objective
Verify AC-4 / FR-7 / BR-5 / BR-7: an adjustment cannot be applied to a period that already has a Finalized payroll run; HR creates a correction for the finalized June 2026 period, and the system targets the next available period (July 2026), includes it as an "Arrears" line item, and the record references the original payroll run / payslip being corrected.

## 2. Related Requirements
- User Story: US-PAY-007
- Acceptance Criteria: AC-4
- Functional Requirements: FR-7
- Business Rules: BR-5 (arrears must reference original payslip + show as "Arrears"), BR-7 (cannot apply to a Finalized period -> next period)
- Data Requirements: S7 (reference_payroll_slip_id, applicable_pay_month/year)

## 3. Preconditions
- Tenant "acme"; user with `Payroll.*.All`.
- June 2026 payroll run is FINALIZED; Employee Y has a finalized June payslip with a known error to correct.
- July 2026 has no Finalized run yet.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Original | June 2026 finalized run + Employee Y payslip id `slipJun` | to correct |
| Correction | type=Correction, employee=Y, amount=4000.00, intended period=June 2026 | AC-4 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a Correction adjustment for Employee Y, amount=4000, selecting June 2026 (a Finalized period). | The system detects June is Finalized (BR-7); it does NOT apply to June. HR is informed the correction will be applied to the next available period (July 2026) as arrears. |
| 2 | Confirm/save the correction. | `payroll_adjustment` persists type=Correction, applicable_pay_month=7/applicable_pay_year=2026, status=Pending, `reference_payroll_slip_id`=`slipJun` (FR-7, BR-5). |
| 3 | Inspect the saved record's period and reference fields. | Effective period = July 2026 (not June); reference to the original June run/payslip is stored (FR-7). |
| 4 | Execute the July 2026 payroll run. | The correction appears on Employee Y's July payslip as an "Arrears" line item of 4,000, clearly labelled Arrears and referencing the corrected June payslip (BR-5, AC-4). |
| 5 | Re-verify the finalized June payslip is unchanged. | June payslip is immutable; the correction lives only in July as arrears (BR-7). |

## 6. Postconditions
- The correction is applied in July 2026 as an arrears line referencing the original June payslip; June stays immutable.

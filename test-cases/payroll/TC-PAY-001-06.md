# TC-PAY-001-06: Boundary — numeric(18,2) precision, deduction exceeding gross (BR-4), and pagination max 100 (boundary)

## 1. Test Objective
Verify monetary and pagination edge values: (a) `default_value` / `override_value` are stored and returned as numeric(18,2) — max magnitude accepted, extra decimal places handled per the documented rounding rule, negative/non-numeric rejected; (b) BR-4 — a deduction whose evaluated amount exceeds the gross earnings total is rejected at structure definition; (c) NFR-3 — pagination defaults to 25, honors a requested page size, and caps `page_size` at 100.

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-1, AC-3
- Functional Requirements: FR-1, FR-3
- Non-Functional Requirements: NFR-3
- Business Rules: BR-4

## 3. Preconditions
- Tenant "acme" with `Payroll.*.All` HR Officer authenticated.
- A structure with an earning total (gross) of 50000.00 exists for the BR-4 check.
- acme has > 100 salary components seeded for the pagination check.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Max monetary | 9999999999999999.99 | numeric(18,2) upper bound |
| Over-precision | 1234.5678 | beyond 2 dp — rounded or rejected per rule |
| Negative | -100.00 | invalid for value/percentage |
| Non-numeric | "abc" | invalid |
| Gross earnings | 50000.00 | for BR-4 |
| Deduction attempt | 60000.00 fixed | exceeds gross |
| page_size requested | 100, 101, 0 | cap test |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a component with `default_value` = 9999999999999999.99 | 201; value persisted exactly as numeric(18,2); round-trips without precision loss. |
| 2 | Create a component with `default_value` = 1234.5678 | Value is rounded to 2 dp (1234.57) per the documented rule, OR rejected with a validation error if over-precision is disallowed; behavior is deterministic and documented. |
| 3 | Create a component with `default_value` = -100.00, then with "abc" | Both rejected with 422 validation errors; no row created. |
| 4 | In a structure with gross 50000.00, add a Deduction with evaluated amount 60000.00 and validate | Rejected per BR-4: "deduction exceeds gross earnings". The structure is not saved with an over-deduction. |
| 5 | Add a Deduction evaluating to exactly 50000.00 (equal to gross) | Accepted (boundary equal-to-gross is allowed; net = 0) OR rejected per the documented rule — assert the chosen boundary semantics. |
| 6 | `GET /api/v1/payroll/components` with no page_size | Returns default 25 items with pagination metadata. |
| 7 | `GET .../components?page_size=100` then `?page_size=101` then `?page_size=0` | 100 returns 100; 101 is capped to 100 (not 101) per NFR-3; 0 falls back to default/min. Metadata reports total count + page count. |

## 6. Postconditions
- Monetary precision, BR-4 deduction constraint, and pagination caps behave per spec.

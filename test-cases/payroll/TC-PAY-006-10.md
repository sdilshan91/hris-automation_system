# TC-PAY-006-10: Single-employee tax calculation completes in <10ms; statutory rules cached in Redis (30-min TTL) and the cache is invalidated on any write

## 1. Test Objective
Verify NFR-2 / NFR-1: the statutory tax calculation for a single employee completes in < 10ms (P95) so the 5,000-employee / 10-minute payroll batch SLA holds; and statutory rules are served from a Redis cache with a 30-minute TTL, keyed per tenant, with the cache invalidated on any write (create/update/delete of a rule/slab/social-security/exemption). The isolated, side-effect-free calc service (NFR-5) makes the per-call timing meaningful.

## 2. Related Requirements
- User Story: US-PAY-006
- Acceptance Criteria: AC-1, AC-2, AC-3
- Non-Functional Requirements: NFR-1 (Redis cache + invalidation), NFR-2 (<10ms calc), NFR-5 (isolated service)
- Data Requirements: S7

## 3. Preconditions
- Tenant "acme" with active tax slabs + EPF rule; a seeded performance environment.
- Redis available (cache key e.g. `tenant:{tenantId}:payroll:statutory:{fiscalYear}`).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Calc SLA | < 10ms P95 single employee | NFR-2 |
| Cache TTL | 30 minutes | NFR-1 |
| Cache key | tenant:{tenantId}:payroll:statutory:{fiscalYear} | tenant-scoped |
| Iterations | >= 1,000 calc calls | P95 sample |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm the cache (first resolve loads rules from DB into Redis). | Rules cached under the tenant-scoped key with a 30-minute TTL (NFR-1). |
| 2 | Run >= 1,000 single-employee tax calculations against cached rules; record latency. | P95 calc time < 10ms per employee (NFR-2); rule reads served from Redis, not the DB, on the hot path. |
| 3 | Update a tax slab (write). | The statutory cache for that tenant/FY is invalidated immediately (NFR-1); the next resolve reloads fresh rules. |
| 4 | Recompute after the write. | The new slab values are reflected -- no stale cached rule used post-write. |
| 5 | Verify the cache key is tenant-scoped (cross-check with TC-PAY-ISO-024). | No shared/global statutory cache key; tenant A's rules never served to tenant B from cache. |
| 6 | If no Redis layer exists today, assert direct DB resolution. | CONDITIONAL: calc still meets <10ms with a tenant-filtered query and no shared/global cache key; cache TTL assertion deferred to when Redis is enabled. |

## 6. Postconditions
- No persistent state change beyond the test slab edit (reverted); calc SLA and cache-invalidation-on-write verified.

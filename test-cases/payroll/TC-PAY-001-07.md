# TC-PAY-001-07: Formula validation — rejects circular references and invalid syntax; accepts a valid safe expression (BR-6)

## 1. Test Objective
Verify FR-4 / BR-6: formula-based components are validated for syntax and circular references before saving. A valid safe expression (`basic * 0.12`) is accepted and evaluable; invalid syntax is rejected; a circular reference (component references itself directly or via a cycle) is rejected; and arbitrary/unsafe code is not executed (safe evaluator only).

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-1, AC-3
- Functional Requirements: FR-1, FR-4
- Business Rules: BR-6
- Constraints: S10 (safe subset of math ops; no arbitrary code execution)

## 3. Preconditions
- Tenant "acme" has components BASIC (Earning) and GROSS reference available to the evaluator.
- HR Officer authenticated in acme with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Valid formula | `basic * 0.12` | PF — valid |
| Valid nested | `(basic + hra) * 0.1` | references other components |
| Invalid syntax | `basic * * 0.12` | malformed |
| Invalid token | `basic + unknownComp` | references non-existent component |
| Self-reference | PF formula = `pf + 100` | direct circular |
| Cycle | A = `b + 1`, B = `a + 1` | indirect circular |
| Unsafe | `System.exit(0)` / `import os` | code-execution attempt |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a Formula component with `basic * 0.12` and use the "Test" button against sample values | Accepted; the test evaluates to the expected number (e.g. basic=50000 -> 6000.00); component persists with `formula_expression`. |
| 2 | Create a component with `(basic + hra) * 0.1` | Accepted; resolves referenced components in processing order; evaluates correctly. |
| 3 | Submit `basic * * 0.12` (malformed) | Rejected with a syntax-error validation message; nothing persisted. |
| 4 | Submit `basic + unknownComp` | Rejected: references an unknown component/identifier; nothing persisted. |
| 5 | Set the PF component's own formula to `pf + 100` (direct self-reference) | Rejected: circular reference detected (BR-6). |
| 6 | Create A=`b + 1` and B=`a + 1` (indirect cycle) | The save that closes the cycle is rejected: circular reference detected across the dependency graph. |
| 7 | Submit an unsafe expression (`System.exit(0)`, file/network/`import` constructs) | Rejected by the safe evaluator; NO code execution, no process/file/network side effect (S10). |

## 6. Postconditions
- Only syntactically valid, acyclic, safe formulas are persisted; all others rejected without side effects.

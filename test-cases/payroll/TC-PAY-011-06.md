# TC-PAY-011-06: Selective + bulk re-send -- "Re-send All Failed" re-sends only Failed deliveries; per-employee re-send re-sends a single recipient; newly added email addresses can be sent without re-emailing already-Sent employees (alternative / FR-4)

## 1. Test Objective
Verify FR-4 and FR-5: after an initial distribution that left some deliveries Failed or Skipped, HR can selectively re-send. "Re-send All Failed" targets ONLY the Failed (and not the already-Sent) employees; a per-employee "Re-send" action re-sends a single recipient; an employee who was Skipped for a missing email but now has an address added can be sent without re-emailing the already-Sent employees. Already-Sent employees are not duplicated by a selective re-send.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-3, AC-4
- Functional Requirements: FR-4, FR-5
- Business Rules: BR-6 (summary updates), BR-3 (skipped -> later sendable once email added)

## 3. Preconditions
- Tenant "acme" Finalized run R, prior distribution state: EMP-001=Sent, EMP-002=Failed, EMP-003=Failed, EMP-004=Skipped (no email at send time).
- SMTP relay now accepts all recipients; EMP-004 has now had a valid email added in Core HR.
- HR Officer authenticated with `Payroll.*.All`; SMTP sink captures mail.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| EMP-001 | Sent | must NOT be re-sent by "All Failed" |
| EMP-002, EMP-003 | Failed | targets of "Re-send All Failed" |
| EMP-004 | Skipped, email now added | selectively sendable (FR-4) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Click "Re-send All Failed" on run R. | Only EMP-002 and EMP-003 are re-sent; EMP-001 (Sent) is NOT re-emailed (FR-4). |
| 2 | Verify the SMTP sink after step 1. | Exactly 2 new emails (EMP-002, EMP-003), each with their own PDF; no duplicate to EMP-001. |
| 3 | Verify `payslip_email_log` for EMP-002/003. | Status updated Failed -> Sent; fresh sent_at; retry_count/attempt recorded (FR-5). |
| 4 | Use the per-employee "Re-send" action on a single employee (e.g. EMP-002 again, with explicit confirm). | Only EMP-002 is re-sent; no other recipient affected (selective single re-send, FR-4). |
| 5 | Selectively send to EMP-004 (now has an email) without re-sending the others. | EMP-004 receives the email with their PDF; status Skipped -> Sent; EMP-001/002/003 are not re-emailed (BR-3, FR-4). |
| 6 | View the distribution summary (BR-6). | Sent count increases to include EMP-002/003/004; Failed and Skipped counts drop accordingly. |

## 6. Postconditions
- Failed deliveries re-sent without touching Sent ones; a newly added email lets a previously Skipped employee be sent selectively; summary counts reconcile.

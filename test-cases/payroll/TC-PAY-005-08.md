# TC-PAY-005-08: Payslip data is strictly read-only for employees (no edit/delete) and no other employee's data appears in list / URL / errors (security / BR-4 / BR-5)

## 1. Test Objective
Verify BR-4 / BR-5: the employee payslip surface exposes only read operations -- there is no edit or delete capability, and any attempt to mutate a payslip (PUT/PATCH/DELETE) is rejected (405/403/404, no state change). Additionally, no other employee's salary data is ever exposed via list responses, URLs, autocomplete/search, or error messages.

## 2. Related Requirements
- User Story: US-PAY-005
- Acceptance Criteria: AC-4
- Functional Requirements: FR-5, FR-8
- Business Rules: BR-4, BR-5
- Non-Functional Requirements: NFR-4

## 3. Preconditions
- Tenant "acme"; Employee EMP-001 with `Payroll.Read.Self` authenticated.
- EMP-001 owns a Finalized May 2026 payslip; EMP-002 owns a separate Finalized payslip.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Own payslip | EMP-001 May 2026 | read-only |
| Mutation verbs | PUT / PATCH / DELETE on my-payslips/{id} | must be rejected |
| Other employee | EMP-002 | must not leak |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As EMP-001, send PUT my-payslips/{ownId} with a modified net salary. | 405 Method Not Allowed / 403; payslip unchanged (BR-4). |
| 2 | Send PATCH my-payslips/{ownId} altering a deduction. | Rejected; no mutation persisted. |
| 3 | Send DELETE my-payslips/{ownId}. | Rejected; the payslip still exists and is still listed. |
| 4 | Inspect the My Payslips list payload thoroughly. | Only EMP-001's slips; no EMP-002 ids, names, amounts, or storage paths embedded anywhere in the payload (BR-5). |
| 5 | Inspect URLs/links rendered on the page. | All payslip links reference EMP-001's own slip ids only; no enumerable other-employee ids exposed. |
| 6 | Trigger error responses (invalid id, not-Finalized id, other-employee id). | Error bodies are generic; they never echo another employee's salary data, name, or path (BR-5, NFR-4). |
| 7 | Confirm there is no UI affordance to edit or delete a payslip. | The detail card offers only View / Download PDF; no edit/delete controls exist (BR-4). |

## 6. Postconditions
- Payslips remain immutable from the employee surface; no cross-employee data is exposed by any channel.

# TC-PAY-012-03: Salary component update writes an audit_log entry with timestamp/actor/action="SalaryComponent.Updated"/resource_type/resource_id/before+after JSON/IP/user-agent (golden audit-capture, happy path)

## 1. Test Objective
Verify AC-3 and FR-2/FR-3: when an HR Officer modifies a salary component and saves, the system writes exactly one `audit_log` entry capturing the full required schema -- timestamp, actor (actor_user_id + actor_employee_no), action="SalaryComponent.Updated", resource_type="SalaryComponent", resource_id (the component id), before (old values as JSON), after (new values as JSON), ip_address, user_agent, and trace_id. This is the golden assertion that the before/after JSON reflects the ACTUAL changed fields.

## 2. Related Requirements
- User Story: US-PAY-012
- Acceptance Criteria: AC-3
- Functional Requirements: FR-2, FR-3
- Business Rules: BR-1 (every write logs), BR-6 (point-in-time before/after captured as-was)
- Data Requirements: audit_log (S19.9): tenant_id, timestamp, actor_user_id, actor_employee_no, action, resource_type, resource_id, before(jsonb), after(jsonb), ip_address, user_agent, trace_id

## 3. Preconditions
- Tenant "acme" Active; salary component "HRA" exists with known values (e.g. calculation_type=Percentage, value=20, is_taxable=true) from US-PAY-001.
- HR Officer "Maya Singh" (user_id U1, employee_no E-1001) authenticated in acme with `Payroll.*.All`, from a known client IP/user-agent.
- Audit logging infrastructure operational (S24).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Component | HRA, value 20 -> 25, is_taxable true -> true | before/after delta |
| Expected action | SalaryComponent.Updated | AC-3, FR-3 |
| Expected resource_type | SalaryComponent | FR-3 |
| Expected resource_id | {HRA component id} | FR-3 |
| Actor | actor_user_id=U1, actor_employee_no=E-1001 | FR-3 |
| ip_address / user_agent | server-captured from request | FR-3, BR-5 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Edit component HRA changing value 20 -> 25; save. | The component update succeeds (200); exactly ONE new audit_log row is written for this change (BR-1, no duplicates). |
| 2 | Inspect the audit_log row's identity fields. | tenant_id=acme; timestamp set (server clock, UTC); action="SalaryComponent.Updated"; resource_type="SalaryComponent"; resource_id = HRA's component id. |
| 3 | Inspect the actor fields. | actor_user_id=U1 and actor_employee_no=E-1001 resolved from the JWT/identity -- NOT client-supplied. |
| 4 | Inspect the before JSON. | `before` jsonb captures the prior values (value=20, is_taxable=true, etc.) as they were before the save (BR-6). |
| 5 | Inspect the after JSON. | `after` jsonb captures the new values (value=25, is_taxable=true); the changed field (value) differs, unchanged fields preserved -- the diff is reconstructable. |
| 6 | Inspect ip_address, user_agent, trace_id. | ip_address + user_agent captured from the request headers (server-derived); trace_id present and correlates with the request trace (S19.9). |

## 6. Postconditions
- HRA updated; one audit_log row exists with the full FR-3 schema and accurate before/after JSON.

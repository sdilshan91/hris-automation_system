# TC-PAY-001-12: Accessibility — component slide-over, inline-editable table, and drag-and-drop reorder meet WCAG 2.1 AA (accessibility)

## 1. Test Objective
Verify the Payroll Settings UI meets WCAG 2.1 AA: the slide-over panel for create/edit components, the Notion-style inline-editable component table, the formula editor, and the drag-and-drop processing-order reorder are all keyboard-operable, screen-reader-friendly, and meet color-contrast and responsive requirements (stack < 768px). Drag-and-drop must have a keyboard-accessible alternative (per WCAG 2.5.7 / 2.1.1).

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-1, AC-3, AC-4
- UI/UX Notes: S8 (slide-over panel, inline-editable table, drag-and-drop reorder, formula editor, responsive < 768px, tenant branding)

## 3. Preconditions
- Tenant "acme" Payroll Settings page available with at least 3 components and one structure.
- Axe / Lighthouse accessibility tooling and a screen reader (NVDA/VoiceOver) available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewports | 360px, 768px, 1280px, 1920px | responsive |
| Tooling | axe-core, keyboard only, NVDA | a11y audit |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the "New Component" slide-over using only the keyboard | Focus moves into the panel, is trapped within it, Esc closes and returns focus to the trigger; panel has `role="dialog"`/`aria-modal` and an accessible name. |
| 2 | Tab through all form fields (name, code, type, calculation method, value, taxability, active) | Every control is reachable, labeled (programmatic label/aria), and shows a visible focus ring; required/invalid states announced. |
| 3 | Run axe-core on the slide-over and the inline component table | Zero serious/critical violations; the inline-editable cells expose proper roles and editable state to AT. |
| 4 | Reorder processing order via keyboard (not mouse drag) | A keyboard alternative exists (e.g. move-up/move-down buttons or aria-grabbed pattern); order changes are announced; new order persists (cross-ref AC-4). |
| 5 | Operate the formula editor and "Test" button via keyboard + screen reader | Editor is labeled; syntax errors and test results are announced via an aria-live region. |
| 6 | Check color contrast of status badges, action buttons (tenant primary color), and text | All meet >= 4.5:1 (normal text) / 3:1 (large text & UI components); tenant branding does not break contrast. |
| 7 | Resize to 360px and 768px | Columns stack vertically per S8; component list is horizontally scrollable if needed; no loss of content or function. |

## 6. Postconditions
- The Payroll Settings UI is operable by keyboard and screen reader and meets WCAG 2.1 AA across breakpoints.

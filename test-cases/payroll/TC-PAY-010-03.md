# TC-PAY-010-03: Leave encashment -- HR triggers encashment of 5 eligible days at daily rate 1,000 -> encashment 5,000 added as an earning adjustment to the NEXT payroll run (golden) (happy path)

## 1. Test Objective
Verify AC-3 / FR-5: when HR triggers leave encashment processing for an employee with unused encashable leave, the system computes `eligible_days * daily_rate` and posts that amount as an earning adjustment to the NEXT payroll run (not retroactively into a finalized run). With the golden data (5 eligible days at daily_basic 1,000), `leave_encashment_days = 5` and `leave_encashment_amount = 5,000` appear on the next run's payslip as an additional earning.

## 2. Related Requirements
- User Story: US-PAY-010
- Acceptance Criteria: AC-3
- Functional Requirements: FR-5
- Business Rules: BR-6
- Data Requirements: S7 (payroll_slip.leave_encashment_days / leave_encashment_amount)

## 3. Preconditions
- Tenant "acme" Active; Payroll module enabled.
- Employee Z has 5 days of unused leave on an encashment-ENABLED leave type, and those 5 days EXCEED the carry-forward limit (so they are encashment-eligible, BR-6).
- Z's daily_basic (monthly_basic / total_working_days) = 1,000.
- A future (next) payroll run for acme exists or can be created in a non-finalized state.
- HR user `hr1` authenticated in acme with `Payroll.Run`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Eligible encashment days | 5 | encashable type, over carry-forward (BR-6) |
| daily_rate | 1,000 | monthly_basic / working_days |
| Expected encashment_amount | 5 * 1,000 = 5,000 | golden |
| Target run | NEXT payroll run | FR-5 (not retroactive) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As hr1, open the encashment UI for Z and trigger encashment of 5 eligible days. | System validates the type is encashment-enabled and the days exceed carry-forward (BR-6); 5 days accepted. |
| 2 | Confirm the computed amount. | encashment_amount = 5 * daily_rate = 5 * 1,000 = 5,000 (FR-5). |
| 3 | Inspect where the encashment posts. | It is queued as an earning adjustment for the NEXT payroll run, not injected into any Finalized run (FR-5). |
| 4 | Run the next payroll period for acme. | Z's payslip shows `leave_encashment_days = 5` and `leave_encashment_amount = 5,000` as an additional earning. |
| 5 | Verify gross/net impact. | Gross/net increase by 5,000; payslip totals reconcile (AC-3). |
| 6 | Verify the encashed balance is decremented in the leave module. | Z's encashable balance is reduced by 5 days (no double-encash on a subsequent trigger). |

## 6. Postconditions
- Z's next-run payslip carries a 5,000 leave-encashment earning; encashable balance decremented; nothing posted to a finalized run.

# TC-PAY-002-05: Future-dated assignment does not supersede current until the effective date arrives

## 1. Test Objective
Verify AC-2 and BR-1/BR-2: when an employee already has a current active salary structure and HR assigns a new structure with a FUTURE effective date, the new assignment is saved but the current structure remains active (effective for payroll) until the future date arrives; only one structure is "active now" at any point in time (BR-1). Salary revision history is maintained.

## 2. Related Requirements
- User Story: US-PAY-002
- Acceptance Criteria: AC-2
- Business Rules: BR-1, BR-2, BR-3
- Functional Requirements: FR-1, FR-4
- Data Requirements: S7 (effective_from/effective_to), salary_revision_history

## 3. Preconditions
- Ravi Kumar has a CURRENT active assignment: FT-IN, CTC 600,000, effective_from 2026-01-01, effective_to=null.
- A second active structure "Senior FT" (SR-FT) exists.
- "Today" is 2026-06-15 (current date). HR authenticated with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Current structure | FT-IN, CTC 600,000, eff 2026-01-01 | active now |
| New structure | SR-FT, CTC 840,000 | future |
| New effective_from | 2026-10-01 | future-dated (after today 2026-06-15) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Assign SR-FT to Ravi with CTC 840,000 and effective_from 2026-10-01; confirm `POST .../salary`. | 201 Created; new assignment saved as scheduled/future; current FT-IN assignment is NOT immediately superseded. |
| 2 | Query Ravi's current active structure as of today (2026-06-15). | Returns FT-IN (CTC 600,000) -- the future SR-FT does not affect current payroll (BR-2). |
| 3 | Inspect the future assignment's dates. | SR-FT row has `effective_from`=2026-10-01; FT-IN `effective_to` is set to 2026-09-30 (close boundary), not earlier. |
| 4 | Verify salary_revision_history. | A revision row captures old_structure=FT-IN, new_structure=SR-FT, old_ctc=600000, new_ctc=840000, effective_from=2026-10-01, changed_by, changed_at (BR-3). |
| 5 | Simulate clock at 2026-10-01 (or query "as of 2026-10-01"). | SR-FT is now the current active structure (CTC 840,000); FT-IN closed. |
| 6 | Attempt a second future assignment overlapping SR-FT's date. | System enforces single active structure at a time per effective window (BR-1); overlap handled (supersede or reject per design) with revision history updated. |

## 6. Postconditions
- Current payroll still uses FT-IN until 2026-10-01; SR-FT scheduled; revision history records the transition.

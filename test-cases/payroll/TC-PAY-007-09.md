# TC-PAY-007-09: Authz (Payroll.*.All only) + supporting-document file-type/size validation + XSS/SQLi on description; audit-on-change

## 1. Test Objective
Verify AC-5 / FR-1 / FR-2 / FR-8 / NFR-3 / NFR-5: only users with `Payroll.*.All` (or Tenant Admin) may create/modify/cancel adjustments or upload bulk CSVs; others get 403, unauthenticated 401. Supporting documents are validated for type (PDF/JPG/PNG only) and size (max 5MB). Free-text fields resist XSS/SQL injection. Adjustment create/modify is audit-logged with before/after values.

## 2. Related Requirements
- User Story: US-PAY-007
- Acceptance Criteria: AC-5
- Functional Requirements: FR-1, FR-2, FR-8
- Non-Functional Requirements: NFR-3 (audit before/after), NFR-5 (file type/size)
- Business Rules: BR-1

## 3. Preconditions
- Tenant "acme"; an HR Officer with `Payroll.*.All`; a plain Employee user (Self scope only); an unauthenticated client.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Valid docs | receipt.pdf, scan.jpg, scan.png each <=5MB | accepted (NFR-5) |
| Bad type | malware.exe, sheet.xlsx, note.svg | rejected (NFR-5) |
| Oversize | big.pdf 6MB | rejected (>5MB) |
| Spoofed | renamed exe -> doc.pdf (content not PDF) | rejected (content-type sniff) |
| XSS | description=`<script>alert(1)</script>` | stored/encoded, not executed |
| SQLi | description=`'; DROP TABLE payroll_adjustment;--` | parameterized; no effect |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As the Employee user (no Payroll.*.All), POST a new adjustment and POST a bulk CSV. | Both 403 Forbidden -- adjustments require `Payroll.*.All` (AC-5, FR-1, FR-2). |
| 2 | As unauthenticated, call the adjustments create / list / bulk endpoints. | 401 Unauthorized on all. |
| 3 | As HR (`Payroll.*.All`), create/modify/cancel an adjustment. | Allowed (AC-5). |
| 4 | Upload receipt.pdf, scan.jpg, scan.png each <=5MB. | All accepted; stored at `acme/payroll/adjustments/{id}/` (NFR-5). |
| 5 | Upload malware.exe, sheet.xlsx, note.svg, and big.pdf (6MB). | All rejected with a clear validation error (type not in {PDF,JPG,PNG} / size > 5MB) (NFR-5). |
| 6 | Upload a renamed .exe with a .pdf extension (content not PDF). | Rejected -- validation checks actual content type, not just the extension (NFR-5). |
| 7 | Create an adjustment with XSS in description and another with SQLi in description. | XSS stored encoded and not executed on render; SQLi has no effect (parameterized queries); table intact. |
| 8 | Modify an existing adjustment's amount as HR. | An audit entry records before/after values (amount old->new), actor, timestamp (NFR-3; full audit store owned by the Audit module S24 -- the enqueue/record is asserted). |

## 6. Postconditions
- Only authorized users mutate adjustments; only valid documents stored; injection neutralized; change audited.

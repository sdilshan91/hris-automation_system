# TC-PAY-008-12: Approval queue, split review layout, sticky action bar, and history timeline WCAG 2.1 AA + 360-1920 responsive

## 1. Test Objective
Verify the approval UI meets WCAG 2.1 AA and is responsive 360px-1920px: the "Pending Approvals" queue (cards + badge count), the split approval review layout (left summary card / right employee list), the sticky bottom action bar (Approve / Reject / Return with required-comment fields), the previous-month comparison view with colour-coded variance, and the approval history timeline.

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-1, AC-2, AC-3
- Non-Functional Requirements: (UI/UX S8)
- Functional Requirements: FR-4, FR-5, FR-7, FR-9

## 3. Preconditions
- An approver with pending runs in the queue; a run in AwaitingApproval for review; a run with approval history for the timeline.
- Axe/Lighthouse + screen reader (NVDA/VoiceOver) available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Breakpoints | 360, 768, 1024, 1440, 1920 px | responsive |
| Variance colours | green/amber/red | must not rely on colour alone |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run axe on the Pending Approvals queue, review page, and timeline. | Zero critical/serious violations; the badge count has an accessible name (e.g., "3 payroll runs pending approval"). |
| 2 | Keyboard-only: tab through the queue cards, into the review page, the employee list, and the sticky action bar. | All interactive elements reachable + operable; logical focus order; visible focus ring; the sticky action bar does not trap focus and remains reachable. |
| 3 | Trigger Reject / Return -- required comments field. | The required field is programmatically marked required; a validation error is announced to screen readers (aria-live) and is not conveyed by colour alone. |
| 4 | Inspect the variance comparison (green decrease / amber > 5% / red > 15%). | Variance direction/magnitude is conveyed by text/icon + the colour, not colour alone; text vs background meets >= 4.5:1 contrast (WCAG 1.4.1 / 1.4.3). |
| 5 | Screen-reader read the split review layout + history timeline. | Summary metrics, employee list, and the chronological timeline (action, actor, time, comments) are announced with correct roles/labels and reading order. |
| 6 | Resize 360 -> 1920px. | The split layout reflows (stacked on mobile per S8); the action bar stays usable; no horizontal scroll/clipping/overlap; mobile shows summary + approve/reject (employee drill-down deferred to desktop per S8). |

## 6. Postconditions
- The approval queue, review layout, action bar, comparison view, and history timeline are WCAG 2.1 AA compliant and responsive across 360-1920px.

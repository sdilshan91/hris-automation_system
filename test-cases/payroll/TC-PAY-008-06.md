# TC-PAY-008-06: Multi-step workflow routes sequentially through each step; run is Approved ONLY after every step completes (AC-4, FR-2)

## 1. Test Objective
Verify AC-4 / FR-2 / FR-7: when the tenant configures a multi-step approval workflow (e.g., HR Manager then Finance Director), submitting the run routes the approval sequentially -- step 2's approver is notified only after step 1 is approved -- and the run transitions to Approved ONLY when ALL steps are completed. A rejection at any step stops the chain.

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-2, AC-4
- Functional Requirements: FR-2, FR-7
- Non-Functional Requirements: NFR-1
- Business Rules: BR-2, BR-4
- Data Requirements: S7 (step_number)

## 3. Preconditions
- Tenant "acme" configured with a 2-step sequential workflow: step 1 = HR Manager (hrm1), step 2 = Finance Director (fd1); both hold `Payroll.Approve`.
- A June 2026 run is in ReviewPending, submitted by hr1.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Step 1 | hrm1 (HR Manager) | first approver |
| Step 2 | fd1 (Finance Director) | second approver |
| Run | June 2026 | 2-step workflow |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | hr1 submits the run. | Workflow instance created with 2 steps; status -> AwaitingApproval at step 1; ONLY hrm1 (step 1) is notified -- fd1 is NOT yet notified (AC-4, FR-2). |
| 2 | Confirm fd1 cannot act yet. | fd1 attempting to approve at this point is rejected -- step 2 is not active until step 1 completes (FR-2, BR-4). |
| 3 | hrm1 approves step 1. | A history row persists (step_number=1, action=Approved, actor=hrm1); the workflow advances to step 2; run is STILL AwaitingApproval (not Approved); fd1 is now notified within 30s (AC-4, FR-7, NFR-1). |
| 4 | fd1 approves step 2. | A history row persists (step_number=2, action=Approved, actor=fd1); ALL steps complete -> run status -> Approved; HR notified (AC-2, AC-4). |
| 5 | Re-run the flow but have fd1 (step 2) REJECT after hrm1 approved step 1. | The chain stops -> run -> Rejected; HR notified with the reason; the run is NOT Approved despite step 1 having passed (AC-3, AC-4). |
| 6 | Confirm the history captures the per-step sequence. | The timeline shows step 1 (hrm1) then step 2 (fd1) in order with step_number + timestamps (FR-7). |

## 6. Postconditions
- A 2-step run reaches Approved only after both steps approve; any step rejection stops routing; per-step history is recorded.

# TC-PAY-003-07: Penny reconciliation -- sum(component amounts) == declared net; round half-up to 2 decimals (BR-8)

## 1. Test Objective
Verify BR-8 and FR-5e/f: all monetary calculations round HALF-UP to 2 decimal places (numeric(18,2)), and the slip is internally consistent -- `gross_earnings - total_deductions == net_salary`, AND the sum of `payroll_slip_detail.amount` (signed by component_type: Earning/Reimbursement positive, Deduction/Statutory negative) reconciles exactly to `net_salary` with zero residual penny. This guards against rounding drift across many components.

## 2. Related Requirements
- User Story: US-PAY-003
- Acceptance Criteria: AC-2
- Functional Requirements: FR-5 (e. compute gross/deductions/net; f. persist slip + details)
- Business Rules: BR-8
- Data Requirements: S7 (numeric(18,2); payroll_slip totals vs payroll_slip_detail amounts)

## 3. Preconditions
- Tenant "acme"; employee "Maya" with a structure whose percentage components produce fractional thirds (designed to force rounding), e.g. Basic = 1/3 of a CTC that does not divide evenly.
- Attendance + leave for May 2026 finalized.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Component A (Earning %) | 33.3333% of 100,000.01 | Forces rounding |
| Rounding rule | half-up, 2 dp | BR-8 (e.g. 33333.3367 -> 33333.34) |
| Components count | >= 6 (earnings + deductions + statutory) | Accumulates rounding |
| Expected residual | 0.00 | sum(details) == net |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run payroll for May 2026; inspect Maya's slip + details. | Each detail `amount` is numeric(18,2); a value like 33333.3367 is stored as 33333.34 (half-up), 0.005 -> 0.01. |
| 2 | Compute `gross_earnings - total_deductions`. | Equals `net_salary` exactly (no off-by-a-penny). |
| 3 | Sum signed detail amounts (earnings/reimbursement +, deductions/statutory -). | Sum == `net_salary`; residual = 0.00 (penny reconciliation, BR-8). |
| 4 | Boundary: a component yielding exactly x.xx5 at the 3rd decimal. | Rounds UP (half-up), not banker's rounding (x.xx5 -> x.(xx+1)). |
| 5 | Boundary: numeric(18,2) max magnitude (e.g. very high CTC). | No overflow/precision loss; totals still reconcile. |
| 6 | Negative: attempt to persist a slip where sum(details) != net (fault injection). | The run rejects/flags the inconsistency rather than silently persisting a non-reconciling slip. |

## 6. Postconditions
- Every persisted slip reconciles to the penny under half-up rounding; no rounding drift across components.

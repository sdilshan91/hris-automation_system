# TC-PAY-006-09: Statutory config fields resist XSS + SQL injection; numeric fields enforce numeric(18,2) / numeric(5,2) precision and reject invalid input

## 1. Test Objective
Verify NFR-5-adjacent input hardening + FR-1/FR-2 data constraints: text fields (rule_name, component_name, country_code, fiscal_year) sanitize/reject XSS and SQL-injection payloads and render escaped; rate fields are numeric(5,2) (0-100, two decimals) and slab/ceiling amounts are numeric(18,2). Out-of-range, negative, non-numeric, and over-precision values are rejected with field-level 400 errors -- never silently truncated into a wrong statutory amount.

## 2. Related Requirements
- User Story: US-PAY-006
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-6
- Non-Functional Requirements: NFR-5 (isolated calc service, no side effects)
- Data Requirements: S7 (numeric(5,2) rates, numeric(18,2) amounts)

## 3. Preconditions
- Tenant "acme" Active; user authenticated as Tenant Admin / `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS rule_name | `<script>alert(1)</script>` | escaped, not executed |
| SQLi fiscal_year | `2026-2027'; DROP TABLE tax_slab;--` | parameterised, rejected |
| Rate over 100 | 150.00 | reject (numeric(5,2), 0-100) |
| Negative rate | -5 | reject |
| Over-precision rate | 12.345 | reject or round per documented rule |
| Slab amount over magnitude | 10^17+ | numeric(18,2) bound |
| Non-numeric amount | "abc" | reject |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit a rule with rule_name `<script>alert(1)</script>`. | Stored escaped/sanitized; rendered as inert text in the config UI and version timeline; no script executes. |
| 2 | Submit fiscal_year / country_code with a SQL-injection payload. | Treated as a literal via parameterised queries; rejected by format validation; no SQL executed; tables intact. |
| 3 | Submit an employee_rate of 150.00 and of -5. | Both rejected with a 400 field error (rate must be 0-100, numeric(5,2)). |
| 4 | Submit an over-precision rate 12.345. | Rejected (or rounded to 2 dp per the documented numeric(5,2) rule); never silently truncated to a different value. |
| 5 | Submit a slab amount exceeding numeric(18,2) magnitude and a non-numeric amount "abc". | Both rejected with a 400 field error; no overflow/wrap persisted. |
| 6 | Confirm error responses contain no stack traces, SQL fragments, or other tenants' data. | Errors are generic field-level messages; no internal/PII leakage. |

## 6. Postconditions
- Malicious/invalid statutory input is rejected or neutralized; only valid, precision-correct values are persisted.

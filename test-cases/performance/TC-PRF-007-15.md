# TC-PRF-007-15: Filter / query parameters sanitized (SQLi, injection, type/range validation) on dashboard + export endpoints

## 1. Test Objective
Verify input-validation / injection resistance on the dashboard, drill-down, trend, and export endpoints: filter parameters (cycleId, departmentId, gradeId, locationId, employmentType, n, format, cycleIds) are validated for type/range and are NOT interpolated into raw SQL against the materialized view; malformed, oversized, or injection-laden values are rejected (400) or safely ignored, never executed or reflected.

## 2. Related Requirements
- User Story: US-PRF-007
- Non-Functional Requirements: NFR-2 (defense in depth), NFR-3 (materialized-view query safety)
- Functional Requirements: FR-4 (filters), FR-7 (trend cycle list), FR-8 (export format)

## 3. Preconditions
- Tenant "acme" / cycle "FY26" dashboard available.
- HR Officer "Nadia Khan" authenticated in acme with `Performance.Read.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| SQLi payload | `eng' OR '1'='1` in departmentId | injection probe |
| Bad format | `format=exe` | enum validation |
| Bad N | `n=-1`, `n=99999` | range validation |
| Malformed cycleIds | `FY26,;DROP TABLE` | list parsing |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `GET .../dashboard/overview?departmentId=eng' OR '1'='1` | 400 / safe no-match; the value is parameterized, not interpolated; no SQL error, no extra rows, no cross-department leak. |
| 2 | `GET .../dashboard/export?format=exe` | 400 -- only CSV/XLSX/PDF are accepted (enum validation, FR-8). |
| 3 | `GET .../dashboard/top-performers?n=-1` and `n=99999` | n is range-validated (e.g. 1..100); out-of-range rejected or clamped per a documented rule; no unbounded result set. |
| 4 | `GET .../dashboard/trend?cycleIds=FY26,;DROP TABLE performance_summary;--` | The list is parsed/validated as cycle ids; unknown/malformed entries are rejected; no SQL executed. |
| 5 | Send an oversized / non-UUID id where an id is expected | 400 with a validation error; no stack trace / SQL fragment reflected to the client. |
| 6 | Inspect server logs / DB | No raw-string SQL built from the params; queries are parameterized against the tenant-filtered materialized view (NFR-2/NFR-3). |

## 6. Postconditions
- All dashboard/export filter parameters are validated and parameterized; injection and malformed inputs are rejected without leaking data or errors.

# TC-PRF-007-14: Combined filters + empty-state / boundary handling (no data, single employee, all-filters-applied)

## 1. Test Objective
Verify AC-2 / FR-4 edge behavior: combined filters that narrow to a sparse or empty population are handled gracefully -- the widgets show meaningful empty/zero states rather than errors or stale data; a single-employee slice renders a valid (degenerate) distribution; and a filter combination matching nothing returns explicit empty results, not the org-wide fallback.

## 2. Related Requirements
- User Story: US-PRF-007
- Acceptance Criteria: AC-2
- Functional Requirements: FR-4
- Non-Functional Requirements: NFR-4 (charts render valid states)

## 3. Preconditions
- Tenant "acme" / cycle "FY26" with at least one department/grade/location combination that contains exactly one employee, and at least one combination that contains zero employees.
- HR Officer "Nadia Khan" authenticated in acme with `Performance.Read.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Single-employee slice | Dept=Legal + Grade=G6 | exactly 1 employee |
| Empty slice | Dept=Legal + Grade=G1 | 0 employees |
| All filters applied | cycle+dept+grade+location+type | deepest narrowing |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Apply a filter combination matching exactly one employee | All widgets render the single-employee aggregates: headcount=1, average=that employee's score, a valid one-bar distribution; top/bottom list shows that single employee once (no duplicate/overlap). |
| 2 | Apply a filter combination matching zero employees | Widgets show explicit empty states (e.g. "No data for the selected filters") with headcount=0 and empty charts; NO error and NO silent fallback to the org-wide population (AC-2). |
| 3 | Apply all five filters simultaneously (cycle+dept+grade+location+employment type) | The filters AND-compose correctly server-side; the resulting slice is consistent with the seeded intersection. |
| 4 | Export the empty slice | The export produces an empty/zero report for that slice, not the org-wide data. |
| 5 | Clear filters from an empty state | The dashboard returns to a populated org-wide overview without a stuck empty/loading state. |
| 6 | Filter on a cycle with NO submitted reviews | Completion rate=0%, progress counts=0, distribution empty; widgets degrade gracefully. |

## 6. Postconditions
- Sparse, single-employee, and empty filter combinations render correct empty/degenerate states with no errors and no org-wide fallback.

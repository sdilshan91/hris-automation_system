# TC-PRF-006-07: Immutability -- a recorded sign-off cannot be modified by anyone (incl. HR); editing a locked review is rejected; only system-admin compliance correction (NFR-3, BR-5)

## 1. Test Objective
Verify NFR-3 and BR-5: once a digital signature is recorded it is IMMUTABLE -- no user, including HR with `Performance.Review.All`, can modify or delete a recorded signature; and once both parties have signed (status "Signed Off") the entire review is LOCKED and cannot be edited (ratings, notes, sign-offs) by anyone except a system admin performing a documented compliance correction (BR-5). The review_signoffs table is append-only. Verify the locks are enforced SERVER-SIDE via the API (not just hidden in the UI).

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-3, AC-4
- Non-Functional Requirements: NFR-3 (sign-off records immutable; no user incl. HR can modify)
- Business Rules: BR-5 (locked after both sign off; only system admin compliance correction)
- Data Requirements: S7 (review_signoffs immutable append-only)

## 3. Preconditions
- Tenant "acme", Performance module enabled.
- Liam Carter's review is "Signed Off" (manager + employee signatures recorded) -- see TC-PRF-006-01.
- HR Officer "Nadia Khan" (`Performance.Review.All`) and a system admin account exist in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Review status | Signed Off (locked) | BR-5 |
| Signoff row | Employee Liam Carter, <timestamp>, <IP> | NFR-3 immutable |
| Actors | manager, employee, HR, system admin | NFR-3 / BR-5 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Maya (manager), attempt to edit the meeting notes or ratings on the locked review via API (`PUT .../reviews/{reviewId}/...`) | 409/403 -- review is locked (BR-5); no change persisted. |
| 2 | As Liam (employee), attempt to re-sign or change the decision (`POST .../signoff` again) | Rejected -- a sign-off already exists and the review is locked; the existing signature is unchanged (NFR-3); no second employee signoff appended for the same decision slot. |
| 3 | As Nadia (HR `Performance.Review.All`), attempt to modify or delete the recorded EMPLOYEE signature (`PUT/DELETE .../signoff/{signoffId}`) | Rejected -- NO user including HR can modify a recorded signature (NFR-3); the signature row is unchanged. |
| 4 | As Nadia (HR), attempt to edit the locked review's ratings/notes | Rejected -- only a system admin may perform a compliance correction (BR-5); HR is not authorized to edit a locked review. |
| 5 | Attempt a direct UPDATE/DELETE against review_signoffs at the data layer | The table is append-only (S7) -- updates/deletes are rejected / not part of the supported access path; signatures persist immutably (NFR-3). |
| 6 | As a system admin, perform a documented compliance correction | The admin compliance-correction path is permitted (BR-5) and is itself audit-logged with actor + timestamp + reason (FR-7) -- the ONLY route by which a locked review may be touched; assert it is gated to the admin role and never silently editable by HR/manager/employee. |

## 6. Postconditions
- The recorded signatures are unchanged by any non-admin actor; the locked review is editable only via the audited admin compliance-correction path.

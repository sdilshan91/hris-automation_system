# TC-PRF-009-10: Visibility -> progress updates visible to employee/manager/HR, NOT peers (unless tenant enables shared goal visibility) (BR-5)

## 1. Test Objective
Verify BR-5: an employee's progress updates (and the comment thread) are visible to the employee, their manager, and HR, but NOT to peers -- unless the tenant has enabled shared goal visibility. A peer attempting to view the updates (via UI or direct id/IDOR) is blocked when shared visibility is OFF; when the tenant toggles shared visibility ON, peers may view per that setting.

## 2. Related Requirements
- User Story: US-PRF-009
- Business Rules: BR-5 (visibility -- employee/manager/HR; peers only if shared visibility enabled)
- Non-Functional Requirements: NFR-2 (tenant isolation)
- Functional Requirements: FR-3, FR-8

## 3. Preconditions
- Tenant "acme" with shared goal visibility DISABLED (default).
- Employee "Sam Lee" has goals + progress updates; manager "Dana Cole"; HR "Nadia Khan".
- "Pat Wong" is a PEER of Sam (same team, not Sam's manager, not HR).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Owner | Sam Lee | update author |
| Allowed viewers | Sam, Dana (mgr), Nadia (HR) | BR-5 |
| Peer | Pat Wong | blocked when shared OFF |
| Shared visibility | OFF -> ON | tenant toggle |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam, view his own goal updates | Allowed -- Sam sees his updates/timeline (BR-5). |
| 2 | As Dana (manager), drill into Sam's updates | Allowed -- the managing manager sees them (BR-5, AC-4). |
| 3 | As Nadia (HR), view Sam's updates | Allowed -- HR sees them (BR-5). |
| 4 | As Pat (peer) with shared visibility OFF, attempt to view Sam's updates via UI and by direct goal/update id | Blocked (403 / not found) -- peers cannot see another employee's updates by default (BR-5); no IDOR leak. |
| 5 | Enable shared goal visibility for acme; as Pat, retry | Per the tenant setting, Pat may now view Sam's updates (read) as allowed by shared visibility -- the toggle is the only thing that grants peer access. |
| 6 | Verify the toggle is tenant-scoped | Enabling shared visibility in acme does NOT enable it in any other tenant; visibility evaluation is per-tenant config. |

## 6. Postconditions
- Updates are restricted to employee/manager/HR by default; peers are blocked until the tenant enables shared visibility. No cross-tenant or unauthorized peer access.

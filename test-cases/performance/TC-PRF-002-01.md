# TC-PRF-002-01: Employee rates all goals with valid comments and submits -> "Self-Assessment Submitted", manager notified, edits prevented (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1, AC-2 and FR-1/2/3/4: an authenticated Employee with `Performance.Read.Self` opens Performance > My Review during an open self-assessment window, sees every assigned goal with its details and self-rating inputs (AC-1), enters a valid self-rating (within the tenant scale), achievement % (0-100), and a >=20-char comment for each goal, clicks "Submit Self-Assessment", and the system computes the weighted self-score, persists the record tenant-scoped with status "Self-Assessment Submitted", notifies the manager, and prevents further edits (AC-2).

## 2. Related Requirements
- User Story: US-PRF-002
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-3, FR-4
- Business Rules: BR-2, BR-3
- Data Requirements: S7 (self_assessment record: id, tenant_id, employee_id, goal_id, cycle_id, self_rating, achievement_pct, comment, status, weighted_self_score, submitted_at, audit fields)

## 3. Preconditions
- Tenant "acme" exists, status Active, subdomain `acme.yourhrm.com`, Performance module enabled with self-assessment enabled (BR-5).
- An active appraisal cycle "FY26-H1" exists (US-PRF-004) with the self-assessment window OPEN (start <= today <= end).
- Employee "Asha Patel" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Performance.Read.Self`.
- Asha has 3 acknowledged goals for FY26-H1 (US-PRF-001) with weights 40/35/25; no self-assessment exists yet.
- Tenant rating scale is 1-5 numeric; self:manager weight ratio is configured (e.g. 30:70, BR-4).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to `https://acme.yourhrm.com/performance/my-review?cycleId={fy26h1}` | Form displays all 3 goals as expandable cards, each showing title, description, weight, target value, due date alongside self-rating (1-5), achievement % and comment inputs (AC-1, FR-1/2). A progress indicator shows 0/3 rated. |
| 2 | Rate Goal 1: rating 5, achievement 100, comment 28 chars | Card marked rated; progress 1/3. |
| 3 | Rate Goal 2 (rating 4, achievement 85, comment 24 chars) and Goal 3 (rating 3, achievement 70, comment 22 chars) | Progress 3/3; "Submit Self-Assessment" enabled. |
| 4 | Click "Submit Self-Assessment"; observe the API call | Request carries `X-Tenant-Subdomain: acme` + bearer; response 200/201; body returns the persisted self-assessment with `status` = "Self-Assessment Submitted", `tenant_id` = acme, `employee_id` = Asha, `cycle_id` = FY26-H1, `submitted_at` set, and a computed `weighted_self_score` per goal weights (FR-4). |
| 5 | Inspect persisted rows | One submitted self_assessment per goal (or one record with 3 goal lines) for acme/Asha/FY26-H1; status submitted; weighted self-score = (5*40 + 4*35 + 3*25)/100 normalized per the scale = expected value. |
| 6 | Check the manager's (Ravi) notification feed; observe the enqueue | An in-app notification "Asha Patel submitted their self-assessment for FY26-H1" is enqueued/delivered to Ravi (AC-2). Email delivery CONDITIONAL on the Notification System (S25) -- the enqueue is asserted here. |
| 7 | Re-open My Review for FY26-H1 as Asha and attempt to change a rating/comment | The view is read-only (locked); inputs and "Submit" are disabled; a bypass `PUT`/edit call returns 403/409 "submitted assessment is locked" (AC-2, BR-3). No change persists. |

## 6. Postconditions
- A submitted, locked self-assessment exists for Asha in FY26-H1 with a computed weighted self-score; the manager has a submission notification; Asha cannot edit it.

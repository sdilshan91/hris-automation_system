# TC-PRF-009-15: Accessibility/mobile -> add-update flow at 360px + WCAG 2.1 AA + animated progress bars perceivable (NFR-4)

## 1. Test Objective
Verify NFR-4 and the §8 UI notes: the goal tracking UI is mobile-optimized -- the add-update flow is usable at 360px (bottom-sheet form, slider, status chips, file input) -- meets WCAG 2.1 AA (keyboard operability, screen-reader labels, color contrast, status not conveyed by color alone), and the animated progress bars convey their value accessibly and respect reduced-motion preferences.

## 2. Related Requirements
- User Story: US-PRF-009
- Non-Functional Requirements: NFR-4 (mobile-optimized + accessibility)
- UI/UX: §8 (animated progress bars, color-coded status chips, bottom-sheet add update)
- Acceptance Criteria: AC-1, AC-2

## 3. Preconditions
- Tenant "acme"; employee "Sam Lee" authenticated with goals to update.
- Test devices/emulation at 360px, 768px, 1280px, 1920px; axe-core/Lighthouse a11y tooling; a screen reader (NVDA/VoiceOver).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewports | 360 / 768 / 1280 / 1920px | responsive |
| WCAG target | 2.1 AA | NFR-4 |
| Status chips | gray/blue/green/amber/red | not color-only |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Load My Goals at 360px and open "Add Update" | The form opens as a touch-friendly bottom-sheet; the progress slider, status selector, notes field, and file input are all reachable and operable without horizontal scroll. |
| 2 | Complete the add-update flow using only the keyboard | All controls are tab-reachable in a logical order with a visible focus indicator; the slider is operable via arrow keys; Save is reachable and activatable. |
| 3 | Run axe-core / Lighthouse on My Goals + the add-update form at each viewport | Zero WCAG 2.1 AA violations; text + UI contrast >= 4.5:1 (>=3:1 for large/graphical). |
| 4 | Inspect status chips with a screen reader | Each status (Not Started/In Progress/Completed/At Risk/Blocked) is announced as text (e.g. via label/aria), not by color alone -- the chip has a non-color indicator (icon/text). |
| 5 | Inspect the animated progress bar | The bar exposes its value to assistive tech (e.g. role=progressbar + aria-valuenow); the animation is decorative and respects `prefers-reduced-motion` (no essential info lost when motion is reduced). |
| 6 | Verify the update timeline at 360px | The history timeline is readable, expandable, and keyboard/screen-reader navigable on mobile. |

## 6. Postconditions
- The add-update flow and goal tracking UI are usable at 360px, meet WCAG 2.1 AA, and progress bars are accessibly perceivable with reduced-motion support.

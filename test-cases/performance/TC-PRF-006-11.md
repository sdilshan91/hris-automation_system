# TC-PRF-006-11: Authz + workflow ordering -- only the assigned employee can sign; manager cannot sign on the employee's behalf; only the managing manager / HR can add notes (FR-3, BR-1)

## 1. Test Objective
Verify the sign-off workflow authorization and ordering (FR-3, BR-1): only the direct reporting manager (`Performance.Review.Team`) or HR (`Performance.Review.All`) may add meeting notes and request sign-off; the EMPLOYEE sign-off (Acknowledge/Dispute) can only be performed by the review's own employee -- the manager (or any other user) cannot sign or dispute on the employee's behalf; and the workflow order (manager signs first, then the employee is requested) is enforced server-side. Unauthenticated requests are 401; unauthorized roles are 403; cross-user (IDOR) attempts are blocked.

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-2, AC-3
- Functional Requirements: FR-3 (ordered workflow: manager first, then employee)
- Business Rules: BR-1 (notes only by the managing manager/HR after manager review submitted)

## 3. Preconditions
- Tenant "acme", Performance module enabled.
- Liam Carter's review has a submitted manager review; manager Maya (`.Team` over Liam), HR Nadia (`.All`), an UNRELATED manager Omar (no relationship to Liam), and another employee Ben exist in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Authorized notes/request | Maya (Liam's manager), Nadia (HR) | BR-1 |
| Unauthorized notes | Omar (non-managing), Ben (employee) | 403 |
| Employee sign-off | Liam only | FR-3 |
| Impersonation attempt | Maya / Ben signing AS Liam | blocked |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Omar (manager, not Liam's), `POST .../reviews/{liamReviewId}/meeting-notes` | 403 -- only Liam's managing manager or HR may add notes (BR-1). |
| 2 | As Ben (employee), attempt to add notes / request sign-off on Liam's review | 403 -- employees cannot add notes (BR-1). |
| 3 | As Maya, request sign-off (valid); then as Maya attempt to `POST .../signoff {decision:"Acknowledge"}` on Liam's review | The employee sign-off is rejected -- the manager cannot Acknowledge/Sign on the employee's behalf (FR-3); only Liam may. |
| 4 | As Ben (another employee), attempt to sign/dispute Liam's review (IDOR via reviewId) | 403/404 -- a user can only sign their OWN review; cross-user sign-off blocked. |
| 5 | As Liam, "Acknowledge & Sign" his own review | 200 -- the assigned employee signs successfully (AC-3). |
| 6 | Unauthenticated: call any sign-off endpoint with no/expired token | 401 -- authentication required. |
| 7 | Attempt to request employee sign-off BEFORE recording the manager sign-off (out of order) | Rejected -- manager signs first then the employee is requested (FR-3 ordering enforced server-side). |

## 6. Postconditions
- Notes/sign-off requests are restricted to the managing manager/HR; the employee signature is restricted to the review's own employee; ordering is enforced; unauthorized/unauthenticated/cross-user attempts are blocked.

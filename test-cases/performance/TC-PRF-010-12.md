# TC-PRF-010-12: Input validation + sanitization -> recommendation type enum, amounts/percentages range, custom-type config, XSS/SQLi on justification + custom fields neutralized (server-side)

## 1. Test Objective
Verify FR-1 input integrity and S10 sanitization: recommendation type is a valid enum (promotion, bonus, increment, training nomination, lateral move, PIP referral, custom); bonus/increment amounts and percentages are within valid numeric ranges (non-negative, sane upper bounds); custom recommendation types are tenant-configured (not arbitrary client injection of behavior); and free-text fields (justification, custom-type details) are sanitized so XSS/SQL-injection payloads are neutralized. All enforced server-side, not just client-side.

## 2. Related Requirements
- User Story: US-PRF-010
- Functional Requirements: FR-1 (recommendation types incl. tenant-configurable custom), FR-3 (justification)
- Data Requirements: S7 (details JSONB validated); S10 sanitization

## 3. Preconditions
- Tenant "acme"; HR Officer Pat Ng (`Performance.Publish.All`).
- The tenant has a configured custom recommendation type "Spot Award"; "RandomType" is NOT configured.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Invalid type | "RandomType" | not in enum/config -> reject |
| Negative bonus | -$1,000 | reject |
| Over-range increment | 500% | reject (sane upper bound) |
| XSS justification | `<script>alert(1)</script>` | neutralized |
| SQLi field | `'; DROP TABLE recommendations;--` | neutralized |
| Valid custom | "Spot Award" $500 | accepted |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST .../recommendations` with type = "RandomType" | 400 -- type must be a known enum value or a tenant-configured custom type; "RandomType" rejected server-side. |
| 2 | Submit a bonus with amount -$1,000 | 400 -- amount must be non-negative; rejected client + server. |
| 3 | Submit an increment of 500% | 400 -- percentage outside the valid range; rejected per the documented upper bound. |
| 4 | Submit a recommendation whose justification = `<script>alert(1)</script>` | Stored sanitized/encoded; when rendered in the workspace/summary it does NOT execute (no script runs); the payload is inert. |
| 5 | Submit a custom-type detail field containing `'; DROP TABLE recommendations;--` | Treated as literal text via parameterized queries; no SQL executes; the recommendations table is intact. |
| 6 | Submit a valid "Spot Award" $500 (configured custom type) | Accepted -- the configured custom type persists with its details. |

## 6. Postconditions
- Invalid types/amounts are rejected server-side; XSS/SQLi payloads are neutralized and never execute; configured custom types are accepted. No data corruption. Tenant-scoped to acme.

# TC-PRF-009-02: Multiple updates on a goal -> expand card -> chronological timeline with date, progress change, notes, attachments (update history)

## 1. Test Objective
Verify AC-3 and FR-3: after an employee has posted multiple progress updates on a goal, expanding the goal card renders a full, chronological timeline of every update with the date, the progress change (from -> to), the notes, and any attachments. The history is complete (no update missing) and ordered consistently (newest-first or oldest-first per the documented convention).

## 2. Related Requirements
- User Story: US-PRF-009
- Acceptance Criteria: AC-3
- Functional Requirements: FR-3
- Non-Functional Requirements: NFR-3 (append-only history)
- Data Requirements: S7 (goal_progress_updates, append-only)

## 3. Preconditions
- Tenant "acme"; employee "Sam Lee" authenticated with `Performance.Read.Self`.
- Sam's goal "Ship onboarding redesign" has 5 progress updates posted over time: 10% (Mon), 25% (Wed, +1 attachment), 40% (Fri), 55% (next Tue, +1 attachment), 70% (next Thu).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Goal | Ship onboarding redesign | 5 updates |
| Updates | 10 -> 25 -> 40 -> 55 -> 70 | progress deltas |
| Attachments | on the 25% and 55% updates | evidence files |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam, open My Goals and expand "Ship onboarding redesign" | The update history timeline renders showing all 5 updates (AC-3, FR-3). |
| 2 | Inspect each timeline entry | Each entry shows: the date/timestamp, the progress change (e.g. "40% -> 55%"), the notes text, the author avatar, and any attachment(s) as downloadable evidence (AC-3). |
| 3 | Verify ordering | Entries are in chronological order per the documented convention (newest-first or oldest-first), with no gaps -- all 5 present. |
| 4 | Verify attachments | The 25% and 55% entries each expose their attachment; the others show none. Attachment links resolve to acme-scoped storage. |
| 5 | Confirm via API | `GET .../performance/goals/{goalId}/updates` returns exactly 5 records, all tenant_id = acme, ordered, with progress_pct + notes + attachment metadata. |
| 6 | Verify the timeline is read-only | No entry exposes an edit/delete control (history is append-only, NFR-3 -- enforcement asserted in TC-PRF-009-08). |

## 6. Postconditions
- The full 5-update chronological history is displayed; no update is missing or reordered incorrectly. No data mutated.

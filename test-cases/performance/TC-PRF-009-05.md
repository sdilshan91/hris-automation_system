# TC-PRF-009-05: Status rules -> 100% auto-sets Completed (employee can override, BR-2); valid status transitions NotStarted -> InProgress -> Completed / AtRisk / Blocked (FR-7)

## 1. Test Objective
Verify BR-2 and FR-7: setting a goal's progress to 100% automatically changes its status to "Completed", but the employee can override that auto-status to another valid value; and the system supports the status transition machine Not Started -> In Progress -> Completed, with At Risk or Blocked reachable at any point. Invalid/nonsensical transitions are handled per the documented state machine.

## 2. Related Requirements
- User Story: US-PRF-009
- Functional Requirements: FR-7 (status transitions)
- Business Rules: BR-2 (100% auto-Completed, overridable)
- Acceptance Criteria: AC-2 (update captures status)

## 3. Preconditions
- Tenant "acme"; employee "Sam Lee" authenticated with `Performance.Read.Self`.
- Sam has a goal currently at 80% / In Progress in the active (open) cycle window.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Goal | "Migrate billing service" | 80% / In Progress |
| Status enum | NotStarted, InProgress, Completed, AtRisk, Blocked | FR-7 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam, add an update setting progress to 100% WITHOUT explicitly choosing a status | The status auto-sets to "Completed" (BR-2); the update persists with progress_pct=100, status=Completed. |
| 2 | Add another update keeping 100% but overriding the status to "In Progress" (e.g. pending sign-off) | The override is accepted and persisted -- status=InProgress at 100% (BR-2 explicitly allows employee override). |
| 3 | On a fresh goal at Not Started, post an update moving it to In Progress | Transition NotStarted -> InProgress accepted (FR-7). |
| 4 | Post an update moving In Progress -> At Risk | Transition accepted (At Risk reachable at any point, FR-7). |
| 5 | Post an update moving the goal to Blocked | Transition accepted (Blocked reachable at any point, FR-7; manager+HR notification covered in TC-PRF-009-06). |
| 6 | Post an update moving Blocked -> In Progress, then -> Completed | Transitions accepted per the state machine; the goal can recover from Blocked/At Risk. |
| 7 | Attempt an undocumented/invalid transition (per the documented machine) | The system rejects or normalizes it consistently with the documented FR-7 state machine; the status never lands in an undefined value. |
| 8 | Verify each step is an APPEND (not an overwrite) | Each status change creates a new history entry (NFR-3); prior states are preserved in the timeline. |

## 6. Postconditions
- 100% auto-completes but is overridable by the employee; all documented status transitions succeed and each is recorded as an append-only history entry. No invalid status persisted.

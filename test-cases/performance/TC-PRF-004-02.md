# TC-PRF-004-02: Overlapping phases and reversed phase start/end rejected (negative)

## 1. Test Objective
Verify FR-2 and BR-3 phase-sequencing validation: the system rejects a cycle (on create or edit) when two phases overlap in time, when phases are not sequential, or when a phase's start date is on/after its end date (reversed). Validation must fire both client-side and server-side.

## 2. Related Requirements
- User Story: US-PRF-004
- Acceptance Criteria: AC-2 (create), AC-5 (edit)
- Functional Requirements: FR-2
- Business Rules: BR-3

## 3. Preconditions
- Tenant "acme" active; rating scale configured; HR Officer Maya authenticated with cycle permissions.
- Cycle period 2026-07-01 .. 2026-12-31 entered.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Case A overlap | goal-setting 2026-07-01..2026-08-15; self-assessment 2026-08-01..2026-08-31 | P2 starts before P1 ends (overlap) |
| Case B non-sequential | manager-review 2026-08-01..2026-08-31 placed BEFORE self-assessment 2026-09-01..2026-09-30 | out of order |
| Case C reversed | calibration 2026-10-15..2026-10-01 | start after end |
| Case D equal | publish 2026-11-01..2026-11-01 | start == end (zero/negative duration) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter Case A (overlapping goal-setting + self-assessment) and attempt "Create Cycle" | Client-side validation blocks submit with a phase-overlap error naming the conflicting phases; "Create Cycle" disabled. |
| 2 | Bypass the client and `POST /api/v1/tenant/performance/cycles` with Case A | Server returns 400 Bad Request with a validation error; no cycle/phase rows persisted (FR-2). |
| 3 | Enter Case B (manager-review scheduled before self-assessment) and attempt create | Rejected client + server: phases must be sequential; 400; nothing persisted. |
| 4 | Enter Case C (calibration start 10-15 after end 10-01) | Rejected client + server: phase start must be before end; 400. |
| 5 | Enter Case D (publish start == end) | Rejected: each phase must have a positive duration (start < end); 400. |
| 6 | Repeat Case A as a phase EDIT on an existing Draft cycle (AC-5 path) — `PUT .../cycles/{id}/phases` | Same overlap rejection applies on edit; the existing valid phase dates are unchanged; 400. |

## 6. Postconditions
- No invalid cycle/phase configuration is persisted; existing data unchanged.

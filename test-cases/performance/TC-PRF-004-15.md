# TC-PRF-004-15: Boundary — minimum three phases enforced; phases touching the cycle edges; adjacent phases sharing a boundary (FR-1 / FR-2 / BR-3)

## 1. Test Objective
Verify FR-1 (minimum of three phases: goal-setting, assessment, publish), FR-2 (sequential/non-overlapping) and BR-3 (within window) at their boundaries: a cycle with fewer than the required phases is rejected; phases whose first start == cycle start and last end == cycle end are accepted; and adjacent phases that share a boundary day are handled per the system's contiguity rule consistently.

## 2. Related Requirements
- User Story: US-PRF-004
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2
- Business Rules: BR-3

## 3. Preconditions
- Tenant "acme" active; rating scale configured; HR Officer Maya authenticated with cycle permissions.
- Cycle period 2026-07-01 .. 2026-09-30.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Too few phases | goal-setting + publish only (2 phases) | below the FR-1 minimum of 3 |
| Minimum valid | goal-setting + assessment + publish (3 phases) | at the FR-1 minimum |
| Edge-touching | P1 start 2026-07-01 == cycle start; last phase end 2026-09-30 == cycle end | boundary inclusive |
| Adjacent | P1 ends 2026-07-31, P2 starts 2026-08-01 | contiguous, no gap |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Attempt to create a cycle with only goal-setting + publish (2 phases) | Rejected: a cycle requires a minimum of three phases (goal-setting, assessment, publish) (FR-1); 400; nothing persisted. |
| 2 | Create a cycle with exactly the 3 minimum phases, sequential and within the window | Accepted; cycle created with 3 phases (lower boundary passes). |
| 3 | Set the first phase start == cycle start (2026-07-01) and the last phase end == cycle end (2026-09-30) | Accepted: boundary dates are inclusive (BR-3 within-window check is inclusive). |
| 4 | Configure adjacent phases P1 end 2026-07-31, P2 start 2026-08-01 (contiguous, no overlap) | Accepted: back-to-back phases with no gap and no overlap are valid (FR-2). |
| 5 | Configure P1 end 2026-07-31 and P2 start 2026-07-31 (same boundary day) | Handled per the documented contiguity rule (rejected as overlap if phases are treated as inclusive ranges) — assert the behavior is consistent and documented; nothing ambiguous persists. |

## 6. Postconditions
- Phase-count and phase-boundary rules behave correctly at their edges; no invalid configuration persists.

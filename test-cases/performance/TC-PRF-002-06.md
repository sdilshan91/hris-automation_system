# TC-PRF-002-06: Auto-save every 60 seconds -- draft data recovered after a simulated crash (NFR-3)

## 1. Test Objective
Verify NFR-3: while editing a self-assessment the client auto-saves the draft every 60 seconds without an explicit "Save as Draft" click, so that data entered before an unexpected browser crash / tab close is recovered on the next visit.

## 2. Related Requirements
- User Story: US-PRF-002
- Functional Requirements: FR-6 (draft persistence)
- Non-Functional Requirements: NFR-3 (60s auto-save)

## 3. Preconditions
- acme cycle FY26-H1 self-assessment window OPEN; Asha authenticated with `Performance.Read.Self`; 3 acknowledged goals.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Auto-save interval | 60 seconds | NFR-3 |
| Entered before crash | Goal 1 rating 5 + 30-char comment | entered, not manually saved |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter Goal 1 rating 5 and a 30-char comment; do NOT click "Save as Draft" | Fields hold the values; an auto-save indicator is idle/pending. |
| 2 | Wait > 60 seconds; observe the network | An auto-save request fires (~every 60s) and persists the draft server-side (status `draft`); a "Saved at HH:MM" indicator updates. |
| 3 | Simulate a crash: kill the tab/process before any further manual save | Session ends abruptly with unsaved-in-UI but auto-saved-server-side data. |
| 4 | Re-open My Review for FY26-H1 in a fresh session | Goal 1 rating 5 + the 30-char comment are restored from the last auto-save; no data entered before the last auto-save is lost. |
| 5 | Confirm scoping | The auto-saved draft carries tenant_id=acme and employee_id=Asha; it is not submitted and fired no manager notification. |

## 6. Postconditions
- The draft is auto-persisted at least once per 60s and survives a crash; recovered data matches the last auto-save.

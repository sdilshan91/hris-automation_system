# TC-PRF-007-13: Dashboard refreshes from materialized views on a tenant-configurable interval (default 4h via Hangfire)

## 1. Test Objective
Verify BR-4 (+ NFR-3 / S7): dashboard aggregates are served from the performance_summary materialized view, which is refreshed on a tenant-configurable schedule (default every 4 hours) via a Hangfire recurring job. Asserts the refresh seam: a new submitted review is reflected after the materialized view is refreshed, the refresh runs in tenant context, and the interval is configurable per tenant. Written as a conditional/extension-point assertion around the refresh mechanism.

## 2. Related Requirements
- User Story: US-PRF-007
- Business Rules: BR-4 (refresh from materialized views; tenant-configurable interval, default 4h via Hangfire)
- Non-Functional Requirements: NFR-3 (materialized view / caching)
- Data Requirements: S7 (performance_summary materialized view refreshed by Hangfire)

## 3. Preconditions
- Tenant "acme" / cycle "FY26" with the performance_summary materialized view populated and a known current average score.
- A Hangfire recurring refresh job is registered for the materialized view (CONDITIONAL: if not yet wired, the test asserts the refresh seam + manual refresh trigger and documents the Hangfire schedule as the extension point).
- HR Officer "Nadia Khan" authenticated in acme with `Performance.Read.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Default interval | 4 hours | BR-4 |
| Tenant override | e.g. 1 hour for acme | BR-4 configurable |
| New review | one additional submitted review | changes the aggregate |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Record the current dashboard average score for acme/FY26 | Baseline aggregate captured from the materialized view. |
| 2 | Submit one new manager review (US-PRF-003) that would shift the average | The underlying review data changes; the materialized view is NOT yet refreshed -- the dashboard still shows the pre-refresh aggregate (BR-4: served from the view, not real-time). |
| 3 | Trigger the materialized-view refresh job (or wait for the scheduled run) | The Hangfire refresh job runs in acme's tenant context and rebuilds performance_summary for acme only. |
| 4 | Reload the dashboard | The average score now reflects the new review (post-refresh); aggregates are consistent with the refreshed view. |
| 5 | Set a tenant-specific refresh interval (e.g. 1h for acme) | The recurring schedule for acme honors the override; the default (4h) applies when no override is set (BR-4 configurable). |
| 6 | Confirm tenant isolation of the refresh | The acme refresh job rebuilds only acme's rows; another tenant's materialized rows are untouched (see TC-PRF-ISO-028). |

## 6. Postconditions
- Dashboard aggregates update after a tenant-scoped materialized-view refresh; the interval is tenant-configurable with a 4h default; the refresh runs per tenant.

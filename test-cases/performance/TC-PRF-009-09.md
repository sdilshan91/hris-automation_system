# TC-PRF-009-09: Manager comment thread -> manager adds comments on a progress update -> conversation displays per goal (FR-8)

## 1. Test Objective
Verify FR-8: a manager can comment on an employee's progress update, creating a conversation thread (per goal / per update) that displays in order. Comments are lightweight (max 500 chars per the constraints), attributed to the author with a timestamp, and visible to the participants per the visibility rule (BR-5, asserted in TC-PRF-009-10). The employee can see and reply within the thread.

## 2. Related Requirements
- User Story: US-PRF-009
- Functional Requirements: FR-8 (manager comment thread)
- Business Rules: BR-5 (visibility -- employee/manager/HR), constraint: comment max 500 chars
- Acceptance Criteria: AC-4 (manager drill-down context)

## 3. Preconditions
- Tenant "acme"; manager "Dana Cole" and employee "Sam Lee" (Dana's report) authenticated.
- Sam has posted a progress update on a goal (update id known).
- Notification System (S25) available (enqueue asserted).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Update | Sam's 55% update | thread target |
| Comment 1 (Dana) | "Great progress -- can you share the test plan?" | <=500 chars |
| Reply (Sam) | "Attached the plan to the next update." | <=500 chars |
| Over-limit | 501-char comment | rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, drill into Sam's goal and add a comment on the 55% update | The comment persists in goal_comments tenant-scoped, attributed to Dana with a server timestamp; the thread renders the comment below the update (FR-8). |
| 2 | As Sam, open the same update | Sam sees Dana's comment and can reply; the reply appends to the thread in order. |
| 3 | Verify the conversation order | The thread displays comments chronologically (Dana then Sam), each with author + timestamp. |
| 4 | Attempt a 501-char comment | Rejected client + server with a length validation error -- the comment is not persisted (max 500 chars). |
| 5 | Verify notification | Adding a comment enqueues a notification to the other participant (Sam on Dana's comment, Dana on Sam's reply); enqueue asserted, delivery conditional on S25. |
| 6 | Verify tenant scoping | All comments carry acme tenant_id; the thread shows no cross-tenant or cross-goal comments. |

## 6. Postconditions
- A manager-employee comment thread on the update displays in order with valid (<=500 char) comments; the over-limit comment was rejected. No cross-tenant leakage.

# TC-PRF-006-01: Manager adds templated meeting notes -> requests sign-off -> employee reads + Acknowledge & Sign -> signature (name+timestamp+IP) recorded, status Signed Off, review LOCKED (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1..AC-4 and FR-1/2/3/7: an authenticated manager with `Performance.Review.Team` whose manager review for the employee is already submitted (US-PRF-003) opens the employee's review in the active sign-off phase, clicks "Add Meeting Notes" and is shown a rich-text editor pre-populated with a template containing the sections strengths / areas for improvement / agreed development actions (with deadlines) / overall discussion summary (AC-1, FR-1/2); the manager completes the notes and clicks "Request Employee Sign-Off", which saves the notes, records the manager's own sign-off (name + timestamp + IP), changes status to "Pending Employee Sign-Off" and notifies the employee (AC-2, FR-3); the employee opens and reads the notes, clicks "Acknowledge & Sign", and the system records the employee's digital signature (name + timestamp + IP), finalizes status to "Signed Off", and LOCKS the review against further edits (AC-3, FR-7, BR-5); HR/manager can then view the full signed record with goals, ratings, notes, sign-off timestamps and signatures with a PDF export option (AC-4).

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-1, AC-2, AC-3, AC-4
- Functional Requirements: FR-1, FR-2, FR-3, FR-7
- Business Rules: BR-1 (notes only after manager review submitted), BR-5 (review locked after both sign off)
- Data Requirements: S7 (review_meeting_notes; review_signoffs immutable append-only; tenant_id with RLS policy)

## 3. Preconditions
- Tenant "acme" exists, status Active, subdomain `acme.yourhrm.com`, Performance module enabled.
- An active appraisal cycle "FY26 Annual Review" for acme is in the review-meeting / sign-off phase (US-PRF-004).
- Employee "Liam Carter" (Engineering) has a SUBMITTED manager review for the current cycle (US-PRF-003) with goals + ratings.
- A tenant-level meeting-notes template is configured by HR (FR-1) with the four sections.
- Manager "Maya Shah" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Performance.Review.Team` over Liam.
- Employee "Liam Carter" can authenticate in acme to perform the sign-off.

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Maya, navigate to `https://acme.yourhrm.com/performance`, open Liam's submitted review, click "Add Meeting Notes" | A rich-text editor opens pre-populated with the tenant template: sections for strengths, areas for improvement, agreed development actions (with deadline fields), and overall discussion summary; the template also surfaces Liam's goal titles + ratings for reference (AC-1, FR-1/2, S8). |
| 2 | Fill all four sections (incl. an agreed action with a deadline), click "Request Employee Sign-Off"; observe `POST .../performance/reviews/{reviewId}/meeting-notes` then `.../request-signoff` | Request carries `X-Tenant-Subdomain: acme` + bearer; 200/201; notes persisted to review_meeting_notes tenant-scoped (tenant_id=acme); the manager's sign-off is recorded in review_signoffs (role=Manager, name="Maya Shah", server timestamp, captured request IP, FR-7); status -> "Pending Employee Sign-Off". |
| 3 | Observe the employee notification | Liam receives an in-app + email notification with a link to review and sign (AC-2; delivery CONDITIONAL on Notification System S25 -- assert in-app push + email enqueue). |
| 4 | As Liam, open the sign-off link and read the notes | The full meeting notes render read-only with the four sections + goals/ratings; the system records that Liam OPENED/READ the notes (BR-2 read-tracking; see TC-PRF-006-06). The "Acknowledge & Sign" and "Dispute" actions are presented. |
| 5 | Click "Acknowledge & Sign", confirm the modal ("By signing, you acknowledge this review has been discussed"); observe `POST .../performance/reviews/{reviewId}/signoff` body `{decision:"Acknowledge"}` | 200; a digital signature row is appended to review_signoffs (role=Employee, name="Liam Carter", server-side timestamp, captured request IP, FR-7); status finalizes to "Signed Off"; the review is LOCKED (BR-5). |
| 6 | Attempt to edit the meeting notes or re-submit ratings as the manager | The edit is rejected (review locked, BR-5); UI shows read-only; API returns 409/403 (covered in depth by TC-PRF-006-07). |
| 7 | As HR (or Maya), view the completed review | The full record renders: goals, ratings, meeting notes, both sign-off timestamps + signer names, and a "Export PDF" option (AC-4; export covered by TC-PRF-006-09). |

## 6. Postconditions
- Liam's review for FY26 (tenant acme) has persisted meeting notes, a Manager sign-off and an Employee sign-off (each with name+timestamp+IP), status "Signed Off", and is locked against edits.
- All sign-off actions are audit-logged (FR-7; asserted in TC-PRF-006-08).

# TC-PRF-008-05: A second ACTIVE PIP for the same employee is rejected -- only one active PIP at a time (BR-2)

## 1. Test Objective
Verify BR-2: an employee can have only ONE active PIP at a time. When an employee already has a PIP in an active state (Active or Extended), attempting to initiate a second PIP for that employee is rejected client-side AND server-side. A new PIP becomes allowed only after the existing one reaches a terminal state (Successfully Completed / Not Met / Cancelled).

## 2. Related Requirements
- User Story: US-PRF-008
- Business Rules: BR-2 (one active PIP per employee)
- Functional Requirements: FR-2 (status lifecycle terminal states)

## 3. Preconditions
- Employee "Sam Lee" has an ACTIVE PIP in acme (TC-PRF-008-01).
- HR Officer "Nadia Khan" is authenticated in acme with `Performance.Review.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Employee | Sam Lee | already has Active PIP |
| Active states | Active, Extended | block second PIP |
| Terminal states | Successfully Completed, Not Met, Cancelled | release the block |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Nadia, open "Create PIP" for Sam Lee (who has an Active PIP) | The UI surfaces that Sam already has an active PIP and blocks/disables initiation with a clear message (client-side BR-2). |
| 2 | Bypass the UI: `POST .../performance/pips` (+ initiate) for Sam Lee directly | 409 / 422 -- rejected SERVER-SIDE with a "one active PIP per employee" error; NO second active PIP is created. |
| 3 | Repeat while Sam's PIP is in status Extended | Still rejected -- Extended is an active state (BR-2). |
| 4 | Close Sam's existing PIP (Successfully Completed per TC-PRF-008-03 or Cancelled) | The PIP reaches a terminal state. |
| 5 | Re-attempt creating a new PIP for Sam Lee | Now ALLOWED -- a fresh PIP can be initiated (BR-2 only blocks while one is active). |
| 6 | Confirm no orphan records | No partial/duplicate pip / pip_objectives / pip_checkpoints rows were left from the rejected attempts. |

## 6. Postconditions
- Sam Lee never has more than one active PIP at any time; rejected attempts leave no residual rows. No Tenant B data touched.

# TC-PRF-007-09: Distribution + aggregates exclude probation-cycle employees unless explicitly included via filter (BR-2)

## 1. Test Objective
Verify BR-2: by default the score distribution histogram (and the dependent aggregates -- average score, headcount, department bars) EXCLUDES employees who are in probation cycles; when the HR Officer explicitly enables the "include probation" filter, those employees are added back and all widgets recompute to include them.

## 2. Related Requirements
- User Story: US-PRF-007
- Business Rules: BR-2
- Functional Requirements: FR-1 (distribution), FR-2 (department averages), FR-4 (filter to include)

## 3. Preconditions
- Tenant "acme" / cycle "FY26" with a mix of regular-cycle employees AND a known set of probation-cycle employees (US-PRF-004 CycleType=Probation), each with submitted scores.
- HR Officer "Nadia Khan" authenticated in acme with `Performance.Read.All`.
- Known aggregates computed both WITH and WITHOUT the probation set for deterministic assertions.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Regular participants | N_reg (seeded) | always counted |
| Probation participants | N_prob (seeded) | excluded by default |
| Expected default headcount | N_reg | BR-2 |
| Expected with-probation headcount | N_reg + N_prob | filter on |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the FY26 overview (no probation filter); observe the distribution histogram bucket total + headcount | Counts/headcount = N_reg only; the probation employees are NOT included (BR-2). |
| 2 | Verify the average score | Computed over the regular population only; equals the seeded no-probation mean. |
| 3 | Enable the "Include probation cycle employees" filter; observe `GET .../performance/dashboard/overview?cycleId=FY26&includeProbation=true` | All widgets recompute; headcount = N_reg + N_prob; the distribution gains the probation employees' score buckets (BR-2 explicit include). |
| 4 | Verify the average + department bars with probation included | Average + per-department bars recompute to the combined population; values match the seeded with-probation aggregates. |
| 5 | Disable the filter again | Aggregates revert to the regular-only population (BR-2 default). |
| 6 | Confirm server-side enforcement | The exclusion is applied server-side in the aggregate query, not just hidden in the UI -- the default API response omits probation rows from the counts. |

## 6. Postconditions
- Probation-cycle employees are excluded from distribution/aggregates by default and included only when the filter is explicitly set.

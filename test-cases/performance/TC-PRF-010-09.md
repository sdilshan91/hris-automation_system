# TC-PRF-010-09: Scope/access -> employees view NO recommendations; managers see ONLY their team's; HR (Publish.All) full; compensation visibility additionally role-gated

## 1. Test Objective
Verify AC-5 / NFR-5: access to recommendation data is restricted by permission. Employees cannot view ANY recommendations (no general employee access). Managers with `Performance.Read.Team` see ONLY their direct reports' recommendations and status (pending/approved/rejected), never other teams'. HR with `Performance.Publish.All` (or `Performance.Read.All`) has full org-wide access. Compensation fields within recommendations are ADDITIONALLY restricted -- not all HR may have compensation visibility (tenant-configurable). Enforcement is server-side, including IDOR by direct id.

## 2. Related Requirements
- User Story: US-PRF-010
- Acceptance Criteria: AC-5
- Non-Functional Requirements: NFR-5 (access restricted to Publish.All / Read.Team; no general employee access)
- Constraints: compensation access additionally role-restricted (tenant-configurable)

## 3. Preconditions
- Tenant "acme": HR Officer Pat Ng (`Performance.Publish.All`, compensation-visible); HR Officer "Robin" (`Performance.Read.All` but compensation-HIDDEN); Manager "Dana" (`Performance.Read.Team`, direct reports = Jordan + Sam); Manager "Kim" (other team); Employee "Sam Lee" (no recommendation permission).
- Recommendations exist for Jordan (Dana's report) and for Kim's team.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Pat | Publish.All + comp-visible | full |
| Robin | Read.All, comp-hidden | sees recs, NOT comp amounts |
| Dana | Read.Team (Jordan, Sam) | team-only |
| Kim | Read.Team (other team) | cannot see Jordan |
| Sam Lee | Employee, no perm | sees nothing |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam Lee (Employee), navigate to /performance/recommendations and call the API directly | 403 forbidden -- employees have NO access to any recommendation data (AC-5/NFR-5); the FE also redirects away. |
| 2 | As Dana (manager), open Team Recommendations | Only Dana's direct reports (Jordan, Sam) appear with their final scores + recommendation status (pending/approved/rejected); no other team's recommendations are shown (AC-5). |
| 3 | As Dana, request a recommendation belonging to Kim's team by direct id | 403/404 -- a manager cannot read a non-report's recommendation even by id (IDOR blocked); scope is derived from the org tree, not client input. |
| 4 | As Pat (Publish.All, comp-visible), open the workspace | Full org-wide recommendations visible INCLUDING compensation amounts. |
| 5 | As Robin (Read.All, comp-HIDDEN), open the workspace | Recommendations visible org-wide, but compensation fields (bonus amount, increment value, current/recommended pay) are masked/omitted -- compensation visibility is a separate role gate (Constraints), enforced server-side (not just hidden in the UI). |
| 6 | Confirm server-side enforcement | The compensation masking is enforced in the API payload (the amounts are absent for Robin), not merely CSS-hidden; an employee/non-scoped manager gets no recommendation rows at all. |

## 6. Postconditions
- Employees see no recommendations; managers see only their team; HR sees org-wide; compensation amounts are visible only to comp-authorized roles. All enforced server-side. Tenant-scoped to acme.

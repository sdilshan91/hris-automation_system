# TC-PRF-006-14: Sign-off flow on mobile (360px) with touch-friendly confirmation dialogs + WCAG 2.1 AA (NFR-5)

## 1. Test Objective
Verify NFR-5: the sign-off workflow is fully usable on mobile devices -- the notes editor is full-screen at 360px, the "Acknowledge & Sign" / "Dispute" actions have large touch targets, the confirmation modal ("By signing, you acknowledge this review has been discussed") is touch-friendly, and the dispute comment text area is reachable. The flow meets WCAG 2.1 AA: keyboard operability, visible focus, sufficient color contrast, status/timeline not conveyed by color alone, and screen-reader labelling of the sign-off actions and confirmation dialog.

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-1, AC-3
- Non-Functional Requirements: NFR-5 (mobile-accessible sign-off with touch-friendly dialogs)
- UI/UX: S8 (full-screen editor, large touch targets, status timeline)

## 3. Preconditions
- Tenant "acme", Performance module enabled; Liam's review is in "Pending Employee Sign-Off".
- Test devices/viewports: 360px (mobile) up to desktop; axe-core (or equivalent) available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewports | 360px, 768px, 1280px | NFR-5 responsive |
| WCAG target | 2.1 AA | NFR-5 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Liam at 360px, open the sign-off link | The meeting notes render full-screen and readable; the status timeline (Notes Added -> Sign-Off Requested -> Signed/Disputed -> Completed) is legible and NOT color-only (icons/text labels). |
| 2 | Operate "Acknowledge & Sign" / "Dispute" by touch and by keyboard (Tab/Enter) | Both actions have large touch targets (>=44x44 CSS px), are keyboard-focusable with a visible focus ring, and are reachable in a logical tab order. |
| 3 | Trigger the confirmation modal | The modal traps focus, is dismissible via keyboard (Esc) and touch, has an accessible name/role (dialog), and its confirm/cancel buttons are touch-friendly and labelled. |
| 4 | Choose Dispute and open the comment text area at 360px | The text area is reachable, labelled, and the "Submit Dispute" button is touch-friendly; the validation error (empty comment) is announced to assistive tech. |
| 5 | Run axe-core on the sign-off screen + modal at each viewport | No WCAG 2.1 AA violations: contrast, labels, roles, focus order all pass. |
| 6 | Verify across Chrome / Edge / Firefox / Safari | The sign-off flow renders and functions consistently (no layout breakage at 360px). |

## 6. Postconditions
- The sign-off flow is operable by touch and keyboard at 360px-desktop, with touch-friendly dialogs and no WCAG 2.1 AA violations.

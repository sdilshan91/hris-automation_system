# TC-PRF-002-10: File attachment limits -- max 5 files / 10MB each per goal, at and past the boundary (FR-5)

## 1. Test Objective
Verify FR-5: each goal supports up to 5 evidence file attachments, each at most 10MB. Exactly 5 files and a file of exactly 10MB are accepted (inclusive limits); a 6th file and a file of 10MB + 1 byte are rejected with a clear error, both client-side and server-side.

## 2. Related Requirements
- User Story: US-PRF-002
- Functional Requirements: FR-5
- Data Requirements: S7 (optional file attachments per goal)

## 3. Preconditions
- acme cycle FY26-H1 self-assessment window open; Asha authenticated with `Performance.Read.Self`; at least one goal exists.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| 5 files | 5 valid attachments | at the file-count limit |
| 6th file | one more | over the limit |
| 10MB file | exactly 10,485,760 bytes | at the size limit |
| 10MB+1 file | 10,485,761 bytes | over the limit |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Attach 5 files (each <= 10MB) to Goal 1 | All 5 accepted and listed; the add-file control is disabled/blocked for a 6th. |
| 2 | Attempt to attach a 6th file to Goal 1 | Rejected with "maximum 5 files per goal" (FR-5); a bypass upload returns 400/422; only 5 attachments persist. |
| 3 | Attach a file of exactly 10MB to another goal | Accepted (limit is inclusive). |
| 4 | Attempt a file of 10MB + 1 byte | Rejected with "file exceeds 10MB" (FR-5); bypass upload returns 400/413; not persisted. |
| 5 | Inspect persisted attachments | At most 5 attachments per goal, none exceeding 10MB; each linked to the correct goal and self-assessment, tenant-scoped (tenant_id=acme). |

## 6. Postconditions
- No goal holds more than 5 attachments or any file over 10MB; inclusive boundary values are accepted.

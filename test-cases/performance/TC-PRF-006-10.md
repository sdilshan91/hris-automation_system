# TC-PRF-006-10: Meeting-notes template + sections + rich-text XSS/HTML sanitization (FR-1, FR-2, S10)

## 1. Test Objective
Verify FR-1/FR-2 and the S10 sanitization constraint: the meeting-notes editor uses the tenant-configured template with the required sections (key strengths, development areas, agreed actions with deadlines, overall summary), agreed actions support deadline fields, and rich text is stored as SANITIZED HTML to prevent XSS. Verify malicious markup (`<script>`, event handlers, `javascript:` URLs) is stripped/neutralized on save and never executes when the notes are rendered to the employee or in the PDF/export.

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-1 (templated editor)
- Functional Requirements: FR-1 (configurable tenant template), FR-2 (four sections + agreed actions with deadlines)
- Assumptions/Constraints: S10 (rich text stored as sanitized HTML to prevent XSS)

## 3. Preconditions
- Tenant "acme", Performance module enabled; a tenant meeting-notes template is configured.
- Manager "Maya Shah" (`Performance.Review.Team`) authenticated; Liam's manager review is submitted (BR-1 met).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Template sections | strengths / development areas / agreed actions+deadlines / summary | FR-2 |
| XSS payload | `<script>alert('x')</script>`, `<img src=x onerror=alert(1)>`, `<a href="javascript:alert(1)">` | S10 |
| Deadline | 2026-09-30 on an agreed action | FR-2 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open "Add Meeting Notes" | The editor is pre-populated with the tenant template containing exactly the four sections, with deadline inputs on agreed actions (FR-1/FR-2). |
| 2 | Enter an agreed action with a deadline date and valid prose in each section; save | Notes persist with the section structure and the action deadline retained (FR-2). |
| 3 | Inject the XSS payloads into the rich-text sections and save (`POST .../meeting-notes`) | The server sanitizes the stored HTML -- `<script>`, `onerror`/`onclick` handlers, and `javascript:` URLs are stripped or neutralized (S10); benign formatting (bold/lists) is preserved. |
| 4 | Render the saved notes to the employee (and in the PDF export) | No script executes; the payload appears as inert text or is removed; no alert fires in the browser (verify via console -- no injected execution). |
| 5 | Attempt a SQL-injection-style string in a section (`'; DROP TABLE review_meeting_notes;--`) | Stored as literal text via parameterized persistence; no SQL side effect; renders inertly. |

## 6. Postconditions
- Meeting notes follow the tenant template with the four sections + action deadlines; stored HTML is sanitized; no stored XSS is rendered or executed.

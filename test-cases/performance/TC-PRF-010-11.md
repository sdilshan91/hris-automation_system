# TC-PRF-010-11: Compensation fields within recommendations encrypted at rest (pgcrypto) -- asserted at the encryption seam (conditional)

## 1. Test Objective
Verify NFR-3: compensation data within recommendations (bonus amount, increment value/percentage, recommended pay, current compensation snapshot) is encrypted at rest using pgcrypto, as it constitutes sensitive financial PII. Asserted at the encryption SEAM: cleartext compensation values are not stored in the clear on disk; the application reads/writes them through the field-encryption boundary. Conditional on column-level encryption being wired (consistent with the US-PRF-008 pgcrypto posture).

## 2. Related Requirements
- User Story: US-PRF-010
- Non-Functional Requirements: NFR-3 (compensation encrypted at rest via pgcrypto)
- Data Requirements: S7 (sensitive compensation fields encrypted)

## 3. Preconditions
- Tenant "acme"; a recommendation with compensation details (bonus $5,000 / increment 5% -> $94,500) exists.
- Direct database/storage inspection access for the test (read raw column bytes).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Bonus amount | $5,000 | sensitive |
| Increment value | $94,500 | sensitive |
| Recommended pay | band midpoint | sensitive |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a recommendation with a bonus amount $5,000 via the API | The recommendation persists; the API round-trips the cleartext value to authorized callers. |
| 2 | Query the underlying storage column directly (raw bytes) | The compensation column does NOT contain the cleartext "5000" / "94500" -- it is ciphertext (pgcrypto) or routed through the field-encryptor seam. If column encryption is not yet wired, the test asserts the write path routes through the encryption SEAM (`IFieldEncryptor`/pgcrypto) and documents pgcrypto-at-rest as the extension point. |
| 3 | Read the recommendation back via the API as a comp-authorized HR user | The cleartext value is correctly decrypted and returned (round-trip integrity). |
| 4 | Read as a comp-UNauthorized user (TC-PRF-010-09 Robin) | The compensation field is masked/omitted regardless of encryption -- authz and encryption are independent controls. |
| 5 | Confirm tenant scoping holds | Encryption does not weaken tenant isolation; acme rows remain isolated (NFR-2). |

## 6. Postconditions
- Compensation values are not stored in cleartext at rest (or the encryption seam is documented as the wiring point); cleartext round-trips only to authorized callers. Tenant-scoped to acme.

# TC-PRF-005-02: Employee cannot be nominated as their own Peer reviewer (BR-2)

## 1. Test Objective
Verify BR-2: an employee cannot review themselves in the Peer category; self-assessment is a separate, auto-assigned category. Attempting to add the reviewee themselves as a Peer reviewer is rejected client-side and server-side.

## 2. Related Requirements
- User Story: US-PRF-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-2
- Business Rules: BR-2

## 3. Preconditions
- 360-enabled cycle "FY26 Annual Review" active for acme.
- Reviewee "Liam Carter" with Self auto-assigned.
- HR Officer "Nadia Khan" authenticated with `Performance.Review.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Reviewee | Liam Carter | Self already auto-assigned |
| Attempted peer nomination | Liam Carter | == reviewee (invalid, BR-2) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In the 360 nomination UI for Liam, attempt to add Liam Carter himself as a Peer reviewer | The reviewee is excluded from / disabled in the peer auto-suggest and manual-add list; the UI prevents self-as-peer (BR-2). |
| 2 | Bypass the UI: `POST .../performance/360/{liamId}/assignments` with a Peer assignment where reviewer_id == reviewee_id == Liam | Server rejects with 400/422 and a clear message (e.g. "An employee cannot be their own peer reviewer"); no peer assignment row is created. |
| 3 | Confirm Self category is unaffected | Liam's Self (self-assessment) assignment remains intact as a separate category — BR-2 only blocks self-in-Peer, not self-assessment. |
| 4 | Inspect persisted assignments | No `feedback_360` Peer row exists with reviewer_id == reviewee_id. |

## 6. Postconditions
- Liam has no self-as-peer assignment; Self category intact; no orphan rows.

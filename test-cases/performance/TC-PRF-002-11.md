# TC-PRF-002-11: File upload security -- virus scan before acceptance + tenant-scoped storage path (NFR-4)

## 1. Test Objective
Verify NFR-4: every uploaded evidence file is virus-scanned before acceptance (a flagged file is rejected, not stored or linked) and accepted files are written to a tenant-scoped storage path so one tenant's evidence cannot be read or guessed from another tenant's path. Where no scanner is wired today, assert the scanning seam exists and is invoked, and that storage paths are tenant-scoped.

## 2. Related Requirements
- User Story: US-PRF-002
- Non-Functional Requirements: NFR-4
- Assumptions: file storage uses the platform document-management infra with tenant-scoped paths

## 3. Preconditions
- acme cycle FY26-H1 self-assessment window open; Asha authenticated with `Performance.Read.Self`.
- A test virus signature (e.g. EICAR test file) is available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Clean file | evidence.pdf (2MB) | should be accepted |
| Malicious file | EICAR test file | should be rejected by the scan |
| Disguised file | .exe renamed to .pdf | content-type/extension mismatch |
| Storage path pattern | `tenant/{tenantId}/performance/self-assessment/{cycleId}/...` | must include tenant id |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Upload the clean PDF | Accepted only AFTER the virus scan passes; the scan seam is invoked (asserted via the scan call/log). The file is stored and linked to the goal. |
| 2 | Upload the EICAR/malicious file | Rejected before persistence with a "file failed security scan" error; no file is stored and no attachment row is created. (If no scanner is wired today, assert the upload routes through the scan seam and document it as an extension point.) |
| 3 | Upload an `.exe` renamed to `.pdf` (content/extension mismatch) | Rejected by content-type sniffing / allowed-type validation; not stored. |
| 4 | Inspect the storage path of an accepted file | The path includes the acme tenant id (e.g. `tenant/{acmeId}/...`); it is not in a shared/global folder and not guessable across tenants. |
| 5 | As an authenticated globex user, attempt to fetch the acme file by its storage path/URL | Denied -- the file is served only within the owning tenant's context; no cross-tenant retrieval. |

## 6. Postconditions
- Malicious files are rejected pre-storage; accepted files live under tenant-scoped paths retrievable only within the owning tenant.

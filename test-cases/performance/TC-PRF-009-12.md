# TC-PRF-009-12: Boundary -> progress 0 and 100, notes exactly 2000 chars, exactly 3 files / exactly 10MB; BR-1 update only during the active cycle window

## 1. Test Objective
Verify the boundary values for a progress update (FR-2) and the BR-1 window gate: progress at exactly 0 and exactly 100 accepted; notes of exactly 2000 chars accepted (2001 rejected, TC-PRF-009-11); exactly 3 attachments accepted (4th rejected); an attachment of exactly 10MB accepted (10MB+1 rejected); and that updates are permitted only during the active cycle window (between goal-setting close and review-phase start) -- outside that window the add-update path is blocked server-side.

## 2. Related Requirements
- User Story: US-PRF-009
- Functional Requirements: FR-2 (limits)
- Business Rules: BR-1 (update only during the active cycle window)
- Acceptance Criteria: AC-2
- Dependencies: US-PRF-004 (cycle/window dates assumed seeded)

## 3. Preconditions
- Tenant "acme"; employee "Sam Lee" authenticated.
- Two scenarios available: (a) an OPEN active cycle window; (b) a cycle whose review phase has STARTED (tracking window closed) -- assumed seeded via US-PRF-004.

## 4. Test Data
| Field | Boundary | Expected |
|-------|----------|----------|
| Progress | 0 | accepted |
| Progress | 100 | accepted (auto-Completed, BR-2) |
| Notes | exactly 2000 chars | accepted |
| Attachments | exactly 3 files | accepted |
| Attachment size | exactly 10MB | accepted |
| Window | review phase started | update blocked (BR-1) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Post an update at progress 0 | Accepted -- 0% is a valid lower bound; status may be NotStarted/InProgress. |
| 2 | Post an update at progress 100 | Accepted -- 100% is the valid upper bound and auto-sets Completed (BR-2, TC-PRF-009-05). |
| 3 | Post an update with notes exactly 2000 chars | Accepted -- at the max boundary; 2001 is rejected (TC-PRF-009-11). |
| 4 | Post an update with exactly 3 attachments, each <=10MB | Accepted -- at the file-count max; a 4th is rejected. |
| 5 | Post an update with one attachment of exactly 10MB | Accepted -- at the size max; 10MB+1 is rejected. |
| 6 | Switch to the cycle whose review phase has started; attempt to add an update | Blocked server-side (BR-1) -- the add-update action is disabled in the UI and the API rejects it (the tracking window is closed). |
| 7 | Verify before-window-open | Before goal-setting closes (if applicable), updates are likewise not yet permitted per the documented window rule. |

## 6. Postconditions
- All boundary values accepted at their limits; updates outside the active cycle window are blocked. No invalid persistence.

# TC-PRF-005-05: Unauthorized user configuring 360 / submitting on another's behalf is rejected (authz)

## 1. Test Objective
Verify authorization on the 360 surface: only an HR Officer with `Performance.Review.All` (or the reviewee's reporting manager, per AC-1) may configure 360 reviewers and release results; a regular employee, a non-managing manager, or an unauthenticated caller is blocked. A reviewer may only submit feedback for an assignment that belongs to them (no submitting on another reviewer's behalf, incl. IDOR).

## 2. Related Requirements
- User Story: US-PRF-005
- Acceptance Criteria: AC-1, AC-2, AC-3
- Functional Requirements: FR-1, FR-2
- Non-Functional Requirements: NFR-2

## 3. Preconditions
- 360-enabled cycle "FY26 Annual Review" active for acme; Liam Carter under review with assignments created.
- Employee "Priya Nair" (no Performance permissions) authenticated in acme.
- A manager "Raj Patel" who is NOT Liam's manager and lacks `.All`, authenticated in acme.
- Peer reviewer "Ava Reyes" and a different reviewer "Ben Cho", both authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Unauthorized employee | Priya Nair | no perms |
| Non-managing manager | Raj Patel | not Liam's manager, no .All |
| Reviewer A / B | Ava Reyes / Ben Cho | distinct assignments |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Priya, call `POST .../performance/360/{liamId}/assignments` and `GET` the 360 config UI | 403 Forbidden; the config UI is not reachable (role guard) — no reviewer can be configured. |
| 2 | As Raj (non-managing manager without `.All`), attempt to configure Liam's 360 and to release results | 403 Forbidden — AC-1 limits configuration to HR `.All` or the reviewee's own reporting manager. |
| 3 | Unauthenticated: call the 360 config/submit/release endpoints with no bearer | 401 Unauthorized. |
| 4 | As Ava, attempt to submit feedback against Ben's assignment id (`POST .../feedback/{benAssignmentId}/submit`) | 403/404 — a reviewer can only submit for their OWN assignment; IDOR by assignment id is blocked. |
| 5 | As Ava, submit against her own assignment | 200 — legitimate path still works. |

## 6. Postconditions
- Only authorized users configure/release 360; reviewers submit only their own feedback; no cross-reviewer submission.

# TC-PRF-001-01: Manager sets goals summing to 100%, goals saved and employee notified (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1, AC-2, FR-1/2/3/7: an authenticated Manager with `Performance.SetGoal.Team` opens the goal-setting form for a direct report during an open goal-setting window (AC-1), enters multiple valid goals whose weights are in 5% increments and sum to exactly 100% (FR-2/3, BR-3), clicks "Save Goals", and the system persists all goals scoped to the tenant, links them to the employee and active cycle, and sends an in-app notification to the employee (AC-2, FR-7).

## 2. Related Requirements
- User Story: US-PRF-001
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-3, FR-7
- Business Rules: BR-2, BR-3, BR-4
- Data Requirements: S7 (goal record: id, tenant_id, employee_id, cycle_id, weight, audit fields)

## 3. Preconditions
- Tenant "acme" exists, status Active, subdomain `acme.yourhrm.com`, Performance module enabled.
- An active appraisal cycle "FY26-H1" exists in acme (created via US-PRF-004) with the goal-setting window OPEN (start <= today <= end).
- Manager "Ravi Kumar" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Performance.SetGoal.Team`.
- Employee "Asha Patel" is a direct report of Ravi in the org tree and has no goals yet for FY26-H1.

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to `https://acme.yourhrm.com/performance/goals?employeeId={asha}&cycleId={fy26h1}` | The goal-setting form displays with fields: title, description, category (KPI/Competency/Project), weight (%), target value, measurement unit, due date (AC-1). The window is open so the form is editable. |
| 2 | Add Goal 1 (Revenue target, KPI, 40%, target 1,000,000, USD, due 2026-12-31) | Goal card added; weight bar shows 40% allocated, 60% remaining. |
| 3 | Add Goal 2 (Code quality, Competency, 35%) and Goal 3 (Onboarding revamp, Project, 25%) | Weight distribution bar shows 100% allocated, 0% remaining; "Save Goals" enabled. |
| 4 | Click "Save Goals"; observe `POST /api/v1/performance/goals` | Request carries `X-Tenant-Subdomain: acme` + bearer; response 201 Created; body lists 3 goals each with `id` (UUID), `tenant_id`=acme, `employee_id`=Asha, `cycle_id`=FY26-H1, `created_by`=Ravi, `created_at`/`updated_at`. |
| 5 | Inspect the persisted rows | 3 goal rows exist for acme with `tenant_id`=acme, total weight = 100, status = `draft` (or `submitted` per FR-2 flow). |
| 6 | Check Asha's notification feed; observe the enqueue | An in-app notification "New goals have been assigned for FY26-H1" is enqueued/delivered to Asha (AC-2, FR-7). Email delivery is CONDITIONAL on the Notification System (S25) — the enqueue is asserted here. |

## 6. Postconditions
- Three tenant-scoped goals exist for Asha Patel in cycle FY26-H1 totalling 100% weight; Asha has an in-app goal-assignment notification.

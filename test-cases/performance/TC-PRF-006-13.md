# TC-PRF-006-13: Meeting-notes editor loads within 400ms (P95) (NFR-1)

## 1. Test Objective
Verify NFR-1: the meeting-notes editor (template + the employee's goals/ratings reference data + any existing draft notes) loads within 400ms at the 95th percentile. The load query must be tenant-scoped and avoid N+1 access when pulling goals/ratings for the template reference.

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-1 (editor open)
- Non-Functional Requirements: NFR-1 (editor loads <=400ms P95)

## 3. Preconditions
- Tenant "acme" seeded with a performance environment: a review with the maximum realistic number of goals + ratings for the template reference.
- Liam's manager review is submitted (BR-1) so the editor is reachable.
- A performance harness is available to issue repeated requests and compute percentiles.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Goals on review | realistic max (e.g. 10) | template reference data |
| Sample size | >=100 requests | for P95 |
| SLA | <=400ms P95 | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm caches; issue >=100 sequential `GET .../reviews/{reviewId}/meeting-notes/editor` (template + goals/ratings) requests | Responses return the editor payload tenant-scoped to acme. |
| 2 | Record server processing time per request and compute the P95 | P95 <= 400ms (NFR-1). |
| 3 | Inspect the data access for the goals/ratings reference | No N+1 -- goals + ratings load in a bounded number of queries; the query is filtered by tenant + review. |
| 4 | If a cache layer (S10) backs the editor reference data | Cache keys are tenant-scoped (no shared/global key); CONDITIONAL on a cache layer existing -- if computed on demand, assert tenant-filtered queries with no shared key. |

## 6. Postconditions
- The editor consistently loads within the 400ms P95 SLA with tenant-scoped, non-N+1 data access.

# TC-PRF-004-01: HR creates a cycle with valid non-overlapping sequential phases + scope, Hangfire jobs scheduled, confirmation (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1, AC-2 and FR-1/2/3/5/6: an authenticated HR Officer with `Performance.SetGoal.All` (or `Performance.Publish.All`) opens the "Create New Cycle" form (AC-1), fills in a valid cycle (name, period, >=3 sequential non-overlapping phases each within the cycle window, participant scope, rating scale, 360/calibration toggles, self:manager weights), clicks "Create Cycle", and the system persists the cycle + phases + participants scoped to the tenant, schedules Hangfire jobs for phase-transition notifications and deadline reminders, and displays a confirmation (AC-2).

## 2. Related Requirements
- User Story: US-PRF-004
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-3, FR-5, FR-6
- Business Rules: BR-3 (phase dates within cycle window)
- Data Requirements: S7 (cycles, cycle_phases, cycle_participants — all with tenant_id)

## 3. Preconditions
- Tenant "acme" exists, status Active, subdomain `acme.yourhrm.com`, Performance module enabled.
- A rating scale (e.g. 1-5) is configured in acme Performance settings (precondition for cycle creation).
- Employee records, departments and grades are set up in Core HR for acme.
- HR Officer "Maya Shah" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Performance.SetGoal.All` and `Performance.Publish.All`.

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to `https://acme.yourhrm.com/performance/cycles` and click "Create New Cycle" | The cycle creation form displays with fields: cycle name, period (start/end), phases (goal-setting, self-assessment, manager-review, calibration, publish) each with their own date ranges, participant scope (all / departments / grades), rating scale selection, 360-degree toggle (AC-1). |
| 2 | Fill in name, type, period, the five phase date ranges (sequential, non-overlapping, all inside 2026-07-01..2026-12-31), scope to Engineering + Sales, select Scale 1-5, set self:manager 40:60, enable 360 + calibration | Inline validation passes; no overlap/out-of-range/reversed-date errors; "Create Cycle" enabled. |
| 3 | Click "Create Cycle"; observe `POST /api/v1/tenant/performance/cycles` | Request carries `X-Tenant-Subdomain: acme` + bearer; response 201 Created; body has cycle `id` (UUID), `tenant_id`=acme, status `Draft`, participant count = headcount of Engineering+Sales, 5 phase rows, `created_by`=Maya, scheduled job ids. |
| 4 | Inspect persisted rows | One `cycles` row (tenant_id=acme), five `cycle_phases` rows linked to the cycle, N `cycle_participants` rows (one per scoped employee), all stamped tenant_id=acme. |
| 5 | Inspect Hangfire scheduled jobs for this cycle | Phase-start, deadline-reminder, phase-close and overdue-escalation jobs are registered for the cycle, each carrying the acme tenant context (FR-5). |
| 6 | Observe the UI | A confirmation is displayed (e.g. "Cycle 'FY26 Annual Review' created" with the participant count + scheduled-reminder summary) (AC-2). |

## 6. Postconditions
- A Draft cycle "FY26 Annual Review" exists for acme with 5 phases, participants from Engineering+Sales, and Hangfire jobs registered under the acme tenant.

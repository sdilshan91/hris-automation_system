# TC-PRF-007-01: HR opens Performance Dashboard -> overview shows completion rate, average score, distribution histogram, department bar, top/bottom performers, cycle progress (happy path)

## 1. Test Objective
Verify the primary success flow for AC-1 and FR-1/2/3/6: an authenticated HR Officer with `Performance.Read.All` + `Reports.View.All` navigates to Performance > Dashboard for a tenant with at least one completed or in-progress appraisal cycle, and the system renders the overview widgets computed over the tenant's org-wide population: (a) cycle completion rate (% of reviews completed); (b) average performance score; (c) score distribution histogram (rating distribution / bell curve, FR-1, chart.js); (d) department-wise average bar chart (FR-2); (e) top N and bottom N performers list with name/department/score/trend indicator (FR-3, default N=10); and (f) cycle progress metrics -- total participants, completed goal-setting, completed self-assessment, completed manager review, signed off (FR-6). All values are tenant-scoped and consistent with the underlying review data.

## 2. Related Requirements
- User Story: US-PRF-007
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-2, FR-3, FR-6
- Non-Functional Requirements: NFR-3 (aggregates via materialized view / Redis -- mechanism), NFR-4 (chart.js)
- Data Requirements: S7 (performance_summary materialized view aggregating by department/grade/cycle; tenant_id scoped)

## 3. Preconditions
- Tenant "acme" exists, status Active, subdomain `acme.yourhrm.com`, Performance module enabled.
- At least one appraisal cycle "FY26 Annual Review" exists for acme with SUBMITTED/completed reviews across multiple departments (US-PRF-003/004).
- The performance_summary materialized view is populated (refreshed) for acme (BR-4 / S7).
- HR Officer "Nadia Khan" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Performance.Read.All` + `Reports.View.All`.
- Seeded data has a known org-wide average score, a known completion rate, and identifiable top/bottom performers so assertions are deterministic.

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Nadia, navigate to `https://acme.yourhrm.com/performance` > Dashboard; observe `GET .../performance/dashboard/overview?cycleId=FY26` | Request carries `X-Tenant-Subdomain: acme` + bearer; 200; payload contains completionRate, averageScore, distribution buckets, departmentAverages[], topPerformers[], bottomPerformers[], cycleProgress{} -- all for acme only (NFR-2). |
| 2 | Observe the completion-rate widget (donut) + average-score KPI | Completion rate = seeded % (reviews completed / total participants); average score = seeded org-wide mean (AC-1, FR-6). |
| 3 | Observe the score distribution histogram (FR-1) | A chart.js histogram renders the rating distribution (counts per score band) over the org-wide population; bucket counts sum to the participant count (minus excluded probation per BR-2, see TC-PRF-007-09). |
| 4 | Observe the department-wise average bar chart (FR-2) | A horizontal bar chart shows each department's average score; bars match the seeded per-department means; only acme departments appear. |
| 5 | Observe the top/bottom performers list (FR-3) | Top 10 and bottom 10 performers render with name, department, score, and a trend indicator (vs prior cycle); the seeded highest/lowest scorers appear in the correct lists. |
| 6 | Observe the cycle progress widget (FR-6) | Shows total participants, completed goal-setting, completed self-assessment, completed manager review, and signed-off counts; counts reconcile with the cycle's review states. |
| 7 | Confirm aggregate source | The overview is served from the performance_summary materialized view / cached aggregate (NFR-3), not a row-by-row real-time scan (asserted indirectly via response time TC-PRF-007-11 + the refresh seam TC-PRF-007-13). |

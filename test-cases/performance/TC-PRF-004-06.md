# TC-PRF-004-06: Phase extension re-validates sequencing/non-overlap, reschedules Hangfire jobs, notifies affected participants (AC-5)

## 1. Test Objective
Verify AC-5 and FR-2/FR-5: when the HR Officer edits a cycle to extend a phase end date, the system re-validates that phase dates remain sequential and non-overlapping (and within the cycle window), updates the affected Hangfire job schedules (deadline reminders / phase-close / overdue), and notifies the affected participants of the new deadline.

## 2. Related Requirements
- User Story: US-PRF-004
- Acceptance Criteria: AC-5
- Functional Requirements: FR-2, FR-5
- Non-Functional Requirements: NFR-3 (tenant-scoped, resilient jobs)
- Business Rules: BR-3

## 3. Preconditions
- Active cycle "FY26 Annual Review" in acme; self-assessment phase currently 2026-08-01 .. 2026-08-31; manager-review 2026-09-01 .. 2026-09-30.
- Hangfire deadline-reminder + phase-close jobs are registered for the self-assessment phase end of 2026-08-31.
- 40 participants have not yet submitted self-assessment (the "affected" set).
- HR Officer Maya authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Phase | self-assessment | extend its end date |
| Old end | 2026-08-31 | |
| New end (invalid) | 2026-09-07 | would overlap manager-review starting 2026-09-01 — rejected (step 1) |
| New end (valid) | manager-review moved to 2026-09-08+ so phases stay sequential | extension accepted once downstream phase is shifted (step 2) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the cycle edit form and change the self-assessment end date from 2026-08-31 to 2026-09-07 (which would now overlap manager-review starting 2026-09-01) | Validation rejects: the extension would overlap manager-review; HR is prompted to also move manager-review or pick an earlier end (AC-5 sequencing re-check). |
| 2 | Change the self-assessment end to 2026-08-31 -> a valid non-overlapping value, and shift manager-review start to 2026-09-08 so phases stay sequential; save — `PUT .../cycles/{id}/phases` | 200 OK; phases persist sequential, non-overlapping, within the cycle window. |
| 3 | Inspect Hangfire jobs after save | The self-assessment deadline-reminder, phase-close and overdue jobs are rescheduled to the new dates (old schedules removed/updated); jobs still carry the acme tenant context (NFR-3). |
| 4 | Check notifications | The 40 non-submitters (affected participants) receive an in-app notification of the new self-assessment deadline; participants who already submitted are NOT notified. Email delivery is CONDITIONAL on the Notification System (S25) — the enqueue is asserted. |
| 5 | Attempt to extend a phase end past the cycle's overall end date | Rejected (BR-3) — same boundary rule as TC-PRF-004-03 applies on edit. |

## 6. Postconditions
- The phase has its new valid end date; Hangfire jobs match the new schedule; affected participants were notified.

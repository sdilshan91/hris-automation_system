# TC-PRF-008-03: PIP lifecycle (positive) Draft -> Active -> checkpoint recorded -> Extended (new end date + additional objectives) -> Successfully Completed (employee returns to normal status) (AC-4, FR-2/FR-6)

## 1. Test Objective
Verify the positive PIP lifecycle for AC-4 (FR-2/FR-6): a PIP progresses Draft -> Active, has a checkpoint recorded, is EXTENDED with a new end date and additional objectives (FR-6), and at the end HR reviews the checkpoint summary and sets the final outcome "Successfully Completed", which closes the PIP and returns the employee to normal status. The full status enum (Draft, Active, Extended, Successfully Completed) is exercised; each transition is recorded immutably (FR-5).

## 2. Related Requirements
- User Story: US-PRF-008
- Acceptance Criteria: AC-4
- Functional Requirements: FR-2 (status lifecycle), FR-6 (extension), FR-5 (immutable history)
- Business Rules: BR-1 (HR closes/extends)
- Data Requirements: S7 (pip, pip_objectives, pip_checkpoints)

## 3. Preconditions
- An Active PIP for Sam Lee exists in acme with a checkpoint due 2026-07-31 (TC-PRF-008-01).
- HR Officer "Nadia Khan" is authenticated in acme with `Performance.Review.All` (BR-1).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| PIP | Sam Lee's Active PIP | 2026-07-01..2026-09-29 |
| Checkpoint outcome | On Track | recorded mid-PIP |
| New end date (Extend) | 2026-10-29 | FR-6 |
| Added objective | new title + success criteria + due 2026-10-15 | FR-6 |
| Final outcome | Successfully Completed | AC-4 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Confirm the PIP is Active (initiated in TC-PRF-008-01) | Status = Active; lifecycle started from Draft (FR-2). |
| 2 | Manager/HR records the 2026-07-31 checkpoint as On Track (per TC-PRF-008-02) | Checkpoint recorded; employee notified; status remains Active. |
| 3 | As Nadia, click "Extend PIP", set new end date 2026-10-29 + add an objective; `POST .../performance/pips/{id}/extend` | 200; status -> Extended (FR-2); end date updated; the additional objective persisted (FR-6); affected stakeholders notified; Hangfire jobs rescheduled to the new dates. |
| 4 | At the (extended) PIP end, as Nadia open the PIP outcome review | The system presents a summary of ALL recorded checkpoints and offers the outcomes: Successfully Completed / Extended / Not Met (AC-4). |
| 5 | Select "Successfully Completed"; `POST .../performance/pips/{id}/outcome` body `{outcome:"SuccessfullyCompleted"}` | 200; status -> Successfully Completed; PIP closed; the employee returns to normal status (no active PIP); end-state recorded immutably (FR-5). |
| 6 | Verify employee state | Sam Lee has NO active PIP afterwards; a new PIP could be initiated later (BR-2 no longer blocks). |
| 7 | Inspect history | The full transition trail Draft -> Active -> (checkpoint) -> Extended -> Successfully Completed is present and immutable (FR-5). |

## 6. Postconditions
- Sam's PIP is Successfully Completed and closed in acme; employee back to normal status; full immutable lifecycle history retained. No Tenant B data touched.

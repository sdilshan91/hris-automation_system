# TC-PRF-010-02: Auto-generate recommendations from configurable rating thresholds -> correct employees flagged with correct types; suggestions only, HR must review/submit

## 1. Test Objective
Verify AC-2 / FR-2 / BR-3: HR clicks "Auto-Generate Recommendations" and configures rule thresholds (e.g. rating >= 4.5 -> promotion eligible, rating >= 3.5 -> bonus eligible). The system applies the rules across all employees in the cycle, populates the correct recommendation types, and displays the results for HR review and adjustment. Auto-generated recommendations are SUGGESTIONS ONLY (BR-3) -- nothing is submitted/routed until HR reviews and submits each (or batch-submits after review). Rules are tenant configuration, not hard-coded (S10 / Assumptions).

## 2. Related Requirements
- User Story: US-PRF-010
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2 (rule-based auto-generation)
- Business Rules: BR-3 (auto-generated = suggestions only; HR must review and submit)
- Data Requirements: S7 (recommendations table; type, status draft)

## 3. Preconditions
- Tenant "acme"; HR Officer Pat Ng authenticated with `Performance.Publish.All`.
- Cycle FY25 Completed with published final ratings; a known score distribution: 2 employees >= 4.5, 4 employees in [3.5, 4.5), the rest < 3.5.
- A tenant configuration store for auto-generation rules exists (or is created in this test).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Rule 1 | rating >= 4.5 -> Promotion eligible | configurable threshold |
| Rule 2 | rating >= 3.5 -> Bonus eligible | configurable threshold |
| Emp A (4.7) | expect Promotion suggestion | >= 4.5 |
| Emp B (4.5) | expect Promotion suggestion | boundary inclusive |
| Emp C (3.5) | expect Bonus suggestion | boundary inclusive, < 4.5 |
| Emp D (3.2) | expect NO suggestion | below both thresholds |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Pat, in the FY25 workspace click "Auto-Generate Recommendations" | A rule-configuration wizard opens with a preview step (S8); thresholds are editable, not hard-coded. |
| 2 | Configure Rule 1 (>= 4.5 -> Promotion) + Rule 2 (>= 3.5 -> Bonus); preview | The preview shows which employees each rule would flag BEFORE applying. |
| 3 | Apply | `POST .../performance/recommendations/auto-generate` returns the generated set; Emp A (4.7) + Emp B (4.5) get Promotion suggestions, Emp C (3.5) gets a Bonus suggestion, Emp D (3.2) gets none (FR-2). A 4.6-rated employee gets Promotion (>= 4.5 wins the higher tier per the documented precedence). |
| 4 | Inspect persisted state | Each generated recommendation has status = Draft (NOT Submitted/Pending Approval); none has been routed to the approval workflow (BR-3). All tenant-scoped to acme. |
| 5 | As Pat, adjust one suggestion (e.g. change Emp C from Bonus to Increment) and leave others | HR can review/adjust freely; the change persists as Draft, no workflow routing yet. |
| 6 | Confirm submission is separate | Only after HR clicks Submit (TC-PRF-010-01/-04) does a recommendation route to approval; auto-generation alone never submits (BR-3). |

## 6. Postconditions
- A set of Draft recommendation suggestions exists for acme matching the configured thresholds; none is submitted or routed. HR can review, adjust, and later submit. No cross-tenant data.

# TC-PRF-009-08: Append-only -> attempt to modify or delete a progress update via API -> rejected (NFR-3)

## 1. Test Objective
Verify NFR-3: the progress update history is append-only -- once a progress update is submitted it cannot be modified or deleted by anyone, including the authoring employee, their manager, or HR. Direct API attempts (PUT/PATCH/DELETE on an update) are rejected, and the persisted history remains intact for audit compliance. Corrections are made by posting a NEW update, never by mutating an old one.

## 2. Related Requirements
- User Story: US-PRF-009
- Non-Functional Requirements: NFR-3 (append-only, audit compliance)
- Functional Requirements: FR-3 (history)
- Data Requirements: S7 (goal_progress_updates append-only)

## 3. Preconditions
- Tenant "acme"; employee "Sam Lee" authenticated with `Performance.Read.Self`.
- Sam's goal has an existing progress update (id known) at 40%.
- An HR Officer "Nadia Khan" with `Performance.Review.All` exists in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Existing update | progress 40%, notes "draft v1" | target of mutation attempts |
| Tampered values | progress 99%, notes "edited" | should never persist |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam, attempt `PUT/PATCH .../performance/goals/{goalId}/updates/{updateId}` with progress 99% / notes "edited" | Rejected (405 Method Not Allowed / 403 / 409) -- no update route exists; the stored update remains 40% / "draft v1". |
| 2 | As Sam, attempt `DELETE .../performance/goals/{goalId}/updates/{updateId}` | Rejected -- the update is not deleted; the history count is unchanged. |
| 3 | As Nadia (HR `.All`), repeat the modify + delete attempts | Also rejected -- even HR cannot edit/delete a recorded update (NFR-3); no privileged bypass. |
| 4 | Inspect the persisted update | Still progress 40%, notes "draft v1", original server timestamp -- byte-for-byte unchanged. |
| 5 | Post a NEW update at 99% as the legitimate correction path | Accepted -- a new history entry is appended; both the 40% and 99% entries now appear in the timeline (TC-PRF-009-02). |
| 6 | Verify at the DB level | The goal_progress_updates row for the original id is unchanged; the table grew by one row (the correction), with no UPDATE/DELETE applied to the original. |

## 6. Postconditions
- No progress update was ever modified or deleted via API; corrections are append-only new entries. The audit history is intact.

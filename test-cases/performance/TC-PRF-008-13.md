# TC-PRF-008-13: Checkpoint form usable on mobile (360px) for managers recording during in-person meetings + WCAG 2.1 AA across the PIP UI (NFR-5)

## 1. Test Objective
Verify NFR-5: the PIP UI -- and in particular the checkpoint recording form -- is accessible on mobile devices so managers can record checkpoint notes during in-person meetings. At 360px the checkpoint form is full-screen/single-column and fully operable (touch + keyboard); the PIP creation form, timeline view, and checkpoint modal meet WCAG 2.1 AA (keyboard operability, focus order, labels, status-color not conveyed by color alone, contrast).

## 2. Related Requirements
- User Story: US-PRF-008
- Non-Functional Requirements: NFR-5 (mobile checkpoint recording)
- UI/UX: S8 (timeline view, traffic-light status selector, full-screen mobile checkpoint form)
- Acceptance Criteria: AC-1 (creation form), AC-3 (checkpoint form)

## 3. Preconditions
- An Active PIP for Sam Lee exists in acme with an open checkpoint.
- Manager "Dana Cole" authenticated in acme on a 360px viewport (and tested up to desktop).
- An axe-core / WCAG audit tool + a screen reader are available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewport | 360px -> desktop | NFR-5 responsive |
| Surfaces | PIP form, timeline, checkpoint modal/form | AC-1/AC-3, S8 |
| Status selector | traffic light green/amber/red | must not be color-only |
| Standard | WCAG 2.1 AA | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana on a 360px viewport, open Sam's PIP and tap "Record Checkpoint" | The checkpoint form renders full-screen/single-column with no horizontal scroll; all inputs (status, evidence, comments, attachment) are reachable and operable via touch (NFR-5). |
| 2 | Operate the checkpoint form with keyboard only | Logical focus order, visible focus, all controls operable + submittable via keyboard (WCAG 2.1.1 / 2.4.7). |
| 3 | Inspect the traffic-light status selector (On Track/At Risk/Not Met) | Status is conveyed by TEXT/label + shape/icon, not color alone (WCAG 1.4.1); contrast of text/controls >= 4.5:1 (1.4.3). |
| 4 | Run axe-core on the PIP creation form, timeline, and checkpoint modal | No serious/critical WCAG 2.1 AA violations; all inputs have programmatic labels; the timeline is navigable. |
| 5 | Screen-reader pass over the checkpoint flow | Fields, status options, and the submit action are announced meaningfully; checkpoint outcome confirmation is announced. |
| 6 | Resize 360px -> tablet -> desktop | Layout reflows (full-screen mobile -> timeline+modal desktop) with no loss of content or function. |

## 6. Postconditions
- The PIP UI (esp. the checkpoint form) is mobile-operable at 360px and WCAG 2.1 AA compliant across viewports. No Tenant B data touched.

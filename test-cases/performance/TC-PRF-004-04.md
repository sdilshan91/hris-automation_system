# TC-PRF-004-04: Only authorized users can create/modify cycles; others rejected (negative / BR-1)

## 1. Test Objective
Verify BR-1: only users holding `Performance.SetGoal.All` or `Performance.Publish.All` may create, edit, clone, transition or cancel a cycle. A manager with only team-scoped permissions, a plain employee, and an unauthenticated caller are all rejected.

## 2. Related Requirements
- User Story: US-PRF-004
- Acceptance Criteria: AC-2, AC-5
- Functional Requirements: FR-1, FR-7, FR-8
- Business Rules: BR-1

## 3. Preconditions
- Tenant "acme" active with a Draft cycle "FY26 Annual Review".
- Manager "Ravi" has only `Performance.SetGoal.Team` (no `.All`).
- Employee "Asha" has no Performance management permissions.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Manager | Ravi | Performance.SetGoal.Team only |
| Employee | Asha | no cycle permissions |
| Unauth | (no token) | |
| Target cycle | FY26 Annual Review | Draft |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Ravi (`.Team` only) `POST /api/v1/tenant/performance/cycles` | 403 Forbidden; no cycle created (BR-1). |
| 2 | As Ravi attempt to edit phases / clone / change status / cancel the existing cycle | Each returns 403; cycle unchanged. |
| 3 | As Asha (no perms) attempt any cycle create/edit/clone/transition | 403 Forbidden on every endpoint. |
| 4 | With no bearer token, call any cycle write endpoint | 401 Unauthorized. |
| 5 | In the UI, log in as Ravi / Asha and navigate to `/performance/cycles` | "Create New Cycle" and edit/clone/cancel controls are hidden or disabled; direct navigation to the create form is blocked by the role guard. |
| 6 | As Maya (`.All`) repeat a create | 201 Created — confirms the rule does not over-block authorized users. |

## 6. Postconditions
- Cycle management is performed only by authorized HR users; no unauthorized mutation occurred.

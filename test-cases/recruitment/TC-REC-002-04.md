# TC-REC-002-04: Disallowed file type is rejected by content-based MIME validation (including .exe renamed to .pdf) (negative / security)

## 1. Test Objective
Verify AC-2 / BR-4 / FR-1: only allowed MIME types (application/pdf, application/vnd.openxmlformats-officedocument.wordprocessingml.document, application/msword) are accepted, and validation is based on the actual file content (magic bytes / sniffed content type), not just the file extension or the client-supplied `Content-Type`. A malicious executable renamed to `.pdf` must be rejected and never persisted.

## 2. Related Requirements
- User Story: US-REC-002
- Acceptance Criteria: AC-2
- Business Rules: BR-4
- Functional Requirements: FR-1
- Non-Functional Requirements: NFR-4 (malware-handling adjacent; scanning in TC-REC-002-10)

## 3. Preconditions
- Tenant "acme" exists; vacancy "Senior Backend Engineer" is `Open` and publicly listed.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Disguised executable | malware.pdf (actually a Windows PE/.exe), claimed Content-Type application/pdf | Extension + header spoofed |
| Disallowed type | photo.png, image/png | Not in allow-list |
| Allowed types | application/pdf, ...wordprocessingml.document, application/msword | Accepted |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit the application with `malware.pdf` (a `.exe` renamed to `.pdf`, claimed `Content-Type: application/pdf`) | The server sniffs the actual content (magic bytes), detects it is NOT a real PDF/DOCX/DOC, and rejects with a 4xx clear error; no record/blob is created. |
| 2 | Submit with `photo.png` (`image/png`) | Rejected -- PNG is not in the allowed MIME allow-list (BR-4). |
| 3 | Submit a genuine PDF, a genuine DOCX, and a genuine DOC in turn | Each is accepted (these three MIME types are the allow-list). |
| 4 | Verify the rejected attempts left no trace | No `applicant` row and no blob object exist for the rejected files. |
| 5 | Confirm extension-only spoofing cannot bypass validation | Validation does not rely on the filename extension or the client-declared Content-Type alone. |

## 6. Postconditions
- Only genuine PDF/DOCX/DOC files are persisted; disguised or disallowed files are rejected with no side effects.

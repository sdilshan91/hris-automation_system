# TC-REC-010-02: Pre-fill mapping fidelity from application + offer; pre-filled fields editable + visually distinct (AC-1, FR-2, FR-3)

## 1. Test Objective
Verify the data-mapping contract for the pre-filled form (AC-1, FR-2, FR-3, S7 Data Mapping): every source field is mapped to the correct employee field with the documented mapping, pre-filled fields are visually distinct (subtle highlight / "auto-filled" label), and the HR Officer can review AND modify ANY pre-filled value before creation (FR-3). Asserts each mapping pair explicitly and that an override of a pre-filled value (e.g. salary) is the value actually persisted on Create.

## 2. Related Requirements
- User Story: US-REC-010
- Acceptance Criteria: AC-1
- Functional Requirements: FR-2 (mapped pre-fill), FR-3 (review/modify/complete before create)
- Data Requirements: S7 Data Mapping (application -> employee; offer -> employee)
- UI/UX: S8 (pre-filled fields visually distinct + editable; section headers)

## 3. Preconditions
- Tenant "acme"; applicant {acme_applicantId} Hired with Accepted offer {acme_offerId} carrying KNOWN values for all mapped fields.
- HR Officer with `Recruitment.Manage.All` + `Employee.Create.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| applicant.first_name / last_name | "Maya" / "Fernando" | -> employee.first_name/last_name |
| applicant.email | maya.f@example.com | -> employee.email (+ user.email if account created) |
| applicant.phone | +94-77-1234567 | -> employee.phone |
| offer.offered_position | Senior Engineer | -> employee.job_title_id |
| offer.department_id | {engineeringDeptId} | -> employee.department_id |
| offer.offered_salary | 150000 | -> employee salary structure |
| offer.start_date | 2026-07-01 | -> employee.date_of_joining |
| offer.reporting_manager_id | {managerId} | -> employee.reporting_manager_id |
| Override | salary 150000 -> 155000 | HR edits a pre-filled value |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the convert form for {acme_applicantId} | Form opens; pre-filled fields render with a distinct "auto-filled" style/label vs. blank required fields (S8). |
| 2 | Verify application-sourced mapping | first_name=Maya, last_name=Fernando, email=maya.f@example.com, phone=+94-77-1234567 (FR-2). |
| 3 | Verify offer-sourced mapping | job title=Senior Engineer, department=Engineering, salary=150000, start_date/date_of_joining=2026-07-01, reporting manager={managerId}, probation period populated from offer (FR-2). |
| 4 | Edit a pre-filled value (salary 150000 -> 155000) | The field is editable (FR-3); the new value is accepted. |
| 5 | Complete required fields and Create Employee | The persisted employee carries the OVERRIDDEN salary 155000 (not 150000) and all other mapped values; HR's edits win over the pre-fill (FR-3). |
| 6 | Verify no unintended copy | resume/application documents remain LINKED to the applicant, not copied onto the employee (story assumptions); only the documented mapped fields transfer. |

## 6. Postconditions
- Employee created with the documented mapping + HR overrides; no data mutated beyond the conversion.

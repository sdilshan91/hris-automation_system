# TC-REC-005-13: Scheduling form + calendar/agenda view WCAG 2.1 AA -- keyboard, screen reader, contrast; responsive to 360px (agenda/list on mobile) (NFR-5)

## 1. Test Objective
Verify NFR-5 and the UI/UX notes: the interview scheduling form (interviewer multi-select, date/time picker, type/location/link fields, notes editor, notification preview) and the calendar view meet WCAG 2.1 AA and are responsive down to 360px, switching to a list/agenda view on screens < 768px. Covers keyboard operability (no mouse-only paths), screen-reader labelling, focus management for the slide-over/modal, color contrast (status color-coding must not be the ONLY signal), and conflict-highlight accessibility.

## 2. Related Requirements
- User Story: US-REC-005
- Non-Functional Requirements: NFR-5 (responsive 360px+, mobile agenda view)
- UI/UX: S8 (slide-over form, searchable multi-select, color-coded calendar, mobile agenda)
- Standard: WCAG 2.1 AA

## 3. Preconditions
- Tenant acme; recruiter with `Recruitment.Manage.All`; a running UI with seeded interviews.
- Tooling: keyboard-only, a screen reader (NVDA/VoiceOver), an automated a11y scanner (axe), and responsive viewport emulation.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewports | 360px, 768px, 1024px, 1920px | Responsive breakpoints |
| Mobile threshold | < 768px -> agenda/list view | UI note |
| Contrast target | >= 4.5:1 text / 3:1 UI | WCAG 1.4.3 / 1.4.11 |
| Status signal | color + text/icon | Not color-only (1.4.1) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the scheduling slide-over/modal and operate it keyboard-only | All controls reachable + operable via keyboard; focus is trapped in the dialog, returns to trigger on close; logical tab order (WCAG 2.1.1, 2.4.3). |
| 2 | Drive the interviewer multi-select and date/time picker with keyboard + screen reader | Options/time slots are announced with accessible names; selection is keyboard-operable; required fields + errors are announced (WCAG 1.3.1, 3.3.1, 4.1.2). |
| 3 | Trigger a validation error and a conflict warning | Errors/warnings are programmatically associated + announced; conflict highlight is conveyed by text/icon, not color alone (WCAG 1.4.1, 3.3.1). |
| 4 | Run an axe scan on the form, calendar, and notification preview | Zero critical/serious violations; contrast >= AA on text and status blocks (WCAG 1.4.3, 1.4.11). |
| 5 | Resize to 360px | Layout reflows with no horizontal scroll/clipping; the calendar switches to a list/agenda view; the form is full-width and usable (NFR-5, WCAG 1.4.10). |
| 6 | Verify across Chrome, Edge, Firefox, Safari | Form + calendar/agenda render and behave consistently (cross-browser). |

## 6. Postconditions
- The scheduling form and calendar/agenda are WCAG 2.1 AA compliant, keyboard + screen-reader operable, and responsive to 360px with a mobile agenda view.

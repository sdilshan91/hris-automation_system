# TC-REC-008-05: Application timeline shows a sanitized chronological activity log of status changes

## 1. Test Objective
Verify FR-6 (with BR-3/NFR-5): the portal renders a vertical timeline/activity log for each application showing the applicant-facing status events in chronological order -- e.g. "Application received", "Moved to Screening", "Interview scheduled", "Offer sent". The timeline is SANITIZED: it shows stage/event names and dates but NOT internal notes, rejection reasons, scorecard data, or interviewer comments (cross-checked in TC-REC-008-08). The underlying data comes from `applicant_stage_history` (US-REC-004) filtered to applicant-safe events.

## 2. Related Requirements
- User Story: US-REC-008
- Functional Requirements: FR-6 (timeline of status changes)
- Non-Functional Requirements: NFR-5 (no internal data exposed)
- Business Rules: BR-3 (sanitized view)
- Cross-story: US-REC-004 (`applicant_stage_history` source)

## 3. Preconditions
- Applicant {acme_applicantId} has a stage history: Applied (received) -> Screening -> Interview scheduled, plus at least one internal-only note + (for a different applicant) a rejection reason that must NOT surface here.
- Valid magic link available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| History events | Applied, Screening, Interview scheduled | applicant-safe |
| Internal note | "Strong on system design - fast-track" | must NOT surface |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the portal and view the application | A vertical timeline renders the events in chronological order (oldest -> newest) (FR-6). |
| 2 | Inspect the event labels | Events are applicant-facing: "Application received", "Moved to Screening", "Interview scheduled" -- each with its date (FR-6). |
| 3 | Inspect for internal data | The internal note "Strong on system design..." is NOT present; no rejection reason, scorecard score, or interviewer comment appears in any timeline entry (NFR-5, BR-3). |
| 4 | Verify scope | Only events for {acme_applicantId}'s own application(s) within acme are listed; no other applicant's events appear. |

## 6. Postconditions
- No data is mutated; applicant viewed a sanitized chronological timeline of their own application.

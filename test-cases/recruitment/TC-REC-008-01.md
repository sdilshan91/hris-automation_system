# TC-REC-008-01: Magic link grants access to the correct applicant in the correct tenant; dashboard shows application(s) + step indicator + status (happy path)

## 1. Test Objective
Verify the primary candidate-portal access flow (AC-1, FR-1/FR-2): an applicant who has submitted at least one application opens the candidate portal via the cryptographically signed, time-limited magic link from their confirmation email. On open, the system (a) resolves tenant context from the subdomain (NFR-3), (b) validates the HMAC-SHA256 token (signature, embedded tenant_id, applicant email, expiry), (c) loads ONLY that applicant's application(s) within the resolved tenant, and (d) renders a dashboard where each application card shows vacancy title, department, applied date, current pipeline stage as a horizontal step indicator (Applied -> Screening -> Interview -> Offer -> Hired, completed=green/current=blue/future=gray), and the status. No login/password is required (BR-6). The portal is read-only (BR-1).

## 2. Related Requirements
- User Story: US-REC-008
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1 (signed magic link), FR-2 (application list + step indicator + status)
- Non-Functional Requirements: NFR-3 (tenant resolved from subdomain), NFR-4 (HMAC-signed token)
- Business Rules: BR-1 (read-only), BR-4 (tenant from subdomain), BR-6 (no account; magic link is the auth)
- Data Requirements: S7 (`applicant_portal_token`; reads `applicant`)

## 3. Preconditions
- Tenant "acme" active; applicant {acme_applicantId} (email applicant@example.com) has >=1 application on {acme_vacancyId}, currently in the "Interview" stage.
- A valid, unexpired `applicant_portal_token` row exists for that email+tenant; the corresponding magic link URL is known (the token sent in the confirmation email).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Subdomain | acme.yourhrm.com | Active tenant; resolves tenant context |
| Applicant | {acme_applicantId} | email applicant@example.com |
| Application | {acme_vacancyId} | "Senior Engineer", Engineering, current stage Interview |
| Magic link | https://acme.yourhrm.com/portal?token={validToken} | HMAC-SHA256 signed; tenant_id+email+expiry embedded |
| Token expiry | now + 25 days | Within 30-day default window |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the magic link `https://acme.yourhrm.com/portal?token={validToken}` (no prior session/cookie) | Portal loads without prompting for login/password (BR-6); tenant context resolves to acme from the subdomain (NFR-3); token signature + expiry + embedded tenant_id/email validated server-side (FR-1, NFR-4). |
| 2 | Observe the dashboard | A single-column dashboard renders the applicant's application card(s): vacancy title "Senior Engineer", department "Engineering", applied date, and a horizontal step indicator Applied -> Screening -> Interview -> Offer -> Hired (FR-2). |
| 3 | Inspect the step indicator state | Applied + Screening rendered as completed (green), Interview as current (blue), Offer + Hired as future (gray); the textual status matches "Interview" (FR-2). |
| 4 | Verify scope | ONLY application(s) belonging to {acme_applicantId} (email match) within acme are shown; no other applicants' data is present (AC-1). |
| 5 | Attempt to edit any application field on the portal | No editable controls are offered; the portal is read-only for application data (BR-1). |
| 6 | Verify tenant branding | acme's logo + primary color from branding config are applied to the portal chrome. |

## 6. Postconditions
- No data is mutated; the applicant viewed their own application(s) within acme via the magic link; token remains valid (single view does not consume it).

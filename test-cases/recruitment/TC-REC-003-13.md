# TC-REC-003-13: Kanban accessibility (WCAG 2.1 AA) + keyboard-operable drag alternative + responsive at 360px (NFR-4)

## 1. Test Objective
Verify NFR-4 and accessibility requirements: the Kanban board is fully responsive (on mobile < 768px / down to 360px stages are horizontally scrollable or shown as a stacked list with stage filter tabs), and provides a keyboard-operable alternative to mouse drag-and-drop, with WCAG 2.1 AA conformance (focus order, labels, contrast, screen-reader announcements of stage moves).

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-1, AC-2
- Non-Functional Requirements: NFR-4
- UI/UX: S8 (mobile horizontal scroll / tab navigation)

## 3. Preconditions
- Tenant "acme" is active; a recruiter with `Recruitment.Manage.All` is authenticated.
- A vacancy with applicants across stages exists.
- An automated a11y checker (axe) and a screen reader (NVDA/VoiceOver) are available; viewports of 360px, 768px, 1280px, 1920px can be tested.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewports | 360, 768, 1280, 1920 px | Responsive range |
| Standard | WCAG 2.1 AA | Contrast >= 4.5:1 text |
| Browsers | Chrome, Edge, Firefox, Safari | Cross-browser |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Load the board at 360px | Stages are usable via horizontal scroll OR a stacked list with stage filter tabs; cards stack vertically within a stage; no content is clipped or overlapping (NFR-4, S8). |
| 2 | Tab through the board with the keyboard only | Logical focus order across columns and cards; every interactive element (filters, cards, action buttons, view toggle) is reachable and shows a visible focus indicator. |
| 3 | Move an applicant between stages using only the keyboard | A keyboard-operable alternative to mouse drag exists (e.g. focus a card -> activate "move" -> choose target stage); the move persists identically to drag-and-drop and is confirmed to the user. |
| 4 | With a screen reader active, perform a stage move | Column names + counts, card identity, and the result of a move ("Moved to Screening") are announced via accessible names / live region. |
| 5 | Run axe at each viewport | No serious/critical violations; color contrast for text, badges, and source pills meets >= 4.5:1 (>= 3:1 for large text/UI components). |
| 6 | Repeat key flows in Chrome, Edge, Firefox, Safari | Board, drag/keyboard move, detail slide-over, and filters behave consistently across browsers. |

## 6. Postconditions
- The board is operable by keyboard and screen reader and meets WCAG 2.1 AA across the responsive range and target browsers.

# TC-REC-003-06: Authorization -- view requires Recruitment.Read.All; stage move / bulk require Recruitment.Manage.All; others 403 (negative)

## 1. Test Objective
Verify BR-1 / BR-2: viewing the applicant pipeline requires `Recruitment.Read.All`; moving applicants between stages and performing bulk actions require `Recruitment.Manage.All`. A user lacking the relevant permission is denied (403), and the denial is enforced server-side (not just hidden in the UI).

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-1, AC-2
- Business Rules: BR-1, BR-2

## 3. Preconditions
- Tenant "acme" is active with three users:
  - `viewer@acme` has `Recruitment.Read.All` but NOT `Recruitment.Manage.All`.
  - `manager@acme` has `Recruitment.Manage.All`.
  - `noaccess@acme` has neither recruitment permission.
- A vacancy with applicants exists.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| viewer@acme | Recruitment.Read.All only | May view, may NOT move/bulk |
| manager@acme | Recruitment.Manage.All | May view + move + bulk |
| noaccess@acme | no recruitment perms | May NOT view |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `noaccess@acme`, `GET /api/v1/recruitment/vacancies/{vacancyId}/pipeline` | 403 Forbidden; no board data returned (BR-1). The pipeline nav entry is not actionable in the UI. |
| 2 | As `viewer@acme`, GET the pipeline | 200; board renders (BR-1 satisfied for view). |
| 3 | As `viewer@acme`, attempt a stage move `PATCH /api/v1/recruitment/applications/{applicantId}/stage` | 403 Forbidden; applicant stage unchanged (BR-2). The drag handles / move action are disabled in the UI for this user. |
| 4 | As `viewer@acme`, attempt a bulk move `POST /api/v1/recruitment/applications/bulk/stage` | 403 Forbidden; no applicants changed (BR-2). |
| 5 | As `manager@acme`, perform a stage move and a bulk move | Both succeed (200/204); changes persist -- confirms the 403s above are permission-specific, not a blanket block. |
| 6 | Verify DB after the denied attempts | No `applicant.pipeline_stage_id` changes and no `applicant_stage_history` rows from the denied `viewer@acme`/`noaccess@acme` requests. |

## 6. Postconditions
- Only `manager@acme`'s authorized moves persisted; unauthorized attempts produced 403 with no side effects.

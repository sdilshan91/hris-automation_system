# TC-REC-002-09: Resume filenames are sanitized and renamed to a UUID-based name (path-traversal prevention)

## 1. Test Objective
Verify BR-3 / FR-2: uploaded resume filenames are sanitized and renamed to a UUID-based name before storage, so a malicious or colliding filename cannot escape the tenant-scoped path, overwrite another object, or inject path segments. Path-traversal payloads in the filename must not affect the storage key.

## 2. Related Requirements
- User Story: US-REC-002
- Acceptance Criteria: AC-1, AC-2
- Business Rules: BR-3
- Functional Requirements: FR-2
- Non-Functional Requirements: NFR-3 (tenant isolation of the storage namespace)

## 3. Preconditions
- Tenant "acme" exists; vacancy "Senior Backend Engineer" is `Open` and publicly listed.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Traversal filename | `../../../../etc/passwd.pdf` | Attempted path escape |
| Backslash/UNC filename | `..\\..\\windows\\system32\\cv.pdf` | Windows traversal |
| Absolute-path filename | `/var/www/cv.pdf` | Leading-slash escape |
| Collision filename | `resume.pdf` (used by two different applicants) | Must not overwrite |
| Unicode/control chars | `re‮sumexe.pdf`, embedded NUL | Sanitized |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit a valid PDF whose filename is `../../../../etc/passwd.pdf` | Accepted as a normal PDF, but the stored object key is `{acme_tenantId}/recruitment/{vacancyId}/{applicantId}/{UUID}.pdf` -- the traversal segments are stripped; nothing is written outside the tenant prefix. |
| 2 | Repeat with the backslash/UNC and absolute-path filenames | Same -- stored key stays under the tenant-scoped prefix with a UUID-based name; no directory escape occurs. |
| 3 | Two different applicants each upload a file named `resume.pdf` | Each is stored under a distinct UUID-based key in its own `{applicantId}` folder; neither overwrites the other (no collision). |
| 4 | Submit a filename with unicode RTL-override / control / NUL characters | The name is sanitized; the persisted storage key contains only the safe UUID-based name and a clean extension. |
| 5 | Verify the storage layer | No object exists outside `{acme_tenantId}/recruitment/...`; the original (attacker-controlled) filename is not used as the storage key. |

## 6. Postconditions
- All resumes are stored under tenant-scoped, UUID-named keys; no traversal, overwrite, or namespace escape occurred.

# TC-REC-001-08: Authorization -- only Recruitment.Create.All / Recruitment.Manage.All can create or edit vacancies

## 1. Test Objective
Verify BR-1: only users holding `Recruitment.Create.All` or `Recruitment.Manage.All` can create or edit (and publish/close) vacancies. Authenticated users lacking these permissions are denied (403), and unauthenticated requests are rejected (401), at the API layer (not merely hidden in the UI).

## 2. Related Requirements
- User Story: US-REC-001
- Acceptance Criteria: AC-1 (Draft visible only to Read.All), AC-2, AC-3
- Business Rules: BR-1
- Non-Functional Requirements: NFR-2 (tenant-scoped authorization)

## 3. Preconditions
- Tenant "acme" with Recruitment enabled.
- User "Riley Park" holds `Recruitment.Create.All` (authorized creator).
- User "Morgan Lee" is an authenticated acme employee with NO recruitment permissions.
- User "Sky Reyes" holds `Recruitment.Read.All` only (read but not create/edit).
- An existing Draft vacancy exists in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Authorized | Riley Park (Create.All) | Can create/edit/publish/close |
| Read-only | Sky Reyes (Read.All) | Can view, cannot create/edit |
| No-permission | Morgan Lee | Cannot view Drafts, cannot create |
| Unauthenticated | (no token) | 401 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Riley Park, `POST /api/v1/recruitment/vacancies` with a valid payload | 201 Created (authorized). |
| 2 | As Sky Reyes (Read.All), attempt `POST /api/v1/recruitment/vacancies` | 403 Forbidden; no vacancy created. |
| 3 | As Sky Reyes, attempt `PUT /api/v1/recruitment/vacancies/{id}` and `.../publish` | 403 Forbidden on both. |
| 4 | As Sky Reyes, `GET` the Draft vacancy and listing | 200 OK -- read is permitted with Read.All (AC-1: Drafts visible to Read.All in the same tenant). |
| 5 | As Morgan Lee (no recruitment permission), attempt to GET the Draft vacancy | 403/404 -- Drafts are not visible without `Recruitment.Read.All`. |
| 6 | As Morgan Lee, attempt to create/edit a vacancy | 403 Forbidden. |
| 7 | With no Authorization header, call the create/edit endpoints | 401 Unauthorized. |
| 8 | Confirm the "New Vacancy"/edit controls are also hidden in the UI for Sky Reyes and Morgan Lee | Controls hidden client-side, but the API enforcement in steps 2-7 is the authoritative gate. |

## 6. Postconditions
- Only Create.All / Manage.All holders can mutate vacancies; Read.All can view; others and anonymous are denied.

# TC-REC-009-12: Dashboard loads within 2.5s P95 for a tenant with up to 10,000 applicant records; tenant-scoped caching (NFR-1, NFR-3)

## 1. Test Objective
Verify NFR-1: the dashboard (all KPIs + funnel + source + trend + status + recent activity) loads within 2.5 seconds at P95 for a tenant seeded with up to 10,000 applicant records (with associated stage history, offers, interviews). Measures the aggregation API/page-render path under that volume. NFR-3 caching (materialized view `mv_recruitment_analytics` and/or Redis with tenant-scoped keys) is asserted as a design contract — if pre-aggregation/Redis is not wired in this increment, the case measures the live-query path and asserts the tenant-scoped cache-KEY shape as a design check (CONDITIONAL, not a gap; must NOT be weakened).

## 2. Related Requirements
- User Story: US-REC-009
- Non-Functional Requirements: NFR-1 (<= 2.5s P95 @ 10k applicants), NFR-3 (materialized view / Redis cache, tenant-scoped keys)
- Acceptance Criteria: AC-1 (dashboard composition)
- Dependencies: Redis S27 (optional pre-aggregation), Hangfire S28 (optional MV refresh)

## 3. Preconditions
- Tenant "bigco" seeded with ~10,000 applicants across vacancies/stages, with offers, interviews, and stage history. A load/profiling harness can issue repeated dashboard requests and record latency percentiles.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant volume | ~10,000 | NFR-1 target tenant |
| Target | P95 <= 2.5s | full dashboard load |
| Cache key | tenant:{tenantId}:recruitment:dashboard:{periodHash}:{deptHash} | tenant-scoped (NFR-3) |
| MV (optional) | mv_recruitment_analytics | refreshed via Hangfire |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm the dashboard and issue a representative sample of dashboard loads against bigco | P95 end-to-end load time <= 2.5s (NFR-1). |
| 2 | Vary the date range and department filters across requests | P95 stays within 2.5s across filter combinations (no pathological filter that blows the SLA). |
| 3 | Inspect the analytics cache key (if caching/MV wired) | Key is tenant-scoped (includes tenant_id + period/dept hash); no global/shared key (NFR-3). CONDITIONAL: if caching not wired, assert the documented key shape + measure the live-query path. |
| 4 | (If MV used) Verify MV refresh cadence | `mv_recruitment_analytics` refreshed at most every 15 min via Hangfire (story assumption); reads serve from the MV. CONDITIONAL on MV being implemented. |

## 6. Postconditions
- No data mutated; dashboard meets the P95 SLA at target volume; cache keys (if present) are tenant-scoped.

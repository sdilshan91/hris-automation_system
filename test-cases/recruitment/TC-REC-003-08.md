# TC-REC-003-08: Backward (regressive) stage move requires Recruitment.Manage.All and a reason; forward-only enforced by default (negative + boundary)

## 1. Test Objective
Verify BR-4: stage transitions are unidirectional (forward-only) by default; a backward move (e.g. Interview -> Screening) is permitted only for users with `Recruitment.Manage.All` and only when a reason is supplied. A backward move without a reason, or by a non-Manage user, is rejected.

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-2
- Business Rules: BR-4, BR-5, BR-2 (Manage permission)
- Functional Requirements: FR-3

## 3. Preconditions
- Tenant "acme" is active with `manager@acme` (`Recruitment.Manage.All`) and `viewer@acme` (`Recruitment.Read.All` only).
- Applicant "Sam Patel" exists at stage "Interview".

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant | Sam Patel | At "Interview" |
| Backward target | Screening | Earlier in sequence |
| Reason | "Re-screen against new criteria" | Required for backward move |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `viewer@acme` (no Manage), attempt to move Sam Patel Interview -> Screening | 403 Forbidden (lacks Manage); stage unchanged (BR-4 requires Manage). |
| 2 | As `manager@acme`, attempt the backward move Interview -> Screening WITHOUT a reason | 4xx validation error "reason required for backward move"; stage unchanged; no history row (BR-4). |
| 3 | As `manager@acme`, retry the backward move WITH reason "Re-screen against new criteria" | 200/204; Sam Patel moves to "Screening". |
| 4 | Verify the persisted row + history | `pipeline_stage_id` = Screening; a new `applicant_stage_history` row records from "Interview", to "Screening", actor, timestamp, and the reason (BR-5). |
| 5 | As `manager@acme`, perform a normal forward move (e.g. Screening -> Interview) without a reason | Succeeds (forward is the default-allowed direction; reason not mandated for forward except where BR-3 applies) -- confirms the backward-reason requirement is direction-specific. |

## 6. Postconditions
- Backward move succeeded only under Manage + reason; unauthorized/reason-less backward attempts left no side effects.

# TC-REC-010-01: Convert a Hired applicant with an Accepted offer into an employee -> pre-filled form, employee created + linked, vacancy filled_count++ (happy path)

## 1. Test Objective
Verify the primary conversion flow end-to-end (AC-1, AC-2, FR-1, FR-2, FR-4, FR-6, FR-7, BR-4, BR-6): an HR Officer with `Recruitment.Manage.All` + `Employee.Create.All` clicks "Convert to Employee" on a Hired applicant whose offer is Accepted; a pre-filled employee creation form opens (data mapped from application + offer); the HR Officer completes the remaining required fields and clicks "Create Employee"; the system, in ONE atomic transaction, (a) creates an `employee` record in Core HR with the mapped + completed fields and an auto-generated employee number per the tenant pattern (FR-4), (b) links the applicant to the new employee via `converted_to_employee_id` + `converted_at` + `converted_by` (FR-6, BR-6), and (c) increments the vacancy's `filled_count` (FR-7). The new employee's `date_of_joining` defaults to the offer's `start_date` (BR-4). Atomicity/timing are measured in TC-REC-010-09/13; this case asserts the success path + correct linkage.

## 2. Related Requirements
- User Story: US-REC-010
- Acceptance Criteria: AC-1 (pre-filled form opens), AC-2 (employee created + applicant linked + filled_count++)
- Functional Requirements: FR-1 (action available only for Hired + Accepted), FR-2 (pre-fill mapping), FR-4 (auto employee number), FR-6 (applicant link fields), FR-7 (filled_count++)
- Business Rules: BR-4 (date_of_joining defaults to offer start_date), BR-6 (applicant not deleted; link created)
- Cross-story: US-REC-004/007 (Hired + Accepted preconditions), Core HR (employee creation), US-REC-009 (vacancy filled ratio surfaced on dashboard)

## 3. Preconditions
- Tenant "acme" active; user authenticated with `Recruitment.Manage.All` + `Employee.Create.All`.
- Applicant {acme_applicantId} on vacancy {acme_vacancyId} (headcount 3, filled_count 0) is in the "Hired" stage with an Accepted offer {acme_offerId} (offered job title, department, salary, reporting manager, start_date 2026-07-01).
- Tenant has NOT exceeded `MaxEmployees` (null/unlimited, or current count below the limit).
- Tenant employee-number pattern configured (e.g. `EMP-2026-####`).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open {acme_applicantId}'s detail panel; observe the "Convert to Employee" action | Action is present and enabled (applicant is Hired + offer Accepted) (FR-1). |
| 2 | Click "Convert to Employee" | A pre-filled employee creation form opens with mapped data: first/last name, email, phone (from application); job title, department, reporting manager, salary, start_date, probation period (from offer) (AC-1, FR-2). |
| 3 | Verify `date_of_joining` default | Pre-filled with the offer's start_date 2026-07-01 (BR-4). |
| 4 | Complete remaining required fields (employee number auto-generated, employment type, work location) and click "Create Employee" | Confirmation summary then 200/201; a new `employee` record is created in Core HR with mapped + completed fields; employee number = `EMP-2026-0042` per tenant pattern (AC-2, FR-4). |
| 5 | Verify applicant linkage | Applicant {acme_applicantId} now has `converted_to_employee_id` = new employee id, `converted_at` set, `converted_by` = current user; applicant record is NOT deleted (FR-6, BR-6). |
| 6 | Verify vacancy update | Vacancy {acme_vacancyId} `filled_count` incremented 0 -> 1; status stays Open (headcount 3 not yet filled) (FR-7). |
| 7 | Verify employee field fidelity | employee.first_name/last_name/email/phone match the application; job_title_id/department_id/reporting_manager_id/salary/date_of_joining match the offer mapping (FR-2, data mapping). |

## 6. Postconditions

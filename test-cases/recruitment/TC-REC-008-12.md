# TC-REC-008-12: Candidate portal loads within 2.5s (P95) on a 4G connection

## 1. Test Objective
Verify NFR-1: the candidate portal (dashboard + step indicator + interview + offer + timeline for an applicant with a typical application count) loads within 2.5 seconds at the 95th percentile on a simulated 4G connection. Measures the end-to-end first-meaningful-render including token validation, tenant resolution, and the sanitized portal DTO fetch, with skeleton loaders shown while data loads.

## 2. Related Requirements
- User Story: US-REC-008
- Non-Functional Requirements: NFR-1 (portal load <= 2.5s P95 on 4G)
- Functional Requirements: FR-2 (dashboard render)

## 3. Preconditions
- Applicant {acme_applicantId} with a representative dataset (1-3 applications, 1 upcoming interview, 1 offer, ~10 timeline events). Valid magic link available.
- Test harness can throttle to a 4G profile and run >=100 iterations for a P95.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Network profile | 4G (e.g. ~4 Mbps down, ~100ms RTT) | throttled |
| Dataset | 3 applications, 1 interview, 1 offer, 10 events | typical |
| Iterations | >= 100 | for P95 |
| Target | <= 2.5s P95 | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Throttle to the 4G profile; load the portal via the magic link >=100 times (cold + warm mix) | Each load validates the token, resolves tenant, fetches the portal DTO, and renders the dashboard. |
| 2 | Record load time (first meaningful render) per iteration | Skeleton loaders appear immediately; cards/step indicator populate on data arrival. |
| 3 | Compute the P95 load time | P95 <= 2.5s on the 4G profile (NFR-1). |
| 4 | Inspect the DTO size/queries | The sanitized DTO is compact (no oversized internal data); queries are tenant-scoped and bounded. |

## 6. Postconditions
- P95 portal load time recorded and within the 2.5s budget on 4G; no data mutated.

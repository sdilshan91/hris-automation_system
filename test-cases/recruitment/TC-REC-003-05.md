# TC-REC-003-05: Table/list view toggle shows the same pipeline as a sortable grid (alternative path)

## 1. Test Objective
Verify FR-4: the pipeline view provides a table/list view toggle offering a traditional grid layout with sortable columns, showing the same tenant-scoped applicant set as the Kanban board.

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-1 (same data, alternative presentation)
- Functional Requirements: FR-4

## 3. Preconditions
- Tenant "acme" is active; a recruiter with `Recruitment.Read.All` is authenticated.
- Vacancy "Senior Backend Engineer" has 14 applicants across stages.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| View toggle | Kanban <-> Table | Secondary table view |
| Sort columns | Name, Applied date, Stage, Source | Sortable |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | On the pipeline view, toggle from Kanban to Table view | A grid/list of applicants renders with columns including name, applied date, stage, and source. |
| 2 | Verify the row set | The table lists exactly the same 14 applicants as the board (same tenant-scoped data, FR-4). |
| 3 | Click the "Applied date" column header | Rows sort ascending by applied date; clicking again sorts descending. |
| 4 | Sort by "Stage", then by "Name" | Each sort reorders rows correctly; sorting does not change membership or counts. |
| 5 | Apply an active filter (e.g. source = referral) then toggle Kanban<->Table | The filtered set is consistent across both views. |
| 6 | Toggle back to Kanban | The board re-renders with the same applicants and counts; the chosen view persists for the session if specified by the UI. |

## 6. Postconditions
- No data modified; table view is a read-only alternative presentation of the same pipeline.

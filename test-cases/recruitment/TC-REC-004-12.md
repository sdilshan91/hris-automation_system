# TC-REC-004-12: Stage transition completes <= 800ms P95 including audit persistence, and the stage + history write is atomic (NFR-1, NFR-3)

## 1. Test Objective
Verify NFR-1 and NFR-3: a single stage-transition API call (including writing the `applicant_stage_history` row) completes within 800 ms at P95, and the applicant stage update + history-row insert are ATOMIC (a single DB transaction) -- a failure after the stage update but before the history write leaves NEITHER persisted. REC-003-12 measured an Applied->Screening move; this asserts the SLA + atomicity for the full gated-transition family of REC-004.

## 2. Related Requirements
- User Story: US-REC-004
- Non-Functional Requirements: NFR-1, NFR-3
- Functional Requirements: FR-4
- Data Requirements: S7 (single transaction over `applicant` + `applicant_stage_history`)

## 3. Preconditions
- Tenant "acme" with a realistic pipeline (e.g. 200 applicants distributed across stages).
- A representative mix of transitions (forward, backward, rejection) under steady load.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| SLA | <= 800ms P95 (write incl. audit) | NFR-1 |
| Atomicity | stage + history in 1 transaction | NFR-3 |
| Load | 200-applicant tenant; concurrent transitions | Realistic |
| Fault inject | error after stage update, before history insert | Atomicity check |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run a batch of stage-transition calls under steady load and record latency | P95 latency (server-side, including audit/history persistence) <= 800ms (NFR-1). |
| 2 | Confirm the audit write is inside the measured path | The latency includes `applicant_stage_history` insertion, not just the stage field update. |
| 3 | Inject a fault after the stage update but before the history insert | The whole transaction rolls back: `pipeline_stage_id` is unchanged AND no history row exists (atomic, NFR-3); no half-applied state. |
| 4 | Inject a fault during the history insert | Rollback leaves stage unchanged; retry then succeeds cleanly with exactly one history row. |
| 5 | Verify no partial state under concurrency | Combined with TC-REC-004-11, confirm that conflicts/faults never leave a stage change without its paired history row or vice versa. |
| 6 | Note read SLA boundary | Reads (timeline/pipeline) remain within the read SLA (<=400ms P95) measured under REC-003-12; this case focuses on the write/transition SLA. |

## 6. Postconditions
- Transitions meet the 800ms P95 write SLA; every committed transition has a matching history row; no partial writes survive a fault.

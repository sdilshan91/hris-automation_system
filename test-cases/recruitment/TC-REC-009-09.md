# TC-REC-009-09: Role-based scoping — Reports.View.All sees the full dashboard; Reports.View.Department sees only their department; unauthorized users are denied (BR-5)

## 1. Test Objective
Verify BR-5 and the story preconditions: dashboard access and scope are governed by permission. A user with `Reports.View.All` (+ `Recruitment.Read.All`) sees the full-tenant dashboard. A user with `Reports.View.Department` sees metrics filtered to vacancies in THEIR department only (server-side enforced — not a UI-only filter), per the assumption that department scoping filters by vacancies whose hiring manager is in the user's department. A user lacking both permissions is denied (403) and cannot reach the dashboard endpoints. Confirms a department-scoped user cannot widen scope by tampering with the department filter parameter to another department.

## 2. Related Requirements
- User Story: US-REC-009
- Business Rules: BR-5 (Reports.View.All -> full; Reports.View.Department -> own department)
- Acceptance Criteria: AC-1, AC-5 (scoping)
- Non-Functional Requirements: NFR-2 (tenant-scoped + authz)
- Preconditions: requires `Recruitment.Read.All` + `Reports.View.All` or `Reports.View.Department`

## 3. Preconditions
- Tenant "acme" with two departments (Engineering, Sales). User U-all has `Reports.View.All`; user U-eng has `Reports.View.Department` scoped to Engineering; user U-none has neither reports permission.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| U-all | Reports.View.All | full dashboard |
| U-eng | Reports.View.Department (Engineering) | Engineering-only |
| U-none | no Reports.View.* | denied |
| Tampered param | departmentId=Sales as U-eng | must be ignored/denied |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As U-all, open the dashboard | Full-tenant dashboard: KPIs/funnel/source/trend/status aggregate ALL departments (BR-5). |
| 2 | As U-eng, open the dashboard | Dashboard shows ONLY Engineering metrics (server-side scoping); Sales data is absent (BR-5). |
| 3 | As U-eng, attempt to set the department filter to Sales (UI or direct API `departmentId=Sales`) | Request is denied or silently re-scoped to Engineering; NO Sales data is returned (no scope widening via parameter tampering). |
| 4 | As U-none, attempt to open the dashboard / call the dashboard API | 403 Forbidden; no dashboard data returned. |
| 5 | As an unauthenticated client, call the dashboard API | 401 Unauthorized. |

## 6. Postconditions
- No data mutated; scope strictly follows permission; department-scoped users cannot escalate to other departments.

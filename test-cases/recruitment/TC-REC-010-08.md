# TC-REC-010-08: Vacancy auto-closes when headcount is fully filled by the conversion; recruiter notified; remaining pipeline notified (FR-7, BR-5)

## 1. Test Objective
Verify the auto-close behavior (FR-7, BR-5): when a conversion increments `filled_count` to EQUAL the vacancy's `headcount`, the vacancy status automatically changes to `Closed` and a notification is sent to the recruiter; remaining applicants in the pipeline are notified (if configured). Asserts the boundary: filling the LAST seat closes the vacancy, while filling a non-final seat leaves it Open.

NOTE: Recruiter/pipeline notifications (BR-5) depend on the Notification System (S25) + Hangfire; if delivery is a LOG-ONLY/stub, assert the enqueued outbox/job (tenant_id, recipients, event) — do NOT weaken to "no notification". The auto-close STATUS change itself is asserted directly (in-module).

## 2. Related Requirements
- User Story: US-REC-010
- Functional Requirements: FR-7 (filled_count++; auto-close when filled_count == headcount + recruiter notification)
- Business Rules: BR-5 (auto-close + remaining-pipeline notification when fully filled)
- Cross-story: US-REC-004 BR-4 (headcount-filled warning before reaching capacity)

## 3. Preconditions
- Tenant "acme"; vacancy {acme_vacancyId} headcount = 2, filled_count = 1 (one seat already filled), status Open.
- Two Hired+Accepted applicants A1 (final seat) and a second Hired+Accepted applicant available; recruiter R subscribed to vacancy events.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Vacancy | {acme_vacancyId} | headcount 2, filled_count 1 |
| A1 | Hired + Accepted | converting fills the last seat |
| Recruiter | R | notification recipient |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Convert A1 (the seat that brings filled_count 1 -> 2 == headcount) | 200/201; employee created; filled_count incremented to 2 (FR-7). |
| 2 | Verify auto-close | Vacancy {acme_vacancyId} status changes Open -> `Closed` automatically because filled_count == headcount (FR-7, BR-5). |
| 3 | Verify recruiter notification | A notification/outbox/Hangfire job to recruiter R for the auto-close is enqueued (CONDITIONAL on S25; assert enqueue if stubbed) (FR-7). |
| 4 | Verify remaining-pipeline notification | Remaining active applicants on {acme_vacancyId} are notified the vacancy is filled (if configured) (BR-5; CONDITIONAL on S25). |
| 5 | Boundary check (non-final seat) | On a separate vacancy with headcount 3 at filled_count 1, a conversion -> filled_count 2 leaves status Open (no premature close). |
| 6 | Verify no new applications | The auto-closed vacancy accepts no new applications (existing applicants retained) — consistent with REC-001 close semantics. |

## 6. Postconditions
- Vacancy Closed exactly when filled_count == headcount; recruiter + pipeline notified; non-final fills keep it Open.

# TC-REC-003-03: Applicant detail slide-over shows profile, resume preview and stage timeline (happy path)

## 1. Test Objective
Verify AC-3 / FR-7: clicking an applicant card opens a slide-over detail panel showing the applicant's full profile, resume with inline PDF preview, a chronological stage transition timeline, interview schedules/scores, and notes, plus action buttons (advance, reject, schedule interview). The resume is served via a signed short-lived URL (NFR-5: no raw blob URL exposed).

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-3
- Functional Requirements: FR-7
- Non-Functional Requirements: NFR-5
- Data Requirements: S7 (applicant detail DTO: profile, signed resume URL, stage history, interview data)

## 3. Preconditions
- Tenant "acme" is active; a recruiter with `Recruitment.Read.All` is authenticated.
- Applicant "Jordan Rivera" exists with a PDF resume and a stage history of at least two transitions (Applied -> Screening -> Interview).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant | Jordan Rivera | Has resume + multi-step history |
| Resume | jordan-resume.pdf (multi-page) | Inline pdf.js preview |
| History | Applied -> Screening -> Interview | Timeline with timestamps + actors |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Click Jordan Rivera's card; observe `GET /api/v1/recruitment/applications/{applicantId}` | A slide-over panel animates in from the right (60-70% width on desktop). Response 200 with the full applicant detail DTO. |
| 2 | Inspect the Profile tab | Personal info (name, email, phone, source, applied date) and current stage are displayed. |
| 3 | Inspect the Resume tab | The PDF renders inline via the client-side viewer (pdf.js); all pages are viewable. The resume is fetched via a signed, short-lived URL -- no direct/raw blob storage URL is exposed to the browser (NFR-5). |
| 4 | Inspect the Timeline tab | A chronological stage-transition timeline shows each entry from `applicant_stage_history`: from-stage, to-stage, actor, timestamp -- in order (Applied -> Screening -> Interview). |
| 5 | Inspect the Interviews and Notes tabs | Interview schedules/scores (if any) and notes/comments render; action buttons (advance, reject, schedule interview) are present. |
| 6 | Close the panel | The slide-over dismisses and returns focus to the board; no data was modified by viewing. |

## 6. Postconditions
- No data changed. The signed resume URL was used; no permanent blob URL is exposed in the DOM or network payload.

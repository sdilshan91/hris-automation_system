# TC-REC-006-01: Assigned interviewer submits a complete scorecard -> saved, criterion average computed, audit logged, recruiter notified (happy path)

## 1. Test Objective
Verify the primary success flow (AC-1, FR-1/FR-3/FR-5/FR-7): an interviewer assigned to a Scheduled interview opens the scorecard, rates every configured criterion on the 1-5 scale, adds optional per-criterion comments + general notes, selects a mandatory overall recommendation, and clicks Submit. On submit the system (a) persists ONE `interview_scorecard` row (tenant_id=session, interview_id, interviewer_employee_id from auth, overall_recommendation, computed `average_score`, submitted_at) plus one `scorecard_criterion_rating` row per criterion, (b) computes `average_score` as the mean of the criterion scores, (c) writes an audit-trail entry for the submission (FR-7), and (d) notifies the recruiter ASYNCHRONOUSLY (in-app + optional email via Hangfire, FR-5). This is REC-006's end-to-end submit walk and the data source REC-004's Offer gate depends on (see TC-REC-006-11).

## 2. Related Requirements
- User Story: US-REC-006
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-3, FR-5, FR-7
- Non-Functional Requirements: NFR-3 (async notification)
- Data Requirements: S7 (`interview_scorecard` row + `scorecard_criterion_rating` rows)

## 3. Preconditions
- Tenant "acme" is active; interviewer empA is authenticated and is assigned to interview {acme_interviewId} (status Scheduled or Completed).
- The tenant has 4 configured criteria (defaults: Technical Skills, Communication, Problem Solving, Cultural Fit) via module config S35.2.9 (BR-2).
- empA is the ONLY assigned interviewer on this interview (single-interviewer case -> status will flip to Completed on submit; see TC-REC-006-02 for the multi-interviewer gate).
- A recruiter (Recruitment.Read.All) exists in acme to receive the notification.
- Notification System (S25) + Hangfire wired, OR a log/outbox stub is in place (see Conditional note).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As empA, open the scorecard form for {acme_interviewId} | Form renders the 4 configured criteria, each with a 1-5 selector + inline comment toggle, plus the overall-recommendation control (Strong Hire/Hire/No Hire/Strong No Hire) (FR-1). |
| 2 | Rate all 4 criteria (4/5/3/4), add one comment, select recommendation=Hire, add general notes, `POST /api/v1/recruitment/interviews/{acme_interviewId}/scorecards` | 201; body returns scorecard id (UUID), tenant_id=acme, interviewer_employee_id=empA, overall_recommendation=Hire, average_score=4.0, submitted_at set (AC-1, FR-1, FR-3). |
| 3 | Verify persistence | ONE `interview_scorecard` row (acme, interview={acme_interviewId}, empA) + FOUR `scorecard_criterion_rating` rows (one per criterion with score + comment); fields match the request. |
| 4 | Verify average computation | `average_score` = mean of criterion scores = (4+5+3+4)/4 = 4.0; recomputed server-side, not trusted from the client (FR-3). |
| 5 | Verify audit log | A scorecard-submission entry is recorded (who=empA, what=scorecard submitted, when=submitted_at, interview_id) (FR-7). |
| 6 | Verify recruiter notification (async) | The 201 returns BEFORE notification delivery; an in-app (+ optional email) notification to the recruiter is queued via Hangfire/outbox, not inline on the request thread (FR-5, NFR-3). |
| 7 | Verify interview status (single-interviewer case) | Because empA is the only assigned interviewer and has now submitted, interview status -> Completed (FR-4; the multi-interviewer gate is TC-REC-006-02). |

## 6. Postconditions
- One scorecard (with 4 criterion ratings) exists for empA on {acme_interviewId} with average_score=4.0; audit entry written; recruiter notification queued; interview status Completed.

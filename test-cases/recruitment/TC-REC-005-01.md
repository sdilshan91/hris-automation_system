# TC-REC-005-01: Schedule an interview (interviewers + date/time + type + location/link) -> saved, all participants notified, Hangfire reminder job scheduled (happy path)

## 1. Test Objective
Verify the primary success flow (AC-1, FR-1/FR-3/FR-4, NFR-3): a recruiter with `Recruitment.Manage.All` schedules an interview for an applicant in the "Interview" stage by selecting interviewer(s), date, start time, duration, interview type (video here), and a video link, and on save the system (a) persists one `interview` row (status=Scheduled, tenant_id=session, round_number=1, hangfire_job_id set) with the `interview_interviewer` junction rows, (b) sends creation email + in-app notifications ASYNCHRONOUSLY to every interviewer AND the applicant, and (c) schedules a Hangfire reminder job for ~24h before the interview. This is REC-005's end-to-end create walk and the seam REC-004 referenced (TC-REC-004-01 step 2 "prompts to schedule").

## 2. Related Requirements
- User Story: US-REC-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-3, FR-4
- Non-Functional Requirements: NFR-3 (async notifications)
- Data Requirements: S7 (`interview` row + `interview_interviewer` junction; `hangfire_job_id`)

## 3. Preconditions
- Tenant "acme" is active; a recruiter with `Recruitment.Manage.All` is authenticated.
- Applicant "Jordan Rivera" exists at stage "Interview" with a valid email on the application.
- Two active employees exist in acme to act as interviewers, each with a work email.
- Notification System (S25) + Hangfire are wired, OR a log/outbox stub is in place (see Conditional note).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /api/v1/recruitment/interviews` with applicantId, vacancyId, interviewerIds=[empA,empB], date, startTime, duration=60, type=video, videoLink, notes | 201; body returns the interview with id (UUID), status=Scheduled, round_number=1, tenant_id=acme, hangfire_job_id populated (AC-1). |
| 2 | Verify persistence | One `interview` row (Scheduled, acme) + two `interview_interviewer` rows (empA, empB); fields match the request. |
| 3 | Verify participant notifications | Creation email + in-app notification queued/sent to empA work email, empB work email, AND the applicant's application email -- three recipients (FR-3, BR-7). |
| 4 | Verify notifications are async | The 201 response returns BEFORE notification delivery completes; delivery is via Hangfire/outbox, not inline on the request thread (NFR-3). |
| 5 | Verify reminder job scheduled | A Hangfire job exists keyed by `hangfire_job_id`, scheduled to fire ~24h before 2026-06-25 10:00 (i.e. 2026-06-24 10:00), carrying tenant_id=acme in its parameters (FR-4, NFR-4). |
| 6 | Confirm cancelling does NOT change pipeline stage seam | The applicant remains at "Interview"; scheduling did not auto-advance or write an `applicant_stage_history` row (interview lifecycle is separate from pipeline stage). |

## 6. Postconditions
- One Scheduled interview (round 1) exists in acme with two interviewers; creation notifications dispatched to all three participants; a tenant-aware reminder job is queued for 24h prior.

# TC-REC-008-10: Portal is read-only for application data; offer accept/decline is a single irreversible applicant action

## 1. Test Objective
Verify BR-1 / BR-2 / BR-6: the candidate portal does not allow the applicant to edit their submitted application (no edit endpoints/controls), and the only mutating action available is a one-time offer Accept or Decline which cannot be changed by the applicant after submission. Confirms there is no traditional account/password (BR-6) -- the magic link is the sole access mechanism. Attempts to mutate application fields via crafted API calls with the portal token are rejected.

## 2. Related Requirements
- User Story: US-REC-008
- Business Rules: BR-1 (read-only application status), BR-2 (accept/decline one-time, not reversible by applicant), BR-6 (no account; magic link auth)

## 3. Preconditions
- Applicant {acme_applicantId} has an application and an active `Sent` offer {acme_offerId}; valid magic link available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Application | {acme_applicantId} | read-only |
| Offer | {acme_offerId} | Sent; one accept/decline |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Inspect the portal UI for any edit controls on application fields (name, resume, cover letter, stage) | None present; all application data is display-only (BR-1). |
| 2 | Attempt to PATCH/PUT an application field via the portal API using the portal token | Rejected (403/404/method not allowed); no application data is mutated (BR-1). |
| 3 | Accept the offer (TC-REC-008-03 flow), then attempt to Decline it afterwards | The second action is blocked; the response is immutable from the portal side once submitted (BR-2). |
| 4 | After accepting, attempt to re-submit accept/decline via a crafted API call with the portal token | Rejected; the offer is already responded; no state change (BR-2). |
| 5 | Confirm no account creation/login is required anywhere in the flow | The portal never prompts for password/registration; access is solely via the magic link (BR-6). |

## 6. Postconditions
- No application data mutated; offer response captured exactly once and immutable from the applicant; no account created.

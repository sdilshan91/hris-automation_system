# TC-REC-005-03: Reschedule an interview -> old Hangfire reminder cancelled + new one created for the new time + "updated" notifications to all participants (AC-3, BR-6)

## 1. Test Objective
Verify AC-3 / BR-6 / FR-3: when a recruiter edits an interview's date/time, the system (a) cancels the ORIGINAL Hangfire reminder job, (b) creates a NEW reminder job for the updated time (24h before the new start), (c) persists the new schedule on the SAME interview record (status stays Scheduled), and (d) sends an "updated/rescheduled" notification (email + in-app) to all participants. No stale reminder for the old time may remain, and no duplicate reminder may be created.

## 2. Related Requirements
- User Story: US-REC-005
- Acceptance Criteria: AC-3
- Functional Requirements: FR-3 (update notification), FR-4 (reminder job)
- Business Rules: BR-6 (old job cancelled, new created), BR-7 (recipients)

## 3. Preconditions
- A Scheduled interview exists in acme (from TC-REC-005-01), original start 2026-06-25 10:00, hangfire_job_id = {oldJobId}.
- Recruiter with `Recruitment.Manage.All` authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Original start | 2026-06-25 10:00 | {oldJobId} reminder at 2026-06-24 10:00 |
| New start | 2026-06-27 14:00 | Future; new reminder at 2026-06-26 14:00 |
| Participants | empA, empB, applicant | All notified of change (BR-7) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `PUT/PATCH /api/v1/recruitment/interviews/{interviewId}` with new date 2026-06-27 / time 14:00 | 200; same interview record updated, status still Scheduled, scheduled_date/start_time = new values (AC-3). |
| 2 | Verify old reminder cancelled | {oldJobId} is deleted/cancelled in Hangfire; it will NOT fire at 2026-06-24 10:00 (BR-6). |
| 3 | Verify new reminder created | A NEW hangfire_job_id is stored on the interview, scheduled for 2026-06-26 14:00 (new start - 24h), tenant_id=acme (BR-6, FR-4). |
| 4 | Verify exactly one active reminder | Only the new job is pending for this interview; no stale or duplicate reminder remains. |
| 5 | Verify update notifications | An "interview rescheduled/updated" email + in-app notification is sent to empA, empB, AND the applicant with the new date/time (FR-3, BR-7). |
| 6 | Verify applicant pipeline stage unchanged | The applicant remains at "Interview"; rescheduling does not alter the pipeline stage or write `applicant_stage_history`. |

## 6. Postconditions
- The interview reflects the new schedule; exactly one tenant-aware reminder is queued for the new time; all participants were notified of the change.

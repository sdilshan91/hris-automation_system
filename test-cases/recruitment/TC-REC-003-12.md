# TC-REC-003-12: Board load <= 400ms P95 @ 200 applicants; stage move persists <= 800ms P95 (NFR-1, NFR-2)

## 1. Test Objective
Verify NFR-1 and NFR-2: the Kanban board loads within 400 ms (P95) for a vacancy with up to 200 applicants across all stages, and a drag-and-drop stage transition persists within 800 ms (P95) with optimistic UI feedback. Measurements are tenant-scoped.

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-1, AC-2
- Non-Functional Requirements: NFR-1, NFR-2
- Data Requirements: S7 (index on `(tenant_id, vacancy_id, pipeline_stage_id)`)

## 3. Preconditions
- Tenant "acme" has a vacancy "Volume Role" seeded with 200 applicants distributed across all six stages.
- The DB index on `(tenant_id, vacancy_id, pipeline_stage_id)` exists.
- A load/measurement harness (k6/JMeter or equivalent) is configured against the API.
- NOTE: If a Redis board cache (key like `tenant:{tenantId}:vacancy:{vacancyId}:pipeline`) is DEFERRED in the delivered increment, this TC measures the DB-backed path; treat the cache as a CONDITIONAL optimization, not a coverage gap.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicants | 200 across 6 stages | NFR-1 ceiling |
| Board load SLA | <= 400 ms P95 | Read |
| Stage move SLA | <= 800 ms P95 | Write |
| Sample size | >= 100 iterations each | For a stable P95 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run >= 100 iterations of `GET /api/v1/recruitment/vacancies/{volumeRoleId}/pipeline` under representative concurrency | The board-data response time P95 is <= 400 ms (NFR-1). |
| 2 | Confirm the query plan uses the `(tenant_id, vacancy_id, pipeline_stage_id)` index | No sequential scan of `applicant` for the board query; tenant filter applied. |
| 3 | Run >= 100 iterations of `PATCH /api/v1/recruitment/applications/{id}/stage` (forward moves) | The stage-move persistence P95 is <= 800 ms (NFR-2). |
| 4 | Observe UI behaviour during a move | Optimistic UI feedback is immediate; the card appears in the target column before the server confirms, and reverts on error (NFR-2). |
| 5 | Verify isolation does not skew results | All requests run under acme's tenant context; no cross-tenant rows are scanned/returned. |

## 6. Postconditions
- Board load and stage-move latencies meet their P95 SLAs at the 200-applicant ceiling; any deferred cache is noted, not assumed.

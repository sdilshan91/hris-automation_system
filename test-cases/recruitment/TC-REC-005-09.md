# TC-REC-005-09: Interviewer eligibility -- interviewers must be ACTIVE employees within the SAME tenant; inactive/foreign/non-employee IDs rejected (BR-2)

## 1. Test Objective
Verify BR-2: every selected interviewer must be an ACTIVE employee belonging to the current tenant. The system rejects a schedule referencing (a) an inactive/terminated employee, (b) an employee from another tenant, or (c) an arbitrary/non-employee ID. The interviewer multi-select dropdown only surfaces active same-tenant employees, and the API enforces the same rule server-side (defense against tampered requests).

## 2. Related Requirements
- User Story: US-REC-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1 (interviewer multi-select)
- Business Rules: BR-2 (active employees, same tenant)
- Dependencies: Core HR (employee records)

## 3. Preconditions
- Tenant acme has: {empActive} (active), {empTerminated} (inactive/terminated).
- Tenant globex has {empGlobex} (active in globex).
- Recruiter with `Recruitment.Manage.All` authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Active same-tenant | {empActive} (acme) | Eligible |
| Terminated | {empTerminated} (acme) | Reject (inactive) |
| Foreign tenant | {empGlobex} (globex) | Reject (not in acme) |
| Random ID | non-existent UUID | Reject |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the interviewer multi-select dropdown as acme recruiter | Only ACTIVE acme employees are listed; terminated and other-tenant employees do not appear (BR-2, FR-1). |
| 2 | Schedule with {empActive} | 201; accepted (positive control). |
| 3 | POST a schedule with interviewerIds=[{empTerminated}] (bypassing the dropdown) | 400/422; rejected -- interviewer must be active (BR-2); nothing persisted. |
| 4 | POST with interviewerIds=[{empGlobex}] (cross-tenant) | 404/400; rejected -- the employee is not visible/eligible in acme (BR-2 + tenant isolation); nothing persisted. |
| 5 | POST with a random/non-existent employee ID | 400/404; rejected. |
| 6 | POST a mix [{empActive}, {empTerminated}] | The whole request is rejected (no partial save with an ineligible interviewer). |

## 6. Postconditions
- Only active, same-tenant employees can be assigned as interviewers; ineligible IDs are rejected server-side with no persistence.

# TC-REC-005-07: Past-date / out-of-business-hours scheduling rejected (BR-3, NFR-6) -- date/time must be in the future

## 1. Test Objective
Verify BR-3 / NFR-6: the scheduling form/API rejects an interview whose date/time is in the PAST, and validates against configured business hours where enabled. Rejection returns a clear validation error and persists NOTHING -- no interview row, no notifications, no reminder job. Applies to both create and reschedule (a reschedule to a past time is equally rejected).

## 2. Related Requirements
- User Story: US-REC-005
- Acceptance Criteria: AC-1 (scheduling), AC-3 (reschedule)
- Non-Functional Requirements: NFR-6 (future + business-hours validation)
- Business Rules: BR-3 (no past-date scheduling)

## 3. Preconditions
- Tenant acme; recruiter with `Recruitment.Manage.All` authenticated.
- "Now" is fixed at 2026-06-15 (server clock) for deterministic past/future checks.
- Business hours configured (e.g. 09:00-18:00) where the feature is enabled.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Past date | 2026-06-10 10:00 | Before now -> reject (BR-3) |
| Past time today | 2026-06-15 (earlier than current time) | Reject |
| Future valid | 2026-06-20 10:00 | Accept |
| Out-of-hours (if enabled) | 2026-06-20 03:00 | Reject per NFR-6 |
| Reschedule to past | move existing -> 2026-06-09 | Reject |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create an interview with date 2026-06-10 10:00 (past) | 400 validation error ("date/time must be in the future"); no interview row, no notifications, no reminder job (BR-3). |
| 2 | Create with today's date but a time already passed | 400; rejected as past (BR-3). |
| 3 | Create with future 2026-06-20 10:00 (in business hours) | 201; accepted (positive control). |
| 4 | Create with future but out-of-business-hours 03:00 (where enabled) | 400 / warning per the configured business-hours rule (NFR-6); if business-hours validation is soft/disabled, document as CONDITIONAL (see Conditional note). |
| 5 | Reschedule an existing interview to a past time | 400; rejected; the existing schedule and its reminder are unchanged (BR-3 on edit). |
| 6 | Verify validation runs server-side | The rejection holds even if the client-side date picker is bypassed (API-level validation), defending against tampered requests. |

## 6. Postconditions
- No past-dated or out-of-hours interview is persisted; valid future in-hours scheduling succeeds; reschedule honors the same rule.

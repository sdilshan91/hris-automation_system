# TC-REC-001-05: Publishing a vacancy without required fields is rejected with field-level errors (negative)

## 1. Test Objective
Verify BR-2: a vacancy cannot be published without at least a title, department, job title, hiring manager, headcount, and description. Each missing required field is blocked with a clear validation message, and the vacancy is NOT promoted to `Open`.

## 2. Related Requirements
- User Story: US-REC-001
- Acceptance Criteria: AC-2 (publish path)
- Functional Requirements: FR-1 (required fields)
- Business Rules: BR-2
- Test Hint: submit without required fields and verify appropriate error messages

## 3. Preconditions
- Tenant "acme" with Recruitment enabled.
- Recruiter "Riley Park" (Recruitment.Create.All) is authenticated in acme.
- A partially-filled Draft vacancy exists missing the description and hiring manager.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Title | Senior Backend Engineer | Present |
| Department | Engineering | Present |
| Job Title | Senior Backend Engineer | Present |
| Hiring Manager | (empty) | MISSING required field |
| Headcount | 2 | Present |
| Description | (empty) | MISSING required field |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Riley Park, open the Draft vacancy missing description and hiring manager and click "Publish" | The client-side form blocks submission and shows field-level errors: "Description is required" and "Hiring manager is required". The vacancy is not published. |
| 2 | Bypass the UI and call `POST /api/v1/recruitment/vacancies/{id}/publish` directly with the incomplete record | Response is 422/400 with a validation error listing the missing required fields (title/department/job title/hiring manager/headcount/description per BR-2). Status remains `Draft`. |
| 3 | Repeat for each individual missing required field (omit title only, then department only, then job title only, then headcount only) | Each attempt is rejected with a field-specific message; the vacancy never transitions to `Open`. |
| 4 | Fill all required fields and publish | Publish now succeeds (200 OK); status becomes `Open`. |
| 5 | Verify the persisted row across the rejected attempts | Status stayed `Draft` for every incomplete attempt; only the complete attempt set `Open`. |

## 6. Postconditions
- A vacancy missing any BR-2 required field is never published.
- The complete vacancy publishes successfully.

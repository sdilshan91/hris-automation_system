# TC-REC-008-07: Tampered / forged / replayed magic-link token is rejected; token is HMAC-SHA256 signed over tenant_id + email + expiry

## 1. Test Objective
Verify NFR-4 (with FR-1/FR-8): the magic-link token is cryptographically signed (HMAC-SHA256) over the embedded tenant_id, applicant email, and expiry timestamp, and the server validates the signature on every portal request. Any token whose payload is modified (different email, different tenant_id, extended expiry), whose signature is forged/stripped, or that is signed with the wrong key is REJECTED with no data disclosure. Modifying the email to point at another applicant must not grant access to that applicant's data (the signature check fails before any lookup).

## 2. Related Requirements
- User Story: US-REC-008
- Non-Functional Requirements: NFR-4 (HMAC-SHA256 token over tenant_id+email+expiry)
- Functional Requirements: FR-1 (signed magic link), FR-8 (expiry enforced)
- Security: token integrity / forgery / replay defense

## 3. Preconditions
- Tenant "acme"; a valid token for applicant@example.com exists. Tester can decode the token structure (it is signed, not necessarily encrypted) and craft variants.
- A second applicant other@example.com exists in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Valid token | {validToken} | baseline |
| Tampered-email token | payload email -> other@example.com, original signature | signature now invalid |
| Tampered-expiry token | expiry pushed +1 year, original signature | signature now invalid |
| Tampered-tenant token | tenant_id -> globex, original signature | signature now invalid |
| Forged token | re-signed with attacker key | wrong HMAC key |
| Signature-stripped token | payload only, no/empty signature | malformed |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the portal with the tampered-email token (email -> other@example.com) | Rejected; signature validation fails before any lookup; NO access to other@example.com's data (NFR-4). |
| 2 | Open with the tampered-expiry token (expiry extended) | Rejected; the extended expiry is not honoured because the signature no longer matches (NFR-4, FR-8). |
| 3 | Open with the tampered-tenant token (tenant_id -> globex) | Rejected; signature invalid; also fails tenant binding (see TC-REC-ISO-017). |
| 4 | Open with the forged token (re-signed with a wrong key) | Rejected; HMAC verification fails. |
| 5 | Open with the signature-stripped / malformed token | Rejected with a generic error; no stack trace or internal detail leaked. |
| 6 | Confirm error responses | All rejections return a generic "invalid or expired link" message; none disclose whether the email/tenant exists (no enumeration). |

## 6. Postconditions
- No access granted via any tampered/forged token; no data disclosed; valid token unaffected.

# TC-REC-006-12: Scorecard submission API responds within 800ms P95; recruiter notification dispatched async (non-blocking)

## 1. Test Objective
Verify NFR-1 (and NFR-3 async dispatch): the scorecard submission endpoint responds within 800 ms at P95, INCLUDING the criterion-rating writes, average computation, audit entry, and ENQUEUING the recruiter notification -- but NOT the notification delivery itself, which is dispatched asynchronously (Hangfire/outbox) and must not block the response. Also spot-checks the consolidated read (applicant detail with multiple scorecards) stays responsive.

## 2. Related Requirements
- User Story: US-REC-006
- Non-Functional Requirements: NFR-1, NFR-3, NFR-4 (analytics aggregation sub-second up to 1000 scorecards)
- Acceptance Criteria: AC-1

## 3. Preconditions
- Tenant "acme" active with a realistic dataset (e.g. several hundred interviews/scorecards).
- empA assigned to interview {acme_interviewId}; load harness configured for P95 measurement.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Submission payload | 4 criteria + recommendation + notes | Representative card |
| Concurrency | sustained load to derive P95 | NFR-1 |
| Dataset | up to 1000 scorecards/tenant | NFR-4 read-side sanity |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit scorecards under sustained load; measure server-side response time | P95 <= 800 ms for `POST .../scorecards` including criterion writes + average + audit + notification enqueue (NFR-1). |
| 2 | Verify notification delivery is async | The response returns BEFORE the recruiter notification is delivered; delivery is via Hangfire/outbox, not inline on the request thread (NFR-3). If notifications are a LOG-ONLY stub, assert the enqueue/outbox write is what is timed (CONDITIONAL -- see note). |
| 3 | Consolidated read latency | Loading the applicant detail panel with multiple scorecards (per-interviewer + aggregate) returns responsively; the aggregation over up to 1000 scorecards/tenant is sub-second (NFR-4). |
| 4 | Verify average computation is not a hotspot | Average + aggregate computation does not push the write path over budget (computed in-request, not via N+1 queries). |

## 6. Postconditions
- Scorecard submission meets the 800ms P95 budget with async notification dispatch; consolidated reads remain responsive.

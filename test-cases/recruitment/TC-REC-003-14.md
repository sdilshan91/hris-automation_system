# TC-REC-003-14: Input sanitization on search/filter + stage-move tampering rejected (XSS / injection / forged stage id)

## 1. Test Objective
Verify input-handling security for the pipeline view: free-text search and notes are sanitized/parameterized (no XSS execution, no SQL injection); and a stage-move request with a forged/non-existent target stage id, an applicant id from another vacancy, or a body-injected `tenant_id` is rejected server-side.

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-2, AC-4
- Functional Requirements: FR-3, FR-6, FR-7 (notes)
- Non-Functional Requirements: NFR-3 (tenant-scoped)

## 3. Preconditions
- Tenant "acme" is active; `manager@acme` (`Recruitment.Manage.All`) is authenticated.
- A vacancy with applicants exists; pipeline stages are configured.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS search | `<script>alert(1)</script>` | Must not execute |
| SQLi search | `' OR '1'='1` | Must be parameterized |
| XSS note | `<img src=x onerror=alert(1)>` | Sanitized on store/render |
| Forged stage id | random UUID not in tenant stages | Reject |
| Cross-vacancy applicant | applicant id from another vacancy | Reject/validate |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter `<script>alert(1)</script>` in the board search box | The string is treated as a literal search term (no results / safe results); the script does not execute; it is rendered as inert text in the active-filter chip. |
| 2 | Search `' OR '1'='1` | No injection: the query is parameterized; the board does not return all/cross-tenant applicants; safe empty/normal results. |
| 3 | Add a note `<img src=x onerror=alert(1)>` via the detail panel, then re-open it | The note is stored sanitized/encoded and renders as inert text; no script/handler executes (FR-7). |
| 4 | Send `PATCH .../applications/{applicantId}/stage` with a `toStageId` that is a random UUID not among the tenant's stages | 4xx (validation/not found); no stage change; no history row. |
| 5 | Send a stage move for an applicant id that belongs to a different vacancy/tenant | Rejected (404/403); the EF tenant query filter + validation prevent acting on out-of-scope applicants. |
| 6 | Send a stage move with a body-injected `tenant_id` for another tenant | The body field is ignored; tenant is derived from the session/JWT; no cross-tenant effect (NFR-3). |

## 6. Postconditions
- No script executed; no injection succeeded; tampered/forged stage moves were rejected with no side effects.

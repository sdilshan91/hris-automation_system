# TC-REC-006-08: Lock period -- edits allowed within 48h, rejected after the lock; in-window edits create version history

## 1. Test Objective
Verify FR-2 / BR-4: a submitted scorecard remains editable by its author until a configurable lock period (default 48 hours after the interview), after which it is immutable. An edit within the window updates the card (and the recomputed average), and creates a version-history entry (if version history is implemented). An edit attempt AFTER the lock (locked_at passed) is rejected. The lock is per-scorecard, keyed off the interview time + tenant-configurable lead.

## 2. Related Requirements
- User Story: US-REC-006
- Functional Requirements: FR-2
- Business Rules: BR-4
- Data Requirements: S7 (`locked_at`; version-history if implemented)

## 3. Preconditions
- Tenant "acme" active; empA submitted a scorecard for interview {acme_interviewId} (interview held at a known time T).
- Lock period configured at the default 48h (BR-4).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Interview time T | 2026-06-15 10:00 | Reference for lock |
| Lock period | 48h (default) | locked_at = T + 48h = 2026-06-17 10:00 |
| Edit within window | change Technical 4 -> 5 at T+2h | Allowed |
| Edit after lock | change at T+49h | Rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As empA, within 48h of T, `PUT/PATCH` the scorecard changing Technical 4 -> 5 | 200; card updated; `average_score` recomputed to reflect the new score (FR-2, FR-3). |
| 2 | Verify version history (if implemented) | An in-window edit creates a version-history entry capturing the prior values (BR-4). If version history is NOT yet implemented, assert at minimum that the update is audited (FR-7) -- do NOT skip; see Conditional note. |
| 3 | Advance the clock past the lock (T + 49h, locked_at passed) | The scorecard is now locked. |
| 4 | As empA, attempt to edit the (now locked) scorecard | 409/422 "scorecard locked"; the edit is rejected; no change persisted (BR-4). |
| 5 | Verify locked_at is set | `locked_at` equals T + configured lock period; reads still succeed after lock (immutable, not hidden). |
| 6 | Negative: another user cannot edit even within the window | Only the author (empA) can edit their own card within the window (ties to BR-1); a non-author edit is 403 regardless of timing. |

## 6. Postconditions
- In-window edit succeeded (average recomputed, version/audit captured); post-lock edit was rejected; the card is immutable after locked_at.

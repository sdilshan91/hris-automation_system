# TC-REC-010-04: Auto-create user account DISABLED -> employee created WITHOUT a user account; no welcome email; HR must create the account separately (AC-3, FR-5, BR-7)

## 1. Test Objective
Verify the alternative account branch (AC-3, FR-5, BR-7): when the tenant setting "Auto-create user accounts on hire" is DISABLED, the conversion still creates the employee + links + filled_count++ but does NOT create a `User`/`UserTenant`/role and does NOT send login credentials; the success state indicates the account must be created separately by the HR Officer. This is the negative/alternative complement to TC-REC-010-03 and protects BR-7's optionality.

## 2. Related Requirements
- User Story: US-REC-010
- Acceptance Criteria: AC-3
- Functional Requirements: FR-5 (account creation only if enabled)
- Business Rules: BR-7 (if disabled, HR creates the account separately)

## 3. Preconditions
- Tenant "acme"; setting "Auto-create user accounts on hire" = DISABLED.
- Applicant {acme_applicantId} Hired with Accepted offer.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Auto-create setting | DISABLED | BR-7 |
| Applicant | {acme_applicantId} | Hired + Accepted |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Convert {acme_applicantId} to an employee | 200/201; employee created, applicant linked, vacancy filled_count++ (AC-2). |
| 2 | Verify NO user account | No `User`/`UserTenant`/`user_tenant_role` is created for the new employee's email (FR-5, BR-7). |
| 3 | Verify NO credential email | No welcome email with login credentials is queued/sent (the credential portion is gated on account creation). |
| 4 | Verify success-state guidance | The success state / employee profile indicates "no login account — create separately" (BR-7), with an action to create one later. |
| 5 | Verify the rest of the conversion is unaffected | Employee fields, applicant link, and vacancy filled_count are identical to the enabled case (only the account/email steps are skipped). |

## 6. Postconditions
- Employee created without a user account; conversion otherwise complete; no orphaned account artifacts.

# TC-REC-001-09: Rich-text description/qualifications are sanitized to prevent stored XSS (NFR-4)

## 1. Test Objective
Verify NFR-4: the rich text editor sanitizes HTML input so that injected scripts and dangerous markup are stripped/neutralized, preventing stored XSS when the description and qualifications are rendered on the internal vacancy view and the public careers page.

## 2. Related Requirements
- User Story: US-REC-001
- Acceptance Criteria: AC-1, AC-3
- Non-Functional Requirements: NFR-4 (HTML sanitization, OWASP Top 10)
- Test Hint: inject `<script>` tags in the description and verify they are stripped

## 3. Preconditions
- Tenant "acme" with Recruitment enabled and the public careers page enabled.
- Recruiter "Riley Park" (Recruitment.Create.All) is authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Payload 1 | `<p>Great role</p><script>alert('xss')</script>` | Inline script tag |
| Payload 2 | `<img src=x onerror="alert(document.cookie)">` | Event-handler attribute |
| Payload 3 | `<a href="javascript:alert(1)">apply</a>` | javascript: URI |
| Payload 4 | `<iframe src="https://evil.example"></iframe>` | Disallowed embed |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create/edit a vacancy entering Payload 1 in the description and Payload 2 in qualifications, then save | Save succeeds; the persisted HTML has the `<script>` element removed and the `onerror` handler stripped (only safe markup retained). |
| 2 | Inspect the stored description/qualifications in the DB | No `<script>`, no inline event handlers (`onerror`/`onclick`/...), no `javascript:` URIs, no `<iframe>` are present. |
| 3 | Render the vacancy on the internal detail view | The page renders sanitized content; no script executes (no alert dialog; clean browser console). |
| 4 | Publish the vacancy and open it on the public careers page `https://acme.yourhrm.com/careers/{slug}` (anonymous) | The public page renders sanitized content; injected scripts do not execute for anonymous visitors. |
| 5 | Repeat with Payload 3 and Payload 4 | `javascript:` href neutralized/removed; `<iframe>` stripped; nothing executes on either view. |
| 6 | Confirm sanitization occurs server-side (not only Angular's client sanitizer) | Submitting the payloads directly via the API still stores sanitized HTML, so a non-Angular consumer of the data is also safe. |

## 6. Postconditions
- Stored description/qualifications contain only safe HTML; no injected script executes on internal or public rendering.

# TC-REC-003-10: Bulk select multiple applicants and move them to a stage (FR-8)

## 1. Test Objective
Verify FR-8 (bulk stage move): a user with `Recruitment.Manage.All` selects multiple applicant cards and moves them to a target stage in one action; all selected applicants are updated, each gets a stage-history record, and board counts recompute. Bulk move is subject to BR-3 (reason for Rejected) and BR-4 (Manage + reason for backward).

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-2 (extends single-move persistence to multi)
- Functional Requirements: FR-8
- Business Rules: BR-2, BR-3, BR-4, BR-5

## 3. Preconditions
- Tenant "acme" is active; `manager@acme` (`Recruitment.Manage.All`) is authenticated.
- Vacancy "Senior Backend Engineer" has at least 5 applicants in "Applied".
- NOTE: If bulk stage move (FR-8) is DEFERRED to a later Recruitment story in the delivered increment, this TC is CONDITIONAL -- the single-applicant move (TC-REC-003-02) verifies the per-applicant persistence; mark this BLOCKED pending FR-8 delivery rather than weakening it.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Selected applicants | 5 cards in "Applied" | Multi-select |
| Target stage | Screening | Forward bulk move |
| Actor | manager@acme | Recruitment.Manage.All |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter multi-select mode and select 5 applicant cards in "Applied" | The 5 cards show a selected state; a bulk-action bar shows the count and a "Move to stage" action. |
| 2 | Choose "Move to Screening" and confirm; observe `POST /api/v1/recruitment/applications/bulk/stage` with the 5 applicant ids + target stage | 200/204; the 5 cards move to Screening (optimistic UI then confirmed). |
| 3 | Verify the persisted rows | All 5 `applicant` rows now reference "Screening"; partial failures (if any) are reported and not silently dropped. |
| 4 | Verify history | 5 new `applicant_stage_history` rows are recorded, one per applicant, with from "Applied", to "Screening", actor, timestamp (BR-5). |
| 5 | Verify board counts | Applied count decremented by 5; Screening count incremented by 5; total unchanged. |
| 6 | Attempt a bulk move to "Rejected" without a reason | Rejected per BR-3 (reason required); no applicants changed. Supplying a reason succeeds for all. |

## 6. Postconditions
- All selected applicants moved to the target stage, each with a history record; reason rules enforced for the bulk path.

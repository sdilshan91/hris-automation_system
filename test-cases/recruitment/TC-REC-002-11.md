# TC-REC-002-11: Public application form allows anonymous submission but is protected against spam/bot abuse (rate limit / CAPTCHA)

## 1. Test Objective
Verify NFR-2 (no auth required) together with the spam/abuse constraint (S10): the public application form accepts anonymous submissions yet is protected from automated abuse via rate limiting and/or CAPTCHA. A legitimate single submission succeeds; rapid repeated/bot submissions are throttled or challenged. Also verify input sanitization on the free-text fields (anti-XSS).

## 2. Related Requirements
- User Story: US-REC-002
- Acceptance Criteria: AC-1
- Non-Functional Requirements: NFR-2
- Constraints: S10 (CAPTCHA / rate limiting on the public form to prevent spam/bot submissions)
- Notes: input sanitization of cover letter / name fields (anti-XSS)

## 3. Preconditions
- Tenant "acme" exists; vacancy "Senior Backend Engineer" is `Open` and publicly listed.
- The public form is reachable without authentication.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Legitimate submit | one valid application, no token | Should succeed anonymously |
| Burst | N rapid submissions from one IP/session | Should be throttled/challenged |
| Missing CAPTCHA | submission with absent/invalid CAPTCHA token (if enabled) | Rejected |
| XSS payload | cover letter `<script>alert(1)</script>`, name `<img src=x onerror=alert(1)>` | Sanitized/escaped, not executed |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit one valid application anonymously (no bearer token) | Accepted (201) -- the public form requires no authentication (NFR-2). |
| 2 | Issue a rapid burst of submissions from the same IP/session | After the configured threshold, requests are rejected with 429 Too Many Requests (or a CAPTCHA challenge), throttling automated abuse (S10). |
| 3 | (If CAPTCHA enabled) submit with an absent/invalid CAPTCHA token | Rejected until a valid challenge response is provided. |
| 4 | Submit with `<script>`/`onerror` payloads in cover letter and name fields | Accepted but the values are sanitized/escaped on storage and rendering; no script executes when a recruiter views the applicant (anti-XSS). |
| 5 | Verify the legitimate applicant from Step 1 is unaffected | The single valid submission remains a normal `Applied` record. |

## 6. Postconditions
- Anonymous submission works; automated/bot abuse is throttled or challenged; stored free-text is XSS-safe.

# TC-REC-007-12: PDF generation <= 3s for a standard 2-page template; email delivery async (non-blocking) (NFR-1, NFR-4)

## 1. Test Objective
Verify offer-letter performance (NFR-1, NFR-4): generating the offer-letter PDF for a standard 2-page template (with variable substitution + tenant branding) completes within 3 seconds; and the send action returns success after QUEUING the email (with PDF attachment) via Hangfire/outbox -- i.e. email delivery is asynchronous and does not block the API response (NFR-4). Measured under tenant-scoped query filters.

## 2. Related Requirements
- User Story: US-REC-007
- Non-Functional Requirements: NFR-1 (PDF gen <= 3s @ 2-page template), NFR-4 (async email)
- Functional Requirements: FR-2 (PDF generation), FR-5 (email)
- Acceptance Criteria: AC-1, AC-2

## 3. Preconditions
- Tenant "acme" active; a standard 2-page offer template with branding configured; an applicant in "Offer" stage.
- A representative data set (the tenant's offers) loaded so generation is measured against a realistic table.
- PDF library + Hangfire/outbox wired, OR a stub whose enqueue path is measured (see Conditional note).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Template | standard 2-page | NFR-1 baseline |
| PDF gen SLA | <= 3s | NFR-1 |
| Send response | returns after enqueue | NFR-4 |
| Runs | >= 20 generations | for a stable median/P95 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Generate the offer PDF for the 2-page template (warm), repeated >= 20x | PDF generation (render + variable substitution + store) completes within 3 seconds per generation (NFR-1); record median + P95. |
| 2 | Verify content correctness at speed | The fast-path PDFs still have correct variable substitution + branding (no truncation/skip to meet the SLA). |
| 3 | Measure the send API latency | `POST /offers/{id}/send` returns promptly (does not wait for SMTP delivery); the email + attachment are queued via Hangfire/outbox (NFR-4). |
| 4 | Verify async delivery decoupling | If the mail transport is slow/unavailable, the send API still returns success and the email stays queued for retry; the API thread is not blocked (NFR-4). |
| 5 | Verify tenant-scoped measurement | Generation/queries run under the acme tenant filter; no cross-tenant rows are scanned. |

## 6. Postconditions
- PDF generation meets the 3s SLA with correct content; offer email is queued asynchronously and never blocks the send API.

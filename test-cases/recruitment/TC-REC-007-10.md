# TC-REC-007-10: Authorization -- only Recruitment.Offer.All may generate/send/respond/withdraw/manage offers (BR-1)

## 1. Test Objective
Verify offer authorization (BR-1): every offer mutation -- generate, send, record response (accept/decline), withdraw, and version/supersede -- requires the `Recruitment.Offer.All` permission within the resolved tenant. Users without it (e.g. a Recruitment.Read-only recruiter, an unrelated employee, an unauthenticated caller) are rejected (401/403) with no offer created, sent, mutated, or PDF generated. This is the access-control gate around all REC-007 actions and complements tenant isolation (TC-REC-ISO-016).

## 2. Related Requirements
- User Story: US-REC-007
- Business Rules: BR-1 (Recruitment.Offer.All only)
- Acceptance Criteria: AC-1, AC-2, AC-3 (all gated by BR-1)
- Non-Functional: NFR-2 (tenant + authz)

## 3. Preconditions
- Tenant "acme" active with: `recruiter@acme` (HAS Recruitment.Offer.All), `readonly@acme` (Recruitment.Read.All only, NO Offer), `employee@acme` (no recruitment permission), and an unauthenticated client.
- Applicant {acme_applicantId} in "Offer" stage; a `Sent` offer {acme_offerId} for the respond/withdraw checks.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Authorized | recruiter@acme | Recruitment.Offer.All |
| Read-only | readonly@acme | Read.All, NO Offer |
| Unrelated | employee@acme | no recruitment perm |
| Anonymous | (no token) | -- |
| Offer | {acme_offerId} | Sent |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `readonly@acme`, attempt generate / send / withdraw / version | 403 on every mutation; no offer created/sent/mutated; no PDF generated (BR-1). |
| 2 | As `employee@acme`, attempt the same offer mutations | 403 on every mutation; no side effects. |
| 3 | As anonymous (no token), call the offer mutation endpoints | 401; rejected before any work; no side effects. |
| 4 | As `recruiter@acme` (authorized), generate -> send -> withdraw | All succeed (positive control), confirming the gate allows the right permission (AC-1/AC-2). |
| 5 | Recording a response (accept/decline) by recruiter requires Offer.All | A read-only/unrelated user recording a manual response is 403; the authorized recruiter (or the candidate-portal action) succeeds (AC-3, BR-1). |
| 6 | Verify no information leak on 403/401 | The rejection does not disclose offer contents, salary, or PDF storage keys. |

## 6. Postconditions
- Only `Recruitment.Offer.All` holders can mutate offers; unauthorized/anonymous attempts are rejected with no side effects or data leak.

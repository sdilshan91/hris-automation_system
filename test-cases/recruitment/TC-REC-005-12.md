# TC-REC-005-12: Scheduling API <= 800ms P95 including outbox writes; notification delivery is async (non-blocking) (NFR-1, NFR-3)

## 1. Test Objective
Verify NFR-1 / NFR-3: the interview-scheduling API call (persisting the interview + interviewer junction rows + queueing notification outbox entries + enqueueing the reminder job) completes within 800 ms at P95. CRITICALLY, the response time MUST NOT include synchronous email sending -- notification DELIVERY is offloaded to Hangfire (async). The request returns once the interview is committed and the outbox/reminder jobs are enqueued; SMTP latency never bleeds into the API SLA.

## 2. Related Requirements
- User Story: US-REC-005
- Non-Functional Requirements: NFR-1 (<= 800ms P95 incl. outbox writes), NFR-3 (async notifications)
- Functional Requirements: FR-3, FR-4

## 3. Preconditions
- Tenant acme with a realistic dataset (e.g. 200 interviews, 100 employees) under steady load.
- Hangfire + an outbox (or stub) configured; SMTP delivery deliberately slowed to prove non-blocking.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Write SLA | <= 800ms P95 (incl. outbox writes) | NFR-1 |
| Delivery | async via Hangfire | NFR-3 |
| Injected SMTP delay | e.g. 3s per email | Must NOT affect API latency |
| Load | concurrent schedule calls | Realistic |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run a batch of POST schedule calls under steady load; record server-side latency | P95 <= 800ms including the interview + junction + outbox-entry writes and reminder enqueue (NFR-1). |
| 2 | Confirm outbox writes are inside the measured path | The latency includes persisting notification outbox rows, not just the interview insert. |
| 3 | Inject a 3s SMTP delay and re-measure | API P95 is UNCHANGED (still <= 800ms): email delivery runs on the Hangfire worker, never inline (NFR-3). |
| 4 | Verify reminder enqueue cost is bounded | Enqueueing the Hangfire reminder job adds negligible, bounded latency to the request. |
| 5 | Note read SLA for the calendar | Calendar/agenda reads stay within the read SLA (<= 400ms P95); this case targets the scheduling write SLA. |
| 6 | Verify no thread starvation under load | Concurrent schedules do not block on notification delivery; worker queue drains independently. |

## 6. Postconditions
- Scheduling meets the 800ms P95 write SLA; notification delivery is fully async and slow SMTP does not degrade the API.

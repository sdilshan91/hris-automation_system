# TC-REC-004-05: Backward stage move (Interview -> Screening) requires Recruitment.Manage.All AND a mandatory reason; records a regressive history row (FR-5)

## 1. Test Objective
Verify FR-5: a backward (regressive) stage transition -- e.g. Interview -> Screening -- is permitted ONLY for users with `Recruitment.Manage.All`, REQUIRES a mandatory reason (unlike optional notes on forward moves), and records a normal `applicant_stage_history` row whose from_stage is later in sequence than to_stage. This deepens TC-REC-003-08 (which asserted backward-needs-Manage+reason at the board level) with the explicit Interview->Screening regression and the mandatory-reason validation.

## 2. Related Requirements
- User Story: US-REC-004
- Functional Requirements: FR-5
- Acceptance Criteria: AC-2
- Business Rules: BR-2 (reactivation is a related backward-style move -- see TC-REC-004-06)

## 3. Preconditions
- Tenant "acme".
- Applicant "Dana Cole" at "Interview".
- User1 = recruiter WITH `Recruitment.Manage.All`; User2 = user WITH only `Recruitment.Read.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant | Dana Cole ({acme_applicantId}) | At Interview |
| Backward move | Interview -> Screening | Regressive |
| Reason (required) | "Re-screen for relocation constraint" | Mandatory for backward |
| Empty reason | "" | Must be rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As User2 (Read only), attempt Interview -> Screening | 403 Forbidden; backward move requires `Recruitment.Manage.All`; no change. |
| 2 | As User1 (Manage), attempt Interview -> Screening with EMPTY reason | 400 validation error; backward move requires a mandatory reason; no change, no history row. |
| 3 | As User1, Interview -> Screening with a valid reason | 200; stage=Screening; one history row from=Interview, to=Screening, notes=reason, changed_by=User1. |
| 4 | Verify the history row direction | from_stage sequence > to_stage sequence (a recorded regression), and the timeline shows it as a backward step with the reason visible. |
| 5 | Forward-only default check | With backward moves disabled by tenant config, even a Manage user cannot regress (cross-ref TC-REC-003-08 forward-only default); when enabled, Steps 1-3 hold. |

## 6. Postconditions
- Dana Cole is back at "Screening" via an authorized, reasoned, audited backward move; unauthorized/reasonless attempts left no trace.

# TC-REC-002-10: Uploaded files are virus-scanned before the storage URL is persisted; EXIF stripped from images

## 1. Test Objective
Verify FR-3 / NFR-4: every uploaded resume is scanned for malware (ClamAV or cloud service) and the storage URL is persisted only after a clean result; an infected file is rejected and the application is not created. Also verify FR-4: EXIF/metadata is stripped from any image files uploaded as part of the application.

## 2. Related Requirements
- User Story: US-REC-002
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-3, FR-4
- Non-Functional Requirements: NFR-4
- Dependencies: File & Document Management module (S26.3 virus scan + EXIF strip)

## 3. Preconditions
- Tenant "acme" exists; vacancy "Senior Backend Engineer" is `Open` and publicly listed.
- The virus-scanning service (ClamAV/cloud) is reachable from the upload pipeline.
- A safe EICAR test file (`eicar.pdf` carrying the standard EICAR signature) is available for the malware case.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Infected file | eicar.pdf (EICAR test signature) | Must be quarantined/rejected |
| Clean file | clean-resume.pdf | Passes scan |
| Image with EXIF | (where image attachments are allowed) photo.jpg with GPS/EXIF | EXIF must be stripped |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit an application with the EICAR-signature `eicar.pdf` | The scan flags it as infected; the upload is rejected with a clear error; NO `applicant` row is created and NO storage URL is persisted (scan precedes persistence -- FR-3/NFR-4). |
| 2 | Inspect storage after the infected attempt | No object remains in `{tenantId}/recruitment/...` for the infected file (rejected/quarantined, not persisted). |
| 3 | Submit a clean PDF resume | Scan passes; only then is the storage URL persisted and the `applicant` row created (201). |
| 4 | Verify the ordering | The storage URL/key is populated only after a clean scan result (no window where an unscanned URL is persisted). |
| 5 | (If image attachments are accepted) upload a JPG containing GPS/EXIF metadata | The stored image has EXIF/metadata stripped (FR-4); the original GPS/camera metadata is not retrievable from the stored object. |

## 6. Postconditions
- Only scanned-clean files have persisted storage URLs; infected files leave no record or blob; stored images carry no EXIF.

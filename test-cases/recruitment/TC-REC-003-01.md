# TC-REC-003-01: Pipeline Kanban board renders one column per stage with cards, per-column counts and a total (happy path)

## 1. Test Objective
Verify the primary success flow (AC-1, FR-1/FR-2/FR-5): a recruiter with `Recruitment.Read.All` opens a vacancy's pipeline view and sees a Kanban board with one column per configured pipeline stage (Applied, Screening, Interview, Offer, Hired, Rejected) ordered left-to-right by stage sequence, each column showing applicant cards (name, application date, source badge), an aggregate count badge per stage, and a total applicant count for the vacancy.

## 2. Related Requirements
- User Story: US-REC-003
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-2, FR-5
- Data Requirements: S7 (stages array, each with ordered applicant summary DTOs; `pipeline_stage_id` FK on `applicant`)

## 3. Preconditions
- Tenant "acme" is active; a recruiter with `Recruitment.Read.All` is authenticated.
- Vacancy "Senior Backend Engineer" exists in acme with applicants distributed across stages, e.g. Applied (5), Screening (3), Interview (2), Offer (1), Hired (1), Rejected (2) -> total 14.
- Tenant pipeline stages are configured (default set) with a defined sequence order.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Subdomain | acme.yourhrm.com | Active tenant |
| Vacancy | Senior Backend Engineer | Has 14 applicants across 6 stages |
| Stages (ordered) | Applied, Screening, Interview, Offer, Hired, Rejected | Left-to-right by sequence |
| Stage counts | 5 / 3 / 2 / 1 / 1 / 2 | Sum = 14 (total) |
| Card fields | name, applied date, source badge | public/internal/referral |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to the vacancy's applicant pipeline view and observe `GET /api/v1/recruitment/vacancies/{vacancyId}/pipeline` | Request carries `X-Tenant-Subdomain: acme` and bearer token. Response is 200 with an array of stages, each containing an ordered array of applicant summary DTOs. |
| 2 | Inspect the board columns | Exactly one column per configured stage, rendered left-to-right in stage-sequence order: Applied, Screening, Interview, Offer, Hired, Rejected (FR-1). |
| 3 | Inspect each column header | Each header shows stage name + count badge: "Applied (5)", "Screening (3)", "Interview (2)", "Offer (1)", "Hired (1)", "Rejected (2)" (FR-5). |
| 4 | Inspect a representative applicant card | Card shows applicant name, application date (relative, e.g. "Applied 3 days ago"), and a colored source badge (public/internal/referral); a new/unread indicator appears for unviewed applications (FR-2). |
| 5 | Inspect the board-level total | A total applicant count for the vacancy is shown and equals 14 (sum of column counts) (FR-5). |
| 6 | Verify counts match the data | Each column's card count equals its badge number and equals the persisted `applicant` rows at that `pipeline_stage_id` for the vacancy in acme. |

## 6. Postconditions
- No data was modified; the board is a read-only view reflecting current applicant distribution.

# TC-REC-007-07: One active offer per applicant per vacancy at a time (BR-2)

## 1. Test Objective
Verify the single-active-offer constraint (BR-2): an applicant can have only ONE active (non-expired, non-declined, non-withdrawn) offer per vacancy at a time. Attempting to generate/send a SECOND active offer while a `Draft` or `Sent` offer is still active is rejected (or routed to the versioning path, TC-REC-007-08), NOT allowed to create two simultaneously-active offers. Once the active offer reaches a terminal non-active status (`Declined`, `Withdrawn`, `Expired`) -- or is superseded by a new version -- a new active offer is permitted.

## 2. Related Requirements
- User Story: US-REC-007
- Business Rules: BR-2 (one active offer per applicant/vacancy)
- Functional Requirements: FR-6 (status), FR-9 (versioning interaction)
- Acceptance Criteria: AC-1, AC-2 (generation/send respect BR-2)

## 3. Preconditions
- Tenant "acme" active; recruiter `recruiter@acme` with `Recruitment.Offer.All`.
- Applicant {acme_applicantId} on vacancy {acme_vacancyId} in "Offer" stage with an active `Sent` offer {acme_offerId}.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant | {acme_applicantId} | one active offer |
| Vacancy | {acme_vacancyId} | -- |
| Active offer | {acme_offerId} | status Sent (active) |
| Active states | Draft, Sent | count as "active" for BR-2 |
| Non-active states | Declined, Withdrawn, Expired | free up a new offer |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | With active `Sent` offer {acme_offerId} present, attempt to generate a brand-new SEPARATE active offer for {acme_applicantId}/{acme_vacancyId} | Rejected with a clear "active offer already exists" error -- OR routed to the supersede/version flow (TC-REC-007-08); the system does NOT end up with two simultaneously-active offers (BR-2). |
| 2 | Verify only one active offer remains | A query of offers for the applicant/vacancy shows exactly one active (Draft/Sent) offer. |
| 3 | Decline (or withdraw/expire) {acme_offerId}, then generate a new offer | Now allowed; the new offer becomes the single active offer; the previous one stays terminal (Declined/Withdrawn/Expired) for the record (BR-2). |
| 4 | Cross-vacancy check | The same applicant CAN have a separate active offer for a DIFFERENT vacancy {acme_vacancyId2}; BR-2 scopes "one active" to applicant+vacancy, not applicant alone. |
| 5 | Verify Accepted is terminal-but-not-replaceable | Once an offer is Accepted (applicant Hired), no new active offer is generated for that applicant/vacancy (the position outcome is settled). |

## 6. Postconditions
- At most one active offer exists per applicant/vacancy; terminal/non-active offers free up a new offer; cross-vacancy offers are independent.

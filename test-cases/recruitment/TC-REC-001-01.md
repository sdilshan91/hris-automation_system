# TC-REC-001-01: Recruiter creates a Draft vacancy, publishes it, and it appears on the internal listing (happy path)

## 1. Test Objective
Verify the primary success flow: an authenticated recruiter with `Recruitment.Create.All` can fill in the vacancy form (title, department, job title, description, headcount, hiring manager, employment type) and "Save as Draft" to persist a vacancy with status `Draft` (visible only to `Recruitment.Read.All` users in the same tenant, with `tenant_id` taken from session context and an auto-generated reference number); then "Publish" transitions it to `Open` and it appears on the internal vacancy listing.

## 2. Related Requirements
- User Story: US-REC-001
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-3
- Business Rules: BR-2
- Data Requirements: S7 (UUID PK, tenant_id FK, reference number VAC-YYYY-NNNN, status, audit)

## 3. Preconditions
- Tenant "acme" exists with status `active`, subdomain `acme.yourhrm.com`, and the Recruitment module enabled in its subscription plan.
- At least one department ("Engineering"), job title ("Senior Backend Engineer"), and one active employee available as hiring manager ("Dana Cole") exist in acme master data.
- Tenant recruitment pipeline stages are configured (or defaults Applied/Screening/Interview/Offer/Hired/Rejected are active).
- Recruiter "Riley Park" is authenticated in acme (valid JWT with `tenant_id`) and holds `Recruitment.Create.All` and `Recruitment.Read.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Subdomain | acme.yourhrm.com | Active tenant |
| User | Riley Park (Recruiter) | Has Recruitment.Create.All + Read.All |
| Title | Senior Backend Engineer | Required, within 200 chars |
| Department | Engineering | Required dropdown |
| Job Title | Senior Backend Engineer | Required dropdown |
| Employment Type | Full-time | Required |
| Hiring Manager | Dana Cole | Required employee dropdown |
| Headcount | 2 | Integer >= 1 |
| Description | "<p>Build and own backend services.</p>" | Rich text, required |
| Qualifications | "<p>5+ years .NET</p>" | Rich text, optional |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to `https://acme.yourhrm.com/recruitment/vacancies` and click "New Vacancy" | The vacancy creation form (slide-over or full-page) opens with sections Basic Info, Description, Requirements, Settings. |
| 2 | Fill title, select department, job title, employment type, hiring manager (searchable dropdown with avatar), enter headcount 2, enter rich-text description and qualifications | Fields accept input; no validation errors. |
| 3 | Click "Save as Draft" and observe `POST /api/v1/recruitment/vacancies` | Request carries `X-Tenant-Subdomain: acme` + bearer token. Response is 201 Created. |
| 4 | Inspect the response body | Body contains `id` (UUID), `tenant_id` matching acme, `reference_number` matching the `VAC-2026-NNNN` pattern, `status: "Draft"`, `created_by` = Riley Park, `created_at`/`updated_at` timestamps. |
| 5 | Verify the persisted `vacancy` row in the DB | One row exists with the returned `id`; `tenant_id` equals acme; `status = Draft`; `headcount = 2`; description/qualifications stored. |
| 6 | Open the internal vacancy listing | The Draft vacancy is visible to Riley Park (Read.All) with a gray "Draft" status badge. |
| 7 | Open the Draft vacancy and click "Publish" and observe `POST /api/v1/recruitment/vacancies/{id}/publish` (or PATCH status) | Response is 200 OK; response `status: "Open"`. |
| 8 | Reload the internal vacancy listing | The vacancy now shows a green "Open" status badge and appears in the active listing. |
| 9 | Verify the persisted row after publish | `status = Open`; `updated_at` advanced; reference number unchanged. |

## 6. Postconditions
- One `vacancy` row exists in acme with status `Open`, a unique reference number, and `tenant_id` = acme.
- The vacancy is visible on the internal listing.

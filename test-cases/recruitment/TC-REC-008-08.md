# TC-REC-008-08: Portal sanitization -- rejection reasons, scorecard data, interviewer comments, and internal notes are NEVER exposed to the applicant (defense at the API, not just the UI)

## 1. Test Objective
Verify NFR-5 / BR-3: the candidate portal returns a SANITIZED view of the pipeline. The applicant sees stage names, dates, sanitized timeline events, interview logistics (date/time/type/link/interviewer names), and offer details -- but NEVER internal data: rejection reasons, scorecard criterion ratings/averages, interviewer written comments/recommendations, internal recruiter notes, or other applicants' PII. This is enforced at the portal API (the response DTO omits these fields), not merely hidden in the UI -- so inspecting the raw network/JSON response must also show no leaked fields.

## 2. Related Requirements
- User Story: US-REC-008
- Non-Functional Requirements: NFR-5 (no internal data exposed)
- Business Rules: BR-3 (sanitized pipeline view)
- Acceptance Criteria: AC-1 (dashboard), AC-2 (interview)
- Cross-story: US-REC-004 (rejection reason), US-REC-006 (scorecards/comments), US-REC-003 (internal notes)

## 3. Preconditions
- Applicant {acme_applicantId} has: a rejection reason on one application (US-REC-004), >=1 submitted scorecard with criterion ratings + interviewer comments + recommendation on a completed interview (US-REC-006), and an internal recruiter note on the applicant (US-REC-003).
- Valid magic link available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Rejection reason | "NotQualified - weak on system design" | must NOT surface |
| Scorecard | criterion ratings + avg 3.2 + comment "borderline" + rec "No Hire" | must NOT surface |
| Internal note | "candidate negotiating with competitor" | must NOT surface |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the portal, view dashboard + timeline + interview + offer sections | None of the sanitized-out fields render anywhere in the UI (NFR-5, BR-3). |
| 2 | Capture the raw portal API response(s) (network tab / direct call with the valid token) | The response DTO contains ONLY applicant-safe fields (vacancy, department, applied date, stage, status, sanitized timeline labels, interview logistics + interviewer names, offer summary + PDF link); it does NOT include rejection_reason, scorecard ratings/average, interviewer comments, recommendation, or internal notes. |
| 3 | Specifically search the JSON for the rejection reason text, scorecard score, comment, recommendation, and internal note | None are present in any field, including nested objects (NFR-5). |
| 4 | Attempt to reach an internal recruiter endpoint (e.g. scorecard/notes API) using the portal token | Rejected (the portal token is not an authenticated recruiter session); no internal data returned. |
| 5 | Confirm interviewer names ARE shown (allowed) but comments are NOT | Interviewer names appear (per story #10 assumptions); their comments/scores do not (NFR-5). |

## 6. Postconditions
- No internal/sensitive recruiter data was exposed via the UI or the API; portal returned a sanitized DTO only.

# TC-REC-007-14: Offer PDF stored encrypted at rest; accessed via signed/tenant-scoped key (no raw blob URL); variable substitution leaves no unresolved placeholders (NFR-3, FR-2/FR-3)

## 1. Test Objective
Verify offer-PDF storage security + substitution integrity (NFR-3, FR-2/FR-3): the generated offer PDF is stored ENCRYPTED at rest in blob storage at the tenant-scoped path `{tenantId}/recruitment/{vacancyId}/{applicantId}/offers/{filename}`, and is served only via a short-lived signed URL or an authorized, tenant-checked endpoint -- never as a raw, guessable, public blob URL. Also verifies that variable substitution is complete: a generated PDF contains NO unresolved `{{placeholder}}` tokens (missing values resolve to a safe default/blank, not a leaked raw token), and that a placeholder absent from the form does not break generation.

CONDITIONAL: encryption-at-rest (NFR-3) depends on the File & Document Management module (S26). If the blob layer is stubbed in this increment, assert the tenant-scoped key shape + signed/authorized access contract + substitution completeness; the at-rest encryption assertion becomes an extension point against the real S26 store. It MUST NOT be weakened to "raw public URL acceptable".

## 2. Related Requirements
- User Story: US-REC-007
- Non-Functional Requirements: NFR-3 (PDF encrypted at rest)
- Functional Requirements: FR-2 (variable substitution), FR-3 (tenant-scoped storage path)
- Acceptance Criteria: AC-1
- Dependency: File & Document Management (S26)

## 3. Preconditions
- Tenant "acme" active; a generated offer {acme_offerId} with a PDF at the tenant-scoped path.
- File & Document Management (S26) wired, OR a blob stub exposing the storage key + access path (see Conditional note).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Inspect the stored PDF object | The PDF is stored encrypted at rest (server-side encryption) in blob storage; the object is not world-readable (NFR-3). |
| 2 | Verify access path | The recruiter views/downloads the PDF only via a short-lived signed URL or an authorized, tenant-checked endpoint; the raw blob URL is not exposed in the API/UI and is not directly retrievable without authorization. |
| 3 | Attempt to guess/enumerate the blob URL | A direct request to the storage path (without a valid signature/auth) is denied; the path is tenant-scoped and not guessable across applicants/tenants (FR-3). |
| 4 | Verify substitution completeness | The generated PDF contains NO literal `{{...}}` tokens; all template placeholders are substituted; a placeholder with no supplied value resolves to a safe blank/default, not a leaked raw token (FR-2). |
| 5 | Missing-variable generation | Generating from a template referencing a not-supplied placeholder still succeeds with that field blank/defaulted; generation does not error or emit a raw token. |
| 6 | Verify filename uniqueness/no overwrite | Each generated/versioned PDF gets a distinct filename; a new version does not overwrite a prior version's PDF (supports TC-REC-007-08). |

## 6. Postconditions
- Offer PDFs are encrypted at rest, accessed only via signed/authorized tenant-scoped paths, and fully variable-substituted with no leaked tokens.

# TC-REC-010-12: Authorization -> conversion requires BOTH Recruitment.Manage.All AND Employee.Create.All; missing either is denied (BR-1)

## 1. Test Objective
Verify the dual-permission authorization gate (BR-1, story preconditions): the convert action AND endpoint require BOTH `Recruitment.Manage.All` and `Employee.Create.All` in the resolved tenant. A user with only one of the two — or neither — is denied (403) and no employee/account/link is created. The UI hides/disables the action for unauthorized users (defense-in-depth), but the server-side check is authoritative (a forged/direct API call is still rejected).

## 2. Related Requirements
- User Story: US-REC-010
- Business Rules: BR-1 (conversion requires Recruitment.Manage.All + Employee.Create.All)
- Preconditions: story S2 (both permissions required within the resolved tenant)

## 3. Preconditions
- Tenant "acme"; applicant {acme_applicantId} Hired with Accepted offer.
- Users: U_both (both perms), U_recOnly (Recruitment.Manage.All only), U_empOnly (Employee.Create.All only), U_none (neither, e.g. a basic Employee role).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| U_both | Recruitment.Manage.All + Employee.Create.All | authorized |
| U_recOnly | Recruitment.Manage.All only | denied |
| U_empOnly | Employee.Create.All only | denied |
| U_none | neither | denied |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As U_both, convert {acme_applicantId} | Allowed; conversion succeeds (control case) (BR-1). |
| 2 | As U_recOnly, call the convert API directly | 403 denied (missing Employee.Create.All); no employee/account created (BR-1). |
| 3 | As U_empOnly, call the convert API directly | 403 denied (missing Recruitment.Manage.All); no writes (BR-1). |
| 4 | As U_none, call the convert API directly | 403 denied; the UI also hides/disables the "Convert to Employee" action. |
| 5 | Verify UI vs server | For U_recOnly/U_empOnly/U_none the UI hides the action; the direct API call is STILL rejected server-side (server check authoritative). |
| 6 | Verify no partial writes on denial | No employee/User/UserTenant/link rows and no filled_count change result from any denied attempt. |

## 6. Postconditions
- Only a user holding both permissions can convert; every under-permissioned attempt is denied with no side effects.

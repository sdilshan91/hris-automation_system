# TC-NTF-004-08: Append-only / immutability -> the application cannot UPDATE or DELETE an audit_log row

## 1. Test Objective
Verify that audit records are immutable: the application cannot modify or delete an `audit_log` row.
There is no application endpoint or service method that updates/deletes audit rows, and an attempt to
do so is rejected. Confirms BR-1 / FR-6 (append-only audit trail).

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-1 (immutable, tamper-proof audit record)
- Functional Requirements: FR-6 (audit_log append-only; app DB role lacks UPDATE/DELETE)
- Business Rules: BR-1 (audit records cannot be modified or deleted through the application)

## 3. Preconditions
- Tenant A is active; an admin/auditor `admin1` is authenticated.
- At least one audit row exists for Tenant A.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| target audit row | an existing audit_log_id | the immutability target |
| actor | admin1 | highest available privilege |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Survey the API surface for any endpoint that edits or deletes an audit row | NO such endpoint exists -- audit log is read-only at the application surface (viewer only, US-NTF-005) |
| 2 | Survey the application/service layer for any code path that issues UPDATE/DELETE against audit_log | NO application code path mutates audit rows; the interceptor only INSERTs |
| 3 | Attempt to mutate an audit row via any available admin operation | Operation is unavailable / rejected; the row is unchanged |
| 4 | [CONDITIONAL / DEFERRED -- DB role] Using the application DB role, issue a raw `UPDATE audit_log SET action='x'` and a `DELETE FROM audit_log` | EXPECTED once the append-only DB grant is provisioned: permission-denied error. NOTE: per platform, the INSERT-only DB role + grant revocation (FR-6) is a deferred hardening step; assert at the application layer today and mark the DB-grant enforcement CONDITIONAL until the role is provisioned |
| 5 | Re-read the target audit row | The row is byte-for-byte unchanged (action, before, after, timestamp all intact) |

## 6. Postconditions
- The audit row is unchanged; no application path can mutate it. DB-role enforcement tracked as deferred.

# TC-NTF-002-05: "Send Test Email" delivers the rendered template to a specified address

## 1. Test Objective
Verify that the "Send Test Email" action renders the current template with sample data and delivers
exactly one email to the recipient address entered by the admin, for preview purposes.

## 2. Related Requirements
- User Story: US-NTF-002
- Functional Requirements: FR-8 (send a test email on demand)
- Supporting: FR-2 (placeholder resolution), BR-3 (HTML + plain-text)

## 3. Preconditions
- Tenant Admin A is authenticated and editing the "Leave Approved" template (custom content present).
- An SMTP relay / transactional email service (or capture/sandbox) is configured.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| recipient | qa.tester@acme.com | entered in the Send Test modal |
| event_key | leave_approved | |
| content | current editor content (custom) | rendered with sample data |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Click "Send Test Email" | A modal opens prompting for the recipient address |
| 2 | Enter `qa.tester@acme.com` and confirm | The request is accepted; a success toast/confirmation is shown |
| 3 | Inspect the recipient mailbox / capture | Exactly one email arrives at `qa.tester@acme.com` rendered from the CURRENT editor content with sample data; placeholders resolved (no raw `{{...}}`) |
| 4 | Verify the email parts | Email contains both HTML and plain-text parts (BR-3); subject matches the current template subject rendered with sample data |
| 5 | Enter an invalid address (e.g. `not-an-email`) and confirm | Validation rejects it; no email is sent |
| 6 | Verify scope | The test email uses Tenant A's session context (sender/branding); it does not affect persisted templates |

## 6. Postconditions
- One test email delivered to the specified address; no template state changed.

# TC-NTF-001-02: Unread badge increments on arrival and decrements on read

## 1. Test Objective
Verify the unread-count badge reflects the true unread total: it increments as notifications
arrive and decrements as individual notifications are marked read. Implements the story's
"badge count" test hint (send 5 -> "5"; read 2 -> "3").

## 2. Related Requirements
- User Story: US-NTF-001
- Acceptance Criteria: AC-2, AC-4
- Functional Requirements: FR-5 (badge), FR-7 (mark as read)

## 3. Preconditions
- `emp1` logged in (Tenant A), SignalR connected, badge = 0, no prior notifications.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| notifications sent | 5 | distinct types |
| notifications read | 2 | individually clicked/marked |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Trigger 5 notifications for `emp1` | Badge increments 0->1->2->3->4->5 in real time; displays "5" |
| 2 | Open the panel; all 5 appear unread (bold + blue dot) | List shows 5 unread, most recent first |
| 3 | Mark notification #1 as read | Badge decrements 5 -> 4; item #1 changes to read style |
| 4 | Mark notification #2 as read | Badge decrements 4 -> 3; displays "3" |
| 5 | Reload the page; SignalR reconnects | Badge persists at "3" (server-sourced unread count, not client memory) |

## 6. Postconditions
- 2 notifications read, 3 unread; badge = 3 in DB and UI.

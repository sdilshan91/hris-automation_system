# TC-NTF-002-04: "Reset to Default" removes the override; future emails revert to default + audit record

## 1. Test Objective
Verify that clicking "Reset to Default" on a customized template (after confirmation) soft-deletes the
tenant override, reverts future emails for that event to the system default, and creates an audit record.

## 2. Related Requirements
- User Story: US-NTF-002
- Acceptance Criteria: AC-4 (reset -> override removed/soft-deleted, revert to default, audit record)
- Functional Requirements: FR-6 (fall back to default), FR-9 (log template changes)

## 3. Preconditions
- Tenant A has an EXISTING custom "Leave Approved" override (from TC-NTF-002-01).
- Tenant Admin A is authenticated.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| event_key | leave_approved | |
| current status | Custom | before reset |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the custom "Leave Approved" template and click "Reset to Default" | A confirmation dialog appears |
| 2 | Confirm the reset | The override is soft-deleted (is_active=false / removed) scoped to Tenant A; the list status reverts to "Default" |
| 3 | Inspect the audit log | An audit record exists for the reset action: actor=adminA, event_key=leave_approved, action=reset_to_default, tenant_id=Tenant A, timestamp set |
| 4 | Trigger a new leave approval for a Tenant A employee | The email is rendered from the SYSTEM DEFAULT template, not the (now-removed) custom one |
| 5 | Cancel the dialog on a re-open instead of confirming | No change is made; override (if re-created) remains as-is — reset only on explicit confirmation |

## 6. Postconditions
- Tenant A's "Leave Approved" override is soft-deleted; emails use the system default; reset audited.

# TC-NTF-001-11: Accessibility — ARIA live region announces new notifications; keyboard navigable (WCAG 2.1 AA)

## 1. Test Objective
Verify the notification bell and panel meet WCAG 2.1 AA: an ARIA live region announces newly
arriving notifications to screen readers, the bell/panel are fully keyboard operable, the badge
count is announced, and color contrast / responsiveness hold from 360px to 4K.

## 2. Related Requirements
- User Story: US-NTF-001
- Acceptance Criteria: AC-2, AC-3
- Non-Functional: NFR-6 (WCAG 2.1 AA, ARIA live region, keyboard), NFR-4 (responsive 360px-4K)

## 3. Preconditions
- `emp1` (Tenant A) logged in, SignalR connected.
- Screen reader available (NVDA/VoiceOver) and an automated a11y scanner (axe).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| live region politeness | polite (aria-live="polite") | non-interrupting |
| viewport widths | 360px, 768px, 1920px, 4K | responsive sweep |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | With screen reader active, trigger a new notification | An ARIA live region announces the new notification (e.g., title) without stealing focus |
| 2 | Tab to the bell icon | Bell is focusable; has an accessible name including the unread count (e.g., "Notifications, 3 unread") |
| 3 | Activate the bell with Enter/Space | Panel opens; focus moves into the panel; Esc closes and returns focus to the bell |
| 4 | Arrow/Tab through the notification items | Each item is reachable and activatable by keyboard; Enter triggers mark-read + navigate |
| 5 | Run axe on the open panel | No WCAG 2.1 AA violations (contrast, roles, names, focus order) |
| 6 | Verify unread blue dot / bold also conveyed non-visually | Unread state exposed via text/aria, not color alone |
| 7 | Resize 360px -> 4K | Panel opens as bottom sheet / full-screen on mobile, dropdown on desktop; no overflow or loss of content |

## 6. Postconditions
- Notification UI usable via keyboard and screen reader; no AA violations.

# TC-NTF-002-03: Live preview renders the template with sample data

## 1. Test Objective
Verify the template editor's live preview renders the current subject/HTML/plain-text content with
sample data, resolving placeholders so the admin sees the email exactly as a recipient would, before
saving or sending.

## 2. Related Requirements
- User Story: US-NTF-002
- Acceptance Criteria: AC-2 (live preview renders with sample data)
- Functional Requirements: FR-3 (variable reference panel), FR-4 (live preview with sample data)

## 3. Preconditions
- Tenant Admin A is authenticated and editing the "Leave Approved" template.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| editor subject | "Hi {{employee.firstName}}, leave {{leave.type}} approved" | |
| editor body_html | "<p>{{tenant.companyName}} approved your {{leave.type}} leave.</p>" | |
| sample employee.firstName | (sample) e.g. "Sample User" | provided by preview sample data |
| sample leave.type | (sample) e.g. "Annual" | |
| sample tenant.companyName | Acme Corp | from Tenant A context |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the "Leave Approved" editor; confirm the variable reference panel | Panel lists placeholders valid for `leave_approved` (e.g. `{{employee.firstName}}`, `{{leave.type}}`, `{{leave.startDate}}`, `{{tenant.companyName}}`) |
| 2 | Type subject and HTML body containing placeholders | The live preview pane updates (live or on change) |
| 3 | Inspect the preview | Placeholders are replaced with sample data values; no raw `{{...}}` tokens remain in the preview |
| 4 | Click a placeholder name in the reference panel while the cursor is in the body | The placeholder token is inserted at the cursor position |
| 5 | Edit the subject and observe | Preview subject updates to match; HTML formatting (bold, links) renders, not shown as raw tags |

## 6. Postconditions
- No persistence required (preview only); editor state unchanged unless saved.

# TC-NTF-004-05: PII read audit -> accessing bank/national-id/salary produces "{Entity}.ReadSensitive" naming the fields accessed

## 1. Test Objective
Verify that reading sensitive PII fields (bank account, national ID, salary details) produces an
audit record with action "{Entity}.ReadSensitive" that names which sensitive fields were accessed,
the accessor's identity, and the trace ID -- without storing the sensitive values themselves.
Confirms read-side auditing of PII (which the SaveChanges interceptor does NOT cover, since reads are
not writes).

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-2 (salary read -> "Employee.ReadSensitive" naming accessed fields + accessor + trace ID)
- Functional Requirements: FR-4 (audit PII reads of bank account, national ID, salary), FR-7 (trace ID enrichment)

## 3. Preconditions
- Tenant A is active; HR Officer `hr1` is authenticated and authorized to view sensitive fields.
- An Employee exists with bank account, national ID, and salary populated.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| sensitive fields accessed | bankAccount, nationalId, salary | named in the audit record |
| accessor | hr1 | actor |
| entity | Employee | resource |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, open the Employee's sensitive/compensation detail (endpoint that surfaces bank/national-id/salary) | Data returns; HTTP 200 |
| 2 | Query `audit_log` for the resource_id; inspect `action` | action = "Employee.ReadSensitive" |
| 3 | Inspect the record's field list | The record names which sensitive fields were accessed (e.g. ["bankAccount","nationalId","salary"]) -- field names, not values |
| 4 | Confirm values are NOT leaked into the audit row | The actual bank/national-id/salary VALUES are NOT stored in before/after (only the field names accessed) |
| 5 | Inspect accessor + trace fields | actor_user_id=hr1, trace_id populated (FR-7), tenant_id=Tenant A |
| 6 | Access only ONE sensitive field (e.g. salary only) | The audit row lists only the field(s) actually accessed (e.g. ["salary"]), not the full set |

## 6. Postconditions
- A "ReadSensitive" audit row exists naming the accessed PII fields; no PII values are persisted in audit.

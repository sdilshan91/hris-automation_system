# TC-NTF-002-09: Maximum 2 language variants per template per tenant (boundary)

## 1. Test Objective
Verify the BR-6 limit: a tenant can create at most 2 language variants of a single template; attempting
to add a 3rd variant is rejected with a clear message, and the 2-variant boundary is accepted.

## 2. Related Requirements
- User Story: US-NTF-002
- Business Rules: BR-6 (max 2 language variants per template per tenant — plan-configurable)
- Functional Requirements: FR-5 (per-language variants)

## 3. Preconditions
- Tenant A is active with i18n config allowing the languages under test.
- Tenant Admin A is authenticated; the plan limit is the default 2 variants.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| event_key | leave_approved | |
| variant 1 | language=en | accepted |
| variant 2 | language=es | accepted (boundary = limit) |
| variant 3 | language=fr | should be rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create the `en` variant and save | Accepted (1 of 2) |
| 2 | Create the `es` variant and save | Accepted (2 of 2 — at the boundary) |
| 3 | Attempt to add a `fr` variant (UI) | The "add variant" control is disabled or shows the limit; a clear message indicates max 2 variants |
| 4 | Attempt to create the 3rd variant via API directly | Rejected (422/400) with a validation error citing the variant limit; no 3rd variant persisted |
| 5 | Verify persisted count | Exactly 2 variants exist for `leave_approved` in Tenant A |
| 6 | (Plan-config) If a higher plan limit is configured, repeat | Limit follows plan configuration; default remains 2 |

## 6. Postconditions
- Tenant A has exactly 2 language variants; no over-limit variant created.

# TC-NTF-001-03: "Mark All as Read" resets badge to 0 and persists to DB

## 1. Test Objective
Verify the bulk "Mark All as Read" action marks every unread notification as read, resets the
badge to zero, and persists the change to the database (survives reload). Implements the
"Mark All as Read" test hint (send 10 -> click -> badge=0, all rows updated).

## 2. Related Requirements
- User Story: US-NTF-001
- Acceptance Criteria: AC-5
- Functional Requirements: FR-7 (bulk mark), FR-3 (persist)

## 3. Preconditions
- `emp1` logged in (Tenant A), SignalR connected.
- 10 unread notifications exist for `emp1`; badge = 10.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| unread before | 10 | |
| unread after | 0 | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the panel; confirm badge shows "10" and 10 unread items | Initial state correct |
| 2 | Click "Mark All as Read" at the top of the panel | Action processed; success indicated |
| 3 | Observe the badge and list | Badge resets to 0 (hidden); all items render in read style (no bold, no blue dot) |
| 4 | Query the `notification` table for `emp1` | All 10 rows have is_read = true |
| 5 | Reload the page; SignalR reconnects | Badge remains 0; items still read — change persisted, not client-only |
| 6 | Verify the action only affected `emp1`'s own notifications | No other user's rows were modified |

## 6. Postconditions
- All of `emp1`'s notifications are read; badge = 0.

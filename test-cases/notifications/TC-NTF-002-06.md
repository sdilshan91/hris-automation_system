# TC-NTF-002-06: Per-language template variants — recipient's language selects the right variant

## 1. Test Objective
Verify that a tenant can maintain English + a secondary-language variant of a template and that, at
send time, the recipient's language preference selects the matching variant.

## 2. Related Requirements
- User Story: US-NTF-002
- Functional Requirements: FR-5 (per-language template variants per the tenant i18n config)
- Business Rules: BR-6 (per-language variants; max 2 per template per tenant)

## 3. Preconditions
- Tenant A is active with i18n config enabling English (`en`) and Spanish (`es`).
- Tenant Admin A is authenticated.
- Employee `empEn` has language preference `en`; employee `empEs` has language preference `es`; both in Tenant A.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| event_key | leave_approved | |
| en subject | "Your leave is approved" | language=en |
| es subject | "Tu permiso ha sido aprobado" | language=es |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open "Leave Approved"; create/save the `en` variant | `en` variant persisted with tenant_id=Tenant A, language=en |
| 2 | Add a second-language (`es`) variant and save | `es` variant persisted (language=es), distinct from the `en` variant |
| 3 | Approve leave for `empEn` (language=en) | The delivered email uses the `en` variant ("Your leave is approved") |
| 4 | Approve leave for `empEs` (language=es) | The delivered email uses the `es` variant ("Tu permiso ha sido aprobado") |
| 5 | Approve leave for an employee whose language has no variant (e.g. `fr`) | The system falls back per i18n config (default language variant / `en`), and still sends an email (BR-2) |

## 6. Postconditions
- Tenant A has 2 language variants of "Leave Approved"; recipients receive the correct variant.

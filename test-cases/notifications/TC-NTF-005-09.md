# TC-NTF-005-09: Meta-audit — viewing the audit log creates an "AuditLog.View" audit record

## 1. Test Objective
Verify the FR-9 / BR-5 meta-audit DELTA: when an authorized user views the audit log list, the system
itself writes an audit record with action "AuditLog.View" recording who viewed the audit trail (actor,
tenant, timestamp, IP/UA). This is a NEW behavior for US-NTF-005 not present in US-ADM-008's read-only
list TCs.

## 2. Related Requirements
- User Story: US-NTF-005
- Acceptance Criteria: (supports AC-1 accountability)
- Functional Requirements: FR-9 (log audit-log access itself -- meta-audit)
- Business Rules: BR-5 (viewing creates an "AuditLog.View" record)

## 3. Preconditions
- `adminA` (Audit.View) authenticated in Tenant A.
- The audit row count for Tenant A is captured as a baseline before viewing.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| actor | adminA | viewer |
| expected action | AuditLog.View | meta-audit |
| tenant | Tenant A | stamped on the meta-audit row |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Capture the Tenant A audit-row baseline count | Baseline recorded |
| 2 | As `adminA`, open the audit log list view | The list renders |
| 3 | Query the audit log for new rows since the baseline | A new row with action "AuditLog.View" exists (FR-9, BR-5) |
| 4 | Inspect the meta-audit row fields | actor_user_id = adminA; tenant_id = Tenant A; timestamp ~ now; IP + user agent enriched |
| 5 | Confirm the meta-audit row itself is tenant-scoped | The "AuditLog.View" row carries Tenant A's tenant_id (visible to Tenant A admins, invisible to other tenants -- see TC-NTF-ISO-017) |
| 6 | [Boundary] Confirm view-logging does not loop infinitely | Viewing the list once produces a bounded number of meta-audit rows (not one-per-displayed-row); re-viewing produces a new record per view event |

## 6. Postconditions
- An "AuditLog.View" meta-audit row exists for adminA in Tenant A; accountability preserved.

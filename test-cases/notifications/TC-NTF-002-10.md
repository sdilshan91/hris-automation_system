# TC-NTF-002-10: Template change is audited with before/after state

## 1. Test Objective
Verify that creating, editing, and resetting a template writes a tenant audit log entry capturing the
actor, event, timestamp, and before/after content — recorded via the EF Core SaveChanges interceptor.

## 2. Related Requirements
- User Story: US-NTF-002
- Functional Requirements: FR-9 (log template changes in the tenant audit log)
- Non-Functional: NFR-6 (audited via EF Core SaveChangesInterceptor)

## 3. Preconditions
- Tenant A is active; Tenant Admin A is authenticated.
- System default "Leave Approved" exists; no Tenant A override yet (clean baseline).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| event_key | leave_approved | |
| before subject | "Your leave request has been approved" | system default baseline |
| after subject | "Maya, your leave is approved!" | customized |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `adminA`, customize "Leave Approved" (change subject + body) and Save | Override saved; an audit entry is written |
| 2 | Inspect the audit log entry for the create/update | Entry has: tenant_id=Tenant A, actor=adminA, entity=email_template, event_key=leave_approved, action=update/create, timestamp |
| 3 | Verify before/after content in the audit entry | Before = prior content (default/previous version); After = the new subject/body — the change is captured, not just "modified" |
| 4 | Edit the template again and Save | A second audit entry is written with the new before/after (version incremented) |
| 5 | Reset to default and inspect audit | A reset audit entry exists (consistent with TC-NTF-002-04) capturing the removal |
| 6 | Confirm audit is automatic | The audit entry is produced by the SaveChanges interceptor without an explicit audit call in the handler |

## 6. Postconditions
- Each template mutation has a corresponding tenant-scoped audit entry with before/after.

# TC-NTF-004-04: Authentication-event audit -> login success/failure, logout, password change, MFA produce rows with IP/UA/status

## 1. Test Objective
Verify that authentication events are audited with the correct auth-specific action types, the
actor's identity, IP address, user agent, and a success/failure status. Auth events are not driven by
the entity SaveChangesInterceptor (they are not entity writes) so this confirms the dedicated auth
audit path emits records for the full set of events.

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-4 (auth event -> auth-specific action, actor, IP, UA, success/failure status)
- Functional Requirements: FR-3 (audit login success/failure, logout, password change, MFA enroll/disable, refresh-token rotation, account lockout), FR-7 (IP/UA enrichment)

## 3. Preconditions
- Tenant A is active; user `u1` has known valid credentials and MFA available.
- The auth audit writer is enabled.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user | u1 | Tenant A member |
| wrong_password | "bad-pass" | for failure case |
| client_ip | 203.0.113.10 | asserted on rows |
| user_agent | "Mozilla/5.0 ... Chrome" | asserted on rows |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Log in as `u1` with valid credentials | Login succeeds; an audit row with action "Auth.LoginSuccess", actor=u1, status=success, ip_address=203.0.113.10, user_agent set |
| 2 | Attempt login with wrong_password | Login fails; an audit row with action "Auth.LoginFailure" (or equivalent), status=failure, IP/UA captured, actor identified by submitted username |
| 3 | Log out | An audit row with action "Auth.Logout", actor=u1, IP/UA captured |
| 4 | Change `u1`'s password | An audit row with action "Auth.PasswordChange", status=success, IP/UA captured; the new/old password values are NOT stored in before/after |
| 5 | Enroll/disable MFA for `u1` | An audit row with action "Auth.MfaEnroll" (and "Auth.MfaDisable" on disable), IP/UA, status captured |
| 6 | Inspect tenant scoping on all rows | Every auth audit row carries tenant_id = Tenant A from the session/resolution context |

## 6. Postconditions
- One audit row per auth event exists with status and IP/UA; no credential secrets are stored.

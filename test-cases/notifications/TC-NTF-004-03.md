# TC-NTF-004-03: Soft-delete audit -> IsDeleted false->true produces "{Entity}.Delete" with before/after on the flag

## 1. Test Objective
Verify that soft-deleting a business entity (setting `is_deleted` from false to true) produces an
audit record with action "{Entity}.Delete", `before` showing `is_deleted: false` and `after` showing
`is_deleted: true`. Confirms soft-deletes are audited as Delete actions, not silent updates.

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-3 (leave request soft-delete -> "LeaveRequest.Delete", before is_deleted:false, after is_deleted:true)
- Functional Requirements: FR-1 (auto-capture DELETE/soft-delete)
- Business Rules: BR-2 (DELETE semantics)

## 3. Preconditions
- Tenant A is active; HR `hr1` is authenticated.
- A LeaveRequest exists in Tenant A with is_deleted = false.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| entity | LeaveRequest | existing, is_deleted=false |
| is_deleted (old) | false | before |
| is_deleted (new) | true | after (soft delete) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, soft-delete the LeaveRequest (DELETE endpoint sets is_deleted=true) and save | The row remains in the table with is_deleted=true (soft delete); HTTP 200/204 |
| 2 | Query `audit_log` for the resource_id; inspect `action` | action = "LeaveRequest.Delete" (soft-delete is recorded as a Delete action, not "Update") |
| 3 | Inspect `before` JSONB | Contains `is_deleted: false` (and at minimum the changed flag) |
| 4 | Inspect `after` JSONB | Contains `is_deleted: true` |
| 5 | Inspect resource + actor fields | resource_type="LeaveRequest", resource_id correct, actor_user_id=hr1, tenant_id=Tenant A |

## 6. Postconditions
- The LeaveRequest is soft-deleted; one "LeaveRequest.Delete" audit row exists.

# TC-NTF-004-12: Capture-boundary cases -> raw-SQL/Dapper bypass acknowledged; BRIN time-range query; per-plan retention (boundary)

## 1. Test Objective
Verify the documented boundaries and supporting behaviors of the audit subsystem: (a) writes that go
through EF Core `SaveChanges` are captured while raw SQL / Dapper writes bypass the interceptor and
are NOT auto-audited (a known constraint), (b) time-range queries over the append-only log are served
efficiently (BRIN index, NFR-3), and (c) retention is configurable per tenant plan (NFR-4 / BR-5).

## 2. Related Requirements
- User Story: US-NTF-004
- Functional Requirements: FR-1 (SaveChanges-captured writes)
- Non-Functional: NFR-3 (BRIN index for time-range queries), NFR-4 (configurable retention: 90d starter / 365d professional / 7y enterprise)
- Business Rules: BR-5 (purge per retention via Hangfire; archive to cold storage first)
- Assumptions/Constraints (S10): raw SQL / Dapper bypass the interceptor and must be audited manually

## 3. Preconditions
- Tenant A is active with a known plan tier; audit rows span a known date range.
- A purge/archival Hangfire job is configured (or its schedule is inspectable).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| EF write | Employee.Update via SaveChanges | captured |
| raw write | direct SQL UPDATE bypassing EF | NOT auto-captured (documented constraint) |
| retention (starter) | 90 days | per-plan |
| time-range query | last 30 days | BRIN-served |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Perform an entity update via EF Core SaveChanges | An audit row is produced (FR-1) |
| 2 | Perform an equivalent write via raw SQL / Dapper bypassing EF | NO audit row is auto-produced -- this is the documented bypass constraint (S10); flag that such paths need manual auditing |
| 3 | Run a time-range query over audit_log (e.g. last 30 days) | Returns the correct rows; the query is served by the BRIN index on timestamp (NFR-3) -- verify the plan uses the BRIN index where available |
| 4 | Inspect retention configuration for the tenant's plan | Retention is configurable per plan: 90d (starter), 365d (professional), 7y (enterprise) -- NFR-4 |
| 5 | Inspect the purge/archival job (BR-5) | A Hangfire scheduled job exists to purge rows beyond the retention window; purged rows may be archived to cold storage first; the job is tenant-aware |
| 6 | [DEFERRED NOTE] Streaming export to ELK/Splunk (FR-9) and month/tenant-range partitioning (NFR-6 Phase 2) | Documented as Phase-2 / deferred; verify the seam exists or record as not-yet-implemented |

## 6. Postconditions
- EF writes audited, raw-SQL bypass documented; time-range queries efficient; per-plan retention + purge job confirmed.

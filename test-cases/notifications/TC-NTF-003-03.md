# TC-NTF-003-03: New user inherits tenant default notification preferences

## 1. Test Objective
Verify that when a new user is provisioned in a tenant, their notification preference matrix is
seeded from the tenant-level defaults (the cascade System defaults < Tenant defaults < User
preferences), so they start with the tenant's configured baseline before any personal change.

## 2. Related Requirements
- User Story: US-NTF-003
- Acceptance Criteria: AC-1 (matrix displays a row per category with channel toggles)
- Functional Requirements: FR-5 (cascade: System < Tenant < User; user overrides tenant), FR-2 (categories), FR-4 (mandatory categories)
- Business Rules: BR-1 (new users inherit tenant default preferences)

## 3. Preconditions
- Tenant A has customized tenant defaults: e.g. "Attendance Alerts" Email = OFF at the tenant level,
  "Security Alerts" mandatory = true; all other categories at system defaults (both channels ON).
- A brand-new user `newuser` is created in Tenant A and has never opened the preferences page.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Tenant A default: Attendance Alerts Email | false | tenant-level default |
| Tenant A default: Security Alerts | mandatory | is_mandatory=true |
| Tenant A default: all others | in-app ON / email ON | system default |
| user | newuser | first login, no personal prefs yet |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `newuser`, open Profile > Notification Preferences for the first time | Matrix renders with a row per category (FR-2) and toggle states reflecting Tenant A defaults, NOT bare system defaults |
| 2 | Inspect "Attendance Alerts" | Email = OFF (inherited from Tenant A default), In-App = ON |
| 3 | Inspect "Security Alerts" | Shown mandatory/locked (inherited is_mandatory=true) |
| 4 | Inspect other categories (e.g. "Leave Updates", "Payroll Notifications") | In-App ON / Email ON (system default, unchanged by tenant) |
| 5 | Inspect persisted/effective preferences for `newuser` | Effective preferences equal the resolved cascade for Tenant A; any stored records carry tenant_id=Tenant A and user_id=newuser |

## 6. Postconditions
- `newuser` has effective preferences matching Tenant A defaults; no custom user override yet.

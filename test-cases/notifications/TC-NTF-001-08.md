# TC-NTF-001-08: Pagination 20 per page with infinite scroll (boundary)

## 1. Test Objective
Verify the notification panel/list loads 20 records initially and lazily loads the next 20 on
infinite scroll, ordered by created_at DESC, with no duplicates or gaps at page boundaries.
Implements the "Pagination" test hint (50 notifications -> 20 then +20).

## 2. Related Requirements
- User Story: US-NTF-001
- Acceptance Criteria: AC-3
- Functional Requirements: FR-6 (pagination 20/page, infinite scroll)

## 3. Preconditions
- `emp1` (Tenant A) has exactly 50 notifications spanning a known created_at ordering.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| total notifications | 50 | |
| page size | 20 | per FR-6 |
| expected pages | 20 + 20 + 10 | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the panel / notifications page | First 20 notifications load, most recent first (created_at DESC) |
| 2 | Scroll to the bottom of the loaded list | Next 20 (items 21-40) load and append; no duplicates with page 1 |
| 3 | Scroll again to the bottom | Final 10 (items 41-50) load and append |
| 4 | Scroll further | No more items load; an end indicator / no further fetch occurs |
| 5 | Verify global ordering across all loaded items | Strictly created_at DESC across the full 50 with no gaps |
| 6 | Boundary: user with exactly 20 notifications | Loads 20; scrolling triggers no second fetch / clean empty next-page |
| 7 | Boundary: user with 0 notifications | Empty-state message shown; no error; badge hidden |

## 6. Postconditions
- All 50 notifications viewable via scroll; correct order; no client errors.

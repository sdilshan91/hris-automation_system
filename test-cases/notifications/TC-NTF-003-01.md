# TC-NTF-003-01: Disable email for "Leave Updates" -> leave approval sends in-app only, no email (happy path)

## 1. Test Objective
Verify that when a user disables the Email channel for the "Leave Updates" category and saves, a
subsequent leave-approval event is delivered ONLY via in-app notification and NO email is sent. The
Notification Dispatcher must honor the user preference at dispatch time. Validates the primary
success path.

## 2. Related Requirements
- User Story: US-NTF-003
- Acceptance Criteria: AC-2 (disable email for Leave Updates -> in-app only, no email; preference persisted with tenant_id + user_id)
- Functional Requirements: FR-6 (preferences applied at dispatch time), FR-3 (channel toggles), FR-8 (tenant_id + user_id set)
- Business Rules: BR-6 (changes take effect for future notifications)

## 3. Preconditions
- Tenant A is active; Employee `emp1` is authenticated within Tenant A and has a pending leave request.
- US-NTF-001 (in-app) and US-NTF-002 (email templates) are operational.
- "Leave Updates" is a non-mandatory category for Tenant A; `emp1` has both channels enabled by default.
- An email capture/sandbox is configured to observe (or confirm absence of) outbound email.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| category | Leave Updates | non-mandatory |
| channel_in_app | true | left enabled |
| channel_email | false | toggled OFF by user |
| event | leave_approved | triggered after save |
| user_id | emp1 | |
| tenant_id | Tenant A | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `emp1`, go to Profile > Notification Preferences | Matrix loads with a "Leave Updates" row showing In-App = ON and Email = ON |
| 2 | Toggle Email OFF for "Leave Updates" | Toggle flips to off; In-App remains ON; debounced auto-save fires and a subtle "Saved" toast appears |
| 3 | Inspect the persisted preference record | Row for category "Leave Updates" has channel_in_app=true, channel_email=false, persisted with tenant_id=Tenant A and user_id=emp1 (FR-8) |
| 4 | As a manager, approve `emp1`'s leave request | Approval persists; a `leave_approved` notification event is raised for `emp1` |
| 5 | Observe in-app delivery | `emp1` receives a real-time in-app notification for the leave approval (badge increments) |
| 6 | Inspect the email capture/sandbox | NO `leave_approved` email is sent to `emp1` -- the Dispatcher skipped the email channel per preference (FR-6) |

## 6. Postconditions
- `emp1` has Email disabled for "Leave Updates"; one in-app notification delivered, zero emails sent.

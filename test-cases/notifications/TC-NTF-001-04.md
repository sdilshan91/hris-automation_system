# TC-NTF-001-04: Clicking a notification marks it read and navigates to the linked resource

## 1. Test Objective
Verify that clicking a notification marks it read, decrements the unread badge, and navigates
the user to the resource referenced by resource_type/resource_id (e.g., a leave_approved
notification routes to the leave request detail page). Implements the "Navigation" test hint.

## 2. Related Requirements
- User Story: US-NTF-001
- Acceptance Criteria: AC-3, AC-4
- Functional Requirements: FR-7 (mark as read), FR-8 (navigate)

## 3. Preconditions
- `emp1` logged in (Tenant A), SignalR connected.
- One unread `leave_approved` notification exists with resource_type=LeaveRequest, resource_id=LR-1001; badge = 1.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| type | leave_approved | |
| resource_type | LeaveRequest | |
| resource_id | LR-1001 | |
| expected route | /leave/requests/LR-1001 | leave request detail |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the panel; confirm badge "1" and the unread item | Initial state correct |
| 2 | Click the `leave_approved` notification | The item is marked read (style changes, blue dot removed) |
| 3 | Observe the badge | Badge decrements 1 -> 0 (hidden) |
| 4 | Observe the router | App navigates to the leave request detail page for LR-1001 |
| 5 | Query the DB row for that notification | is_read = true |
| 6 | Click a notification whose resource_type/resource_id is null/missing | Item marked read + badge decremented; no navigation occurs (or navigates to the notifications list), no error |

## 6. Postconditions
- Clicked notification is read; user is on the linked resource page.

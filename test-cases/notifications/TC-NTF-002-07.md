# TC-NTF-002-07: Unresolvable placeholder is replaced with an empty string, not raw text (negative)

## 1. Test Objective
Verify that a placeholder that cannot be resolved at send time is replaced with an empty string in the
delivered email — never left as the raw `{{...}}` token and never raising the send.

## 2. Related Requirements
- User Story: US-NTF-002
- Business Rules: BR-5 (unresolved placeholders replaced with empty strings, not raw placeholder text)
- Supporting: FR-2 (placeholder resolution at send time), BR-2 (always send a template)

## 3. Preconditions
- Tenant A is active; Tenant Admin A is authenticated.
- A template contains a placeholder that will have no value at send time (e.g. `{{employee.middleName}}`
  where the employee has no middle name, or an unknown/unsupported token).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| event_key | leave_approved | |
| body_html | "<p>Hi {{employee.firstName}} {{employee.middleName}}, approved.</p>" | middleName unresolved |
| unsupported token | "{{leave.nonexistentField}}" | unknown placeholder |
| employee.firstName | Maya | |
| employee.middleName | (none) | unresolved |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Save the template containing `{{employee.middleName}}` and `{{leave.nonexistentField}}` | Save succeeds |
| 2 | Trigger a leave approval for `emp1` (no middle name) | Email is enqueued and sent (send not aborted) |
| 3 | Inspect the delivered email body | Unresolved placeholders render as empty strings: "Hi Maya , approved." — NOT "Hi Maya {{employee.middleName}}" |
| 4 | Search the rendered subject and both body parts for `{{` and `}}` | No raw placeholder tokens remain anywhere in the rendered email |
| 5 | Confirm whitespace handling is acceptable | Empty-string substitution leaves no literal `{{...}}`; surrounding text is intact |

## 6. Postconditions
- Email delivered with unresolved placeholders blanked; no raw tokens leaked.

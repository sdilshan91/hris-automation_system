# TC-CHR-001-101: The production `ClamAvVirusScanner` detects the EICAR test string against a real clamd daemon, and passes clean content — US-CHR-001 NFR-3 (ISSUE-101)

## 1. Test Objective
Confirm end-to-end that the pluggable `ClamAvVirusScanner` (registered when `VirusScanning:ClamAv:Host` is set) actually talks to a **live clamd** and enforces the malware gate: the EICAR standard anti-virus test string is flagged **INFECTED** (with the daemon's threat name), and ordinary content passes as clean. Before this arm the only ClamAV coverage was the transport-parser unit test — nothing exercised a real daemon or proved EICAR detection.

## 2. Related Requirements
- User Story: US-CHR-001 (employee documents); NFR-3 (uploaded files are virus-scanned before persistence)
- Findings: ISSUE-101 (wire a production virus scanner — ClamAV)
- Wiring: `IVirusScanner` → `ClamAvVirusScanner` (INSTREAM over TCP :3310) when `VirusScanning:ClamAv:Host` is non-blank; else the `AllowWithLogVirusScanner` stub. Fail-closed by default (`FailOpen=false`).

## 3. Preconditions
- Docker available; the `clamav/clamav:stable` image (a real clamd with a loaded signature DB). The test spins its own Testcontainer and waits for the image's HEALTHCHECK. **Category-gated (`[Trait("Category","ClamAv")]`) + opt-in** — excluded from the default run because clamd needs ~2 GB RAM + a first-boot signature load. Run: `dotnet test --filter Category=ClamAv`.

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Scan a stream containing the EICAR standard test string via `ClamAvVirusScanner.ScanAsync`. | `IsClean == false`; `ThreatName` non-empty and contains "eicar" (e.g. `Win.Test.EICAR_HDB-1`). `Scan_EicarTestString_IsDetectedInfected`. |
| 2 | Scan an ordinary harmless text stream. | `IsClean == true`; no threat name. `Scan_CleanContent_PassesAsClean`. |

## 5. Postconditions
- The virus-scan integration is proven against a real daemon: a known-bad payload is detected and rejected; clean content is allowed. (In the app, a non-clean result rejects the upload with 400 before persistence.)

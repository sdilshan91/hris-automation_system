# TC-CHR-005-48: Real-Postgres coverage for the `salary_grades` table — `numeric(18,2)` precision, the `(tenant_id, code)` unique index (23505), and the tenant query filter — US-CHR-005 (DF-48)

## 1. Test Objective
Prove on **real Postgres** (Testcontainers) the `salary_grades` behaviours that InMemory cannot enforce (shipped in #389, ISSUE-021):
- **`numeric(18,2)` precision** — a `MinAmount`/`MidAmount`/`MaxAmount` written with >2 decimals is rounded to 2 by the column type (`50000.999 → 50001.00`). InMemory keeps the full decimal — the exact InMemory-masks-Postgres class (cf. BUG-289/290).
- **DB `(tenant_id, code)` unique index** — a duplicate `(TenantId, Code)` insert (same case, bypassing the service's `ToLower` guard) raises Postgres **23505** (`DbUpdateException`). Proves the partial unique index backstop exists (InMemory enforces no unique index).
- **Tenant global query filter translates** — a grade created under tenant A is invisible to a tenant-B context (`WHERE tenant_id = …` on Npgsql), while an `IgnoreQueryFilters` probe confirms the row physically exists.

## 2. Related Requirements
- User Story: US-CHR-005 (job titles + salary grades)
- Findings: DF-48 (real-PG arm for `salary_grades`), ISSUE-021 (SalaryGrade CRUD + FK-validation)

## 3. Preconditions
- A `postgres:17-alpine` Testcontainer, migrated; the real `SalaryGradeService` + DbContext (snake_case).

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a grade with `MinAmount = 50000.999m` (and `.559`, `.004`); read back from a fresh context. | Rounded to `numeric(18,2)` (`50001.00`, `.56`, `.00`). `CreateSalaryGrade_RoundsAmountsToNumeric18_2_OnRealPostgres`. |
| 2 | Direct-insert two rows with identical `(TenantId, Code)`, same case. | 2nd `SaveChangesAsync` → `DbUpdateException` (23505). `DuplicateCode_SameTenant_ViolatesUniqueIndex_23505`. |
| 3 | Create under tenant A; query as tenant B (service + direct). | Empty for B; `IgnoreQueryFilters` confirms the row exists. `SalaryGrade_TenantQueryFilter_IsolatesAcrossTenants`. |

## 5. Postconditions
- The money-column precision, the unique-index backstop, and the tenant filter are proven on the real provider, not just InMemory.

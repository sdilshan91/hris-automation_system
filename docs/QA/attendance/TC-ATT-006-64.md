# TC-ATT-006-64: Regularization approval produces the correct payable OvertimeRecord and never deletes a terminal (Approved) record or its audit history — proven on real Postgres (DF-64 / DF-64-pg)

## 1. Test Objective
Verify on **real Postgres** (FK enforcement InMemory cannot give) the DF-64 regularization→overtime path: approving a regularized OT day rebuilds a **payable-but-Pending** `OvertimeRecord` (`IsPayrollReady=false`); a prior **Pending** auto-detected record is **superseded** (replace-not-duplicate, exactly one record for the day); and — the critical guard — a prior **Approved / payroll-ready** record is **never** deleted/replaced, so its immutable `OvertimeApprovalHistory` row is **not** cascade-deleted (`ON DELETE CASCADE` on the history FK never fires). This is the FK-cascade behaviour the InMemory DF-64 arms structurally cannot prove.

## 2. Related Requirements
- User Story: US-ATT-006 (Overtime Tracking and Approval)
- Acceptance Criteria: AC-1/AC-2 (OT auto-detection + approval); BR-1 complete audit trail
- Finding: DF-64 (regularized OT days must produce a payable record) + DF-64-pg (real-PG FK-cascade coverage)
- Related durable rule: correction paths must not delete terminal records ([[correction-paths-must-not-delete-terminal-records]])

## 3. Preconditions
- Docker available; Testcontainers `postgres:17-alpine`; migrations applied on container start.
- FK parents seeded (a `User` per employee for `fk_employees_users_user_id`, `Department`/`JobTitle`); `DateTimeKind.Utc` timestamps.

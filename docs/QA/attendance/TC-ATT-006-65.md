# TC-ATT-006-65: Re-regularizing a day with a prior auto-detected OT record must not double-count the superseded record in the weekly-cap (BR-5) advisory (DF-64-wk)

## 1. Test Objective
Verify the DF-64-wk fix: when the regularization approve funnel supersedes a prior auto-detected `OvertimeRecord` (staged `RemoveRange`, **not** flushed — the atomic single-commit is preserved) and rebuilds one, the weekly-cap (BR-5) advisory re-evaluation must **not** double-count the record being replaced. Because `EvaluateWeeklyCapAsync` reads `AsNoTracking` (which bypasses the change-tracker and so cannot see the un-flushed removal), the superseded record's ids are threaded through and **excluded** from the weekly sum. Without the exclusion the sum double-counts and falsely trips `WeeklyCapExceeded`.

## 2. Related Requirements
- User Story: US-ATT-006 (Overtime Tracking and Approval)
- Business Rule: BR-5 / FR-8 weekly-cap alert (advisory flag only — no pay impact)
- Finding: DF-64-wk (weekly-cap advisory double-count on re-regularize)

## 3. Preconditions
- An employee with a prior **Pending** auto-detected OT record on a day in the target ISO week.
- Weekly max configured so the real (post-replacement) total is within cap but the double-counted total would exceed it.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Weekly cap | 300 min | BR-5 max |
| Prior superseded Pending record | 180 min | same week, summed pre-fix |
| Rebuilt record (this approval) | 180 min | added as newMinutes |
| Real total | 180 (≤ 300) | flag should be false |
| Double-counted total | 360 (> 300) | flag would be true without the fix |

| Step | Action | Expected Result | Automated by |

## 6. Postconditions

# TC-NTF-005-02: Combined filters (date + action multi-select + actor) use AND semantics; result count shown; URL updated and bookmarkable

## 1. Test Objective
Verify the AC-2 happy path: applying a date range + action filter + actor filter together returns
only rows matching ALL three constraints (AND across filter groups), the result count is displayed,
and the URL is updated with query parameters so the filtered view is bookmarkable/shareable. This is
the headline AC-2 plus the URL-state DELTA (FR-3) that US-ADM-008 did not cover.

## 2. Related Requirements
- User Story: US-NTF-005
- Acceptance Criteria: AC-2 (combined filters refresh table, URL updated/bookmarkable, result count shown)
- Functional Requirements: FR-2 (filter controls), FR-3 (URL-based filter state), FR-7 (result count)
- Base coverage (reference): US-ADM-008 TC-ADM-008-08 (AND logic for combined filters, without URL state)

## 3. Preconditions
- `adminA` (Audit.View) authenticated in Tenant A.
- Seeded rows include: some "Employee.Update" rows by actor "John Doe" within the last 7 days, plus
  noise rows that match only one or two of the three constraints, plus rows outside the date window.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| date range | last 7 days | preset |
| action | ["Employee.Update"] | multi-select with single value |
| actor | John Doe | autocomplete-resolved actor_user_id |
| matching rows | >= 2 | satisfy all three constraints |
| partial-match noise | >= 3 | satisfy only 1-2 constraints |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Apply date range "last 7 days", action "Employee.Update", actor "John Doe"; click Apply Filters | Table refreshes |
| 2 | Inspect returned rows | EVERY row satisfies all three: timestamp within last 7 days AND action = Employee.Update AND actor = John Doe (AND across groups) |
| 3 | Confirm partial-match noise excluded | Rows matching only 1-2 constraints (e.g. John Doe but action Employee.Create, or right action but 10 days ago) are NOT present |
| 4 | Observe the result count | The displayed count equals the number of returned rows (FR-7) |
| 5 | Inspect the browser URL | URL query params encode date_from/date_to, action, actor_user_id reflecting the applied filters (FR-3) |
| 6 | Copy the URL, open it in a fresh tab/session (as adminA) | The same filter state is restored and the same result set is shown (bookmarkable/shareable) |
| 7 | Remove one filter (e.g. clear actor) and re-apply | Result set widens accordingly; URL updates to drop the actor param |

## 6. Postconditions
- Filter state lives in the URL; reloading or sharing the URL reproduces the view.

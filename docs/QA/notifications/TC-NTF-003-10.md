# TC-NTF-003-10: Unauthenticated/no-tenant-context preference requests are rejected

## 1. Test Objective
Verify that all preference endpoints require authentication and a resolved tenant context. Requests
without a valid session/JWT are rejected (401), and requests that cannot resolve a tenant context are
rejected before any preference data is read or written.

## 2. Related Requirements
- User Story: US-NTF-003
- Acceptance Criteria: AC-2 (persisted with tenant_id + user_id), AC-5 (per-tenant membership)
- Functional Requirements: FR-8 (tenant_id + user_id set from session)
- Non-Functional: NFR-2 (tenant isolation via EF Core global query filters; Postgres RLS deferred)

## 3. Preconditions
- The preferences API is running. A valid `emp1` session exists in Tenant A for the positive control.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| no token | (omit Authorization) | expect 401 |
| expired/invalid token | tampered JWT | expect 401 |
| missing tenant context | request that cannot resolve a tenant | expect rejection / 401-403 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | GET preferences with NO Authorization header | 401 Unauthorized; no data returned |
| 2 | PUT a preference change with an expired/tampered JWT | 401 Unauthorized; no write performed |
| 3 | Call a preference endpoint in a context where the tenant cannot be resolved | Request rejected before any preference query; no cross-tenant leakage |
| 4 | GET preferences as authenticated `emp1` in Tenant A (positive control) | 200 OK; returns emp1's matrix scoped to Tenant A and user emp1 |

## 6. Postconditions
- Only authenticated requests with a resolved tenant context can read/write preferences.

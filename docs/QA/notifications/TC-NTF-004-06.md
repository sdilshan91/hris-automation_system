# TC-NTF-004-06: Data-export audit -> CSV/Excel/PDF export writes an audit row with export params + row count

## 1. Test Objective
Verify that performing a data export (CSV, Excel, or PDF) writes an audit record capturing the export
parameters (format, filters, target resource) and the number of rows exported. Confirms exports --
a high-sensitivity bulk-disclosure event -- are auditable even though they are read operations.

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-1 (audit infrastructure; export is a captured action)
- Functional Requirements: FR-5 (audit data exports incl. export parameters and row count), FR-7/8 (enrichment + tenant_id)

## 3. Preconditions
- Tenant A is active; an authorized user `hr1` is authenticated.
- A dataset of a known size exists in Tenant A (e.g. 120 employees match the export filter).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| export format | CSV | also retest Excel, PDF |
| filter | department=Finance | export parameter |
| expected row count | 120 | matches the dataset |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, export employees filtered by department=Finance to CSV | Export produced; HTTP 200/202 |
| 2 | Query `audit_log` for the export action | One audit row with an export action (e.g. "Employee.Export") |
| 3 | Inspect the export parameters captured | The row records format=CSV and the filter (department=Finance) |
| 4 | Inspect the row count captured | The row records row_count = 120 (the number of rows exported) |
| 5 | Repeat for Excel and PDF formats | Each export produces its own audit row with the correct format and row count |
| 6 | Inspect actor + tenant fields | actor_user_id=hr1, tenant_id=Tenant A, trace_id populated |

## 6. Postconditions
- One audit row per export exists with parameters and row count; tenant-scoped.

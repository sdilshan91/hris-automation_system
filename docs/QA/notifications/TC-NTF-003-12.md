# TC-NTF-003-12: Preferences page loads <= 500ms P95; dispatch-time preference lookup is cheap

## 1. Test Objective
Verify the preference page meets its load SLA (<= 500ms P95) and that the dispatch-time preference
lookup does not impose a per-notification DB query when the Redis cache is in force (NFR-3). On a dev
box, record indicative numbers; never relax the stated thresholds.

## 2. Related Requirements
- User Story: US-NTF-003
- Acceptance Criteria: AC-1 (matrix display)
- Non-Functional: NFR-1 (page load <= 500ms P95), NFR-3 (dispatch lookup cached in Redis, TTL 5 min)

## 3. Preconditions
- Tenant A has a representative preference dataset (all categories per user).
- A perf-representative environment is available; if only a dev box is available, record indicative
  numbers and flag Redis caching (NFR-3) as deferred/CONDITIONAL.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| page-load SLA | <= 500ms P95 | NFR-1 |
| cache TTL | 5 minutes | NFR-3 |
| sample size | >= 100 page loads | for P95 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Load the Notification Preferences page >= 100 times and record latencies | P95 load time <= 500ms (NFR-1) |
| 2 | Trigger a burst of notifications for a user and measure preference-lookup cost | With Redis in force, repeated dispatches hit the cache (TTL 5 min), not a DB query per notification (NFR-3) |
| 3 | (If Redis NOT provisioned) measure the equivalent DB lookup cost | Lookup remains tenant+user-scoped and correct; record indicative numbers; document caching as deferred -- do NOT relax NFR-1 |
| 4 | Compare cold vs warm load | Warm loads benefit from caching where applicable; SLA still met on cold load |

## 6. Postconditions
- Page-load SLA is documented against NFR-1; dispatch-lookup caching behavior recorded against NFR-3 (or flagged deferred).

# TC-NTF-002-14: The per-(tenant, event) notification-template language-variant cap is plan-configurable (override > plan > tenant > default 2), not a hardcoded constant — US-NTF-002 BR-6 (DF-5)

## 1. Test Objective
Verify the DF-5 change that makes the notification-template **language-variant cap** (BR-6) plan-configurable instead of a hardcoded `const int MaxLanguageVariants = 2`. `NotificationTemplateService.SaveAsync` now resolves the cap via `PlanLimitResolver` (key `max_template_language_variants`) with precedence **override > plan value > tenant snapshot > default 2** — mirroring the `WorkflowService.MaxWorkflows` pattern — and rejects a new language variant beyond the resolved cap with **422 `variant_limit_reached`**. When nothing is configured, the historical default of 2 is preserved (behaviour-preserving).

## 2. Related Requirements
- User Story: US-NTF-002 (email notification templates per tenant)
- Business Rules: BR-6 (language-variant cap per template per tenant — now plan-configurable)
- Findings: DF-5 (wire the cap to `PlanLimitResolver`; new plan-limit key), BUG-122 (the original variant-cap enforcement)

## 3. Preconditions
- The system-default templates are seeded; the tenant has a resolvable `Tenant` row (the resolver falls back to the default cap when no tenant row exists). Driven through the real `NotificationTemplateService` over EF Core InMemory-through-real-EF.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Default cap | 2 | no plan/override configured (preserved behaviour) |
| PlanLimitOverride | `max_template_language_variants = 3` | raises the cap → a 3rd variant allowed |
| SubscriptionPlan (tenant's plan) | `MaxTemplateLanguageVariants = 1` | lowers the cap → a 2nd variant rejected |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed a Tenant + a PlanLimitOverride of 3; save `en`, `es`, then `fr` variants. | All three succeed — the 3rd variant, rejected under the default 2, is allowed under the override of 3. `Save_variantCap_isRaised_byPlanLimitOverride_df5`. |
| 2 | Seed a Tenant on a plan with `MaxTemplateLanguageVariants = 1`; save `en`, then `es`. | `en` succeeds; `es` (the 2nd variant, allowed under the default 2) is rejected 422 `variant_limit_reached` under the plan cap of 1. `Save_variantCap_isLowered_byPlanValue_df5`. |
| 3 | (Regression) With no plan/override, save `en`, `es`, then `fr`. | The 3rd variant is rejected 422 `variant_limit_reached` — default 2 preserved. `Save_rejects_a_third_language_variant_bug122`. |

## 6. Postconditions
- The variant cap is resolved per tenant from plan/override configuration, defaulting to 2; no schema/behaviour regression for tenants without configuration.

# TC-NTF-002-01: Custom "Leave Approved" template for Tenant A is used and placeholders resolved (happy path)

## 1. Test Objective
Verify that when Tenant Admin A customizes the "Leave Approved" email template, a subsequent
leave-approval event sends an email rendered from the custom template (not the system default)
with all placeholders correctly resolved at send time. Validates the primary success path.

## 2. Related Requirements
- User Story: US-NTF-002
- Acceptance Criteria: AC-2 (placeholder editing), AC-3 (custom override used for future emails)
- Functional Requirements: FR-1 (editor), FR-2 (placeholder resolution), FR-10 (tenant_id from session)
- Business Rules: BR-1 (override takes precedence), BR-3 (HTML + plain-text both present)

## 3. Preconditions
- Tenant A is active; Tenant Admin `adminA` is authenticated within Tenant A.
- System default "Leave Approved" template exists (event_key = `leave_approved`).
- Employee `emp1` (firstName "Maya") belongs to Tenant A and has a pending leave request.
- An SMTP relay / transactional email service (or capture/sandbox) is configured.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| event_key | leave_approved | |
| custom subject | "{{tenant.companyName}}: Your leave is approved, {{employee.firstName}}!" | |
| custom body_html | "<p>Hi {{employee.firstName}}, your {{leave.type}} leave from {{leave.startDate}} is approved.</p>" | |
| custom body_text | "Hi {{employee.firstName}}, your {{leave.type}} leave from {{leave.startDate}} is approved." | |
| tenant.companyName | Acme Corp | resolved from Tenant A |
| employee.firstName | Maya | |
| leave.type | Annual | |
| leave.startDate | 2026-07-01 | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `adminA`, go to Settings > Notifications & Email > Templates and open "Leave Approved" | Editor opens with subject, HTML body, plain-text body fields and a placeholder reference panel |
| 2 | Edit subject, HTML body, and plain-text body with the custom test data and Save | Save succeeds; the override is persisted with tenant_id = Tenant A, event_key = `leave_approved`, version incremented; the list now shows "Custom" for this event |
| 3 | As a manager, approve `emp1`'s leave request | Approval persists; a `leave_approved` email is enqueued via the outbox/Hangfire worker |
| 4 | Inspect the delivered/captured email | Email is rendered from the CUSTOM template, not the default |
| 5 | Verify the subject and body content | Subject = "Acme Corp: Your leave is approved, Maya!"; body (HTML + text) contains "Hi Maya, your Annual leave from 2026-07-01 is approved." — all placeholders resolved, no `{{...}}` left |
| 6 | Confirm both parts are present | The email has both an HTML part and a plain-text part (BR-3) |

## 6. Postconditions
- Tenant A has a persisted custom "Leave Approved" override; one rendered email delivered.

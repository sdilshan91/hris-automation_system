# TC-NTF-004-10: GDPR right-to-be-forgotten -> PII in audit rows replaced with "REDACTED-{id}", audit structure preserved

## 1. Test Objective
Verify that executing a GDPR "right to be forgotten" for a user anonymizes PII contained in that
user's audit records -- replacing PII values with the token "REDACTED-{id}" -- while preserving the
audit trail structure (the rows still exist with intact action/resource/timestamp/actor references).
Confirms BR-6: anonymize, do not delete.

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-1 (tamper-proof trail) -- reconciled with BR-6 anonymization
- Business Rules: BR-6 (GDPR RTBF replaces PII with "REDACTED-{id}", preserving audit structure), BR-1 (append-only -- anonymization is a controlled, privileged, audited operation, not a normal app mutation)

## 3. Preconditions
- Tenant A is active; a privileged data-protection operator `dpo1` is authorized to run RTBF.
- A subject user `subjectU` has audit rows that contain PII (e.g. before/after on personal fields, ReadSensitive entries).
- The anonymization process is invoked through the dedicated RTBF/admin operation (NOT a normal app write path).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| subject | subjectU | the data subject |
| redaction token | "REDACTED-{id}" | replacement format |
| operator | dpo1 | authorized |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Confirm `subjectU` has audit rows containing PII before RTBF | PII present in before/after / field references of those rows |
| 2 | As `dpo1`, execute "right to be forgotten" for `subjectU` | Operation completes successfully |
| 3 | Re-read `subjectU`'s audit rows | The rows STILL EXIST (not deleted) -- audit structure preserved |
| 4 | Inspect the PII fields in those rows | PII values are replaced with "REDACTED-{id}" (using subjectU's id); non-PII metadata (action, resource_type, resource_id, timestamp) is intact |
| 5 | Confirm the anonymization itself is auditable + scoped | The RTBF operation produces its own audit row (operator dpo1, action e.g. "Audit.Anonymize"); only Tenant A rows for subjectU were touched |
| 6 | Confirm no normal app endpoint can do this | Anonymization is reachable ONLY via the privileged RTBF path -- not via standard CRUD (consistent with BR-1 append-only) |

## 6. Postconditions
- subjectU's audit PII is REDACTED; rows preserved; the anonymization is itself audited and tenant-scoped.

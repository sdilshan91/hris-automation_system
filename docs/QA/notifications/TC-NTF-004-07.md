# TC-NTF-004-07: Enrichment -> audit row carries IP, user agent, trace id, and tenant_id from the request/session context

## 1. Test Objective
Verify that every audit record is enriched with the HTTP request's IP address, user agent, the
distributed trace ID (from Serilog/OpenTelemetry context), and the tenant_id resolved from the
authenticated session -- regardless of which capture path (entity write, auth event, PII read, export)
produced it. Confirms FR-2/FR-7/FR-8 enrichment is consistent.

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-1 (record includes IP, user agent, trace ID; tenant_id from session)
- Functional Requirements: FR-2 (record fields incl. ip_address/user_agent/trace_id), FR-7 (enrich with IP/UA/trace), FR-8 (tenant_id from session context)

## 3. Preconditions
- Tenant A is active; HR `hr1` is authenticated.
- The request is issued with a known X-Forwarded-For / client IP and a known User-Agent header.
- Serilog enrichers inject tenant_id and trace_id into the request context.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| client_ip | 198.51.100.7 | asserted on the row |
| user_agent | "Mozilla/5.0 ... Edge" | asserted on the row |
| trace correlation | per-request trace id | from response header / log context |
| tenant | Tenant A | resolved from subdomain/session |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, perform a create that triggers an audit row, capturing the response's trace/correlation id | Entity persists; trace id observed |
| 2 | Inspect the audit row `ip_address` | Equals the request client IP (198.51.100.7), correctly resolved through any proxy header |
| 3 | Inspect the audit row `user_agent` | Equals the request User-Agent string |
| 4 | Inspect the audit row `trace_id` | Equals the request's distributed trace id (matches the same trace in logs) |
| 5 | Inspect the audit row `tenant_id` | Equals Tenant A (from session context, NOT from any client-supplied body field) |
| 6 | Attempt to spoof tenant_id by sending a different tenant in the request body | The audit row's tenant_id remains the session tenant (Tenant A); the body value is ignored (FR-8) |

## 6. Postconditions
- The audit row carries server-derived IP, UA, trace id, and session tenant_id; client-supplied tenant is ignored.

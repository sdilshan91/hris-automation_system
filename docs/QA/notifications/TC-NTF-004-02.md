# TC-NTF-004-02: UPDATE audit -> before has old value, after has new value, ONLY changed fields captured

## 1. Test Objective
Verify that updating a single field on a business entity produces an audit record with action
"{Entity}.Update" whose `before` JSONB holds the old value and `after` JSONB holds the new value,
and that ONLY the changed field(s) are captured in the payloads -- not the entire entity. Validates
FR-1/FR-2 capture and the BR-3 changed-fields-only rule.

## 2. Related Requirements
- User Story: US-NTF-004
- Acceptance Criteria: AC-1 (employee job-title update -> "Employee.Update", before {jobTitleId: old}, after {jobTitleId: new})
- Functional Requirements: FR-1 (auto-capture UPDATE), FR-2 (before/after JSONB)
- Business Rules: BR-3 (only changed fields captured, not the whole entity)

## 3. Preconditions
- Tenant A is active; HR Officer `hr1` is authenticated.
- An Employee exists with jobTitleId = "jt-old" and several other unchanged fields.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| entity | Employee | existing |
| jobTitleId (old) | "jt-old" | current value |
| jobTitleId (new) | "jt-new" | changed value |
| firstName | "Nimal" | NOT changed -- must be absent from payloads |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `hr1`, update only the Employee's jobTitleId from "jt-old" to "jt-new" and save | Update persists; HTTP 200 |
| 2 | Query `audit_log` for the resource_id; inspect `action` | action = "Employee.Update" |
| 3 | Inspect `before` JSONB | Contains `{"jobTitleId": "jt-old"}` |
| 4 | Inspect `after` JSONB | Contains `{"jobTitleId": "jt-new"}` |
| 5 | Confirm changed-fields-only (BR-3) | `before`/`after` do NOT contain firstName or any other unchanged field -- only jobTitleId is present |
| 6 | Update with a no-op (set jobTitleId to the same value) and save | EF detects no change; NO audit row is produced for the no-op |

## 6. Postconditions
- One audit row captures the single-field change; no audit row exists for the no-op save.

# TC-PRF-001-14: Goal read is tenant-scoped + within-tenant authorized (owner/manager/HR), and a goal set finalizes only at exactly 100% then locks against all writes (409) — US-PRF-001 AC-4 / BR-4 / BR-6 (#387, ISSUE-099 / DF-18 / BUG-056)

## 1. Test Objective
Verify two shipped US-PRF-001 goal-lifecycle behaviours delivered under #387:

**(a) Goal read authorization (ISSUE-099 / DF-18).** `GoalService.GetByIdAsync` is tenant-scoped — a foreign-tenant or unknown id is filtered by the EF global query filter and returns **404 `goal_not_found`** (never a leaked/empty 200). Within the tenant it applies BR-4 read authz: HR (`Performance.SetGoal.All`) may read any goal; a `Performance.SetGoal.Team` manager may read only a **direct report's** goal (else **403 `not_direct_report`**); and a self-read branch lets the goal **owner** (`Employee.UserId == caller`) read their own goal even with no SetGoal permission.

**(b) Finalize / lock (BUG-056, AC-4 / BR-6).** `FinalizeGoalsAsync` locks an employee's goal set for a cycle only when its weights sum to **exactly 100%** (else **422 `weight_not_100`**, including the empty-set 0% boundary), requiring HR or the employee's direct manager (else **403 `forbidden`**). Finalizing transitions every goal to `GoalStatus.Finalized`, after which any create / update / delete / bulk-save is rejected **409 `goals_finalized`**, and re-finalizing is likewise 409. A finalized set surfaces as "Finalized" on the manager team dashboard, and a finalized/locked set still appears in the employee's own progress tracking (`GetMyGoals` regression — finalize is the sign-off, not the end of tracking).

## 2. Related Requirements
- User Story: US-PRF-001
- Acceptance Criteria: AC-4 (team dashboard shows the immutable `Finalized` state reached via `POST /tenant/performance/goals/finalize`, #387; subsequent writes → 409 `goals_finalized`)
- Business Rules: BR-4 (only the direct manager or HR `SetGoal.All` may set/read a team member's goals), BR-6 (a set finalizes/locks only at exactly 100%; then immutable)
- Functional Requirement: FR-1/FR-3 (goals scoped to tenant + employee + cycle; weights sum to exactly 100%)
- Findings: ISSUE-099 (GetById tenant-scoped 404), DF-18 (within-tenant read authz), BUG-056 (finalize/lock)

## 3. Preconditions
- A tenant with a seeded goal-owner employee (optionally reporting to a seeded manager), an active appraisal cycle, and Draft goals — driven through the real `GoalService` over EF Core InMemory-through-real-EF (the global query filter is exercised).
- Callers are built as `ICurrentUser` with explicit permission sets: HR (`SetGoal.All`), team manager (`SetGoal.Team`), the goal owner (no perms, `UserId` linked to the owner employee), and an unprivileged decoy.

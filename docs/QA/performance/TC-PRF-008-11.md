# TC-PRF-008-11: Sensitive PIP fields (reason, escalation notes) encrypted at rest via pgcrypto -- asserted at the encryption seam (NFR-4)

## 1. Test Objective
Verify NFR-4: the sensitive PIP fields -- the PIP reason and the escalation notes -- are encrypted at rest using pgcrypto, given the highly sensitive HR/legal nature of PIP data. A direct database read of the underlying column does not return cleartext; the value is decrypted only through the application path for an authorized, tenant-scoped caller. Because encryption may be an infrastructure extension point, the test asserts the encryption SEAM (column-level encryption / pgcrypto) and documents the conditional.

> Note: NFR-4 names pgcrypto column encryption for `pip.reason` + escalation notes. If column-level encryption is not yet wired in this platform, this test asserts that the write/read path ROUTES THROUGH the encryption seam (an `IFieldEncryptor`-style abstraction or pgcrypto `pgp_sym_encrypt`/`pgp_sym_decrypt`) and documents pgcrypto-at-rest as the extension point -- consistent with the module's deferred-infra-as-conditional convention. The tenant-scoping + authz assertions below hold regardless of the encryption mechanism.

## 2. Related Requirements
- User Story: US-PRF-008
- Non-Functional Requirements: NFR-4 (pgcrypto encryption of reason + escalation notes)
- Data Requirements: S7 (sensitive fields encrypted)

## 3. Preconditions
- An Active PIP for Sam Lee exists in acme with a known reason string and (on a Not Met PIP) escalation notes.
- DB-level read access is available to the test harness to inspect the raw column.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| PIP reason | "Consistently missed Q1 delivery targets" | encrypted at rest |
| Escalation notes | "Recommend termination after PIP failure" | encrypted at rest |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Nadia (authorized), `GET .../performance/pips/{id}` | The reason + escalation notes are returned in CLEARTEXT to the authorized, tenant-scoped caller (decrypted on the app path). |
| 2 | Read the raw column directly (`SELECT reason, escalation_notes FROM pip WHERE id = …`) | The stored value is CIPHERTEXT / a pgcrypto byte blob -- NOT the cleartext string; the known reason/escalation substrings are absent from the raw bytes (NFR-4). |
| 3 | Confirm the encryption seam | The write path routes the reason + escalation notes through the field-encryption seam (pgcrypto / `IFieldEncryptor`); if not yet wired, the test asserts the seam exists + documents pgcrypto-at-rest as the extension point. |
| 4 | Confirm non-sensitive fields are unaffected | Non-sensitive fields (status, dates, employee_id) read normally; only reason + escalation notes are encrypted (NFR-4 scope). |
| 5 | Confirm logs/exports don't leak cleartext at rest | The cleartext reason/escalation does not appear in server logs or any persisted artifact outside the decrypt-on-read app path. |

## 6. Postconditions
- PIP reason + escalation notes are stored encrypted at rest and decrypted only on the authorized app path; the encryption seam is asserted. No Tenant B data touched.

# TC-PRF-007-02: Filter dashboard by department + grade + cycle (+ location, employment type) -> all widgets update to the filtered population

## 1. Test Objective
Verify AC-2 and FR-4: when the HR Officer applies the filter panel selections -- cycle, department, grade/band, employment type, and location -- the system updates ALL dashboard widgets (average score, headcount, distribution histogram, department bar, top/bottom performers, completion rate, cycle progress) to reflect ONLY the filtered subset of employees, and the aggregates recompute correctly and remain tenant-scoped.

## 2. Related Requirements
- User Story: US-PRF-007
- Acceptance Criteria: AC-2
- Functional Requirements: FR-4
- Non-Functional Requirements: NFR-3 (aggregate recompute via materialized view / cache)

## 3. Preconditions
- Tenant "acme" with cycle "FY26" and seeded reviews spanning >=2 departments, >=2 grades, >=2 locations, and both Full-Time and Contract employment types so each filter visibly narrows the set.
- HR Officer "Nadia Khan" authenticated in acme with `Performance.Read.All`.
- Known per-department / per-grade averages and headcounts for deterministic assertions.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Cycle filter | FY26 Annual Review | FR-4 |
| Department filter | Engineering | narrows population |
| Grade filter | G4 | narrows further |
| Location filter | Colombo | FR-4 |
| Employment type filter | Full-Time | FR-4 |
| Expected Eng avg | seeded value | for assertion |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the collapsible filter sidebar; select Department = Engineering; observe `GET .../performance/dashboard/overview?cycleId=FY26&departmentId=eng` | 200; ALL widgets (avg score, headcount, distribution, dept bar, top/bottom, completion, progress) update to the Engineering subset only (AC-2). |
| 2 | Verify the average score + headcount widgets | Average score = seeded Engineering mean; headcount = Engineering participant count (AC-2). |
| 3 | Verify the distribution histogram | Buckets recompute to the Engineering population; counts sum to the Engineering headcount (minus excluded probation, BR-2). |
| 4 | Add Grade = G4 to the filter | Widgets narrow again to Engineering + G4; averages/headcount/distribution all recompute consistently (combined filter, FR-4). |
| 5 | Add Location = Colombo and Employment Type = Full-Time | Widgets reflect Engineering + G4 + Colombo + Full-Time only; the combined filter is AND-composed server-side (FR-4). |
| 6 | Switch the Cycle filter to a different cycle (e.g. "FY25 Annual") keeping the other filters | All widgets recompute against FY25 for the same department/grade/location/type slice (AC-2). |
| 7 | Clear all filters | Widgets return to the org-wide overview of TC-PRF-007-01 (AC-1 baseline). |
| 8 | Confirm tenant scoping under filters | The filter query parameters are applied WITHIN the tenant; no department/grade/location id from another tenant can be referenced (cross-tenant covered by TC-PRF-ISO-026). |

## 6. Postconditions
- The dashboard reflects the selected cycle/department/grade/location/employment-type slice; no cross-tenant or out-of-slice data leaks.

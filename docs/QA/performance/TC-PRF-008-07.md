# TC-PRF-008-07: Authorization -- a MANAGER attempting to close/extend a PIP is rejected (managers may only record checkpoints); create/extend/close by any non-HR (employee/unauth) rejected (BR-1)

## 1. Test Objective
Verify BR-1: only HR Officers with `Performance.Review.All` can CREATE, EXTEND, or CLOSE (set outcome) a PIP. A MANAGER can record checkpoints and add comments (BR-1, TC-PRF-008-02) but CANNOT unilaterally create, extend, set the outcome, confirm escalation, or close a PIP. An ordinary employee and an unauthenticated caller are blocked from all PIP mutations. Authorization is enforced SERVER-SIDE, not only by hiding UI controls (no IDOR by id).

## 2. Related Requirements
- User Story: US-PRF-008
- Business Rules: BR-1 (HR-only create/extend/close; manager checkpoint-only)
- Acceptance Criteria: AC-2, AC-4, AC-5 (the mutations being gated)
- Non-Functional Requirements: NFR-2 (tenant isolation -- same-tenant authz here; cross-tenant in ISO TCs)

## 3. Preconditions
- An Active PIP for Sam Lee exists in acme (TC-PRF-008-01).
- Manager "Dana Cole" (`Performance.Review.Team` only, no `.All`) is authenticated in acme.
- Employee "Sam Lee" (no Performance review permission) is authenticated in acme.
- HR Officer "Nadia Khan" (`Performance.Review.All`) is authenticated in acme (positive control).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| PIP | Sam Lee's Active PIP | target of mutations |
| Manager | Dana Cole | .Team only -- checkpoint-only per BR-1 |
| Employee | Sam Lee | no Performance permission |
| HR | Nadia Khan | .All -- positive control |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana (manager), attempt `POST .../performance/pips/{id}/extend` | 403 forbidden -- managers cannot extend a PIP (BR-1); no state change. |
| 2 | As Dana, attempt `POST .../performance/pips/{id}/outcome` (close: Successfully Completed / Not Met) | 403 forbidden -- managers cannot close/set outcome (BR-1); no state change. |
| 3 | As Dana, attempt `POST .../performance/pips` (create a new PIP) | 403 forbidden -- managers cannot create PIPs (BR-1). |
| 4 | As Dana, `POST .../performance/pips/{id}/checkpoints/{cpId}` (record a checkpoint) | 200 -- ALLOWED; managers MAY record checkpoints + comments (BR-1, positive control vs the blocked mutations). |
| 5 | As Sam (employee), attempt create / extend / close / confirm-escalation on any PIP | 403 forbidden on every mutation -- employees have no PIP-management permission. |
| 6 | Unauthenticated, call any PIP mutation endpoint | 401 unauthorized. |
| 7 | As Nadia (HR `.All`), perform create / extend / close / confirm-escalation | 200 -- ALLOWED (positive control; BR-1 grants HR the full lifecycle). |

## 6. Postconditions
- Only HR can create/extend/close/escalate a PIP; managers are limited to checkpoints; employees/unauth are fully blocked. No unauthorized state change occurred. No Tenant B data touched.

# TC-PRF-005-03: A reviewer cannot submit feedback twice for the same reviewee in the same cycle (BR-3)

## 1. Test Objective
Verify BR-3: a reviewer can submit only one feedback per employee per cycle. After a reviewer has submitted, a second submission for the same reviewee/cycle is rejected (server-side), preventing duplicate/ballot-stuffing feedback and keeping the aggregation accurate.

## 2. Related Requirements
- User Story: US-PRF-005
- Acceptance Criteria: AC-3
- Functional Requirements: FR-1
- Business Rules: BR-3

## 3. Preconditions
- 360-enabled cycle "FY26 Annual Review" active for acme; Liam Carter under review.
- Peer reviewer "Ava Reyes" assigned to Liam and authenticated in acme.
- Ava has already submitted her feedback once (status Completed).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Reviewer | Ava Reyes (Peer) | already submitted |
| Reviewee | Liam Carter | same cycle |
| Cycle | FY26 Annual Review | same cycle |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Ava, re-open the feedback form for Liam after submitting | The form shows read-only / "Already submitted" state; the Submit action is disabled (AC-3). |
| 2 | Bypass the UI: `POST .../performance/360/feedback/{avaAssignmentId}/submit` a second time | Server rejects with 409 Conflict (or 400) and a duplicate-submission message; no second `feedback_360` row is written and the existing row is unchanged. |
| 3 | Attempt to submit a NEW assignment for the same reviewer+reviewee+cycle pair via the API | Rejected — a unique constraint on (tenant_id, cycle_id, reviewee_id, reviewer_id) blocks a second feedback record (BR-3). |
| 4 | Inspect the aggregation | Liam's per-category averages count Ava's feedback exactly once. |

## 6. Postconditions
- Exactly one feedback record exists for Ava->Liam in FY26; aggregation unaffected by the duplicate attempt.

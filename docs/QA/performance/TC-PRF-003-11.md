# TC-PRF-003-11: All manager rating actions are audit-logged with the manager's user ID + timestamp (submit, reopen, re-submit)

## 1. Test Objective
Verify FR-7: every manager rating submission (and related state change -- reopen, re-submit) is written to the audit log with the acting user's ID, the action, the affected review/employee/cycle, the tenant_id, and a timestamp. The audit entry is tenant-scoped and immutable from the application surface.

## 2. Related Requirements
- User Story: US-PRF-003
- Functional Requirements: FR-7
- Non-Functional Requirements: NFR-2 (audit scoped per tenant)

## 3. Preconditions
- acme cycle FY26-H1; Ravi reviewing Asha; HR Nadia available to reopen.
- The audit log surface (S24 / AuditInterceptor) is reachable for assertion.

## 4. Test Data
| Action | Actor | Expected audit fields |
|--------|-------|------------------------|
| Submit manager review | Ravi | user_id=Ravi, action=ManagerReviewSubmitted, review_id, employee_id=Asha, cycle_id, tenant_id=acme, timestamp |
| Reopen review | Nadia | user_id=Nadia, action=ManagerReviewReopened, ... |
| Re-submit after edit | Ravi | user_id=Ravi, action=ManagerReviewSubmitted, new timestamp |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Ravi submits the manager review | An audit entry records Ravi's user id, the submit action, the review/employee/cycle ids, tenant_id=acme, and a timestamp (FR-7). |
| 2 | Nadia reopens the review | A second audit entry records Nadia's user id + reopen action + timestamp. |
| 3 | Ravi edits and re-submits | A third entry records the re-submit with a fresh timestamp; prior entries remain intact (append-only). |
| 4 | Query the audit log as a globex (other-tenant) user | acme's review audit entries are NOT visible (tenant-scoped, NFR-2). |

## 6. Postconditions
- Each manager rating action leaves an immutable, tenant-scoped audit entry with user id + timestamp.

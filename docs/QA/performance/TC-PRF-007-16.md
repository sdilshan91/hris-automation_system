# TC-PRF-007-16: The branded performance-dashboard PDF embeds the tenant logo image (read in-process via IFileStorage), and degrades gracefully to the colour-only header when the logo is absent or corrupt — US-PRF-007 FR-8 (DF-6)

## 1. Test Objective
Verify the DF-6 change: `PerformanceDashboardService`'s PDF export now embeds the tenant `LogoUrl` image in the branded header (previously only the `PrimaryColor` band was rendered). The logo bytes are read **in-process via `IFileStorage`** (mirroring the payslip renderer — no HTTP fetch), scoped to the current tenant. The PDF must still render when the logo is missing or unreadable.

## 2. Related Requirements
- User Story: US-PRF-007 (performance dashboard + analytics); FR-8/AC-4 (export)
- Findings: DF-6 (embed the tenant logo in the branded dashboard PDF), ISSUE-126

## 3. Preconditions
- Driven through the real `PerformanceDashboardService` (InMemory-through-real-EF) with a substituted `IFileStorage` + `ITenantContext.LogoUrl`.

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | No logo configured (LogoUrl null); export PDF. | `%PDF`, non-empty; storage never read (baseline). `Export_pdf_NoTenantLogo_StillRenders_NoStorageRead`. |
| 2 | Tenant logo configured; storage returns a valid PNG; export PDF. | `%PDF`; the storage read happened (`OpenReadAsync(tenantId, …)`); the PDF is **larger than the no-logo baseline** — proving the image is embedded (a dropped `.Image()` mutant makes both identical). `Export_pdf_WithTenantLogo_EmbedsLogo_LargerThanNoLogoBaseline`. |
| 3 | Tenant logo configured but storage returns non-image bytes. | `%PDF` still (the `IsRenderableImage` guard rejects it → colour-only header, no crash). `Export_pdf_CorruptLogoBytes_DegradesGracefully_StillRendersPdf`. |

## 5. Postconditions
- The dashboard PDF carries the tenant logo when present and available; otherwise it renders the colour-band header exactly as before. The logo read is tenant-scoped (`_tenantContext.TenantId`).

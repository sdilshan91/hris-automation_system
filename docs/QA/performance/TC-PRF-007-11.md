# TC-PRF-007-11: Dashboard loads within 2.5s (P95) for a tenant with 5,000 employees (materialized-view / Redis aggregate path)

## 1. Test Objective
Verify NFR-1 + NFR-3: the performance dashboard overview (all widgets) loads within 2.5 seconds at the 95th percentile for a tenant with up to 5,000 employees, and the aggregate computations are served from a materialized view (performance_summary) and/or Redis cache rather than expensive real-time row scans. Asserts there is no N+1 / per-employee query fan-out behind the aggregates.

## 2. Related Requirements
- User Story: US-PRF-007
- Non-Functional Requirements: NFR-1 (<=2.5s P95 @ 5,000 employees), NFR-3 (materialized view / Redis caching)
- Data Requirements: S7 (performance_summary materialized view)

## 3. Preconditions
- Tenant "acme" seeded with ~5,000 employees and a cycle "FY26" with submitted reviews across departments/grades/locations.
- The performance_summary materialized view is populated for acme (BR-4 / S7); a Redis cache layer is available (NFR-3) -- CONDITIONAL: if no cache is wired today the test asserts the materialized-view / set-based aggregate path with no per-employee fan-out.
- A representative performance environment (seeded data + warm caches) is available for timing.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Population | ~5,000 employees | NFR-1 scale |
| SLA | <=2.5s P95 | overview load |
| Iterations | >=50 requests | for P95 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm the aggregate (ensure the materialized view / cache is populated for acme/FY26) | The performance_summary view / cache holds the FY26 aggregates. |
| 2 | Issue >=50 `GET .../performance/dashboard/overview?cycleId=FY26` requests; record latency distribution | P95 end-to-end load <=2.5s (NFR-1); the overview returns all widget data in a single aggregate response. |
| 3 | Inspect the DB query plan / SQL log for one request | Aggregates come from the materialized view / a set-based GROUP BY, NOT a per-employee loop; no N+1 (NFR-3). |
| 4 | Apply a department filter and repeat the timing | Filtered overview also meets <=2.5s P95 (the filter is pushed into the aggregate query). |
| 5 | Exercise the cache path (repeat identical request) | The repeated request is served from cache (if wired) -- tenant-scoped key (see TC-PRF-ISO-028); CONDITIONAL on the cache layer. |
| 6 | Document the perf mechanism / extension point | If Redis is not yet wired, the test records the materialized-view path as the mechanism and Redis as the extension point (consistent with the module's deferred-Redis convention). |

## 6. Postconditions
- The 5,000-employee dashboard meets the <=2.5s P95 SLA via the materialized-view / cache aggregate path with no per-employee query fan-out.

# TC-PRF-009-01: Employee opens My Goals -> goal cards with progress/status/progress bar -> "Add Update" (progress %, status, notes, attachment) -> timestamped + logged + manager notified + progress bar updates (happy path)

## 1. Test Objective
Verify the primary success flow for AC-1 and AC-2 (FR-1/FR-2/FR-5): an authenticated employee with `Performance.Read.Self` navigates to Performance > My Goals and sees all active-cycle goals rendered as cards with title, target, current progress (% complete), status (not started / in progress / completed / at risk), last update date, and an animated progress bar. On "Add Update" the system shows a form (progress percentage slider, status selector, rich-text notes, optional file attachment for evidence); on save the progress update is created tenant-scoped, timestamped with the server clock, logged (append-only, NFR-3), the manager receives a notification (FR-5), and the goal card progress bar + last update date refresh to the new value.

## 2. Related Requirements
- User Story: US-PRF-009
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-5
- Business Rules: BR-1 (update only during active cycle window, satisfied here)
- Non-Functional Requirements: NFR-3 (append-only, asserted in TC-PRF-009-08)
- Data Requirements: S7 (goal_progress_updates table; tenant_id scoped, append-only)

## 3. Preconditions
- Tenant "acme" exists, status Active, subdomain `acme.yourhrm.com`, Performance module enabled.
- Employee "Sam Lee" is authenticated in acme (valid JWT carrying acme `tenant_id`) and holds `Performance.Read.Self`.
- Sam has 3 assigned + acknowledged goals in the active cycle (US-PRF-001); the active cycle is between goal-setting close and review-phase start (US-PRF-004), so the tracking window is open (BR-1).
- Sam reports to manager "Dana Cole" (Core HR org tree).
- The Notification System (S25) and file management module are available (enqueue asserted; delivery conditional).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Sam, navigate to `https://acme.yourhrm.com/my-review` (or Performance > My Goals) | All 3 active-cycle goals render as cards, each showing title, target, current progress %, status chip, last update date, and an animated progress bar (AC-1). Request carries `X-Tenant-Subdomain: acme` + bearer; only Sam's acme goals returned. |
| 2 | Click "Add Update" on "Ship onboarding redesign" | A form opens with a progress percentage slider (defaulted to the current 20%), a status selector, a rich-text notes field, and an optional file attachment input (AC-2, FR-2). |
| 3 | Set progress to 55%, status In Progress, enter notes, attach wireframes.pdf; click Save | `POST .../performance/goals/{goalId}/updates` (multipart) returns 200/201; the update persists tenant-scoped with progress_pct=55, status, notes, and the attachment stored under an acme-scoped path. |
| 4 | Inspect the persisted update | The update has tenant_id = acme, goal_id = the goal, employee_id = Sam, progress_pct = 55, status, notes, attachment ref, and a SERVER-derived created_at timestamp (client-supplied timestamps ignored). |
| 5 | Observe the goal card | The progress bar animates from 20% to 55%, the current progress reads 55%, and the last update date refreshes to today (AC-2). |
| 6 | Check notifications | An in-app + email notification is enqueued to Dana (manager) announcing Sam posted a progress update on "Ship onboarding redesign" (FR-5); enqueue asserted, delivery conditional on S25. |
| 7 | Confirm logging | The update is recorded in the goal's append-only history (visible in the timeline, TC-PRF-009-02); no prior update was overwritten. |

## 6. Postconditions

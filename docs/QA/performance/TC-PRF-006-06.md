# TC-PRF-006-06: Read-tracking -- system records whether the employee opened/read the notes before signing (BR-2)

## 1. Test Objective
Verify BR-2: the employee must review the notes before signing, and the system TRACKS whether the employee has opened/read the meeting notes. Verify a read/opened timestamp is recorded when the employee views the notes, that the "Acknowledge & Sign" action is gated on having opened the notes (or at minimum the read state is recorded and surfaced on the signed record), and that the read indicator is tenant-scoped and reflected in the audit trail.

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-3 (employee reviews then signs)
- Business Rules: BR-2 (employee must review notes before signing; system tracks opened/read)
- Functional Requirements: FR-7 (audit)

## 3. Preconditions
- Tenant "acme", Performance module enabled.
- Liam Carter's review is in "Pending Employee Sign-Off" (manager signed, employee notified, employee has NOT yet opened the notes).
- Employee "Liam Carter" authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| notes_opened_at | null -> <timestamp> | BR-2 read-tracking |
| Decision | Acknowledge | requires prior read (BR-2) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Liam, before opening the notes, query the review state | The notes read/opened flag is unset (e.g. `notesOpenedAt = null`); the signed record would show the notes were not yet reviewed. |
| 2 | Attempt to "Acknowledge & Sign" WITHOUT opening the notes (bypass UI): `POST .../signoff {decision:"Acknowledge"}` | Per BR-2 the system enforces review-before-sign: either the API rejects the sign-off with a "notes must be reviewed first" error, OR (if signing is permitted) the recorded signature explicitly flags that the notes were not opened -- assert whichever the implementation documents, and that the read state is NOT silently lost. |
| 3 | As Liam, open the sign-off link and load the meeting notes; observe `GET .../reviews/{reviewId}/meeting-notes` (or a `mark-read` call) | The system records `notesOpenedAt` = server timestamp for Liam on this review (BR-2); subsequent reads do not overwrite the FIRST-opened timestamp (or it tracks last-opened per the documented rule). |
| 4 | Now "Acknowledge & Sign" | Sign-off succeeds; the signed record shows the notes were opened/read before signing (BR-2). |
| 5 | Confirm audit + scope | The read/opened event is audit-logged (FR-7) and tenant-scoped (acme); HR viewing the signed review can see the notes were reviewed prior to signature. |

## 6. Postconditions
- Liam's review records that the notes were opened/read prior to the employee signature; the read state is auditable and tenant-scoped.

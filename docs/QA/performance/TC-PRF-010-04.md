# TC-PRF-010-04: Approval workflow -> submit a recommendation -> routes through the configured approvers (sequential/parallel) -> approved / rejected status

## 1. Test Objective
Verify FR-4 / AC-3: a submitted recommendation routes through the tenant's configured approval workflow engine (sequential or parallel approvers). Each approver acts in turn (or concurrently); the recommendation status reflects the workflow outcome (Submitted -> Pending Approval -> Approved or Rejected). A rejection at any step stops the chain and sets status Rejected; full approval sets status Approved (which is the gate for downstream integration, TC-PRF-010-10).

## 2. Related Requirements
- User Story: US-PRF-010
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4 (approval workflow integration, sequential or parallel)
- Data Requirements: S7 (recommendations.status, approver chain, approval history)
- Assumptions: the recommendation approval workflow uses the same engine as other modules (leave/attendance).

## 3. Preconditions
- Tenant "acme"; HR Officer Pat Ng (`Performance.Publish.All`); a two-step SEQUENTIAL approver chain configured: Approver 1 = HR Manager "Lee", Approver 2 = VP "Sam".
- A second tenant config "globex" uses a PARALLEL chain (for the parallel branch, optional).
- A submitted Promotion recommendation for Jordan (from TC-PRF-010-01) is Pending Approval.
- Notification System (S25) available (enqueue asserted).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Recommendation | Jordan -> Promotion G6 | Pending Approval |
| Chain (sequential) | Lee then Sam | both must approve |
| Reject reason | "Budget not confirmed for this band yet." | on the reject path |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Inspect the recommendation after submit (TC-PRF-010-01) | Status Pending Approval; the approval task is assigned to Approver 1 (Lee), not yet to Sam (sequential); approval history is empty. |
| 2 | As Lee, approve step 1 | History records Lee's approval (actor + server timestamp); the task advances to Approver 2 (Sam); status still Pending Approval. |
| 3 | As Sam, approve step 2 | All approvers complete -> status = Approved; approval history has both entries; the submitting HR is notified (S25). |
| 4 | Repeat on a second recommendation; at step 1 REJECT with a reason | The chain stops -> status = Rejected; the reason is recorded; Sam never receives a task; the submitting HR is notified. A rejected recommendation does NOT trigger any downstream integration. |
| 5 | Authz on approval | A non-assigned user (e.g. an unrelated HR Officer or an employee) cannot approve/reject the step (403); approvers act only on their assigned step. |
| 6 | (Parallel branch, optional) On globex with a parallel chain | Both approvers receive the task simultaneously; status -> Approved only when all required parallel approvers approve; any rejection -> Rejected. |

## 6. Postconditions
- One recommendation is Approved (both steps), one is Rejected (reason recorded). Approval history is complete and tenant-scoped. Only the Approved one is eligible for downstream integration (TC-PRF-010-10).

# TC-PRF-001-13: Sidebar nav shows Performance routes to the right persona only (ISSUE-210 regression)

## 1. Test Objective
Verify that the sidebar navigation never offers a persona a link to a route its
guard would reject (ISSUE-210). Specifically: the management "Performance" item
(→ `/performance`) is shown to holders of `Performance.View.Team` / `.View.All` /
`.Manage` (Manager/HR/Admin) and NOT to employees; the employee self-service item
(→ `/my-review`) is shown to employees (`Performance.View.Own`) and NOT the
management link. The crisp invariant: an employee-only principal must NOT see a
`/performance` link, which would dead-end at `/forbidden`.

## 2. Related Requirements
- User Story: US-PRF-001 (nav entry point to the Performance module; cross-cuts US-PRF-001..010)
- Finding: ISSUE-210 (HIGH — Performance module unreachable / mis-gated sidebar item)
- Acceptance Criteria: AC-4 (team dashboard reachable by the managing persona)
- Design rule: no persona is shown a nav link to a route its guard would reject

## 3. Preconditions
- `MainLayoutComponent` rendered under Karma with the real `AuthService`.
- The current principal's roles + permissions are set via the AuthService token path
  (`activateImpersonation` of a crafted JWT), so `hasRole`/`hasPermission` and the
  component's own `visibleNavItems()` filter run for real.
- Tenant-switcher and idle-timeout HTTP calls are stubbed; child banner/bell/idle
  components are replaced with inert stubs.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Management principal | roles `['HR Manager']`; perms `Performance.View.All`, `Performance.View.Team`, `Performance.Manage` (NOT `View.Own`) | Can enter `/performance` |
| Employee principal | roles `['Employee']`; perms `Performance.View.Own` (NOT `View.Team`/`View.All`/`Manage`) | Cannot enter `/performance` |
| Rendered-nav query | `nav.sidebar-nav a.nav-item` → `href` | Asserts the actually-rendered links, not a hand-built list |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Sign in as the management principal; render the layout; read the rendered nav hrefs | Nav contains `/performance`; nav does NOT contain `/my-review`. |
| 2 | Sign in as the employee principal; render the layout; read the rendered nav hrefs | Nav contains `/my-review`; nav does NOT contain `/performance`. |
| 3 | Sign in as an employee-only principal (`Performance.View.Own` only); render; read hrefs | Nav does NOT contain `/performance` (would dead-end at `/forbidden`). |

## 6. Postconditions
- No system state changed (pure render assertion).
- Each persona sees only nav links to routes its guard admits.

# TC-PRF-001-09: Input validation and sanitization on goal fields (XSS / SQL injection / field validation)

## 1. Test Objective
Verify FR-2 field validation and NFR security expectations: goal text fields (title, description, measurement unit) are sanitized against XSS and SQL injection, and field-level constraints (category enum, weight range 1-100, due date a valid date) are enforced server-side.

## 2. Related Requirements
- User Story: US-PRF-001
- Functional Requirements: FR-2
- NFR: NFR-2 (tenant scope), input-sanitization

## 3. Preconditions
- Manager "Ravi Kumar" authenticated in acme with `Performance.SetGoal.Team`; window OPEN; Asha is his direct report.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS title | `<script>alert('x')</script>` | must be stored escaped / not executed |
| SQLi description | `'; DROP TABLE goals;--` | must be treated as literal text |
| Invalid category | `Random` | not in {KPI, Competency, Project} |
| Invalid weight | 0 and 101 | outside FR-2 range 1-100 |
| Invalid due date | `2026-13-40` | not a real date |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Save a goal with the XSS title and SQLi description | Saved as literal text; on retrieval the title renders escaped (no script execution); the goals table is intact (no SQL executed). |
| 2 | `POST .../goals` with category `Random` | 400/422 — category must be one of KPI/Competency/Project (FR-2). |
| 3 | `POST .../goals` with weight 0, then 101 | Both 400/422 — weight must be 1-100 (FR-2). (Note: the 5% increment rule BR-3 is covered separately in TC-PRF-001-04.) |
| 4 | `POST .../goals` with due date `2026-13-40` | 400/422 — invalid date rejected. |
| 5 | Render the saved XSS goal in the team dashboard and detail view | No script executes; payload shown as inert text. |

## 6. Postconditions
- Goal fields are validated and sanitized; no injection persists or executes.

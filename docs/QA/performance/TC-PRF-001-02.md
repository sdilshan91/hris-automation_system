# TC-PRF-001-02: Goal weights summing to 95% and 105% are rejected with "Goal weights must total 100%"

## 1. Test Objective
Verify AC-3 and FR-3: when a Manager attempts to save goals whose weights do not sum to exactly 100%, the system displays the validation error "Goal weights must total 100%" and prevents submission. Both the under-allocated (95%) and over-allocated (105%) cases are exercised, and the check is enforced server-side (not only in the UI).

## 2. Related Requirements
- User Story: US-PRF-001
- Acceptance Criteria: AC-3
- Functional Requirements: FR-3
- Business Rules: BR-3

## 3. Preconditions
- Manager "Ravi Kumar" authenticated in acme with `Performance.SetGoal.Team`.
- Active cycle FY26-H1 with the goal-setting window OPEN; Asha Patel is Ravi's direct report.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Case A (95%) | Goal1 50% + Goal2 45% | sums to 95 |
| Case B (105%) | Goal1 60% + Goal2 45% | sums to 105 |
| Each weight | multiple of 5 | so the only failing rule is the 100% total (BR-3 satisfied) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Add two goals with weights 50% and 45% (total 95%) and click "Save Goals" | UI shows inline error "Goal weights must total 100%"; weight bar flags 95%; submission blocked. |
| 2 | Bypass the UI: `POST /api/v1/performance/goals` with goals totalling 95% | Response 400 (or 422); error message/body contains "Goal weights must total 100%"; no goal rows persisted. |
| 3 | Adjust to weights 60% and 45% (total 105%) and click "Save Goals" | UI shows the same error "Goal weights must total 100%"; submission blocked. |
| 4 | Bypass the UI: `POST .../goals` with goals totalling 105% | Response 400/422 with "Goal weights must total 100%"; no goals persisted. |
| 5 | Verify persistence | Zero goals exist for Asha in FY26-H1 — neither invalid attempt was saved. |

## 6. Postconditions
- No goals persisted for Asha; the 100%-total invariant (FR-3) is enforced both client- and server-side.

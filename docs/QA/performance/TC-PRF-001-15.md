# TC-PRF-001-15: A finalized goal set can be re-opened (unlocked) by HR or the finalizing direct manager with a mandatory audit reason, resetting Finalized→Acknowledged and restoring writability — US-PRF-001 AC-4 / BR-4 (DF-46, BUG-056 follow-up)

## 1. Test Objective
Verify the goal-set **re-open / unlock** flow shipped for DF-46 — the undo for the BUG-056 finalize/lock (TC-PRF-001-14). `GoalService.ReopenGoalsAsync` lets an authorized caller unlock a mistakenly-finalized set:

- **Authorization (BR-4, same gate as finalize).** Only HR (`Performance.SetGoal.All`) or the employee's **direct manager** (`Performance.SetGoal.Team` on their own report) may re-open; any other caller → **403 `forbidden`** and the set stays locked.
- **Mandatory reason.** The re-open `Reason` is required (`ReopenGoalsValidator`, enforced at the MediatR ValidationBehavior layer) — empty **and** whitespace-only reasons are rejected; the trimmed reason is written into the `Goal.Reopened` audit trail.
- **State transition + writability.** Every `Finalized` goal in the set transitions back to `GoalStatus.Acknowledged`; **only** finalized goals are touched (a Draft in the same set is left untouched). That transition alone restores writability — a create/update/delete/bulk-save that was `409 goals_finalized` while locked now succeeds.
- **Guard.** Re-opening a set that is **not** finalized (nothing to undo) → **409 `goals_not_finalized`**.

## 2. Related Requirements
- User Story: US-PRF-001
- Acceptance Criteria: AC-4 (the finalized/immutable state reached via `POST /tenant/performance/goals/finalize` is reversible via `POST /tenant/performance/goals/reopen`, restoring an editable `Acknowledged` set)
- Business Rules: BR-4 (only the direct manager or HR `SetGoal.All` may set/finalize/re-open a team member's goals)
- Findings: DF-46 (goal-set re-open/unlock flow), BUG-056 (the finalize/lock this reverses)
- Decision: re-open is permitted for **HR or the finalizing direct manager**, requires a **mandatory audit reason**, and resets the set to **Acknowledged** (not Draft) — locked product decision, 2026-07-20.

## 3. Preconditions
- A tenant with a seeded goal-owner employee (optionally reporting to a seeded manager), an active appraisal cycle, and a goal set — driven through the real `GoalService` over EF Core InMemory-through-real-EF (the tenant global query filter is exercised).
- Callers built as `ICurrentUser` with explicit permission sets: HR (`SetGoal.All`) and an unprivileged decoy (no perms).

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Finalize a 100% set, then re-open it with a reason. | Success; every goal reset to `Acknowledged` (persisted, none Finalized). `Reopen_FinalizedSet_FlipsToAcknowledged_AndRestoresWritability`. |
| 2 | After re-open, run the bulk-save that was 409 while locked. | Succeeds — writability restored. (same test as step 1) |
| 3 | Re-open a set holding one Finalized + one Draft goal. | The Finalized→Acknowledged; the Draft stays Draft (selectivity). `Reopen_OnlyTransitionsFinalizedGoals_LeavesOthersUntouched`. |
| 4 | Re-open a set that is not finalized (both Acknowledged). | 409 `goals_not_finalized`. `Reopen_NonFinalizedSet_Returns409_GoalsNotFinalized`. |
| 5 | Re-open a finalized set as a non-manager (no SetGoal perms). | 403 `forbidden`; the set is still Finalized/locked. `Reopen_NonManager_Returns403_AndSetStaysLocked`. |
| 6 | Re-open with a valid reason; inspect the audit trail. | One `Goal.Reopened` audit row per goal, each with the reason in `Detail`. `Reopen_WritesGoalReopenedAuditRow_WithReasonInDetail`. |
| 7 | Validate a re-open command with empty / whitespace reason / a genuine reason. | Empty + whitespace → invalid on `Reason`; genuine → valid. `ReopenValidator_MissingOrBlankReason_IsInvalid`, `ReopenValidator_WithReasonAndIds_IsValid`. |

## 6. Postconditions
- A mistakenly-finalized goal set is recoverable: HR or the finalizing manager can unlock it with an audited reason, returning it to an editable `Acknowledged` state without data loss; the reason is retained in the audit trail.

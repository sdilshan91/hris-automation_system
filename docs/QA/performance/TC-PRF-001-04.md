# TC-PRF-001-04: Goal weights not in 5% increments are rejected (BR-3)

## 1. Test Objective
Verify BR-3: goal weights must be in increments of 5%. Weights such as 33%, 7%, or 12.5% are rejected even if the set sums to 100%, server-side.

## 2. Related Requirements
- User Story: US-PRF-001
- Functional Requirements: FR-2
- Business Rules: BR-3

## 3. Preconditions
- Manager "Ravi Kumar" authenticated in acme with `Performance.SetGoal.Team`; window OPEN; Asha is his direct report.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Set A | 33% + 33% + 34% | sums to 100 but not multiples of 5 |
| Set B | 7% + 93% | not multiples of 5 |
| Single weight | 12.5% | fractional, not a multiple of 5 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter a weight of 33% on a goal | UI flags the field: weight must be in 5% increments; the weight input/stepper constrains to multiples of 5. |
| 2 | Enter the set 33/33/34 (totals 100) and click "Save Goals" | UI blocks save citing the 5% increment rule (BR-3) even though the total is 100%. |
| 3 | Bypass the UI: `POST .../goals` with weights 33/33/34 | Response 400/422 citing the 5% increment rule; no goals persisted. |
| 4 | Bypass the UI: `POST .../goals` with a 12.5% weight | Response 400/422; fractional/non-5%-increment weight rejected. |
| 5 | Verify persistence | No goals persisted for any BR-3-violating set. |

## 6. Postconditions
- Only weights that are multiples of 5% are accepted; the increment rule is enforced independently of the 100%-total rule.

# TC-PRF-007-10: Top N / Bottom N performers list -- correct ordering, configurable N (default 10), name/department/score/trend indicator

## 1. Test Objective
Verify FR-3: the dashboard lists the top N and bottom N performers (default N=10, configurable) for the current cycle/filter scope, each entry showing name, department, score, and a trend indicator (improvement/decline vs the prior cycle). Ordering is correct (top = highest scores descending; bottom = lowest ascending), ties are handled deterministically, and changing N re-fetches the correct list size.

## 2. Related Requirements
- User Story: US-PRF-007
- Functional Requirements: FR-3
- Acceptance Criteria: AC-1
- Business Rules: BR-2 (probation excluded from the pool by default), BR-3 (visible only to `.All`)

## 3. Preconditions
- Tenant "acme" / cycle "FY26" with >20 scored employees so top/bottom 10 are distinct, plus >=2 employees who also have a prior-cycle score so the trend indicator is computable.
- HR Officer "Nadia Khan" authenticated in acme with `Performance.Read.All`.
- Seeded scores with a known descending/ascending order and at least one tie.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Default N | 10 | FR-3 |
| Configured N | 5, then 20 | re-fetch |
| Fields per row | name, department, score, trend | FR-3 |
| Tie pair | two employees at score 4.2 | deterministic tiebreak |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the FY26 overview; observe the top/bottom performers widget (default) | Exactly 10 top + 10 bottom entries; top is the 10 highest scores (descending), bottom the 10 lowest (ascending) (FR-3). |
| 2 | Verify each row's fields | Each entry shows name, department, score, and a trend indicator (up/down/flat vs prior cycle); the trend matches the seeded prior-cycle delta. |
| 3 | Change N to 5; observe `GET .../performance/dashboard/top-performers?n=5` (and bottom) | Lists shrink to 5 each, preserving order; server honors the configurable N. |
| 4 | Change N to 20 | Lists grow to 20 (or to the available count if fewer); no duplicate or overlap between top and bottom. |
| 5 | Verify tie handling | The tied pair is ordered by a documented deterministic tiebreak (e.g. employee id / name); the same order on repeated fetches. |
| 6 | Confirm BR-2 + BR-3 | Probation employees are absent from the pool by default (BR-2); the widget is present only for `.All` (managers get the team ranking instead, TC-PRF-007-06). |

## 6. Postconditions
- Top/bottom performer lists render with correct ordering, configurable size, and accurate trend indicators for the active scope.

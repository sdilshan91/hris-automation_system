# TC-PRF-001-03: Goal count below 1 and above 10 per employee per cycle is rejected (BR-2)

## 1. Test Objective
Verify BR-2 and FR-1: the system enforces a minimum of 1 and a maximum of 10 goals per employee per cycle. Saving zero goals and attempting to add an 11th goal are both rejected, server-side.

## 2. Related Requirements
- User Story: US-PRF-001
- Functional Requirements: FR-1
- Business Rules: BR-2

## 3. Preconditions
- Manager "Ravi Kumar" authenticated in acme with `Performance.SetGoal.Team`; window OPEN; Asha is his direct report.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Empty save | 0 goals | violates BR-2 minimum |
| Over-max | 11 goals each weight ~9% | violates BR-2 maximum (count, not weight) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | With no goals added, click "Save Goals" | UI prevents save with "At least 1 goal is required"; `POST .../goals` with an empty list returns 400/422; no rows persisted. |
| 2 | Add 10 goals (valid) and attempt to add an 11th | UI blocks the 11th with "A maximum of 10 goals can be assigned per employee per cycle"; the add control is disabled at 10. |
| 3 | Bypass the UI: `POST .../goals` with 11 goals | Response 400/422 referencing the max-10 rule (BR-2); no goals persisted (atomic reject). |
| 4 | Verify persistence | After the failed 11-goal attempt, zero goals exist (the request is rejected as a whole, not truncated to 10). |

## 6. Postconditions
- Goal count outside [1,10] is rejected; no partial saves occur.

# TC-PRF-006-04: Dispute flow -- employee disputes with comments -> manager + HR notified -> status Disputed until HR resolves (AC-3, FR-4/FR-5, BR-4)

## 1. Test Objective
Verify the end-to-end dispute escalation across AC-3, FR-4, FR-5 and BR-4: when the employee chooses "Dispute" and provides mandatory comments, the system captures the dispute, transitions the review to "Disputed", and notifies BOTH the manager and HR with the employee's dispute comments for resolution. The review REMAINS in "Disputed" status (not Signed Off, not auto-closed) until HR resolves it -- by either amending the review or confirming it (resolution paths exercised in TC-PRF-006-12). The dispute is NOT a sign-off, so the review is not locked under BR-5 while Disputed.

## 2. Related Requirements
- User Story: US-PRF-006
- Acceptance Criteria: AC-3 (Dispute path)
- Functional Requirements: FR-4 (dispute capture), FR-5 (escalate to HR with comments)
- Business Rules: BR-4 (Disputed until HR resolves)

## 3. Preconditions
- Tenant "acme", Performance module enabled.
- Liam Carter's review is in "Pending Employee Sign-Off" (manager already signed).
- Manager "Maya Shah" and an HR Officer "Nadia Khan" (`Performance.Review.All`) exist in acme.
- Employee "Liam Carter" authenticated in acme.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Decision | Dispute | FR-4 |
| Dispute comments | "I disagree with the overall summary; please revisit goal 2 rating." | FR-4/FR-5 |
| Notify | Maya Shah (manager) + Nadia Khan (HR) | FR-5 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Liam, open the sign-off screen, read the notes, click "Dispute", enter valid comments, click "Submit Dispute"; observe `POST .../performance/reviews/{reviewId}/signoff` `{decision:"Dispute", comments:"..."}` | 200; the dispute (comments + employee identity + server timestamp + IP) is recorded; status -> "Disputed" (BR-4). |
| 2 | Observe notifications | BOTH the manager (Maya) and HR (Nadia) receive an in-app + email notification carrying the dispute comments and a link to resolve (FR-5; delivery CONDITIONAL on Notification System S25 -- assert in-app push + email enqueue). |
| 3 | As Liam, refresh; attempt to "Acknowledge & Sign" while Disputed | The acknowledge action is unavailable (the review is now in HR's hands); the employee cannot also sign while a dispute is open. |
| 4 | As Maya, attempt to edit ratings/notes while Disputed | Edits are gated to HR resolution (the dispute is HR-owned per FR-5/BR-4); the manager sees the dispute comments read-only. |
| 5 | Let time pass past the BR-3 auto-close window while still Disputed | The auto-close job does NOT convert a Disputed review to "No Response" -- Disputed reviews are excluded from auto-close (BR-3 applies to unsigned, not disputed); status remains "Disputed" awaiting HR (BR-4). |
| 6 | Confirm status persistence | The review stays "Disputed" indefinitely until an HR resolution action (amend or confirm) is taken (TC-PRF-006-12); no automatic transition occurs. |

## 6. Postconditions
- Liam's review is in "Disputed" status with recorded dispute comments; manager + HR were notified; the review is not locked and not auto-closed; it awaits HR resolution.

# TC-PAY-008-10: Complete approval audit trail -- who/when/comments/IP with tamper-proof timestamps (FR-7, NFR-5); comments/reason fields resist XSS + SQL injection

## 1. Test Objective
Verify FR-7 / NFR-5: every approval action (Submitted, Approved, Rejected, Returned, Escalated) writes a complete, append-only `payroll_approval_history` row capturing actor_user_id, acted_at (tamper-proof timestamp), comments/reason, ip_address, step_number, and workflow_instance_id; the trail cannot be edited or deleted; and the free-text comment/reason fields are stored/rendered safely (no XSS execution, no SQL injection).

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-2, AC-3
- Functional Requirements: FR-7
- Non-Functional Requirements: NFR-5
- Data Requirements: S7 (payroll_approval_history)
- Note: full tamper-proof audit storage references the Audit module (S24); the record/enqueue is asserted here.

## 3. Preconditions
- A June 2026 run progressing through submit -> approve/reject/return for acme.
- fin1 (Payroll.Approve), hr1 (Payroll.Run).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS payload | `<script>alert('x')</script>` in reject reason | NFR-5 |
| SQLi payload | `'; DROP TABLE payroll_approval_history;--` in comment | NFR-5 |
| Fields asserted | actor_user_id, acted_at, comments, ip_address, step_number, action | FR-7 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit, then Reject with a reason, then (on a re-submitted run) Approve with a comment. | Each action persists a `payroll_approval_history` row with action, actor_user_id, acted_at, ip_address, comments, step_number, workflow_instance_id, tenant_id (FR-7). |
| 2 | Confirm the recorded IP + timestamp. | ip_address is the request IP (server-derived, not client body); acted_at is a server timestamp (tamper-proof, not client-supplied) (FR-7, NFR-5). |
| 3 | Attempt to edit or delete an existing history row via API. | Rejected -- the approval history is append-only/immutable; no update/delete endpoint exists (FR-7, NFR-5). |
| 4 | Enter the XSS payload as a rejection reason; then view the timeline + HR notification. | The payload is stored encoded and rendered as inert text -- no script executes in the timeline, banner, or email (NFR-5). |
| 5 | Enter the SQLi payload as an approval comment. | Treated as a literal string via parameterized queries; no SQL executes; the table is intact; the comment is stored verbatim/escaped (NFR-5). |
| 6 | Reload the run detail and re-read the timeline. | The full who/when/comments/IP trail persists and matches across reloads; ordering by acted_at is stable (FR-7). |

## 6. Postconditions
- A complete, immutable, injection-safe approval audit trail exists for the run with server-derived IP + timestamps.

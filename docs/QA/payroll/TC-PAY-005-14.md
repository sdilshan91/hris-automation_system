# TC-PAY-005-14: My-Payslips supports an optional pay-period (month) filter that composes with the year filter — US-PAY-005 FR-6 (ISSUE-164)

## 1. Test Objective
Verify the ISSUE-164 addition: the employee **My Payslips** list accepts an optional `month` (pay-period) filter alongside the existing `year` filter (FR-6). `GET /api/v1/payroll/my-payslips?year=&month=` filters slips to the given pay month (1–12) when provided, composing with the year filter; omitting `month` returns all months. Filtering remains scoped to the caller's own Finalized-run payslips (FR-2/FR-8).

## 2. Related Requirements
- User Story: US-PAY-005 (employee self-service payslips)
- Functional Requirement: FR-6 (search/filter payslip history by pay period), FR-2/FR-8 (own Finalized slips only, tenant-scoped)
- Findings: ISSUE-164 (My-Payslips search by pay period not implemented — `month` silently ignored)

## 3. Preconditions
- The caller is linked to an employee with payslips from Finalized runs across multiple months. Driven through the real query → handler → `MyPayslipService` stack.

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Employee has slips for month 1 and month 12 (same year); query `month=12`. | Only the December slip (`PayMonth == 12`). `List_MonthFilter_ScopesToPayMonth`. |
| 2 | Query `month=1`. | Only the January slip. (same test) |
| 3 | Query with no month. | Both slips returned. (same test) |
| 4 | (Regression) Query `year=2025` with slips across 2025/2026. | Only 2025 slips — year filter unaffected. `List_YearFilter_ScopesToYear`. |

## 5. Postconditions
- The payslip history can be filtered by pay period (year and/or month); the two filters compose; own/tenant scoping is unchanged.

## 6. Test Category Tags
- [x] Happy path (month filter returns the right slip)
- [x] Boundary (month 1 / 12 / none) · [x] Multi-tenant isolation (own Finalized slips only — inherited)
- [ ] Security / Perf / A11y / Cross-browser

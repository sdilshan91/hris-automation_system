# TC-PAY-013-03: Completing an offboarding auto-computes and persists a Final Settlement (pro-rated pay + statutory + forfeitable-leave encashment) using the Last Working Day as the separation date

## 1. Test Objective
Verify AC-3 / FR-2 / FR-4 / FR-5 / BR-2 / BR-7: when HR completes an offboarding (US-ONB-005 FR-6), the real `IPayrollFnFIntegration` implementation (`RealPayrollFnFIntegration.TriggerFinalSettlementAsync`, wired via `OffboardingService.CompleteAsync`) computes and persists a `FinalSettlement` + `FinalSettlementLine` rows. The settlement equals pro-rated final-month pay + statutory deductions + forfeitable-leave encashment per the effective policy, computed off the employee's Last Working Day, and stored in its own tables (not `PayrollSlip`). The trigger chain proves the DI swap from the `LogOnlyPayrollFnFIntegration` stub is live.

## 2. Related Requirements
- User Story: US-PAY-013
- Acceptance Criteria: AC-3
- Functional Requirements: FR-2, FR-4, FR-5
- Business Rules: BR-2, BR-7
- Data Requirements: FinalSettlement (offboarding_instance_id, employee_id, last_working_day, country_code, fiscal_year, component totals, net_payable, policy_effective_from, computed_at_utc, status) + FinalSettlementLine

## 3. Preconditions
- Tenant A Active, Payroll module enabled.
- An HR user completes an offboarding instance for an employee with an assigned salary structure (US-ONB-005 flow reaches "Complete Offboarding" with all mandatory clearances done).
- The offboarding completion supplies the offboarding instance id + the authoritative Last Working Day.
- For the per-component compute arms: tenant default country "LK" with an income-tax rule ([0,10000)@0%, [10000,inf)@10%) and/or an encashable Annual leave type (carry-forward-limit 5, max-encash 10, balance 20).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| MonthlyBasic | 30,000 | BASIC earning |
| LWD | 2026-06-15 | separation date, factor 15/30 -> pro-rated gross 15,000 |
| Income tax (LK) | [0,10000)@0%, [10000,inf)@10% | taxable 15,000 -> tax (15,000-10,000)x10% = 500 |
| Encashable leave | balance 20, CF-limit 5, max-encash 10 | forfeitable = min(20-5, 10) = 10 days x 1,000 = 10,000 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Initiate offboarding, complete all mandatory clearances, and click "Complete Offboarding" (US-ONB-005). | Completion succeeds; the response returns a non-null `FinalSettlementRef` — the real integration persisted the settlement (AC-3, FR-4). |
| 2 | Query the `final_settlement` table for the offboarding instance id. | Exactly one `FinalSettlement` row exists; its id equals the returned `FinalSettlementRef`; `EmployeeId` matches the offboarded employee (AC-3, FR-2, BR-7 — stored in its own table, not `PayrollSlip`). |
| 3 | Trigger a settlement for an employee whose country resolves to the tenant default "LK" with statutory ON. | `CountryCode` = "LK", `FiscalYear` = "2026", `StatutoryTotal` = 500, `StatutorySkipped` = false, `NetPayable` = 15,000 - 500, a Statutory line present — statutory computed off the LWD via `StatutoryDeductionResolver` (AC-3, FR-5, BR-2). |
| 4 | Trigger a settlement with the encashment toggle ON. | `LeaveEncashmentTotal` = 10,000; an Encashment line of 10,000 present; `NetPayable` includes the encashment — the leave-encashment engine is reused (AC-3, FR-5, BR-2). |

## 6. Postconditions
- A `FinalSettlement` + its `FinalSettlementLine` rows are persisted for the offboarding instance, using the LWD as the separation date; the offboarding-complete -> RealPayrollFnFIntegration seam is proven wired.

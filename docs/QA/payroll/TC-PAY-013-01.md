# TC-PAY-013-01: Tenant Admin configures an effective-dated F&F policy (component toggles + final-period ownership) and each toggle demonstrably changes the computed settlement

## 1. Test Objective
Verify AC-1 / FR-1: a Tenant Admin configures a `TenantFnFPolicy` — which components apply (pro-rated final pay / statutory / forfeitable-leave encashment) and whether the settlement owns the final pay period — and the policy is persisted as an effective-dated record. Each component toggle demonstrably changes the computed settlement (pro-rated-only excludes statutory + encashment; all-off yields a zero settlement; the encashment toggle includes the forfeitable-leave amount), proving the policy actually governs the computation.

## 2. Related Requirements
- User Story: US-PAY-013
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-6
- Business Rules: BR-1
- Data Requirements: TenantFnFPolicy (effective_from, include_pro_rated_final_pay, include_statutory, include_leave_encashment, final_period_owned_by_settlement, is_active)

## 3. Preconditions
- Tenant "acme" Active, Payroll module enabled.
- User authenticated in acme as Tenant Admin (`Payroll.*.All`) for the policy CRUD API (`FnFPolicyController`).
- An employee with an assigned salary structure (BASIC 30,000/month), a tenant default country ("LK"), and — where relevant — an encashable leave type (Annual, carry-forward-limit 5, max-encash 10) with a 20-day ledger balance.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| effective_from | 2026-01-01 | policy version date |
| MonthlyBasic | 30,000 | BASIC earning |
| LWD | 2026-06-15 | mid-month leaver, factor 15/30 = 0.5 -> pro-rated gross 15,000, daily rate 1,000 |
| Policy A (pro-rated only) | proRated=true, statutory=false, encashment=false | AC-1 toggle arm |
| Policy B (all off) | proRated=false, statutory=false, encashment=false | AC-1 toggle arm |
| Policy C (encashment on) | proRated=true, statutory=false, encashment=true | AC-1 toggle arm |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Tenant Admin, configure an F&F policy via `FnFPolicyController` with the component toggles + `final_period_owned_by_settlement` and an `effective_from` (manual/API step — see notes). | The policy is persisted as an effective-dated `TenantFnFPolicy` row for acme, not overwriting history (AC-1, FR-1). |
| 2 | With Policy A (pro-rated ON, statutory + encashment OFF), trigger a settlement for the LWD. | `ProRatedGross` = 15,000; `StatutoryTotal` = 0; `LeaveEncashmentTotal` = 0; `NetPayable` = 15,000; the only settlement lines are Earning lines (AC-1). |
| 3 | With Policy B (all toggles OFF), trigger a settlement. | `ProRatedGross` = 0; `StatutoryTotal` = 0; `LeaveEncashmentTotal` = 0; `NetPayable` = 0; no settlement lines (AC-1 — every toggle off produces a zero settlement). |
| 4 | With Policy C (pro-rated + encashment ON), trigger a settlement. | Forfeitable = balance(20) - carryForwardLimit(5) = 15, capped at maxEncash(10) = 10 days x 1,000/day = 10,000; `LeaveEncashmentTotal` = 10,000; `NetPayable` = 15,000 + 10,000 = 25,000; an Encashment line of 10,000 is present (AC-1 — the encashment toggle changes the settlement). |

## 6. Postconditions
- The effective-dated policy is persisted; each toggle change is reflected in the computed settlement components, proving the policy governs the computation.

# TC-PAY-004-04: Generate Payslips for a run NOT in ReviewPending/Approved/Finalized -> 400 rejected (BR-1)

## 1. Test Objective
Verify BR-1: payslip generation is permitted ONLY for payroll runs whose status is ReviewPending, Approved, or Finalized. A generate request against a run in any other status (Draft/Queued/Processing/Cancelled/Failed) is rejected with 400 Bad Request, no Hangfire job is enqueued, and no `payroll_slip.pdf_status` is mutated. The allowed statuses succeed.

## 2. Related Requirements
- User Story: US-PAY-004
- Acceptance Criteria: AC-1 (precondition: run completed ReviewPending/Approved/Finalized)
- Business Rules: BR-1
- Functional Requirements: FR-4 (no job enqueued on reject)

## 3. Preconditions
- Tenant "acme"; HR Maya with `Payroll.*.All`.
- Runs in each status: Queued (Rq), Processing (Rp), ReviewPending (Rr), Approved (Ra), Finalized (Rf), Cancelled (Rc).

## 4. Test Data
| Run Status | Generate Allowed? | Expected |
|-----------|-------------------|----------|
| Queued | No | 400 |
| Processing | No | 400 |
| Cancelled | No | 400 |
| ReviewPending | Yes | accepted (job enqueued) |
| Approved | Yes | accepted |
| Finalized | Yes | accepted |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | POST generate on Rq (Queued). | 400 Bad Request with a clear "payroll run must be ReviewPending, Approved, or Finalized" message; NO Hangfire job enqueued; no slip pdf_status changed. |
| 2 | POST generate on Rp (Processing). | 400; same rejection; no job. |
| 3 | POST generate on Rc (Cancelled). | 400; same rejection; no job. |
| 4 | POST generate on Rr (ReviewPending). | Accepted; one GeneratePayslipsJob enqueued (allowed per BR-1). |
| 5 | POST generate on Ra (Approved). | Accepted; job enqueued. |
| 6 | POST generate on Rf (Finalized). | Accepted; job enqueued (finalized runs may still have payslips generated). |
| 7 | Verify state after each rejection. | Run status unchanged; no partial PDFs; no pdf_* fields written for the rejected runs. |

## 6. Postconditions
- Only ReviewPending/Approved/Finalized runs proceed to generation; disallowed statuses are blocked with 400 and zero side effects.

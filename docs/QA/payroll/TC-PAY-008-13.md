# TC-PAY-008-13: Separation of duties — distinct-person guard + configurable step→role approvers (AC-4/FR-2, BUG-076)

## 1. Test Objective
Verify AC-4 / FR-2 separation of duties on multi-step payroll approval: (a) a single approver can NOT complete more than one step (distinct-person guard); (b) when a tenant configures a step→role mapping, only a holder of the step's assigned role may approve that step; (c) the step configuration is authoritative for the number of steps; (d) the step-config surface is admin-only (non-maker) and validated. Closes BUG-076, where one user could approve every step.

## 2. Related Requirements
- User Story: US-PAY-008
- Acceptance Criteria: AC-4 (sequential, distinct HR Manager / Finance Director)
- Functional Requirements: FR-2 (configurable steps)
- Business Rules: BR-5 (maker-checker)

## 3. Preconditions
- Tenant with ≥2 users holding `Payroll.Approve` via distinct roles (e.g. an "HR Manager" role and a "Finance" role, each granted `Payroll.Approve`).
- A payroll run submitted for approval (AwaitingApproval) with 2 steps.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Step config | step1→RoleHR, step2→RoleFin | Both roles hold Payroll.Approve |
| Approver A | holds RoleHR only | |
| Approver B | holds RoleFin only, ≠ A | |
| Submitter | HR Officer (maker, no Payroll.Approve) | |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit a run when a 2-step config exists (caller passes totalApprovalSteps=1) | `TotalApprovalSteps` persisted as 2 — config is authoritative (FR-2). |
| 2 | Approver A (RoleHR) approves step 1 | Advances to step 2; run stays AwaitingApproval; one Approved history row. |
| 3 | Approver A approves step 2 (same person) | 403 `distinct_approver_required`; run unchanged at step 2; still one Approved row (SoD). |
| 4 | A user WITHOUT RoleFin approves step 2 | 403 `not_step_approver` (step-role binding). |
| 5 | Approver B (RoleFin, distinct person) approves step 2 | Run → Approved; two Approved history rows (AC-4 complete). |
| 6 | Set step-config as a maker (HR Officer, no Payroll.Approve) | 403 — config is admin-only / non-maker. |
| 7 | Set a non-contiguous config (steps 1,3) or a step role lacking Payroll.Approve | 400 (`steps_not_contiguous` / `role_missing_approve_permission`); nothing persisted. |

## 6. Postconditions
- A multi-step run can only reach Approved via distinct approvers, each holding the step's configured role. The step-config is settable only by non-maker admins and is validated + audited.

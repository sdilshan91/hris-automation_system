# TC-PAY-007-08: Field validation -- type/amount/period/recurrence; BR-1 active-structure required; numeric(18,2) precision; bonus taxable vs reimbursement non-taxable defaults (boundary)

## 1. Test Objective
Verify FR-1 / BR-1 / BR-2 / BR-4: adjustment field validation enforces required fields and valid enum/amount/period values; an adjustment can only be created for an employee with an active salary structure assignment (BR-1); numeric(18,2) amount precision rules hold; is_taxable defaults correctly (bonus per BR-2, reimbursement non-taxable per BR-4 unless overridden).

## 2. Related Requirements
- User Story: US-PAY-007
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1
- Business Rules: BR-1 (active structure), BR-2 (bonus earning/taxable), BR-4 (reimbursement non-taxable default)
- Data Requirements: S7 (amount numeric(18,2), adjustment_type, applicable_pay_month/year, is_taxable)

## 3. Preconditions
- Tenant "acme"; user with `Payroll.*.All`.
- Employee X has an active structure; Employee Z has NO active salary structure assignment.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Missing required | type omitted / amount omitted / period omitted | each rejected |
| Bad type | adjustment_type="Refund" | not in enum -> reject |
| Amount precision | 100000000000000.00 (max magnitude); 12.999 (over-precision); -50; "abc" | boundary set |
| Period | month=0, month=13 | out of range -> reject |
| No structure | employee=Z (no active structure) | BR-1 reject |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Submit adjustments omitting type, then amount, then period in turn. | Each rejected with a 400 + field-level validation error (FR-1). |
| 2 | Submit adjustment_type="Refund". | Rejected -- only Bonus/Deduction/Reimbursement/Correction accepted (FR-1). |
| 3 | Submit amount at max numeric(18,2) magnitude (16 integer digits . 2). | Accepted at the documented max; one digit beyond -> rejected (boundary). |
| 4 | Submit amount=12.999 (3 decimals). | Either rejected or rounded half-up to 13.00 per the documented numeric(18,2) rule; never stored as 12.999. |
| 5 | Submit amount=-50 and amount="abc". | Both rejected (amount must be a positive numeric value). |
| 6 | Submit applicable_pay_month=0 and =13. | Both rejected (1-12 only). |
| 7 | Create an adjustment for Employee Z (no active structure). | Rejected per BR-1 -- adjustments only for employees with an active salary structure assignment. |
| 8 | Create a Bonus without setting is_taxable; create a Reimbursement without setting is_taxable. | Bonus defaults to taxable handling per BR-2; Reimbursement defaults is_taxable=false per BR-4 (overridable). |

## 6. Postconditions
- No invalid adjustment persisted; defaults applied per BR-2/BR-4; BR-1 enforced.

# TC-PAY-013-02: F&F policy is resolved effective-dated (latest EffectiveFrom <= LWD wins); a newer policy is never applied retroactively; a safe all-components-on default governs when none is configured

## 1. Test Objective
Verify AC-2 / FR-6 / BR-1 / NFR-5: the effective F&F policy for a settlement is the policy row whose `EffectiveFrom` <= the employee's Last Working Day (latest wins). A leaver whose LWD predates a newer policy resolves the older policy; a leaver on/after the newer policy's effective date resolves the newer one. An already-resolved settlement captures the policy version it used (`PolicyEffectiveFrom`) and is never rewritten by a later policy edit. When no policy is configured for the tenant, a safe code-default (all components ON, final period owned by settlement) governs.

## 2. Related Requirements
- User Story: US-PAY-013
- Acceptance Criteria: AC-2
- Functional Requirements: FR-6
- Business Rules: BR-1
- Non-Functional: NFR-5 (settlement is an immutable point-in-time event; policy version captured for audit)

## 3. Preconditions
- Tenant "acme" Active, Payroll module enabled, tenant default country "LK".
- Employee with an assigned BASIC 30,000 structure and an encashable Annual leave type (carry-forward-limit 5, max-encash 10) with a 20-day balance.
- Two effective-dated policies exist: Policy A (2026-01-01, encashment ON) and Policy B (2026-06-01, encashment OFF).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Policy A effective_from | 2026-01-01 | proRated=true, statutory=false, encashment=true |
| Policy B effective_from | 2026-06-01 | proRated=true, statutory=false, encashment=false (newer) |
| Early leaver LWD | 2026-02-20 | predates Policy B -> Policy A governs |
| Later leaver LWD | 2026-06-15 | on/after Policy B -> Policy B governs |
| No-policy tenant | (no TenantFnFPolicy rows) | code-default all-ON governs |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Trigger a settlement for the early leaver (LWD 2026-02-20). | `PolicyEffectiveFrom` = 2026-01-01 (Policy A resolved); `LeaveEncashmentTotal` > 0 — the newer Policy B does NOT retroactively rewrite the earlier settlement (AC-2, FR-6, BR-1). |
| 2 | Trigger a settlement for the later leaver (LWD 2026-06-15). | `PolicyEffectiveFrom` = 2026-06-01 (Policy B resolved); `LeaveEncashmentTotal` = 0 — on/after Policy B's effective date, encashment is OFF (AC-2, FR-6). |
| 3 | For a tenant with NO configured F&F policy, trigger a settlement (income tax + encashable leave present). | The code-default (all includes ON) governs: `ProRatedGross` = 15,000, `StatutoryTotal` = 500, `LeaveEncashmentTotal` = 10,000, `NetPayable` = 15,000 + 10,000 - 500 (AC-2 safe default, FR-6). |

## 6. Postconditions
- Each settlement records the policy version it resolved (`PolicyEffectiveFrom`); later policy edits cannot alter a completed settlement; a no-policy tenant is served by the safe all-on default.

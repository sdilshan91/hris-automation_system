# TC-PAY-011-05: SMTP failure -> Polly retries the send up to 3 times with exponential backoff, then marks the delivery Failed with the error logged and surfaced to HR; transient-then-success recovers (negative / AC-4 / NFR-2)

## 1. Test Objective
Verify AC-4 and NFR-2/FR-5: when email sending fails for an employee (e.g. SMTP error), the delivery is retried up to 3 times with exponential backoff via Polly. If a transient failure clears within the retry budget the email succeeds and is marked Sent; if it fails permanently after all retries, the delivery is marked Failed with the error details captured in `failure_reason` + retry_count, and surfaced to HR in the distribution summary. A single employee's permanent failure does NOT abort the job for the others.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-4
- Functional Requirements: FR-2, FR-5
- Non-Functional Requirements: NFR-2 (Polly retry, exponential backoff)
- Business Rules: BR-6 (Failed count in summary)
- Data Requirements: S7 (status=Failed, failure_reason, retry_count)

## 3. Preconditions
- Tenant "acme" Finalized run R for May 2026 with 3 employees (EMP-001, EMP-002, EMP-003), all with emails + generated PDFs.
- The test SMTP relay is configured to: permanently reject mail to EMP-002 (e.g. 5xx), reject EMP-003 transiently twice then accept (transient), and accept EMP-001 normally.
- HR Officer authenticated with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| EMP-001 | SMTP accepts | Sent, retry_count=0 |
| EMP-002 | SMTP rejects always (5xx) | Failed after 3 retries |
| EMP-003 | SMTP fails twice then accepts | Sent after backoff retries |
| Backoff | exponential (e.g. ~2s, 4s, 8s) | NFR-2 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Send Payslips on run R; let the job run through retries. | Job processes all 3 employees; does not abort on EMP-002's failure (AC-4). |
| 2 | Observe the retry timing for the failing sends (NFR-2). | Polly retries the failing send up to 3 times with increasing (exponential) backoff intervals -- visible in logs/timestamps; not an immediate tight loop. |
| 3 | Verify EMP-003 (transient). | After 2 failures the 3rd attempt succeeds; log row = Sent, retry_count reflects the retries; email delivered with the PDF. |
| 4 | Verify EMP-002 (permanent). | After exhausting 3 retries the delivery is marked status=Failed; `failure_reason` captures the SMTP error detail; retry_count = 3; sent_at null. |
| 5 | Verify EMP-001 + overall continuation. | EMP-001 Sent on first attempt; the job completed for all employees despite EMP-002's permanent failure. |
| 6 | View the run distribution summary (BR-6, AC-4). | Total=3, Sent=2, Failed=1; the Failed count is expandable and lists EMP-002 with its error, surfaced to HR. |

## 6. Postconditions
- Transient failures recover within the Polly budget (Sent); a permanent failure is recorded Failed with error + retry_count and shown to HR; the job completes for all employees.

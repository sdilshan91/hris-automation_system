# TC-PAY-001-04: Deleting a salary component that is in use by active employees is rejected with 409 and an affected-count message (negative)

## 1. Test Objective
Verify AC-5 / FR-1: when a salary component is in use by active employees (linked via assigned salary structures), an attempt to delete it is prevented. The system returns 409 Conflict and an error listing the count of affected employees. The component is NOT deleted.

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-5
- Functional Requirements: FR-1, FR-3
- Business Rules: BR-3 (statutory components cannot be removed when statutory compliance is enabled)

## 3. Preconditions
- Tenant "acme" has a component "Basic Salary" (BASIC) linked to a structure "Full-Time India" which is assigned to 3 active employees.
- A statutory component "EPF" (is_statutory=true) linked to the same structure; tenant statutory compliance is enabled.
- HR Officer authenticated in acme with `Payroll.*.All`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Component in use | BASIC | Used by 3 active employees |
| Statutory component | EPF | is_statutory = true |
| Unused component | OLD-BONUS | Not linked to any active assignment |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `DELETE /api/v1/payroll/components/{basic_id}` | Response 409 Conflict; body message names the affected employee count (e.g. "Cannot delete: in use by 3 active employees"). No row deleted. |
| 2 | Verify the DB | The `salary_component` row for BASIC still exists with `tenant_id` = acme; its structure links are intact. |
| 3 | `DELETE /api/v1/payroll/components/{epf_id}` (statutory, compliance enabled) | Response 409 Conflict citing statutory compliance (BR-3); the statutory component is not removed. |
| 4 | `DELETE /api/v1/payroll/components/{old_bonus_id}` (not in use) | Response 200/204 — an unused, non-statutory component CAN be deleted (alternative valid path). |
| 5 | Verify the DB | OLD-BONUS is removed (or soft-deleted per design); BASIC and EPF remain. |

## 6. Postconditions
- In-use and statutory components are retained; only the unused component is removed.

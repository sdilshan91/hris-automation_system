# TC-PAY-004-14: The payslip PDF download file name zero-pads the pay month (`EMP_05_2026`, not `EMP_5_2026`) — US-PAY-004/005 BR-5 (ISSUE-163)

## 1. Test Objective
Verify the ISSUE-163 fix in the shared `PayslipStoragePath.DownloadFileName` helper (used by both the admin download US-PAY-004 and the self-service download US-PAY-005): the pay month is formatted to **two digits** (`{PayMonth:D2}`), so a single-digit month produces `EMP-0042_05_2026.pdf` rather than `EMP-0042_5_2026.pdf`. This keeps file names sorting correctly and reading consistently across both download surfaces and the ZIP-of-all export.

## 2. Related Requirements
- User Story: US-PAY-004 (admin payslip download), US-PAY-005 (employee self-service download) — same shared helper
- Business Rules: BR-5 (`{EmployeeNo}_{PayMonth}_{PayYear}.pdf` file-name format)
- Findings: ISSUE-163 (month not zero-padded)

## 3. Preconditions
- None — `PayslipStoragePath` is a pure static helper (no I/O).

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `DownloadFileName("EMP-0042", 5, 2026)`. | `"EMP-0042_05_2026.pdf"` (padded). `DownloadFileName_FollowsBr5Format`, `DownloadFileName_ZeroPadsMonthToTwoDigits`. |
| 2 | Month 1 / 12. | `_01_` / `_12_`. `DownloadFileName_ZeroPadsMonthToTwoDigits`. |
| 3 | EmployeeNo with a separator (`"../EMP/01"`). | Sanitized (no `/`, no `..`), month padded → `..._03_2026.pdf`. `DownloadFileName_SanitizesSeparatorsInEmployeeNo`. |
| 4 | End-to-end downloads (admin one, self-service one, ZIP-of-all, emailed attachment). | All file names carry the padded month. `PayslipGenerationIntegrationTests.DownloadOne…/DownloadAll…`, `MyPayslipIntegrationTests.DownloadPdf_OwnPayslip…`, `PayslipDistributionIntegrationTests.Send_ThenRun…`. |

## 5. Postconditions
- Payslip download file names use a two-digit month everywhere the shared helper is used.

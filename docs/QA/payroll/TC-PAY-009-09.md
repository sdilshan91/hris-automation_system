# TC-PAY-009-09: Authz -- only Payroll.*.All / Reports.*.All may view/generate/export reports + bank advice + tax statements; others 403, unauth 401; filter inputs resist XSS+SQLi

## 1. Test Objective
Verify the preconditions authz model + NFR security: every report surface -- view/generate Payroll Summary/Register/Statutory/Variance/CTC, Generate Bank Advice, Year-End Tax Statements, and Export (CSV/Excel/PDF) -- requires `Payroll.*.All` or `Reports.*.All`. Users without that permission get 403; unauthenticated requests get 401. Report filter parameters (period, department, designation, employment type, date range, custom narration) are server-side validated and resist XSS and SQL injection.

## 2. Related Requirements
- User Story: US-PAY-009
- Acceptance Criteria: AC-1, AC-2, AC-3, AC-4
- Functional Requirements: FR-1, FR-2, FR-3, FR-8
- Non-Functional Requirements: NFR-4
- Business Rules: BR-2

## 3. Preconditions
- Tenant "acme"; Finalized May 2026 run.
- Users: `hr1` (Payroll.*.All), `rep1` (Reports.*.All), `emp1` (no payroll/reports perm), unauthenticated client.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS probe | `<script>alert(1)</script>` in department filter | sanitization |
| SQLi probe | `'; DROP TABLE payroll_slip;--` in period/custom-range | parameterized |
| Roles | hr1 / rep1 allow; emp1 deny | authz matrix |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As hr1, then rep1, generate each report + bank advice + tax statements + export. | All succeed for both Payroll.*.All and Reports.*.All (FR-1/2/3). |
| 2 | As emp1 (no permission), call each report/generate/export/bank-advice/tax-statement endpoint. | Every call returns 403 Forbidden; no report data, file, or download link returned (FR-8). |
| 3 | As an unauthenticated client, call the same endpoints. | Every call returns 401 Unauthorized. |
| 4 | As hr1, inject `<script>alert(1)</script>` into the department/designation filter. | Input is rejected/sanitized; never reflected unescaped in HTML, the report, or the exported file (NFR-4). |
| 5 | As hr1, inject `'; DROP TABLE payroll_slip;--` into the period / custom-date-range / narration. | Treated as a literal/invalid value via parameterized queries; no SQL executed; no schema change; safe validation error (NFR-4). |
| 6 | Confirm the bank-advice full-file download specifically requires the permission. | emp1's attempt to download the full bank advice file -> 403; masked preview is also denied (BR-2, FR-8). |

## 6. Postconditions
- All report/export/bank-advice/tax-statement surfaces are permission-gated (403/401 as appropriate); filter inputs are injection-safe.

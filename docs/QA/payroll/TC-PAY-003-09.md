# TC-PAY-003-09: Authorization -- only holders of `Payroll.Run` may initiate/cancel/re-run a payroll run; everyone else 403; unauthenticated 401

## 1. Test Objective
Verify the authorization surface of the payroll run endpoints: initiating, cancelling, and re-running a payroll run require the `Payroll.Run` permission (Tenant Admin / Payroll Manager). An authenticated user WITHOUT `Payroll.Run` (e.g. a plain Employee, or a Recruiter) receives 403 Forbidden; an unauthenticated request receives 401 Unauthorized. Authorization is enforced server-side regardless of UI affordances.

## 2. Related Requirements
- User Story: US-PAY-003
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-2 (trigger), FR-7 (re-run)
- Preconditions: "HR Officer has Payroll.Run permission"
- Security: authentication + role-based authorization

## 3. Preconditions
- Tenant "acme"; a fully-prepared May 2026 period.
- Users: Maya (`Payroll.Run`), Dev (Employee, no payroll perms), Recruiter (Recruitment perms only).

## 4. Test Data
| User | Permission | Expected |
|------|-----------|----------|
| Maya | Payroll.Run | allowed |
| Dev | Employee (none) | 403 |
| Recruiter | Recruitment.* only | 403 |
| (none) | unauthenticated | 401 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Maya, `POST /api/v1/payroll/runs` for May 2026. | 202 Accepted; run created (authorized path). |
| 2 | As Dev (no payroll perms), `POST /api/v1/payroll/runs`. | 403 Forbidden; no run created; no Hangfire job enqueued. |
| 3 | As Recruiter, `POST /api/v1/payroll/runs`. | 403 Forbidden -- a different-module permission does not grant Payroll.Run. |
| 4 | Unauthenticated (no bearer), `POST /api/v1/payroll/runs`. | 401 Unauthorized. |
| 5 | As Dev, attempt to cancel and to re-run an existing run. | 403 Forbidden on both; run state unchanged. |
| 6 | Verify the "New Payroll Run" button is hidden for Dev/Recruiter (defense in depth). | Button not rendered for users lacking Payroll.Run; but server still enforces (steps 2-3 are the authoritative check). |

## 6. Postconditions
- Only `Payroll.Run` holders can initiate/cancel/re-run; unauthorized attempts are blocked server-side with no side effects.

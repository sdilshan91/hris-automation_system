# TC-PAY-010-10: Pre-payroll attendance reconciliation report + advisory attendance/leave lock on transition to Processing (FR-6, FR-7, NFR-2)

## 1. Test Objective
Verify FR-7 and FR-6 / NFR-2: (a) the pre-payroll reconciliation report shows, per employee, working days, present days, leave days by type, absent days, overtime hours, and calculated LOP days, and flags mismatches (e.g. an absent day with no leave record); (b) when the payroll run transitions to Processing, the attendance and leave records for the period are locked via an ADVISORY application-level flag (not a DB lock), preventing modifications that would invalidate the calculation; (c) the lock releases if the run is cancelled, and approved post-lock regularizations are deferred to the next run (BR-9).

## 2. Related Requirements
- User Story: US-PAY-010
- Acceptance Criteria: AC-4
- Functional Requirements: FR-6, FR-7
- Non-Functional Requirements: NFR-2
- Business Rules: BR-9

## 3. Preconditions
- Tenant "acme" Active; Payroll module enabled.
- Attendance for the period FINALIZED; employees with a mix of present/absent/leave/OT data, including at least one absent day with NO leave record (a reconciliation mismatch).
- HR user `hr1` with `Payroll.Run`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Reconciliation columns | working/present/leave-by-type/absent/OT/LOP days | FR-7 |
| Mismatch probe | absent day with no leave record | flagged by Reconcile |
| Lock type | advisory app-level flag | NFR-2 (not DB lock) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As hr1, open the pre-payroll reconciliation report for the period. | Per-employee rows show working days, present days, leave days by type, absent days, OT hours, and calculated LOP days (FR-7). |
| 2 | Click "Reconcile" to surface mismatches. | The employee with an absent day but no leave record is flagged as a mismatch (FR-7 / UI Reconcile). |
| 3 | Initiate the payroll run; observe the transition to Processing. | On entering Processing, attendance + leave records for the period are locked via an advisory application-level flag (FR-6, NFR-2). |
| 4 | While Processing, attempt to edit an attendance record for the period. | The edit is prevented/warned by the advisory lock; the in-flight calculation cannot be invalidated (FR-6). |
| 5 | Confirm the lock is advisory, not a DB-level lock. | No long-running DB transaction holds the rows; other non-conflicting reads proceed normally (NFR-2). |
| 6 | Cancel the run; then approve an attendance regularization after the lock. | The advisory lock releases on cancellation; a regularization approved after lock is deferred as a correction to the NEXT payroll run (BR-9). |

## 6. Postconditions
- Reconciliation report renders all required columns + mismatch flags; advisory lock applied during Processing and released on cancel; post-lock regularizations deferred.

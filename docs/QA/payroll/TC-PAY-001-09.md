# TC-PAY-001-09: Input sanitization — component/structure names and formula fields resist XSS and SQL injection (security)

## 1. Test Objective
Verify that free-text fields (component name, structure name, description, formula_expression) are sanitized/parameterized so that script payloads are not stored-and-reflected as executable HTML (XSS) and injection strings do not alter SQL. Formula fields additionally route through the safe evaluator (no code execution — cross-ref TC-PAY-001-07).

## 2. Related Requirements
- User Story: US-PAY-001
- Acceptance Criteria: AC-1, AC-3
- Functional Requirements: FR-1, FR-2, FR-4
- Non-Functional Requirements: NFR-5 (audit integrity)

## 3. Preconditions
- Tenant "acme" with `Payroll.*.All` HR Officer authenticated.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| XSS name | `<script>alert(1)</script>` | stored XSS attempt |
| XSS desc | `<img src=x onerror=alert(1)>` | attribute-based XSS |
| SQLi code | `BASIC'; DROP TABLE salary_component;--` | SQL injection attempt |
| Formula payload | `basic * 0.1; DROP TABLE ...` | injection via formula |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a component with name `<script>alert(1)</script>` | Either rejected by validation or stored encoded; when rendered in the component list/slide-over the script does NOT execute (output-encoded). |
| 2 | Set a structure description to `<img src=x onerror=alert(1)>` and view the detail page | The payload renders inert (no alert); attributes sanitized. |
| 3 | Submit a component code/name containing `'; DROP TABLE salary_component;--` | Treated as literal text via parameterized queries; `salary_component` table still exists; no rows dropped. |
| 4 | Submit a formula `basic * 0.1; DROP TABLE ...` | Rejected by the safe evaluator/syntax validator (BR-6); no SQL executed, no table dropped. |
| 5 | Verify audit log entries for the above writes | Audit records store the payloads safely (escaped); the log itself is not corrupted (NFR-5). |

## 6. Postconditions
- No stored XSS executes; no injection alters the database; payloads stored/encoded safely.

# TC-PAY-013-05: Money-safety — statutory skipped + flagged when the tax country is unresolvable or has no rules; net payable floored at 0; structure statutory/deduction lines never double-counted; encashment money figure correct on real Postgres

## 1. Test Objective
Verify AC-5 / NFR-1 / BR-3 / BR-4 / BR-6 / FR-5: the settlement fails closed on money-critical edges. Statutory is computed under the employee's resolved tax country (Location -> Tenant default -> single-country fallback -> none); when the country is unresolvable (multi-country, no employee/tenant country) OR resolves but has no configured rules, statutory is SKIPPED and flagged (never taxed under the wrong country). The net payable is floored at 0 (never negative). Only Earning/Reimbursement components feed the settlement gross; structure statutory/deduction lines are dropped so they are not double-counted. The encashment money figure is proven end-to-end on real Postgres.

## 2. Related Requirements
- User Story: US-PAY-013
- Acceptance Criteria: AC-5
- Functional Requirements: FR-5
- Business Rules: BR-3, BR-4, BR-6
- Non-Functional: NFR-1 (money-critical correctness — fail closed, floor at 0, no double-count)

## 3. Preconditions
- Tenant A Active, Payroll module enabled.
- Employees with an assigned salary structure; policies with statutory ON where relevant.
- Country/rule configurations per arm: (a) no tenant default + no location + rules for two countries (unresolvable); (b) tenant default "US" but rules only for LK + IN (resolved-but-no-rules); (c) 100% income tax over 10,000 + 100% professional-tax-on-gross (statutory exceeds gross); (d) BASIC + HRA earnings + LOAN deduction + PF structure-statutory (multi-component gross); (e) real Postgres with encashable leave.

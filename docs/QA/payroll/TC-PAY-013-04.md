# TC-PAY-013-04: Settlement creation is idempotent per offboarding instance — a re-trigger returns the existing settlement (one row); the DB unique index rejects a duplicate with SQLSTATE 23505

## 1. Test Objective
Verify AC-4 / FR-3 / BR-5 / NFR-1: exactly one `FinalSettlement` exists per offboarding instance. Re-triggering the settlement for the same offboarding instance (including under a concurrent retry) returns the existing settlement and never double-creates. The idempotency guarantee is enforced at two layers: the service returns the existing ref, and a unique index on `offboarding_instance_id` is the DB backstop that rejects a duplicate insert with Postgres SQLSTATE 23505.

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Trigger `TriggerFinalSettlementAsync` for the offboarding instance; capture the returned ref (`ref1`). | A settlement is created; `ref1` is returned (AC-4). |
| 2 | Trigger `TriggerFinalSettlementAsync` again for the SAME offboarding instance; capture `ref2`. | `ref2` == `ref1` — the retried offboarding-complete returns the existing settlement, not a recompute (AC-4, BR-5). |
| 3 | Count `final_settlement` rows for the offboarding instance id. | Exactly 1 row exists (AC-4, FR-3 — one settlement per offboarding instance). |
| 4 | (Postgres DB backstop) Insert two `FinalSettlement` rows with the same `offboarding_instance_id` directly, bypassing the service dedupe. | The second insert throws `DbUpdateException` whose inner `PostgresException.SqlState` = "23505" — the unique index on `offboarding_instance_id` enforces idempotency even under a concurrent-retry race (AC-4, FR-3). |

## 6. Postconditions
- One and only one settlement exists per offboarding instance; both the service-level dedupe and the DB unique-index backstop hold.

# TC-PAY-008-16: Real-Postgres coverage for `PayrollApprovalStepConfig` — atomic RemoveRange+re-add replace (no 23505), the `(tenant_id, step_number)` unique index, the `UserHoldsRoleAsync` role-join translation, and tenant isolation — US-PAY-008 (DF-16)

## 1. Test Objective
Prove on **real Postgres** the step-config behaviours that InMemory cannot:
- **Atomic replace** — `SetApprovalStepConfigAsync` does a `RemoveRange(old)` + `Add(new)` in one `SaveChanges`; replacing `{1→A, 2→B}` with `{1→C, 2→D, 3→E}` must DELETE-before-INSERT so the overlapping step numbers 1/2 don't collide on the `(tenant_id, step_number)` unique index. A wrong order would raise 23505 — this arm confirms the ordering is correct on Npgsql (InMemory can't enforce the index at all).
- **`(tenant_id, step_number)` unique index** — a duplicate direct insert raises 23505.
- **`UserHoldsRoleAsync` role-join** — the `UserTenant → UserTenantRole` join (exercised via `ApproveAsync`'s step-role gate) translates to SQL: a role-holder approves, a non-holder gets 403 `not_step_approver`.
- **Tenant isolation** — a tenant-B config is invisible to tenant-A `GetApprovalStepConfigAsync`.

## 2. Related Requirements
- User Story: US-PAY-008 (payroll approval workflow); AC-4/FR-2 (configurable step→role)
- Findings: DF-16 (real-PG + cross-tenant arms for `PayrollApprovalStepConfig`)

## 3. Preconditions
- `postgres:17-alpine` Testcontainer, migrated; the real `PayrollApprovalService`/DbContext; seeded `Tenant`/`Role`/`UserTenant`/`UserTenantRole` FK rows (Postgres enforces these; InMemory does not).

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed `{1→A,2→B}`; set `{1→C,2→D,3→E}`. | Old rows gone, exactly the new 3 persist (no 23505). `SetApprovalStepConfig_AtomicReplace_OverlappingStepNumbers_CommitsTheNewSet`. |
| 2 | Direct-insert two rows same `(TenantId, StepNumber)`. | `DbUpdateException` (23505). `DuplicateTenantStepNumber_IsRejectedBy_UniqueIndex`. |
| 3 | Configured step role; a holder vs a non-holder approves. | Holder → `Approved`; non-holder → 403 `not_step_approver`, run untouched. `ApproveStepWithConfiguredRole_HolderApproves_NonHolderRejected_OnNpgsql`. |
| 4 | Tenant-B config vs tenant-A read. | Invisible to tenant A. `GetApprovalStepConfig_IsTenantIsolated_OnNpgsql`. |

## 5. Postconditions

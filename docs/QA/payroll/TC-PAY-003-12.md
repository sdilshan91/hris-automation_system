# TC-PAY-003-12: Payroll Runs table, New-Run modal, real-time progress bar, and status stepper meet WCAG 2.1 AA

## 1. Test Objective
Verify the WCAG 2.1 AA accessibility of the US-PAY-003 UI surface: the Notion-style Payroll Runs table (sortable/filterable), the "New Payroll Run" modal (Pay Month/Year dropdowns + pre-run validation summary), the SignalR progress bar during processing, and the horizontal status stepper (Queued > Processing > Review > Approved > Finalized) -- across keyboard, screen reader, color-contrast, and responsive (360px-1920px) dimensions.

## 2. Related Requirements
- User Story: US-PAY-003
- Acceptance Criteria: AC-1 (initiate UI), AC-3 (progress/notification), UI/UX Notes (S8)
- Functional Requirements: FR-6 (real-time progress)
- Standard: WCAG 2.1 AA

## 3. Preconditions
- Tenant "acme"; Payroll Runs page reachable; at least one run in each status for the stepper/badges.
- Axe (or equivalent) + NVDA/VoiceOver available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewports | 360px, 768px, 1280px, 1920px | responsive |
| Tools | axe-core, NVDA/VoiceOver | a11y audit |
| Status badges | color-coded | contrast + non-color cue |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Tab through the Payroll Runs table: sort headers, filters, row actions, "New Payroll Run". | All interactive elements reachable in a logical order; visible focus ring; sort/filter operable via keyboard (Enter/Space). |
| 2 | Open the New-Run modal via keyboard. | Focus moves into the modal and is TRAPPED; Esc closes and restores focus to the trigger; Pay Month/Year are labelled selects; the pre-run validation summary is announced (aria-live or associated description). |
| 3 | Initiate a run; observe the progress bar. | Progress uses role="progressbar" with aria-valuenow/min/max (or an aria-live status); "Processing X / Y" updates are announced without flooding the SR. |
| 4 | Inspect the status stepper. | Current step conveyed by more than color (text/aria-current); steps are readable by SR in order. |
| 5 | Run axe on the table, modal, progress, stepper. | Zero serious/critical violations; status badge text vs background >= 4.5:1 (3:1 for large text); badges carry a text label, not color alone. |
| 6 | Resize 1920px -> 360px. | No loss of content/function; table reflows or scrolls accessibly; modal usable; no horizontal-scroll trap (1.4.10 reflow). |

## 6. Postconditions
- The payroll-run UI is operable by keyboard + screen reader, meets contrast/reflow, with no serious/critical axe violations.

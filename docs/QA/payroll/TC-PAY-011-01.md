# TC-PAY-011-01: Send Payslips on a Finalized run -> 202 + Hangfire SendPayslipEmailsJob -> each employee receives an individual email with their own PDF attached, tenant-branded subject "Your Payslip for {Month} {Year}", per-employee email log row (happy path)

## 1. Test Objective
Verify the primary success flow across AC-1, AC-2 and FR-1/FR-2/FR-3/FR-5/FR-8: an HR Officer with `Payroll.*.All` clicks "Send Payslips" on a payroll run in Finalized status; the API enqueues a single Hangfire `SendPayslipEmailsJob` carrying tenant_id + run_id and returns 202 Accepted; the worker (with `ITenantContext` restored from job args) iterates over every employee in the run, retrieves that employee's pre-generated payslip PDF (US-PAY-004) from blob storage, and sends one individual email per employee using the tenant-branded notification template with subject `Your Payslip for {Month} {Year}` and the employee's own PDF attached; one `payslip_email_log` row per employee is written with status transitioning Queued -> Sent, recipient_email, sent_at timestamp, and links to payroll_run_id / payroll_slip_id / employee_id.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1, FR-2, FR-3, FR-5, FR-8
- Business Rules: BR-1 (Finalized only), BR-2 (tenant template), BR-6 (per-run status tracking)
- Data Requirements: S7 (payslip_email_log)

## 3. Preconditions
- Tenant "acme" Active, subdomain `acme.yourhrm.com`, Payroll module enabled, tenant branding (company name/logo) + notification template configured (BR-2).
- A payroll run R for May 2026 in status **Finalized** (US-PAY-008) with 3 employees, each having a generated payslip PDF at `{acmeTenantId}/payroll/{R}/{employeeId}.pdf` (US-PAY-004).
- All 3 employees (EMP-001, EMP-002, EMP-003) have a valid email address on file in Core HR.
- Tenant SMTP relay configured; a test SMTP sink (MailHog/Papercut) is capturing outbound mail.
- HR Officer "Maya Singh" authenticated in acme with `Payroll.*.All`.
- Hangfire worker operational.

| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the run R detail page; the "Send Payslips" button is enabled (Finalized + PDFs generated). Click it and confirm the dialog. | API enqueues ONE `SendPayslipEmailsJob` with args {tenant_id=acme, run_id=R}; request returns 202 Accepted with a job/tracking handle (AC-1, FR-1). |
| 2 | Verify the worker restores tenant context. | Job logs show `ITenantContext=acme` restored from job args before any query; correlation id logged (FR-8). |
| 3 | Worker iterates the 3 employees, fetches each PDF and sends individual emails (FR-2). | Exactly 3 separate emails are produced -- one per employee; each is addressed to that employee's recipient_email only (no CC/BCC of others). |
| 4 | Inspect each captured email at the SMTP sink. | Subject = "Your Payslip for May 2026"; body rendered from the tenant template ({EmployeeName}/{PayMonth}/{PayYear}/{CompanyName} substituted); exactly one attachment = that employee's own `{employeeId}.pdf`. |
| 5 | Verify `payslip_email_log` rows (FR-5). | One row per employee: tenant_id=acme, payroll_run_id=R, payroll_slip_id + employee_id + recipient_email set, status=Sent, sent_at set, retry_count=0, failure_reason null. |
| 6 | Reload the run detail; view the distribution summary card (BR-6). | Summary: Total=3, Sent=3, Failed=0, Skipped=0, Queued=0; started_at + completed_at set. |

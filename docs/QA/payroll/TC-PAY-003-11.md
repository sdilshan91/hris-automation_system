# TC-PAY-003-11: Full payroll run for 5,000 employees completes in < 10 minutes; slips persisted via batch insert (AC-5 / NFR-1 / NFR-6)

## 1. Test Objective
Verify AC-5 / NFR-1 and NFR-6: a complete payroll run for a tenant with 5,000 active employees (all with salary structures, finalized attendance/leave) completes end-to-end (Queued -> ReviewPending) in under 10 minutes; payslip + detail rows are written using batch inserts / bulk copy (NFR-6) rather than row-by-row inserts; and salary structure data is read from the cache during processing to reduce DB load (NFR-7).

## 2. Related Requirements
- User Story: US-PAY-003
- Acceptance Criteria: AC-5
- Non-Functional: NFR-1 (< 10 min for 5,000), NFR-6 (batch insert), NFR-7 (Redis-cached structure reads)
- Reference: technical document section 1.4 success criterion #3

## 3. Preconditions
- Tenant "acme-load" seeded with 5,000 active employees, each with an assigned salary structure.
- Attendance + leave for May 2026 finalized for all; statutory rules configured.
- Test runs on a representative environment; Hangfire worker operational.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Active employees | 5,000 | NFR-1 scale |
| Period | May 2026 | single run |
| SLA | < 10 min (600 s) | wall clock Queued -> ReviewPending |
| Insert strategy | batch/bulk | NFR-6 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Initiate the run; record start time when status becomes Processing. | Run enqueued + starts; progress bar (SignalR) increments processed/total toward 5,000. |
| 2 | Measure wall-clock to status=ReviewPending. | Total elapsed < 10 minutes (600 s); all 5,000 eligible slips persisted. |
| 3 | Inspect persistence path (query log / instrumentation). | Slips + details inserted in batches (bulk copy), NOT 5,000 individual INSERT round-trips (NFR-6). |
| 4 | Inspect structure reads during processing. | Salary structure/component data served from cache (NFR-7); DB read volume bounded, not one structure fetch per employee uncached. |
| 5 | Verify correctness at scale. | processed_employees = 5,000; summary totals reconcile (sum of slip nets == total_net); no slips dropped/duplicated. |
| 6 | Capture resource profile. | No unbounded memory growth; worker completes without OOM; correlation id + counts logged (NFR-4). |

## 6. Postconditions
- 5,000-employee run completes under SLA via batch inserts and cached structure reads, with correct totals.

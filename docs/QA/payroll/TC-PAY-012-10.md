# TC-PAY-012-10: Audit-query performance P95 <= 2s over 1 year / 50,000+ entries (BRIN on timestamp) + async (fire-and-forget) audit writes do not impact the primary payroll operation

## 1. Test Objective
Verify NFR-2 and NFR-1/NFR-3: an audit-trail query spanning up to 1 year of data (>= 50,000 entries) returns within P95 <= 2 seconds, leveraging time-range-efficient indexing (BRIN on timestamp columns per NFR-3); and audit-log writes are asynchronous (fire-and-forget) so they do not add latency to the primary payroll write operation.

## 2. Related Requirements
- User Story: US-PAY-012
- Acceptance Criteria: AC-4
- Functional Requirements: FR-4
- Non-Functional Requirements: NFR-1 (async writes), NFR-2 (P95 <= 2s, 1yr), NFR-3 (BRIN on timestamp)

## 3. Preconditions
- A seeded performance environment for tenant "acme" with >= 50,000 payroll audit_log entries spanning ~12 months; BRIN index on the timestamp column present (or noted as the extension point if not yet added).
- A baseline latency for a primary payroll write (e.g. component update) measured WITHOUT audit, and WITH audit enabled.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Entry volume | 50,000+ over 1 year | NFR-2 |
| Query | last 12 months audit trail, filtered | FR-4 |
| Target | P95 <= 2s | NFR-2 |
| Primary-op overhead | ~0 added by audit write | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Run the 1-year audit-trail query repeatedly under load (>= 50 iterations / concurrent users). | P95 response time <= 2s; results correct and complete. |
| 2 | Inspect the query plan. | Time-range filter uses the BRIN index on timestamp (range scan), not a full sequential scan (NFR-3). (CONDITIONAL: if BRIN not yet created, assert the query is index-assisted + note BRIN as the optimisation extension point.) |
| 3 | Measure a primary payroll write (component update) latency with audit logging enabled. | Latency is within the primary operation's own SLA; the audit write adds negligible latency (async fire-and-forget, NFR-1). |
| 4 | Simulate a slow/unavailable audit sink. | The primary payroll operation still succeeds and returns on time; the audit write is decoupled (queued/outbox) and does not block or fail the primary op (NFR-1). |
| 5 | Re-run the query with combined filters (date + action + actor). | Still within the <= 2s P95 budget. |

## 6. Postconditions
- 1-year audit query meets P95 <= 2s; audit writes are async and impose no measurable latency on primary payroll operations.

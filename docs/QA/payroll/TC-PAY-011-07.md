# TC-PAY-011-07: Idempotent resume -- re-running the job after a partial failure picks up only the not-yet-Sent employees and does NOT re-email already-Sent employees (boundary / NFR-3)

## 1. Test Objective
Verify NFR-3 and FR-5: the email distribution job is idempotent. If the job is interrupted (worker crash / restart) or re-run after a partial failure, it resumes from where it left off -- sending only to employees whose log row is not yet in a terminal Sent state (Queued/Failed) and NOT re-emailing employees already marked Sent. This guarantees no duplicate emails from a retry/resume of the same run.

## 2. Related Requirements
- User Story: US-PAY-011
- Acceptance Criteria: AC-1, AC-4
- Functional Requirements: FR-2, FR-5
- Non-Functional Requirements: NFR-3 (idempotent resume)

## 3. Preconditions
- Tenant "acme" Finalized run R with 5 employees, all with emails + generated PDFs.
- A first job execution sent EMP-001 and EMP-002 (Sent), then was interrupted before EMP-003/004/005 (their log rows remain Queued / not-yet-Sent).
- SMTP relay now accepts all; HR Officer authenticated with `Payroll.*.All`; SMTP sink captures mail.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| EMP-001, EMP-002 | Sent (before interruption) | must NOT be re-sent |
| EMP-003, EMP-004, EMP-005 | Queued (not yet sent) | resume targets |
| Run | R, Finalized | same run, resumed job |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Confirm pre-state: EMP-001/002 = Sent, EMP-003/004/005 = Queued. | The log accurately reflects which deliveries completed before interruption. |
| 2 | Re-run / resume the `SendPayslipEmailsJob` for run R. | The job reads existing log rows and sends ONLY to EMP-003/004/005 (the not-yet-Sent set), skipping EMP-001/002 (NFR-3). |
| 3 | Verify the SMTP sink. | Exactly 3 new emails (EMP-003/004/005); NO duplicate emails to EMP-001/002. |
| 4 | Verify `payslip_email_log`. | EMP-003/004/005 transition Queued -> Sent; EMP-001/002 rows untouched (single Sent, no second sent_at). |
| 5 | Run the job a third time with everything Sent. | No emails sent (nothing left in a non-Sent state); the job is a no-op -- idempotent. |

## 6. Postconditions
- A resumed/re-run job emails only the outstanding employees exactly once; already-Sent employees are never duplicated; a fully-Sent run resends nothing.

# TC-PAY-013-07: Multi-tenant isolation — every F&F settlement table ships a dormant `tenant_isolation` RLS policy (defence-in-depth), and settlement data is tenant-scoped via EF Core global query filters

## 1. Test Objective
Verify AC-7 / NFR-3: F&F policy and settlement data are tenant-isolated. The NEW-TENANT-TABLE rule requires every tenant_id table to ship its dormant `tenant_isolation` RLS policy in its migration; this TC asserts that policy exists for all three settlement tables (`tenant_fnf_policy`, `final_settlement`, `final_settlement_line`) on real Postgres. Read isolation at runtime is enforced by EF Core global query filters + `TenantInterceptor` on write, with the dormant RLS policy as defence-in-depth (armed when the platform RLS flag is enabled — see notes).

- User Story: US-PAY-013

## 3. Preconditions

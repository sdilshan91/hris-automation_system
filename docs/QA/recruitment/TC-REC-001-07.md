# TC-REC-001-07: Boundary validation for title length (200 chars) and headcount (>= 1, reject 0)

## 1. Test Objective
Verify FR-1 field boundaries: title accepts up to 200 characters and rejects 201; headcount accepts the minimum valid value 1 and rejects 0 (and negatives), since headcount must be an integer >= 1.

## 2. Related Requirements
- User Story: US-REC-001
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1 (title max 200 chars; headcount integer >= 1)
- Business Rules: BR-4 (headcount = max positions to fill)

## 3. Preconditions
- Tenant "acme" with Recruitment enabled.
- Recruiter "Riley Park" (Recruitment.Create.All) is authenticated in acme.
- A vacancy form is open with all other required fields valid.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Title (boundary in) | 200-character string | Exactly at max -> accept |
| Title (boundary out) | 201-character string | Over max -> reject |
| Headcount (boundary in) | 1 | Minimum valid -> accept |
| Headcount (boundary out low) | 0 | Below min -> reject |
| Headcount (invalid) | -1 / 2.5 / blank | Reject (integer >= 1) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter a 200-character title and save the draft | Accepted (201 Created); title persisted in full (no truncation). |
| 2 | Enter a 201-character title and attempt to save | Rejected with "Title must be 200 characters or fewer" (or equivalent); not persisted. The API also rejects (400/422) if the UI cap is bypassed. |
| 3 | Set headcount = 1 with a valid title and save | Accepted; `headcount = 1` persisted. |
| 4 | Set headcount = 0 and attempt to save | Rejected with "Headcount must be at least 1" (or equivalent); not persisted; API also rejects when bypassing the UI. |
| 5 | Set headcount = -1, then 2.5, then blank and attempt to save each | Each rejected (must be a positive integer); none persisted. |

## 6. Postconditions
- Only titles <= 200 chars and headcount integers >= 1 are accepted and persisted.

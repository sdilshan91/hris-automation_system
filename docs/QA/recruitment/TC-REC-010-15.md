# TC-REC-010-15: Real-Postgres coverage for hire-provisioning — the `IsRelational()`-gated transaction provisions User/UserTenant/UserTenantRole atomically, and a transient-failure retry provisions the account EXACTLY once (BUG-264 rollback-detach) — US-REC-010 (DF-15)

## 1. Test Objective
Prove on **real Postgres** the applicant→hire provisioning path that is InMemory-unreachable: `ApplicantConversionService` guards `BeginTransactionAsync` behind `IsRelational()`, so the account provisioning + its retry/rollback-detach (BUG-264) only run on a relational provider.
- **Atomic provisioning:** with `AutoCreateUserOnHire=true`, converting an applicant creates a `User` (passwordless), an Active `UserTenant`, a `UserTenantRole` (Employee), and links `Employee.UserId` — all in one committed transaction.
- **Retry provisions exactly once (BUG-264):** a single transient failure on the SaveChanges that carries the conversion audit + the provisioned rows forces an execution-strategy retry; after the retry the account rows exist **exactly once** (the rollback-detach prevents a duplicate User/UserTenant), and the result is a real success (not a spurious `already_converted`).

## 2. Related Requirements
- User Story: US-REC-010 (applicant → employee conversion / hire provisioning)
- Findings: DF-15 (Testcontainers arm for the retry-detach), BUG-264 (retry duplicate class)

## 3. Preconditions
- `postgres:17-alpine` Testcontainer, migrated; the real `ApplicantConversionService`/`EmployeeService`; the `FailOnceOnConversionAuditInterceptor` (from the existing retry-strategy suite) to inject one transient failure; a seeded built-in "Employee" role + tenant setting `AutoCreateUserOnHire=true`.

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Convert an applicant with auto-create ON. | User (passwordless) + Active UserTenant + UserTenantRole(Employee) + `Employee.UserId` link all committed (read from a fresh context). `Convert_WithAutoCreateOn_ProvisionsUserAccount_InSameCommittedTransaction`. |
| 2 | Convert with one injected transient failure on the atomic save. | `ThrowCount == 1`; real success; exactly ONE User/UserTenant/UserTenantRole after the retry. `Convert_WithAutoCreateOn_FailsTransientlyThenRetries_ProvisionsAccountExactlyOnce`. |

## 5. Postconditions
- Hire provisioning commits atomically and is retry-safe against duplicates on the real provider.

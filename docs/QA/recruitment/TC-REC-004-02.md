# TC-REC-004-02: Structured rejection -- reason dropdown REQUIRED (NotQualified/PositionFilled/Withdrew/Other), optional notes, reason persisted (AC-4, FR-3)

## 1. Test Objective
Verify AC-4 / FR-3: the reject flow requires a structured rejection reason chosen from a fixed enumeration (NotQualified, PositionFilled, Withdrew, Other) plus optional free-text notes. Rejection with no reason is blocked; rejection with a valid reason moves the applicant to "Rejected", stores the reason in `applicant_stage_history.rejection_reason`, and queues the configurable rejection email. This extends REC-003's TC-REC-003-07 (which only asserted "a reason is required") by validating the REQUIRED dropdown ENUMERATION and that the chosen reason is stored as structured data.

## 2. Related Requirements
- User Story: US-REC-004
- Acceptance Criteria: AC-4
- Functional Requirements: FR-3
- Data Requirements: S7 (`applicant_stage_history.rejection_reason`, notes)

## 3. Preconditions
- Tenant "acme"; recruiter with `Recruitment.Manage.All` authenticated.
- Applicant "Sam Lee" at "Screening" (any active stage).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Valid reasons | NotQualified, PositionFilled, Withdrew, Other | Fixed dropdown enum |
| Invalid reason | (empty), "MadeUpReason" | Must be rejected |
| Notes | "Did not meet 5y experience bar" | Optional free text |
| Applicant | Sam Lee ({acme_applicantId}) | At Screening |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the Reject modal on Sam Lee | Modal shows a REQUIRED reason dropdown with exactly the four options (NotQualified, PositionFilled, Withdrew, Other) and an optional notes textarea. |
| 2 | Submit reject with NO reason selected | 400 validation error; the move is blocked; applicant stays at "Screening"; no history row written. |
| 3 | `PATCH .../stage` to "Rejected" with `rejectionReason="MadeUpReason"` (not in enum) | 400; the server rejects an out-of-enum reason (client dropdown cannot send it, but the API must validate too). |
| 4 | Submit reject with reason="NotQualified" and notes | 200; stage = Rejected; one `applicant_stage_history` row: from=Screening, to=Rejected, rejection_reason="NotQualified", notes stored, changed_by/changed_at/tenant_id set. |
| 5 | Verify the rejection email seam | A configurable rejection-email outbox entry is queued (not sent inline); template/variable substitution covered by TC-REC-004-10. |
| 6 | Verify reason is stored as structured data | The stored `rejection_reason` is the enum value (queryable/reportable), not buried only inside free-text notes. |

## 6. Postconditions
- Sam Lee is at "Rejected" with a structured, queryable rejection reason recorded.

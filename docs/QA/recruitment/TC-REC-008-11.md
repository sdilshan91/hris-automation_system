# TC-REC-008-11: Rate limiting on the magic-link regeneration endpoint prevents abuse / enumeration

## 1. Test Objective
Verify NFR-6: the magic-link generation/regeneration endpoint is rate-limited to prevent abuse (email-bombing an applicant, brute-forcing/enumerating which emails have applications, exhausting the email provider). After a threshold of rapid requests (by IP and/or email), further requests are throttled (HTTP 429 or equivalent) and no additional links are generated/emailed. Throttling must not reveal whether an email exists (combine with the neutral response from TC-REC-008-06).

## 2. Related Requirements
- User Story: US-REC-008
- Non-Functional Requirements: NFR-6 (rate limiting on magic-link generation)
- Functional Requirements: FR-8 (regeneration), BR-5 (email verification)

## 3. Preconditions
- Tenant "acme"; the regeneration prompt is reachable on acme's subdomain. A known email applicant@example.com has an application.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Endpoint | POST /portal/request-link (acme subdomain) | regeneration |
| Burst | 20 requests in rapid succession | same email + same IP |
| Threshold | implementation-configured | e.g. N/min |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Send the configured threshold N of regeneration requests for applicant@example.com within a short window | The first up-to-threshold requests are accepted (each returns the neutral response); links are generated within sane limits. |
| 2 | Continue past the threshold (e.g. 20 rapid requests) | Subsequent requests are throttled (429 / "too many requests"); NO additional magic links are generated or emailed (NFR-6). |
| 3 | Repeat the burst with an UNKNOWN email | Same throttling applies; responses remain the neutral "if an application exists, a link has been sent" -- throttling does not reveal existence (NFR-6, BR-5). |
| 4 | Wait for the window to reset, then send one request | The endpoint accepts again after the limit window resets. |
| 5 | Verify no email flood | The applicant's mailbox received at most the allowed number of links, not one per request. |

## 6. Postconditions
- Excess regeneration requests were throttled; no link/email flood; existence not revealed by the throttle behaviour.

# TC-REC-009-07: Recent Activity feed shows latest recruitment events with timestamps and deep links (FR-9)

## 1. Test Objective
Verify FR-9: the dashboard "Recent Activity" feed lists the latest recruitment events (new applicant, stage change, offer sent, hire) in reverse-chronological order, each with an icon, a human-readable description, a relative timestamp ("2 hours ago"), and a link to the relevant applicant or vacancy. Asserts ordering, event coverage across the four event types, relative-time formatting, and that links navigate to the correct in-tenant entity. Confirms the feed honours the global date filter.

## 2. Related Requirements
- User Story: US-REC-009
- Functional Requirements: FR-9 (recent activity feed)
- Acceptance Criteria: AC-1 (dashboard composition), AC-2 (period scope)
- Business Rules: BR-4 (refresh on load; no real-time streaming in Phase 1)

## 3. Preconditions
- Tenant "acme" with a set of recent events of each type with known timestamps: a new applicant 10 min ago, a stage change 2 hours ago, an offer sent yesterday, and a hire 3 days ago.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| New applicant | 10 min ago | "new applicant" event |
| Stage change | 2 hours ago | "moved to Interview" event |
| Offer sent | 1 day ago | "offer sent" event |
| Hire | 3 days ago | "hired" event |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | View the Recent Activity feed | Events render newest-first: new applicant, stage change, offer sent, hire (FR-9). |
| 2 | Inspect each entry | Each shows an icon, descriptive text, and a relative timestamp ("10 minutes ago", "2 hours ago", "yesterday", "3 days ago"). |
| 3 | Verify event-type coverage | All four event types (new applicant, stage change, offer sent, hire) are represented. |
| 4 | Click an applicant-linked event | Navigates to the correct applicant detail within acme (no cross-tenant or broken link). |
| 5 | Click a vacancy-linked event | Navigates to the correct vacancy within acme. |
| 6 | Reload the page | Feed refreshes to current state (BR-4: refresh on load, no streaming). |
| 7 | Narrow the date filter to exclude older events | Feed shows only in-period events; empty state if none. |

## 6. Postconditions
- No data mutated; the feed accurately reflects recent in-tenant events with working deep links.

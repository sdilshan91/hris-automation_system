# TC-REC-004-10: Stage-transition email notifications are queued asynchronously (Hangfire/outbox), non-blocking, with tenant template substitution (FR-6, NFR-5, BR-5)

## 1. Test Objective
Verify FR-6 / NFR-5 / BR-5: each stage transition (and rejection) enqueues a configurable applicant email via the notification outbox for async Hangfire delivery -- the email does NOT block the API response -- and the email uses the tenant's configured template with variable substitution (applicant name, vacancy title, stage name, company name). NOTE: the Notification System (S25) and Hangfire delivery are external dependencies; if email delivery is a LOG-ONLY stub in this increment, assert the queued outbox entry + async contract, CONDITIONAL on the Notification System being wired (not a gap).

## 2. Related Requirements
- User Story: US-REC-004
- Functional Requirements: FR-6
- Non-Functional Requirements: NFR-5
- Business Rules: BR-5
- Dependencies: Notification System (S25), Hangfire

## 3. Preconditions
- Tenant "acme" with configured stage-transition + rejection email templates.
- Applicant "Noor Ali" at "Applied".

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant | Noor Ali ({acme_applicantId}) | At Applied |
| Template vars | {applicantName}, {vacancyTitle}, {stageName}, {companyName} | Substituted |
| Delivery | Hangfire async (or log-only stub) | Non-blocking |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Move Noor Applied -> Screening and measure the API response | 200 returns promptly; the response does NOT wait on email send (NFR-5); an outbox/notification entry is created. |
| 2 | Inspect the queued notification | Entry references the applicant + transition; targets the applicant's email; status = queued/pending for Hangfire pickup. |
| 3 | Inspect rendered template variables | The queued message resolves {applicantName}=Noor Ali, {vacancyTitle}, {stageName}=Screening, {companyName}=acme's name (BR-5). |
| 4 | Reject Noor (reason) and check the rejection email | A configurable rejection email is queued using the rejection template (AC-4 cross-ref). |
| 5 | Async delivery / stub check | The Hangfire job processes the queue out-of-band; if delivery is a LOG-ONLY stub, assert the log/outbox record exists and the API stayed non-blocking -- CONDITIONAL on S25 wiring. |
| 6 | Failure isolation | A notification send failure does NOT roll back or fail the stage transition (the transition + history are already committed; see TC-REC-004-12 atomicity). |

## 6. Postconditions
- Each transition queued a templated, tenant-scoped notification without blocking the API; transition success is independent of email delivery.

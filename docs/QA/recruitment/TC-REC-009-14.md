# TC-REC-009-14: Recruitment dashboard returns 200 with a corrupt stage-history row (ISSUE-231 — dashboard read path)

## 1. Test Objective
Verify that a single `applicant_stage_history` row holding a `from_stage`/`to_stage` string outside the enum does **not** 500 the entire recruitment dashboard. The dashboard projects every history row (funnel + KPIs), so a strict converter aborts the whole query on one bad row. Through the tolerant converter the bad value maps to the off-funnel `Unknown` sentinel. Regression for ISSUE-231 (dashboard read path — surfaced by `@integration-enforcer` as a higher-traffic sibling of the pipeline-board case).

## 2. Related Requirements
- User Story: US-REC-009 (Recruitment Dashboard and Analytics)
- Finding: ISSUE-231 (PR #348), dashboard read path (`RecruitmentDashboardService`)
- Root cause: EF strict enum→string converter throws while materializing the projected `to_stage`/`from_stage`

## 3. Preconditions
- Real PostgreSQL (Testcontainers `postgres:17-alpine`), migrations applied — Postgres-only (raw SQL is the only way to plant an out-of-enum string).
- A vacancy + applicant + one stage-history row.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Seeded history | Applied → Screening | valid, via EF |
| Corrupted `to_stage` | `'LegacyPhoneScreen'` | raw-SQL `UPDATE`, out-of-enum |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed a stage-history row, then raw-SQL `UPDATE applicant_stage_history SET to_stage='LegacyPhoneScreen'`. | Row persisted with an out-of-enum stage string. |
| 2 | Call the real `RecruitmentDashboardService.GetDashboardAsync` (default filter). | `IsSuccess == true` (200, not 500) — the strict converter would 500 the whole dashboard here. |

## 6. Postconditions
- Dashboard available despite the corrupt history row; the `Unknown` sentinel is off-funnel (`StageRank` = -1) and never a real funnel stage.

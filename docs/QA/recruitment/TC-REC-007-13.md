# TC-REC-007-13: Offer creation form + PDF preview WCAG 2.1 AA, responsive 360px; custom-clause/benefits text sanitized (no XSS into PDF/UI)

## 1. Test Objective
Verify NFR-5 (offer template/editor + form mobile-responsive) and WCAG 2.1 AA for the offer surface: the offer creation form (Position Details, Compensation w/ currency + pay-frequency, Timeline, Additional Clauses) and the PDF preview (pdf.js inline viewer with Download + Send) are keyboard-operable, screen-reader friendly, meet contrast, and remain usable at 360px (full-width form; PDF preview in a modal with pinch-to-zoom). Also asserts that recruiter-supplied free text (benefits summary, custom clauses) is sanitized so it cannot inject script when (a) rendered back in the UI and (b) substituted into the generated PDF/HTML template -- defense against stored XSS via offer content.

## 2. Related Requirements
- User Story: US-REC-007
- Non-Functional Requirements: NFR-5 (template editor + form mobile-responsive, rich text + placeholders)
- Functional Requirements: FR-1 (form), FR-2 (template substitution), FR-4 (preview)
- Acceptance Criteria: AC-1 (generation + preview surface)

## 3. Preconditions
- Tenant "acme" active; `recruiter@acme` can reach the offer form + PDF preview.
- Accessibility tooling (axe/Lighthouse) + screen reader (NVDA/VoiceOver) available; viewport set to 360px.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Viewport | 360px, 768px, 1280px | Mobile to desktop |
| XSS payload in custom clause | `<img src=x onerror=alert(1)>` | Must be neutralized in UI + PDF |
| XSS payload in benefits | `<script>alert(1)</script>` | Must be neutralized |
| Salary control | amount + currency + pay frequency | accessible names |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Operate the entire offer form by keyboard only (tab order through Position/Compensation/Timeline/Clauses, salary currency + frequency, Generate) | All controls reachable + operable via keyboard; visible focus indicators; logical tab order; salary amount/currency/frequency have accessible names (FR-1). |
| 2 | Run axe/Lighthouse on the form + PDF-preview screen | Zero WCAG 2.1 AA violations (contrast >= 4.5:1, labelled inputs, ARIA on the currency selector + preview controls + status badges). |
| 3 | Screen-reader pass | Each section, the salary (amount + currency + frequency), the expiry/start dates, and the preview's Download/Send actions are announced meaningfully; offer status badges convey status by label, not color alone. |
| 4 | Resize to 360px | Form is full-width and usable without horizontal scroll; the PDF preview opens in a modal with pinch-to-zoom; Generate/Send reachable (NFR-5). |
| 5 | XSS render check (UI) | Submit benefits/custom-clause text containing the payloads; when re-rendered in the UI the payload is inert (escaped/stripped) -- no script executes. |
| 6 | XSS render check (PDF/template) | The same payloads substituted into the generated PDF/HTML template are rendered as literal text, not executable markup -- no injection into the PDF or any HTML preview path (FR-2). |
| 7 | Cross-browser smoke | Form + PDF preview render and submit correctly on Chrome, Edge, Firefox, Safari. |

## 6. Postconditions
- Offer form + PDF preview pass WCAG 2.1 AA, are usable at 360px, and render recruiter-supplied text safely (no XSS into UI or PDF).

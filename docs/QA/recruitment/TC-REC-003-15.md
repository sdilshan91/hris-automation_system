# TC-REC-003-15: Pipeline board returns 200 with a corrupt applicant enum row (ISSUE-231 — board no longer poisoned)

## 1. Test Objective
Verify that a single applicant row holding a `source`/`stage` string outside the enum does **not** 500 the whole pipeline board. Through the tolerant converter the bad value maps to the `Unknown` sentinel; the board renders, the corrupt-source card shows `Unknown`, and the corrupt-stage card (sentinel has no column) is simply not shown. Regression for ISSUE-231.

## 2. Related Requirements
- User Story: US-REC-003 (pipeline board)
- Finding: ISSUE-231 (PR #348); supersedes the board-500 seen at TC-REC-003-12
- Root cause: EF strict enum→string converter throws during materialization; one bad row aborts the whole result set

## 3. Preconditions
- Real PostgreSQL (Testcontainers `postgres:17-alpine`), migrations applied — the only way to plant an out-of-enum string (raw SQL); InMemory reads through the same converter and cannot reproduce it.
- A vacancy with several applicants.

## 4. Test Data
| Applicant | Field | Value |
|-----------|-------|-------|
| A (control) | stage/source | Applied / Public |
| B | `source` | `'CareerSite'` (raw-SQL, out-of-enum) |
| C | `stage` | `'LegacyPhoneScreen'` (raw-SQL, out-of-enum) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed the applicants, then raw-SQL corrupt B.source and C.stage. | Rows persisted with out-of-enum strings. |
| 2 | Materialize all applicants on the vacancy (the board's load step). | No throw; B.Source == `Unknown`, C.Stage == `Unknown`. |
| 3 | Call the real `ApplicantService.GetPipelineBoardAsync`. | `IsSuccess == true` (200, not 500). |
| 4 | Inspect the board columns. | No `Unknown` column; Applied column = {A, B}; B's card `Source == Unknown`; C (corrupt stage) appears in **no** column. |

## 6. Postconditions
- Board available despite the corrupt row; a Serilog warning is emitted per tolerated value.

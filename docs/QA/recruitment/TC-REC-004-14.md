# TC-REC-004-14: Reactivating a Rejected applicant is a controlled re-entry -- no forward jump to a later stage (BR-2) [regression: BUG-060]

## 1. Test Objective
Verify BR-2 (a rejected applicant cannot advance until a controlled Manage reactivation): reactivation is a controlled RE-ENTRY at the early pipeline stages (Applied or Screening), not an arbitrary forward jump. A reactivation move to Interview / Offer / Hired -- skipping the funnel -- is rejected. Regression coverage for **BUG-060**: pre-fix, a Rejected applicant could be moved directly forward to any stage (a supplied reason satisfied the existing reactivation gate), leaping the entire pipeline.

> Traceability note: the fix commit labels BUG-060 "US-REC-008, BR-2", but the governing acceptance criterion is US-REC-004 **BR-2 (rejected applicant cannot advance until Manage reactivation)**. US-REC-008 is the candidate-portal story and has no stage-transition AC. This TC is traced to US-REC-004 to satisfy AC linkage.

## 2. Related Requirements
- User Story: US-REC-004
- Business Rules: BR-2 (controlled reactivation out of Rejected)
- Functional Requirements: FR-5 (backward/reactivation move only for Manage, mandatory reason)
- Finding: BUG-060

## 3. Preconditions
- Tenant "acme"; recruiter with `Recruitment.Manage.All` authenticated.
- An applicant exists at stage "Rejected" (with an Applied -> Rejected history row and a structured rejection reason recorded).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant stage | Rejected | Reactivation source under test |
| Forbidden target | Offer | A later stage (>= Interview) -- a forward jump |
| Allowed target | Applied | Early re-entry point (Applied/Screening allowed) |
| Reason | "Reconsidering after a strong referral." | Present, so only the reactivation-target guard can block the forbidden case |
| expectedRowVersion | applicant's current xmin | Passed so the move is not rejected on ISSUE-109 concurrency |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Reactivate the Rejected applicant -> Offer with a reason | 400 `invalid_reactivation_target`; the forward jump is blocked; stage stays "Rejected"; no history row to Offer written. |
| 2 | Control: reactivate the Rejected applicant -> Applied with a reason | 200; the controlled re-entry at the initial stage succeeds; the structured rejection reason is cleared (BR-2). |
| 3 | Regression guard: an existing early reactivation (Rejected -> Screening) still succeeds | 200 (covered by the existing reactivation test); Screening (< Interview) remains a valid re-entry point -- the guard blocks only Interview/Offer/Hired. |

## 6. Postconditions
- The Rejected applicant can only be re-entered at Applied/Screening; late-stage jumps are rejected.

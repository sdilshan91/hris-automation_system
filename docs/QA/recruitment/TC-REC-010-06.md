# TC-REC-010-06: Duplicate conversion rejected -> an already-converted applicant cannot be converted again (BR-2, FR-10, BR-6)

## 1. Test Objective
Verify duplicate-conversion prevention (BR-2, FR-10, BR-6): once an applicant has been converted (has a `converted_to_employee_id`), a second conversion attempt — via the UI action OR a direct API call (defending against a replayed/forged request) — is rejected with a clear error and creates NO second employee, NO additional `filled_count` increment, and NO duplicate user account. The applicant record (and its existing link) is unchanged.

## 2. Related Requirements
- User Story: US-REC-010
- Functional Requirements: FR-10 (prevent duplicate conversions)
- Business Rules: BR-2 (convert once; reject duplicates with a clear message), BR-6 (link preserved, applicant not deleted)

## 3. Preconditions
- Applicant {acme_applicantId} already converted (TC-REC-010-01): has `converted_to_employee_id` = {newEmployeeId}; vacancy filled_count = 1.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Applicant | {acme_applicantId} | already converted |
| Existing link | {newEmployeeId} | converted_to_employee_id set |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Attempt to convert {acme_applicantId} again via the API (`POST .../applicants/{id}/convert`, bypassing the hidden UI action) | Rejected (409/422) with a clear "already converted" message (BR-2, FR-10). |
| 2 | Verify no second employee | No new `employee` row is created; only {newEmployeeId} exists for this applicant. |
| 3 | Verify vacancy unchanged | Vacancy filled_count stays 1 (no double-increment) (FR-7 integrity). |
| 4 | Verify no duplicate account | No second `User`/`UserTenant` is created for the applicant's email. |
| 5 | Verify applicant link intact | {acme_applicantId} still links to {newEmployeeId}; `converted_at`/`converted_by` unchanged; applicant not deleted (BR-6). |
| 6 | Verify the UI does not offer the action | The "Convert to Employee" action is hidden/disabled for the already-converted applicant (defense-in-depth with Step 1). |

## 6. Postconditions
- No duplicate employee/account/increment; applicant's original conversion link is preserved.

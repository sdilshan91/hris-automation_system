# TC-REC-007-04: Applicant declines offer -> status Declined, applicant remains in "Offer" stage (alternative path)

## 1. Test Objective
Verify the decline branch of AC-3 (FR-6): a `Sent` offer is declined via the candidate portal or recorded manually by the recruiter. On decline the system (a) updates the offer status `Sent -> Declined` with `responded_at`/`response=Declined`, (b) does NOT advance the applicant -- they remain in the "Offer" stage with the declined status noted (so the recruiter can re-engage / generate a revised offer), and (c) cancels the pending expiry reminder + auto-status Hangfire jobs (a Declined offer must not later flip to Expired). This complements the accept path (TC-REC-007-03) and exercises the "stays in Offer" requirement explicitly.

## 2. Related Requirements
- User Story: US-REC-007
- Acceptance Criteria: AC-3
- Functional Requirements: FR-6, FR-7 (job cancellation)
- Business Rules: BR-2 (a Declined offer is no longer "active", so a new offer can be generated -- see TC-REC-007-07/08)

## 3. Preconditions
- Tenant "acme" active; a `Sent` offer {acme_offerId} exists for {acme_applicantId}, applicant in "Offer" stage; expiry/reminder jobs scheduled.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Offer | {acme_offerId} | status Sent |
| Applicant | {acme_applicantId} | in "Offer" stage |
| Response | Declined | via portal or recorded by recruiter |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Decline the offer (portal action OR recruiter `POST /api/v1/recruitment/offers/{acme_offerId}/respond` with response=Declined) | 200; offer status `Sent -> Declined`, response=Declined, responded_at set (AC-3, FR-6). |
| 2 | Verify applicant stage UNCHANGED | Applicant {acme_applicantId} REMAINS in the "Offer" stage (NOT advanced, NOT rejected); the declined offer status is noted on the applicant card/timeline. |
| 3 | Verify expiry jobs cancelled | The pending expiry reminder + auto-status jobs for {acme_offerId} are cancelled/no-op; a Declined offer cannot later transition to Expired. |
| 4 | Verify a new offer is now allowed | Because the offer is Declined (no longer "active" per BR-2), the recruiter may generate a NEW offer for the same applicant/vacancy (covered in TC-REC-007-07/08). |
| 5 | Verify terminal status | A subsequent accept/decline on the same Declined offer is rejected; the status is terminal. |

## 6. Postconditions
- Offer {acme_offerId} status=`Declined`, responded_at set; applicant still in "Offer" stage; expiry jobs cancelled; a new offer may be generated.

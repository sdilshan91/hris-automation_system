# TC-REC-003-16: Board + detail tolerate a corrupt applicant `rejection_reason` (ISSUE-316 — completes the ISSUE-231 board hardening)

## 1. Test Objective
Verify that a `rejection_reason` string outside the `RejectionReason` enum does **not** 500 the pipeline board or the applicant detail timeline. The board materializes the whole `Applicant` entity (incl. `rejection_reason`), and the detail timeline reads `applicant_stage_history.rejection_reason` — both were left strict by PR #348, so a corrupt value still 500'd them. Now read through the tolerant converter → the `Unknown` sentinel. Regression for ISSUE-316 (the residual of ISSUE-231).

## 2. Related Requirements
- User Story: US-REC-003 (board), US-REC-004 (rejection reason)
- Finding: ISSUE-316 / DF-11 (PR #351); residual of ISSUE-231 (PR #348)
- Root cause: `RejectionReason` (a separate **nullable** enum) kept strict `.HasConversion<string>()`

## 3. Preconditions
- Real PostgreSQL (Testcontainers `postgres:17-alpine`), migrations applied. Postgres-only (raw SQL is the only way to plant an out-of-enum string).

## 4. Test Data
| Row | Column | Value |
|-----|--------|-------|
| applicant | `rejection_reason` | `'HeadcountFrozen'` (raw-SQL, out-of-enum) |
| applicant_stage_history | `rejection_reason` | `'HeadcountFrozen'` (raw-SQL, out-of-enum) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed a vacancy + applicant; raw-SQL corrupt `applicant.rejection_reason`. | — |
| 2 | Call the real `ApplicantService.GetPipelineBoardAsync`. | `IsSuccess == true` (200, not 500). |
| 3 | Seed a stage-history row (real applicant parent); raw-SQL corrupt its `rejection_reason`. | — |
| 4 | Materialize the history rows (the detail-timeline read). | No throw; the row's `RejectionReason == Unknown`. |

## 6. Postconditions
- Board + detail available despite the corrupt row; nullable `rejection_reason` stays null when null, `Unknown` when corrupt.

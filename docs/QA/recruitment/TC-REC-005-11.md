# TC-REC-005-11: Authorization -- schedule/edit/cancel require Recruitment.Manage.All; other roles get 403; rich-text notes sanitized (BR-1, NFR security)

## 1. Test Objective
Verify BR-1: only users with `Recruitment.Manage.All` may create, edit (reschedule), or cancel an interview; users without it (e.g. Recruitment.Read.All only, or a non-recruiter employee) receive 403 and cannot mutate. Read-only viewing of the calendar follows the module's read permission. Also verify the rich-text "notes for interviewers" field is sanitized (anti-XSS) before persistence/rendering, and authz is enforced server-side regardless of UI state.

## 2. Related Requirements
- User Story: US-REC-005
- Acceptance Criteria: AC-1, AC-3
- Business Rules: BR-1 (Manage required to schedule/edit/cancel)
- Non-Functional Requirements: NFR-6 (validation) + platform XSS sanitization
- Security: authz + input sanitization

## 3. Preconditions
- Tenant acme with: {managerUser} (Recruitment.Manage.All), {readerUser} (Recruitment.Read.All only), {plainUser} (no recruitment permission).
- A Scheduled interview {interviewId} exists for edit/cancel tests.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Manage user | manager@acme | Can schedule/edit/cancel |
| Reader user | reader@acme | Read only -> 403 on mutate |
| Plain user | employee@acme | No perm -> 403 |
| XSS payload (notes) | `<script>alert(1)</script>` | Must be sanitized/escaped |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As {readerUser}, POST create an interview | 403 Forbidden; nothing persisted (BR-1). |
| 2 | As {readerUser}, PATCH reschedule {interviewId} and POST cancel | 403 on both; the interview is unchanged (BR-1). |
| 3 | As {plainUser}, attempt any schedule/edit/cancel | 403 on all (BR-1). |
| 4 | As {managerUser}, perform create/edit/cancel | All succeed (positive control). |
| 5 | As {readerUser}, view the interview calendar | Allowed per read permission; no mutate actions exposed. |
| 6 | As {managerUser}, submit notes containing `<script>...</script>` | The payload is sanitized/escaped on storage + render; no script executes when the notes are displayed (anti-XSS). |

## 6. Postconditions
- Only Manage users can schedule/edit/cancel; read-only and non-recruitment users are blocked at the API; rich-text notes are XSS-safe.

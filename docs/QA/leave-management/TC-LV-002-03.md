# TC-LV-002-03: Real-Postgres coverage for the leave-entitlement ledger balance — the current balance is the latest entry by `OccurredAt` (not insertion order), proving the `ORDER BY` translates and is load-bearing — US-LV-002 (DF-3/BUG-118)

## 1. Test Objective
Prove on **real Postgres** that `LeaveEntitlementService.GetLedgerBalanceAsync` resolves the current balance as the **latest ledger entry by `OccurredAt`** (`OrderByDescending(OccurredAt).ThenByDescending(CreatedAt)`), not by insertion/heap order. This is the InMemory-masks-Postgres money-ordering class (BUG-118): InMemory may return insertion order and hide a dropped/incorrect `ORDER BY`; on Postgres a query with no `ORDER BY` is heap-order, so the sort must be present and translate.

## 2. Related Requirements
- User Story: US-LV-002 (leave entitlement / balances)
- Findings: DF-3 (Testcontainers arms for the InMemory-only money paths), BUG-118 (entitlement recalc + `GetLedgerBalanceAsync` ordering)

## 3. Preconditions
- `postgres:17-alpine` Testcontainer, migrated; the real `LeaveEntitlementService`/DbContext.

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed 3 `LeaveLedger` rows whose INSERTION order disagrees with `OccurredAt` order (the `OccurredAt`-latest row is inserted second, not last); compute the effective entitlement. | `CurrentBalance == 17` (the `OccurredAt`-latest `BalanceAfter`). A dropped `ORDER BY` would return insertion/heap order (`15`) → the sort is load-bearing. `LedgerBalance_IsLatestByOccurredAt_NotInsertionOrder_OnPostgres`. |

## 5. Postconditions
- The ledger balance is the `OccurredAt`-latest entry, proven on the real provider where heap order ≠ effective order.

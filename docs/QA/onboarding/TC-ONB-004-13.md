# TC-ONB-004-13: Asset issuance persists issue_date on real Postgres (BUG-290 — .Date Kind=Unspecified → timestamptz)

## 1. Test Objective
Verify that issuing an asset to an employee persists `asset.IssueDate` on **real PostgreSQL**. `IssueDate` is written to a `timestamptz` column from a `.Date` (Kind=Unspecified) input, which Npgsql rejects — the write used to throw on Postgres (InMemory hid it). The `SpecifyKind(…, Utc)` fix makes it valid. Regression for BUG-290 (Asset site).

## 2. Related Requirements
- User Story: US-ONB-004 (Asset Issuance Tracking During Onboarding)
- Finding: BUG-290 (PR #345), `AssetService.IssueAsync` → `issue_date`
- Class: `.Date`(Unspecified) → timestamptz write

## 3. Preconditions
- Real PostgreSQL (Testcontainers `postgres:17-alpine`), migrations applied. Postgres-only (InMemory ignores Kind).
- An employee to issue the asset to.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| `IssueDate` | `new DateTime(2026,7,1)` — **Kind=Unspecified** | past/today (the `IssueDate > today` guard); Unspecified so the mutant is caught. |
| AssetId | null | a new asset is created inline |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Seed an employee. | — |

## 6. Postconditions

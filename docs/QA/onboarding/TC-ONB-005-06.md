# TC-ONB-005-06: Completion effects — session revocation (old JWT -> 401 via account deactivation) and irreversibility

## 1. Test Objective
Verify FR-7 and BR-6: upon offboarding completion the departing employee's active sessions are revoked so that a previously-issued JWT no longer authorizes requests (401), and the offboarding completion is irreversible — the employee record cannot be reactivated.

## 2. Related Requirements
- User Story: US-ONB-005
- Functional Requirements: FR-7 (session revocation), FR-5 (account deactivation)
- Business Rules: BR-6 (irreversible)

## 3. Preconditions
- Employee E300 has an active user account and a currently-valid JWT (issued before completion).
- Offboarding instance for E300 has all mandatory tasks approved.
- HR Officer authenticated with `Offboarding.Manage`.

> PLATFORM NOTE: The story (FR-7 / S10) specifies session revocation via SignalR disconnect + a Redis JWT denylist. A Redis token denylist is NOT yet wired in this platform (same deferral family as prior modules). This test asserts the revocation effect that IS in force today: the user account is DEACTIVATED, so token validation / any per-request active-account check rejects the old token. If a Redis denylist later lands, step 3 also asserts denylist hit. Flag the Redis denylist as a CONDITIONAL/deferred extension to the caller.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| employee_id | E300 | being offboarded |
| old_jwt | (captured pre-completion) | still within its exp window |
| protected endpoint | GET /api/v1/employees/me | requires auth |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Before completion, call a protected endpoint with old_jwt | 200 — token is currently valid. |
| 2 | HR clicks "Complete Offboarding" and confirms | 200; account deactivated; revocation initiated (FR-5, FR-7). |
| 3 | Re-call the same protected endpoint with the SAME old_jwt | 401 Unauthorized — the deactivated account fails the active-account check (FR-7). (CONDITIONAL: if Redis denylist wired, the token is also denylisted.) |
| 4 | Attempt a fresh login as the offboarded employee | Denied — account deactivated (FR-5). |
| 5 | Attempt to "reactivate"/reverse the completed offboarding via API/UI | Rejected; no reactivation path exists; rehire requires a NEW employee record (BR-6). |

## 6. Postconditions
- Old JWT no longer authorizes requests; employee cannot log in; offboarding completion is permanent.

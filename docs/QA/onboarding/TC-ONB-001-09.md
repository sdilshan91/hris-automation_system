# TC-ONB-001-09: Clone an existing template (FR-6)

## 1. Test Objective
Verify FR-6: cloning an existing template creates a NEW template (new `template_id`) with all tasks duplicated, pre-filled in the form with "(Copy)" appended to the name, scoped to the same tenant, with fresh audit columns. The clone is independent — editing it does not mutate the source.

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-2
- Functional Requirements: FR-6, FR-3, FR-5, FR-8
- Business Rules: BR-1 (clone name must still be unique)

## 3. Preconditions
- HR Officer authenticated in tenant `acme` with `Onboarding.Manage`.
- A source template "Standard Engineer Onboarding" with 8 tasks across 3 categories exists in tenant `acme`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Source template | Standard Engineer Onboarding (8 tasks) | existing |
| Cloned name (pre-filled) | Standard Engineer Onboarding (Copy) | "(Copy)" appended |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | In the template list, click "Clone" on the source template | A pre-filled builder opens; name shows "Standard Engineer Onboarding (Copy)"; all 8 tasks across all 3 categories are present with their fields and order. |
| 2 | Save the clone | Response 201 Created with a NEW `template_id` distinct from the source. |
| 3 | Inspect the cloned template + tasks | 8 task rows duplicated (new task ids), same titles/categories/responsible/offsets/mandatory/sort_order; same `tenant_id`; fresh `created_at`/`created_by` (FR-8). |
| 4 | Edit a task in the clone and save; re-read the SOURCE template | The source template's tasks are unchanged — the clone is fully independent. |
| 5 | Attempt to clone again WITHOUT changing the "(Copy)" name (now a duplicate) | Rejected with the duplicate-name error (BR-1) — confirms clones still obey per-tenant name uniqueness. |

## 6. Postconditions
- A second, independent template exists in tenant `acme`; the source is unmodified.

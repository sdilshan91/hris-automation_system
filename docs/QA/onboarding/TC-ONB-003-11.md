# TC-ONB-003-11: Checklist load API <= 500 ms P95

## 1. Test Objective
Verify NFR-1: the personalized checklist load API responds within 500 ms at the 95th percentile under representative load and data volume.

## 2. Related Requirements
- User Story: US-ONB-003
- Acceptance Criteria: AC-1, AC-2
- Non-Functional Requirements: NFR-1

> PLATFORM NOTE: NFR-1 (<= 500 ms P95) must be measured in a performance-representative environment (prod-like DB, realistic checklist sizes, warmed caches). On a dev box, record indicative numbers and flag the environment caveat — do NOT relax the 500 ms threshold to pass.

## 3. Preconditions
- Tenant `acme` seeded with realistic data (e.g. checklists of ~20-40 tasks across categories, many employees).
- Employee authenticated; load-test tooling available (k6/JMeter); query indexes present.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| endpoint | GET /api/v1/onboarding/checklist (employee self) | read path |
| load profile | sustained concurrent reads | representative |
| SLA | P95 <= 500 ms | NFR-1 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Warm caches; run a sustained read load against the checklist endpoint | Requests succeed (200) with tenant-scoped, employee-scoped results. |
| 2 | Capture the latency distribution | P95 response time <= 500 ms (NFR-1). |
| 3 | Inspect query plans for the checklist read | Tenant filter + employee filter use indexes; no full scans degrading P95. |
| 4 | Record environment context | Note hardware/DB sizing; if not prod-representative, flag indicative-only and do NOT relax the threshold. |

## 6. Postconditions
- Checklist load P95 meets the 500 ms SLA (or indicative numbers recorded with an environment caveat).

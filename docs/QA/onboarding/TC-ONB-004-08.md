# TC-ONB-004-08: Employee self-service — assets/me read-only; employee cannot issue/modify

## 1. Test Objective
Verify AC-4 and BR-6: an employee can view the list of assets currently assigned to them (type, serial number, issue date, condition) via the self-service "Assets" tab, but the view is strictly read-only — the employee cannot issue, reassign, or modify any asset record.

## 2. Related Requirements
- User Story: US-ONB-004
- Acceptance Criteria: AC-4
- Business Rules: BR-6 (self-service view is read-only)

## 3. Preconditions
- Employee "Mia Chen" (E200) authenticated in tenant `acme`, holding assigned assets LAP-001 and IDC-001.
- The employee role does NOT have `Onboarding.Manage`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| self endpoint | GET /api/v1/onboarding/assets/me | read-only |
| assigned assets | LAP-001 (Laptop), IDC-001 (ID Card) | linked to E200 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As E200, open the profile "Assets" tab (GET assets/me) | 200; list shows LAP-001 and IDC-001 with type, serial number, issue date, condition (AC-4). |
| 2 | Verify only the employee's own assets are returned | No assets belonging to other employees appear; results are scoped to E200. |
| 3 | Confirm the UI exposes no issue/edit/return controls | View is read-only; no "Issue Asset" / edit / reassign actions available to the employee (BR-6). |
| 4 | As E200, attempt to POST an asset issuance directly to the API | 403 Forbidden — employee lacks `Onboarding.Manage`; no record created (BR-6). |
| 5 | As E200, attempt to PATCH/modify an existing asset record directly | 403 Forbidden — modification denied; asset unchanged (BR-6). |

## 6. Postconditions
- E200 can read but cannot mutate any asset record; no asset created or modified by the employee.

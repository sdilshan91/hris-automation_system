# TC-ONB-001-01: Create checklist template with multiple categories and tasks (happy path)

## 1. Test Objective
Verify the primary success flow of AC-1 and AC-2: an authenticated HR Officer with `Onboarding.Manage` opens the template builder, enters template metadata, adds multiple tasks grouped into multiple categories, marks some mandatory, and saves. The template and all nested tasks persist with the correct `tenant_id` (from session context, never user input — FR-5) and auto-populated audit columns (FR-8).

## 2. Related Requirements
- User Story: US-ONB-001
- Acceptance Criteria: AC-1, AC-2, AC-4
- Functional Requirements: FR-1, FR-2, FR-3, FR-4, FR-5, FR-8
- Business Rules: BR-2, BR-3
- Data Requirements: onboarding_template + nested onboarding_template_task

## 3. Preconditions
- HR Officer "Maya Cole" is authenticated within tenant `acme` (subdomain resolved) with the `Onboarding.Manage` permission.
- The Onboarding/Offboarding module is enabled for the tenant's subscription plan.
- At least one department and one job title exist in tenant `acme`.
- No template named "Standard Engineer Onboarding" currently exists in tenant `acme`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| template_name | Standard Engineer Onboarding | 28 chars, unique per tenant |
| description | Onboarding for all engineering hires | optional |
| applicable_departments | [Engineering] | must exist in tenant |
| applicable_job_titles | [Software Engineer] | must exist in tenant |
| is_active | true | default |
| Category 1 | Documentation | 3 tasks |
| Category 2 | IT Setup | 3 tasks |
| Category 3 | Training | 2 tasks |
| Task example | "Sign NDA" / category Documentation / responsible HR / due_offset_days 0 / mandatory true / sort_order 0 | per FR-3 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to the Onboarding module and click "Create Checklist Template" | A form opens with fields: template name, description, applicable department(s), applicable job title(s), and a task-list builder (AC-1). |
| 2 | Enter template_name, description, select departments and job titles | Fields accept input; floating-label Material inputs render; no validation errors. |
| 3 | Add 3 categories (Documentation, IT Setup, Training) and a total of 8 tasks; for each task set title, description, category, responsible party, due_offset_days, mandatory flag, sort_order; mark 3 tasks mandatory | Tasks render as cards within their category groups; mandatory tasks show a mandatory indicator (AC-4). |
| 4 | Click Save; observe `POST /api/v1/onboarding/templates` | Request carries the `acme` tenant bearer; response 201 Created with body `{ template_id, template_name, is_active: true, tasks: [...8] }`. |
| 5 | Inspect the persisted `onboarding_template` row | One row: `template_name = "Standard Engineer Onboarding"`, `is_active = true`, `tenant_id` = acme's tenant id set from session context (FR-5), audit columns `created_at`/`created_by` populated automatically (FR-8). |
| 6 | Inspect the persisted task rows | 8 task rows, each with title, description, category, responsible party, `due_offset_days`, `is_mandatory`, `sort_order`; the 3 mandatory tasks have `is_mandatory = true` (AC-4); all carry the same `tenant_id`. |
| 7 | Return to the template list | "Standard Engineer Onboarding" appears with status Active and the correct creation timestamp. |

## 6. Postconditions
- A tenant-scoped active onboarding template with 3 categories and 8 tasks exists in tenant `acme` with correct `tenant_id` and audit metadata; no rows written for any other tenant.

# TC-ONB-002-14: The assign-checklist endpoint resolves the idempotency key as header-then-body (the `Idempotency-Key` header wins; a blank header falls back to the body key) — US-ONB-002 NFR-5 (DF-10)

## 1. Test Objective
Verify `OnboardingChecklistsController.Assign`'s idempotency-key precedence (NFR-5): the `Idempotency-Key` **header** takes precedence over the request-body `IdempotencyKey`, and a missing/blank/whitespace header falls back to the body key (`string.IsNullOrWhiteSpace(headerKey) ? body : header`). Previously untested — a mutation swapping the precedence would have survived (DF-10).

## 2. Related Requirements
- User Story: US-ONB-002 (assign onboarding checklist)
- Non-Functional: NFR-5 (idempotent retry via `Idempotency-Key`)
- Findings: DF-10 (no test on the header-vs-body precedence)

## 3. Preconditions
- Controller-level unit test with a substituted `IMediator`; the dispatched `AssignChecklistCommand` is captured (mediator stubbed to a failure result so the action short-circuits without `HttpContext`).

## 4. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Header `"HEADER-KEY"` + body `"BODY-KEY"`. | Dispatched command carries `IdempotencyKey == "HEADER-KEY"` (header wins). `Assign_HeaderKeyPresent_WinsOverBodyKey`. |
| 2 | Header `null` / `""` / `"   "` + body `"BODY-KEY"`. | Command carries `"BODY-KEY"` (fallback). `Assign_HeaderKeyBlank_FallsBackToBodyKey`. |
| 3 | Header `"HEADER-KEY"` + body `null`. | Command carries `"HEADER-KEY"`. `Assign_OnlyHeaderKey_FlowsThrough`. |

## 5. Postconditions
- The precedence is pinned: a header key always wins over a body key; a blank header defers to the body.

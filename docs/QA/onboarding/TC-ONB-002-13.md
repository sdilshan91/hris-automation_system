# TC-ONB-002-13: Assigning an onboarding checklist persists start/due dates on real Postgres (BUG-289 — .Date Kind=Unspecified → timestamptz)

## 1. Test Objective
Verify that assigning an onboarding checklist to a new hire persists `instance.StartDate` and each task's `DueDate` on **real PostgreSQL**. These are derived via `.Date` (Kind=Unspecified) and written to `timestamptz` columns, which Npgsql rejects — so the assign `SaveChanges` used to throw on Postgres (the InMemory suite ignores DateTimeKind and hid it). The `UtcMidnight` fix makes the write valid. Regression for BUG-289.

## 2. Related Requirements
- User Story: US-ONB-002 (Assign Onboarding Checklist to New Hire)
- Finding: BUG-289 (PR #344)
- Class: `.Date`(Unspecified) → timestamptz write (InMemory-masks-Postgres)

## 3. Preconditions
- Real PostgreSQL (Testcontainers `postgres:17-alpine`), migrations applied. Postgres-only — the InMemory provider ignores DateTimeKind, so it cannot reproduce this.
- An employee with a **FUTURE joining date** so `startDate` comes from `DateOfJoining` (exercises the primary write site, not the `today` fallback).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| `DateOfJoining` | `new DateTime(2026,12,1)` — **Kind=Unspecified** | ⚠ MUST be Unspecified: `DateTime.Date` PRESERVES Kind, so a Utc seed makes the mutant survive (green theater). |

## 5. Test Steps
| Step | Action | Expected Result |

# TC-ONB-003-08: Mandatory gating — all optional tasks done but one mandatory left -> checklist not "fully complete"

## 1. Test Objective
Verify BR-2: the onboarding checklist cannot be marked "fully complete" while any mandatory task remains incomplete, even if every optional task is completed. Once the last mandatory task is completed, the checklist reaches "fully complete".

## 2. Related Requirements
- User Story: US-ONB-003
- Acceptance Criteria: AC-3
- Functional Requirements: FR-4
- Business Rules: BR-2

## 3. Preconditions
- Employee "Alex Reed" authenticated in tenant `acme`.
- Checklist of 4 Employee tasks: 2 optional, 2 mandatory ("Submit ID proof", "Sign code of conduct").

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| optional tasks | 2 | completed in step 1 |
| mandatory tasks | 2 | one left incomplete in step 2 |
| expected state mid-test | not fully complete | per BR-2 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Complete both optional tasks and one mandatory task | Progress reflects 3/4 (75%); checklist status is NOT "fully complete" (BR-2). |
| 2 | Query the checklist "fully complete" flag | False — one mandatory task still pending (BR-2); no 100%/completion celebration triggered. |
| 3 | Complete the remaining mandatory task | Progress = 100%; checklist now flagged "fully complete" (BR-2, FR-4). |
| 4 | Verify completion side effects | Fully-complete state recorded; success UI (e.g. confetti/100% ring) shown; audit reflects all completions. |
| 5 | Boundary: a checklist with 0 mandatory tasks, all optional done | Reaches "fully complete" at 100% optional completion (BR-2 boundary — mandatory set empty). |

## 6. Postconditions
- Checklist only flips to "fully complete" after all mandatory tasks are done; optional-only completion does not satisfy the gate.

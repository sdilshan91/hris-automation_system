# Test-Execution Status Tracker

> Single source of truth used by `/test-all` to find the next **implemented** user story to test.
> Companion to `TEST-FINDINGS.md` (the bugs/issues/enhancements ledger). Safe to hand-edit.
>
> **This loop is REPORT-ONLY** — `/test-all` and `/test-us` execute test cases and log findings; they
> never fix code and never open PRs. Fixing is a separate, human-decided step.
>
> **Statuses:**
> - `[ ]` not-tested — no execution recorded yet
> - `[~]` testing — execution in progress
> - `[x]` tested-clean — all TCs passed, 0 findings
> - `[!]` tested-findings — executed; ≥1 finding logged in TEST-FINDINGS.md (list the IDs)
> - `[b]` blocked — could not execute (stack down, missing seed/dep, tooling not wired)
> - `[s]` skipped — won't be tested (note why)
>
> **Loop convention:** `/test-all` picks the **first `[ ]`** story (scoped by module arg, else priority
> order). Only **implemented** stories (`[x]` in `docs/BA/STATUS.md`) appear here. After a fix lands
> (elsewhere), move the story back to `[ ]` to schedule a re-test.

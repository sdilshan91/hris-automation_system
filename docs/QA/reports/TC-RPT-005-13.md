# TC-RPT-005-13: Upcoming-birthdays dashboard widget is backed by a SQL-translatable recurring-window index (month*100+day) — window include/exclude, year-end wrap, Feb-29 fallback, status filter, and the BirthMonthDay interceptor keeps the key in sync on create/update/clear — US-RPT-005 AC-1 / BR-4 (ISSUE-285a)

## 1. Test Objective
Verify the ISSUE-285(a) index-backed "Upcoming Birthdays" widget on the US-RPT-005 dashboard (AC-1). The recurring-window projection is computed as SQL-translatable integer keys `month*100 + day` via `DashboardService.BuildRecurringWindowKeys(today, days)`: a mid-year window is emitted **inclusively** (e.g. Jun 17 → 617..624 for the next 7 days), a window crossing the year boundary **wraps** (Dec 30 → 1230,1231,101..106), and a non-leap window spanning Feb-28 also emits **229** (so a Feb-29 birthday projected onto Feb-28 still matches the index) while a leap-year window emits 229 exactly once. End-to-end, the widget includes birthdays inside the window and excludes those outside (8th day, already-passed, null DOB), wraps the year-end correctly, and **filters by employee status** (Active + Probation included; Terminated + Suspended excluded). The `Employee.BirthMonthDay` index key is maintained by `EmployeeBirthMonthDayInterceptor`, which sets it on create, recomputes it when DOB changes, and nulls it when DOB is cleared.

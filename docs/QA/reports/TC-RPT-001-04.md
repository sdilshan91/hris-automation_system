# TC-RPT-001-04: Active-status classification per BR-4 (active|probation = active; terminated|resigned|contract_ended = separated)

## 1. Test Objective
Verify that every report which classifies employees as active vs separated applies BR-4 exactly:
status `active` OR `probation` counts as ACTIVE; `terminated`, `resigned`, AND `contract_ended`
count as SEPARATED. No status is silently dropped or miscounted. Validates BR-4 against AC-2
(headcount active/inactive) and AC-3 (separations).

## 2. Related Requirements
- User Story: US-RPT-001
- Acceptance Criteria: AC-2, AC-3
- Business Rules: BR-4 (status classification)

## 3. Preconditions
- Tenant A active; `hr1` authenticated with `Reports.View.All`.
- Seed exactly one employee in each status bucket plus duplicates to make counts distinguishable:
  e.g. 5 `active`, 3 `probation`, 2 `terminated`, 4 `resigned`, 1 `contract_ended`
  -> ACTIVE = 8, SEPARATED = 7, total population = 15.

## 4. Test Data
| Field | Value | Expected classification |
|-------|-------|-------------------------|
| status=active (x5) | active | ACTIVE |
| status=probation (x3) | probation | ACTIVE |
| status=terminated (x2) | terminated | SEPARATED |
| status=resigned (x4) | resigned | SEPARATED |
| status=contract_ended (x1) | contract_ended | SEPARATED |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Generate Headcount Summary (no date/department filter beyond defaults covering the seed) | Active count = 8 (5 active + 3 probation); inactive/separated = 7 |
| 2 | Confirm probation employees are NOT counted as inactive | Probation rolls into ACTIVE, not inactive |
| 3 | Generate Employee Turnover over the period containing the separations | Separations = 7 (terminated 2 + resigned 4 + contract_ended 1) |
| 4 | Confirm `contract_ended` is included as a separation | contract_ended counted as separated, not ignored |
| 5 | Apply employee_status filter = [active] | Only the 5 active appear; probation excluded by the explicit filter (filter is independent of BR-4 roll-up) |
| 6 | Apply employee_status filter = [active, probation] | The 8 active-by-BR-4 employees appear |

## 6. Postconditions
- BR-4 classification verified across headcount and turnover; explicit status filter behaves independently.

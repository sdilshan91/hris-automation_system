# TC-RPT-005-06: Role is derived server-side; role-based widget visibility enforced -- a client cannot request another role's dashboard (AC-1/2/3, FR-1/8, BR-1)

## 1. Test Objective
Verify that the dashboard `role` is derived SERVER-SIDE from the authenticated user's role (never trusted
from the client) and that widget visibility is strictly role-based: an Employee cannot obtain HR/organization
widgets, and a Manager cannot obtain tenant-wide HR widgets, even by tampering with the request. Validates
AC-1, AC-2, AC-3, FR-1, FR-8, BR-1.

## 2. Related Requirements
- User Story: US-RPT-005
- Acceptance Criteria: AC-1, AC-2, AC-3
- Functional Requirements: FR-1 (role-based dashboards), FR-8 (scoped by role-based permissions)
- Business Rules: BR-1 (role-based widget visibility)

## 3. Preconditions
- Tenant A active with `hr1` (HR Officer), `mgr1` (Manager), `emp1` (Employee) all authenticated.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| HR-only widgets | headcount, open_positions, turnover_rate | organizational |
| Employee-only widgets | leave_balance, attendance_this_month | personal |
| tampered query | ?role=hr (as emp1) | must be ignored |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As `emp1`, `GET /api/v1/dashboard/widgets` | `role:"employee"`; ONLY personal widgets returned; NO headcount/open_positions/turnover_rate (BR-1) |
| 2 | As `emp1`, attempt `GET /api/v1/dashboard/widgets?role=hr` (tamper) | server ignores the param; `role` is still `"employee"`; HR widgets are NOT returned (FR-1, server-derived) |
| 3 | As `mgr1`, `GET /api/v1/dashboard/widgets` | `role:"manager"`; team widgets only; NO tenant-wide HR organizational widgets (BR-1) |
| 4 | As `hr1`, `GET /api/v1/dashboard/widgets` | `role:"hr"`; organizational widget set returned (AC-1) |
| 5 | Cross-check `emp1` vs `hr1` widget sets | disjoint where role-specific; an employee never sees organization-level KPI values (BR-1) |
| 6 | Confirm role derivation source | `role` derives from the user's assigned role/permissions in the session, not from any request header/body/query (FR-8) |

## 6. Postconditions
- Each user receives only the widget set permitted by their server-derived role; no role escalation possible.

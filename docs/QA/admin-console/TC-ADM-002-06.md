# TC-ADM-002-06: Hangfire background-job counts surfaced cross-tenant (queued/processing/succeeded/failed)

## 1. Test Objective
Verify AC-1 / FR-5: the dashboard shows a cross-tenant Hangfire job-status view with queued, processing, succeeded, and failed counts that match Hangfire storage, and that the failed count drilldown is available.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-1
- Functional Requirements: FR-5
- Data Source: Hangfire storage (PostgreSQL-backed)

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- Hangfire storage seeded with a known job mix, including at least one failed job.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Queued | 3 | enqueued, not started |
| Processing | 1 | in-flight |
| Succeeded | 120 | completed |
| Failed | 2 | for drilldown |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Load the Monitoring dashboard; locate the Hangfire job-status card | Card shows queued 3, processing 1, succeeded 120, failed 2. |
| 2 | Reconcile against Hangfire storage (or `/hangfire` dashboard) | The four counts match Hangfire's own figures exactly (FR-5). |
| 3 | Click the failed count to drill in | A list of the 2 failed jobs is shown (job type, last error, tenant where applicable) — the FR-5 "drill into failed jobs" capability. |
| 4 | Verify the view is cross-tenant for the System Admin | Counts aggregate jobs across all tenants (system context), not a single tenant. |

## 6. Postconditions
- Hangfire counts reconcile with storage; failed-job drilldown works.

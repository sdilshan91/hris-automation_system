# TC-ADM-009-06: enabled_modules validated against the canonical module list; CoreHR always enabled

## 1. Test Objective
Verify FR-6: `enabled_modules` entries must reference the canonical module list (CoreHR, Leave, Attendance, Recruitment, Onboarding, Payroll, Performance, Training, Asset, Benefits, Reporting, CustomReportBuilder, PublicCareersPage). An unknown module value is rejected. CoreHR is always enabled regardless of the submitted set.

> NOTE (DEFERRED scope): this TC asserts the STORAGE/VALIDATION of `enabled_modules` and the CoreHR-always rule. The RUNTIME ENFORCEMENT that actually gates a disabled module's API endpoints and Angular routes per tenant (BR-6) is a large cross-cutting concern deferred to TC-ADM-009-14.

## 2. Related Requirements
- User Story: US-ADM-009
- Functional Requirements: FR-6 (enabled_modules canonical list; CoreHR always enabled)
- Business Rules: BR-6 (module entitlements — runtime gating deferred, see TC-ADM-009-14)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| valid set | ["Leave","Attendance","Reporting"] | CoreHR auto-added |
| unknown module | ["Leave","TimeTravel"] | rejected |
| empty set | [] | CoreHR still enabled |
| canonical list | CoreHR, Leave, Attendance, Recruitment, Onboarding, Payroll, Performance, Training, Asset, Benefits, Reporting, CustomReportBuilder, PublicCareersPage | reference |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | POST create a plan with enabled_modules=["Leave","Attendance","Reporting"] | 201; persisted enabled_modules includes those modules AND CoreHR (always enabled). |
| 2 | POST create a plan with enabled_modules=["Leave","TimeTravel"] | 400 — validation error: "TimeTravel" is not a canonical module; no plan created. |
| 3 | POST create a plan with enabled_modules=[] | 201; persisted enabled_modules contains at least CoreHR (always enabled per FR-6). |
| 4 | Update an existing plan to remove CoreHR | CoreHR remains enabled (cannot be disabled). |
| 5 | Verify each canonical module value is accepted | All 13 canonical names accepted when used; only non-canonical values rejected. |

## 6. Postconditions
- Only canonical modules stored; CoreHR always present.

# TC-ADM-001-09: Newly provisioned tenant is isolated; cross-tenant ID injection returns 404 (not 403)

## 1. Test Objective
Verify AC-6 and the Test Hints: immediately after Tenant A is provisioned, its owner authenticating at `A.yourhrm.com` can operate only within A's data. A direct cross-tenant ID-injection request (requesting a Tenant B resource by id while authenticated as A) returns **404 Not Found**, not 403 — so the API does not confirm the existence of another tenant's record. Isolation is enforced by the platform's EF Core global query filters + `TenantInterceptor`.

> Platform accuracy note: this codebase enforces tenant isolation through EF Core global query filters (read) and the `TenantInterceptor` (write stamping), NOT PostgreSQL RLS. AC-6/FR-6 reference RLS + `app.current_tenant_id`; that is a deferred extension point. This test asserts the EF query-filter mechanism. See TC-ADM-ISO-003 for the query-filter-specific test.

## 2. Related Requirements
- User Story: US-ADM-001
- Acceptance Criteria: AC-6
- Functional Requirements: FR-6 (asserted via EF query filters; RLS deferred)
- Test Hints: tenant isolation, cross-tenant ID injection -> 404 not 403

## 3. Preconditions
- Tenant A (`alpha`) is freshly provisioned via TC-ADM-001-01 with owner `owner@alpha.com`.
- Tenant B (`beta`) exists with at least one known resource (e.g. an employee with id `EMP-B-1`).
- The owner of A has set a password and obtained a valid A-scoped JWT.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Auth context | owner@alpha.com (tenant alpha) | resolves at alpha.yourhrm.com |
| Target resource | Tenant B employee id EMP-B-1 | belongs to beta |
| Tenant resolution header (dev) | X-Tenant-Subdomain: alpha | mirrors subdomain |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As the alpha owner, call a list endpoint (e.g. `GET /api/v1/employees`) at `alpha.yourhrm.com` | Returns only alpha's data (the seeded owner / empty employee set); zero beta rows. The EF global query filter scopes the query to `TenantId == alpha`. |
| 2 | Inject a beta resource id: `GET /api/v1/employees/EMP-B-1` while authenticated as alpha | Returns **404 Not Found**, NOT 403. The query filter excludes beta rows so the record is invisible (existence not disclosed). |
| 3 | Attempt the same id via a PUT/PATCH (`/api/v1/employees/EMP-B-1`) as alpha | 404 Not Found; no beta row is read or mutated. |
| 4 | Verify from B's side | Authenticating as a beta user, `EMP-B-1` is still present and unchanged — confirming the alpha request never touched it. |

## 6. Postconditions
- Tenant A cannot read or mutate Tenant B data; cross-tenant lookups yield 404, never 403 or B's data.

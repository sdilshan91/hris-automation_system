# TC-ADM-004-01: Suspend an active tenant — status, suspended_at/reason, sessions revoked, 451, lifecycle event + audit, notification dispatched (happy path)

> **⚠ GAP-L6 / 2026-08-10 — status demoted to `draft`; the recorded `pass` was against an UNEXECUTABLE step.**
> A test step below queries **`system_audit_log`**, a table this platform deliberately does not have
> (`information_schema` returns zero rows; `IAuditLogPurgeService.cs:6`: *"this platform reuses the single audit
> table with a system action"*). The step's INTENT is satisfiable — a system-scoped row in `audit_logs` with
> `UserId` null — so the expectation has been corrected in place, but the previous verdict was earned against a
> different and impossible expectation and must be re-earned by an actual run (`/test-us`). Compare
> `TC-NTF-004-11`, which handles this correctly with an explicit conditional step.

## 1. Test Objective
Verify the primary success flow of AC-1: a System Admin suspends an `active` tenant with a valid reason. The tenant transitions to `Suspended`, `SuspendedAt` is stamped and `SuspendedReason` stored, ALL tenant refresh tokens are revoked (BR-5), subsequent tenant-user API calls return HTTP 451, a `tenant_lifecycle_event` with `event_type = 'suspended'` plus a `audit_logs` (system-scoped row: `UserId` null) entry are written (FR-7), and a suspension notification is dispatched (log-only seam today — delivery is TC-ADM-004-18).

## 2. Related Requirements
- User Story: US-ADM-004
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1, FR-7
- Business Rules: BR-1 (active -> suspended), BR-5
- Test Hints: Suspend active tenant

## 3. Preconditions
- System Admin "Olivia" is authenticated at `admin.yourhrm.com` with the `SystemAdmin` role.
- Target tenant "Acme" exists, `status = Active`, non-system (`is_system = false`).
- Acme has at least 2 active users with live refresh tokens (one Tenant Admin, one regular Employee).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| tenant_id | acme-tenant-uuid | active, non-system |
| reason | "ToS violation: confirmed spam outbound — ticket SEC-1190" | >= 10 chars |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Olivia, `POST /api/v1/admin/tenants/{id}/suspend` with `{ reason }` | 200/204; success response. |
| 2 | Re-read the tenant record | `status = Suspended`; `SuspendedAt` set to ~now; `SuspendedReason` stored verbatim. |
| 3 | Query `refresh_token` rows for all Acme users | All previously-active tokens are revoked/invalidated (BR-5); user data and configuration rows untouched. |
| 4 | As a previously-logged-in regular Acme user, call any tenant API with the old access/refresh token | Refresh is rejected; tenant-user API access returns HTTP 451 (Unavailable For Legal Reasons). |
| 5 | Query `tenant_lifecycle_event` | One new row: `event_type = 'suspended'`, tenant=Acme, reason captured, actor=Olivia, timestamp set. |
| 6 | Query `audit_logs` (system-scoped row: `UserId` null) | A suspension entry exists (actor=Olivia, tenant=Acme, reason) — FR-7. |
| 7 | Inspect the notification seam (log/outbox) | A suspension notification targeting the tenant billing email + Tenant Admin users is dispatched (log-only today — AC-1; delivery deferred to TC-ADM-004-18). |

## 6. Postconditions
- Acme is `Suspended`; all its sessions are dead; tenant users (except Tenant Admin per AC-2) are blocked with 451; the transition is immutably audited.

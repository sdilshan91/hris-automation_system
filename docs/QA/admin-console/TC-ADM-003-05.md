# TC-ADM-003-05: Destructive operations blocked even for a FULL SystemAdmin impersonation (403)

## 1. Test Objective
Verify FR-6 / FR-3 / AC-2: certain destructive operations are forbidden during ANY impersonation session, including a NON-read-only (`imp_readonly=false`) full `SystemAdmin` impersonation of an active tenant. Change/reset password, role/permission mutation, and delete user/tenant must each return 403. This is independent of the read-only flag — it is a hard block on destructive ops while impersonating.

## 2. Related Requirements
- User Story: US-ADM-003
- Acceptance Criteria: AC-2
- Functional Requirements: FR-3, FR-6
- Business Rules: BR-1
- Test Hints: (derived from FR-6 — destructive ops blocked)

## 3. Preconditions
- Initiator is a full `SystemAdmin`; target tenant "Acme" is `active`; impersonation session is `imp_readonly=false` (full, non-read-only).
- Target user has active membership; benign write Commands ARE allowed in this session (proves the block is destructive-op-specific, not a blanket read-only).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Session mode | full (imp_readonly=false) | not read-only |
| Destructive ops | change-password, reset-password, role mutation, permission mutation, delete-user, delete-tenant | each must 403 |
| Benign write | update employee notes / non-destructive field | should succeed (200) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Start a FULL SystemAdmin impersonation against the Acme target user | 200; `imp_readonly=false`. |
| 2 | With the token, call change-password / reset-password for any tenant user | 403 each — destructive op blocked during impersonation (FR-6), even for a full admin. |
| 3 | Call a role-assignment / permission-mutation Command | 403 — role/permission mutation blocked. |
| 4 | Call delete-user and delete-tenant Commands | 403 each — destructive deletes blocked. |
| 5 | Call a benign, non-destructive write Command | 200 — proves the block is targeted at destructive ops, not all writes (full session). |
| 6 | Verify no destructive mutation persisted | Passwords, roles, permissions, and user/tenant records are unchanged. |

## 6. Postconditions
- Destructive operations are categorically blocked under impersonation; benign writes still work in a full session.

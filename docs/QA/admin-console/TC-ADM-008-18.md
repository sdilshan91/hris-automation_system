# TC-ADM-008-18: [DEFERRED] DB-role append-only immutability (no UPDATE/DELETE grant on audit_log)

## 1. Test Objective
Verify the DB-LAYER portion of AC-5 / NFR-3: the application database role has NO `UPDATE` or `DELETE` privilege on `audit_log`, so a raw SQL `UPDATE`/`DELETE` executed via the app's DB role is denied at the database, and any such attempt is logged as a security event.

DEFERRED — status: blocked. This grant-revocation is a platform-infra hardening step that is NOT in place today. Today the audit log is append-only BY CODE CONVENTION (no update/delete handler — covered run-green in TC-ADM-008-17). Same deferred family as the PostgreSQL RLS deferrals across US-ADM-001..007 / Payroll / Leave. The retention purge (TC-ADM-008-14) intentionally requires a separate privileged path for bulk deletion within the window.

## 2. Related Requirements
- User Story: US-ADM-008
- Acceptance Criteria: AC-5 (append-only; DB role lacks UPDATE/DELETE; tamper logged as security event)
- Non-Functional Requirements: NFR-3 (immutable at DB layer)

## 3. Preconditions
- Audit row A1 exists.
- (Deferred prerequisite) A DB-role migration revokes UPDATE/DELETE on `audit_log` from the application role.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| tamper SQL | `UPDATE audit_log SET action='Tampered' WHERE audit_id=A1` | must be denied |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | (When implemented) Execute the tamper UPDATE via the app DB role | DB denies with insufficient-privilege; row unchanged. (Test Hints — Immutability.) |
| 2 | Execute a DELETE via the app DB role | DB denies; row retained. |
| 3 | Confirm security-event log | The denied attempt is recorded as a security event. |
| 4 | Until implemented | Expected behavior: "Not available — DB-role append-only grant is deferred platform infra; immutability is by code convention today (TC-ADM-008-17)." |

## 6. Postconditions

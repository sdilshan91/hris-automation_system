# TC-ADM-009-10: PlanLimitResolver — non-expired override > plan field; NULL = unlimited; expiry falls back

## 1. Test Objective
Verify AC-5 + FR-4 + BR-3 + the "Limit override" Test Hint, exercising the pure `PlanLimitResolver` and the `plan_limit_override` table. Runtime limit resolution order is: a non-expired `plan_limit_override` for the tenant+limit_key wins over the `subscription_plan` field; a `NULL` value means "unlimited"; an EXPIRED override is ignored and resolution falls back to the plan field. The override is audited.

## 2. Related Requirements
- User Story: US-ADM-009
- Acceptance Criteria: AC-5
- Functional Requirements: FR-4 (override table + resolution order)
- Business Rules: BR-3 (NULL = unlimited)
- Non-Functional Requirements: NFR-3 (override audited)
- Test Hints (Limit override)

## 3. Preconditions
- System Admin "Pat" authenticated at `admin.yourhrm.com` with `SystemAdmin`.
- Plan `starter` has `max_employees=50`. Tenant "Acme" is on `starter`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| plan starter max_employees | 50 | base |
| override (active) | tenant=Acme, limit_key=max_employees, value=200, expires_at=null | wins |
| override (unlimited) | tenant=Acme, limit_key=max_employees, value=NULL | unlimited (BR-3) |
| override (expired) | tenant=Acme, limit_key=max_employees, value=500, expires_at=yesterday | ignored |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Resolve max_employees for Acme with NO override | PlanLimitResolver returns 50 (plan field). |
| 2 | Add override {Acme, max_employees, 200, expires_at=null}; resolve | Returns 200 (non-expired override wins over plan field). Acme can have up to 200 employees (matches Test Hint). |
| 3 | Inspect system audit log | "PlanLimitOverride.Create" entry: actor=Pat, tenant=Acme, key/value/expires, timestamp. |
| 4 | Set override value to NULL; resolve | Returns "unlimited" (BR-3) — no cap enforced for Acme on max_employees. |
| 5 | Replace with an EXPIRED override {value=500, expires_at=yesterday}; resolve | Override ignored; resolver falls back to the plan field (50). |
| 6 | Resolve a DIFFERENT key with no override (e.g. max_workflows) | Falls back to the plan field for that key (override is per limit_key). |

## 6. Postconditions
- Override resolution honors order + expiry + NULL-unlimited; all override mutations audited.

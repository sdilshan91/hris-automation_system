# TC-ADM-002-02: Per-tenant employee usage gauge — 80% warning boundary (max_employees=5, 4 employees)

## 1. Test Objective
Verify the lower quota boundary of AC-2 for the employee usage gauge (the one usage dimension the platform computes FOR REAL). With a plan limit of `max_employees = 5` and 4 active employees, the tenant's employee gauge reads 80% and is highlighted with the amber WARNING indicator, but is NOT flagged as breached.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2 (limit from `tenant`/`subscription_plan`; employee count from DB), FR-3
- Test Hints: max_employees=5, 4 employees -> 80% warning

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com`.
- Tenant "Acme" is on a plan with `max_employees = 5` (the live `Tenant.MaxEmployees` limit field).
- Acme has exactly 4 active employees.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Tenant | acme | usage subject |
| max_employees | 5 | plan limit |
| Active employees | 4 | 4/5 = 80% |
| Expected gauge | 80% | amber band (80-94%) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | On the Monitoring dashboard, search the tenant usage table for "acme" | Acme's row is shown with an inline employee gauge. |
| 2 | Read the employee gauge value | Reads 4 / 5 = 80%. |
| 3 | Read the gauge color/indicator | Amber WARNING band (80-94%); a warning indicator is present. |
| 4 | Check the breach flag | Acme is NOT flagged as breached (breach is reserved for 100%). |
| 5 | Confirm the gauge measures employees only | No storage / API-call / email gauges show real numbers (those are Deferred — see TC-ADM-002-18); only the employee dimension is populated. |

## 6. Postconditions
- Acme renders at 80% with a warning, not a breach. No data mutated.

# TC-ADM-001-04: Every reserved subdomain is rejected

## 1. Test Objective
Verify AC-2 / FR-2: each subdomain in the hardcoded reserved list is rejected with "Subdomain is unavailable" and prevents creation, both at the real-time availability check and on server-side validation. This is a data-driven negative test covering the full reserved set.

## 2. Related Requirements
- User Story: US-ADM-001
- Acceptance Criteria: AC-2
- Functional Requirements: FR-2

## 3. Preconditions
- System Admin authenticated at `admin.yourhrm.com` with the `SystemAdmin` role.
- The reserved list per the story: `www`, `api`, `admin`, `app`, `mail`, `status`, `docs`, `help`, `support`, `static`, `cdn`, `dev`, `stage`, `prod`, `test`, `qa`.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| Reserved subdomain (parameterized) | each of the 16 reserved values | run once per value |
| Other fields | valid | only the subdomain is reserved |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | For each reserved value, type it into the subdomain field and wait for the debounced check | The indicator shows a red X and "Subdomain is unavailable" for every value (FR-2). |
| 2 | Force a server submit for a sample (`admin`, `api`, `www`) bypassing the client check; observe `POST /api/v1/admin/tenants` | Each is rejected server-side with 400 and "Subdomain is unavailable"; no tenant created. Server-side rejection does not rely on the client check alone. |
| 3 | Confirm case-insensitivity of the reserved check (e.g. `API`, `Admin`) | Reserved matching is case-insensitive (also covered by the uppercase-format rejection in TC-ADM-001-05); reserved values in any case are blocked. |

## 6. Postconditions
- No tenant was created for any reserved subdomain.

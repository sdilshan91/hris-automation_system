# TC-ADM-007-04: Edit active workflow creates a NEW VERSION (v2); prior version retained; before/after audited

## 1. Test Objective
Verify AC-3 / FR-3: editing an existing active workflow (e.g. changing Step 1 SLA from 24h to 48h) creates a NEW VERSION (v2) of the workflow definition. The prior version (v1) is RETAINED — in-flight instances would reference the version they were initiated under (the runtime instance routing is DEFERRED engine work; here we assert the DEFINITION/versioning side). New activity uses v2. The edit is audited with before/after state. (Per the Test Hint "Versioning": verify a new version is created; the "in-flight requests still reference the old version" assertion is the deferred-runtime portion, noted below.)

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-3
- Functional Requirements: FR-3 (versioning; in-flight retain original version)
- Non-Functional: NFR-4 (before/after audit)

## 3. Preconditions
- Dana (`TenantAdmin`) authenticated; Acme `active`.
- An active Leave workflow exists at `version = 1` with Step 1 SLA = 24h.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| edit | Step 1 sla_hours: 24 -> 48 | the change |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, PUT/edit the active Leave workflow changing Step 1 SLA to 48h | 200; a NEW version is created with `version = 2` and Step 1 SLA = 48h. |
| 2 | GET the workflow version history | Both v1 (SLA 24h) and v2 (SLA 48h) are present; v2 is the current/active version. |
| 3 | Confirm v1 is retained (not mutated) | v1's Step 1 SLA is still 24h — the prior version is immutable, not overwritten. |
| 4 | Inspect tenant `audit_log` | One entry: action = workflow edited, actor = Dana, BEFORE = v1 snapshot (SLA 24h), AFTER = v2 snapshot (SLA 48h). |
| 5 | (DEFERRED — runtime) In-flight instances initiated under v1 continue to reference v1 | NOT executed here: per-request `WorkflowInstance` creation + version pinning is deferred engine work (see TC-ADM-007-16/-17). The DEFINITION-side guarantee — v1 is retained and resolvable by version — is verified in steps 2-3. |

## 6. Postconditions
- Workflow has v1 (retained) and v2 (active); one before/after audit row.

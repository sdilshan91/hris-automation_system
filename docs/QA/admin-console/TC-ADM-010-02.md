# TC-ADM-010-02: Manifest validation — SHA-256 checksums + row counts match actual files

## 1. Test Objective
Verify AC-2 / FR-6 Test Hint ("Manifest validation"): every `sha256_checksum` recorded in `manifest.json` matches the SHA-256 computed over the actual bytes of the corresponding file in the bundle, and every `row_count` / `file_size_bytes` matches the actual file. This is the integrity contract that proves the bundle was not truncated or corrupted.

## 2. Related Requirements
- User Story: US-ADM-010
- Acceptance Criteria: AC-2
- Functional Requirements: FR-6 (manifest: per-file row_count, file_size_bytes, sha256_checksum)
- Test Hints: "Manifest validation: verify SHA-256 checksums in the manifest match the actual file checksums."

## 3. Preconditions
- A Completed export bundle from TC-ADM-010-01 (full export of Acme) is available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| bundle | export_bundle.zip | from a Completed ExportRequest |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Extract every file referenced in `manifest.json` | All listed files (`*.csv`, `audit_log.jsonl`) exist in the ZIP. |
| 2 | For each file, compute SHA-256 over the extracted bytes | Computed checksum == `sha256_checksum` recorded in the manifest for that file. |
| 3 | For each file, compare byte length to `file_size_bytes` | Recorded `file_size_bytes` == actual byte length. |
| 4 | For each CSV, count data rows (lines minus header) | Recorded `row_count` == actual data-row count. |
| 5 | Tamper test: flip one byte in an extracted CSV and recompute SHA-256 | Recomputed checksum NO LONGER matches the manifest value — confirms the checksum is content-sensitive, not a placeholder. |

## 6. Postconditions
- No state change; bundle integrity confirmed.

# TC-ADM-005-03: Pagination boundaries — default 20, max 100, over-max clamped/rejected

## 1. Test Objective
Verify the FR-1 pagination contract: default page size 20, maximum 100. Requests above the max are clamped to 100 (or rejected with a validation error) rather than returning an unbounded result set; empty pages return an empty array with correct metadata.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme with > 100 memberships.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| no pageSize | (omitted) | default 20 |
| pageSize | 100 | max allowed |
| pageSize | 250 | over max -> clamp to 100 or 400 |
| page | 9999 | beyond last page |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `GET /api/v1/admin/users` (no pageSize) | 200; exactly 20 rows (default). |
| 2 | `GET /api/v1/admin/users?pageSize=100` | 200; up to 100 rows. |
| 3 | `GET /api/v1/admin/users?pageSize=250` | Either 200 with rows capped at 100 (clamp), or 400 validation error "pageSize max is 100" — never returns 250. |
| 4 | `GET /api/v1/admin/users?page=9999&pageSize=20` | 200; empty array; metadata reports total count and current page (no error, no leakage). |
| 5 | `GET /api/v1/admin/users?page=0` or negative | 400 validation error or normalized to page 1; never negative offset. |

## 6. Postconditions
- No data mutated; the endpoint never returns an unbounded page.

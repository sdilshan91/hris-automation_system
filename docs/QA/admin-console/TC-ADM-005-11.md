# TC-ADM-005-11: Deactivate a user — membership disabled, this-tenant refresh tokens revoked, audited (happy path)

## 1. Test Objective
Verify AC-4: deactivating a user sets `user_tenant.status = 'disabled'`, revokes all of that user's refresh tokens IN THIS TENANT only, prevents the user from logging into this tenant, and records the action in the tenant `audit_log`. (Other-tenant memberships are unaffected — verified in TC-ADM-005-12.)

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-4
- Functional Requirements: FR-1 (status reflected in list)
- Non-Functional: NFR-2 (audit)

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Member "Mark" is `active` in Acme with at least one live Acme refresh token/session.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| user_tenant_id | mark-acme-membership | target |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /api/v1/admin/users/{mark}/deactivate` (confirm) | 200/204 success. |
| 2 | Query `user_tenant` | Mark's Acme membership `status = 'disabled'`. |
| 3 | Query `refresh_token` for Mark scoped to Acme | All Acme refresh tokens revoked/invalidated. |
| 4 | As Mark, attempt to log in / refresh on Acme | Rejected — cannot access Acme; access denied. |
| 5 | `GET /api/v1/admin/users?status=disabled` | Mark appears as `disabled` in the list (FR-1). |
| 6 | Query `audit_log` | A deactivation entry: actor=Dana, before status=active, after=disabled, IP, timestamp (NFR-2). |

## 6. Postconditions
- Mark is disabled in Acme with no live Acme sessions; the action is auditable.

# TC-ADM-006-23: Org-profile save no longer wipes the 4 formerly-unmapped settings — all 4 load from GET and are resent on save (ISSUE-322)

## 1. Test Objective
Verify the ISSUE-322 fix on US-ADM-006 (org-profile settings): the org-profile section is a **full-replace PUT**, so any field the form fails to map is silently wiped on save. Four fields that were previously unmapped must now (1) **load** from the settings GET into the form, and (2) be **resent** in the save payload so an unrelated edit no longer erases them.

## 2. Related Requirements
- User Story: US-ADM-006
- Finding: ISSUE-322 (PR #369 FE follow-up cluster)
- Failure mode: full-replace PUT + partial form mapping = silent data loss

## 3. Preconditions
- Angular Karma/Jasmine unit test with `OrgProfileSectionComponent` (mirrors the component spec).
- The section receives an org-profile input value carrying the 4 previously-unmapped fields.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| The 4 previously-unmapped fields | non-null on the input | must survive a round-trip |
| Fiscal month | numeric | sent as a number on save |

## 5. Test Steps
| Step | Action | Expected Result | Automated by (Karma) |
|------|--------|-----------------|----------------------|
| 1 | Bind the component to an input value carrying all 4 formerly-unmapped fields. | The form loads all 4 fields from the input value. | `org-profile-section.component.spec.ts` → `it('loads all 4 previously-unmapped fields from the input value')` |
| 2 | Dirty the form and save. | The save PUT payload RESENDS all 4 previously-unmapped fields (no silent wipe). | `org-profile-section.component.spec.ts` → `it('sends all 4 previously-unmapped fields in the save payload')` |

## 6. Postconditions
- Editing the org profile preserves all configured settings; the full-replace PUT no longer clears unmapped fields.

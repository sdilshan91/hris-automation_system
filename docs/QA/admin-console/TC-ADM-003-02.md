# TC-ADM-003-02: Reason validation — < 10 chars rejected; valid reason stored verbatim and surfaced in notification

## 1. Test Objective
Verify BR-4 / AC-1 / FR-1: the mandatory `reason` field must contain at least 10 characters. A too-short or empty reason is rejected before any session/token is created; a valid reason is persisted VERBATIM on the `impersonation_sessions` row and included in the tenant-admin notification.

## 2. Related Requirements
- User Story: US-ADM-003
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1
- Business Rules: BR-4
- Test Hints: Reason validation

## 3. Preconditions
- System Admin authenticated; valid active target tenant + active target user available.
- No active impersonation session for the initiator.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| reason (empty) | "" | rejected |
| reason (9 chars) | "too short" | rejected (boundary, 9 < 10) |
| reason (whitespace-padded) | "         " (9 spaces) | rejected — not 10 meaningful chars |
| reason (10 chars, valid) | "ticket1234" | accepted (boundary, exactly 10) |
| reason (>500 chars) | 501-char string | rejected (FR-1 max 500) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `POST /impersonation/start` with `reason=""` | 400/422 validation error "reason is required (min 10 characters)"; NO session row, NO token, NO audit, NO notification. |
| 2 | `POST` with the 9-char reason | 400/422 rejected; nothing created. |
| 3 | `POST` with the 9-space reason | 400/422 rejected — whitespace does not satisfy "10 meaningful characters" (BR-4). |
| 4 | `POST` with the 501-char reason | 400/422 rejected (exceeds max 500). |
| 5 | `POST` with the exactly-10-char valid reason | 200; session created; `impersonation_sessions.reason` equals the exact input string (verbatim, untrimmed of meaningful content, not truncated). |
| 6 | Inspect the notification seam for the successful start | The notification body contains the reason text verbatim (BR-4). |

## 6. Postconditions
- Only the valid request created a session; rejected requests left no side effects.

# TC-ADM-005-02: User list search (name/email) and filter (status, role)

## 1. Test Objective
Verify FR-1 search and filter: the user list supports search by name and email and filtering by membership status and by role, with predicates combinable, all within the tenant scope.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1

## 3. Preconditions
- Tenant Admin "Dana" authenticated on Acme.
- Acme contains, among others: "Maria Lopez" <maria@acme.io> (active, roles Manager+HR Officer), "Mark Stone" <mark@acme.io> (disabled, Employee), and an `invited` pending member "newhire@acme.io".

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| search term | "mar" | matches Maria and Mark by name |
| status filter | disabled | should isolate Mark |
| role filter | HR Officer | should isolate Maria |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `GET /api/v1/admin/users?search=mar` | Returns Maria and Mark (name match); also any email containing "mar"; no unrelated users. |
| 2 | `GET /api/v1/admin/users?search=maria@acme.io` | Returns exactly the Maria membership (email match). |
| 3 | `GET /api/v1/admin/users?status=disabled` | Returns only `disabled` memberships (incl. Mark); excludes `active`/`invited`. |
| 4 | `GET /api/v1/admin/users?role=HR%20Officer` | Returns only members holding the HR Officer role (incl. Maria). |
| 5 | `GET /api/v1/admin/users?search=mar&status=active` | Predicates combine (AND); Mark (disabled) excluded, Maria (active) included. |
| 6 | `GET /api/v1/admin/users?status=invited` | Returns pending invitations surfaced as `invited` memberships (newhire@acme.io). |

## 6. Postconditions
- No data mutated; all results remain tenant-scoped to Acme.

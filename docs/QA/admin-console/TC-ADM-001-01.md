# TC-ADM-001-01: System Admin provisions a new tenant end-to-end (happy path)

> **⚠ GAP-L6 / 2026-08-10 — status demoted to `draft`; the recorded `pass` was against an UNEXECUTABLE step.**
> A test step below queries **`system_audit_log`**, a table this platform deliberately does not have
> (`information_schema` returns zero rows; `IAuditLogPurgeService.cs:6`: *"this platform reuses the single audit
> table with a system action"*). The step's INTENT is satisfiable — a system-scoped row in `audit_logs` with
> `UserId` null — so the expectation has been corrected in place, but the previous verdict was earned against a
> different and impossible expectation and must be re-earned by an actual run (`/test-us`). Compare
> `TC-NTF-004-11`, which handles this correctly with an explicit conditional step.

## 1. Test Objective
Verify the primary success flow of AC-1 and AC-4: an authenticated System Admin submits the "Create Tenant" form with all valid fields and the platform atomically creates the `tenant`, `user`, `user_tenant` with the `TenantOwner` role, seeds default master data, writes a `tenant_lifecycle_event` (`event_type = 'created'`), logs the action to `audit_logs` (system-scoped row: `UserId` null), and dispatches a welcome email with a set-password link. The new tenant then appears in the tenant list with correct status, plan and timestamp.

## 2. Related Requirements
- User Story: US-ADM-001
- Acceptance Criteria: AC-1, AC-4
- Functional Requirements: FR-1, FR-3, FR-4, FR-5, FR-7
- Business Rules: BR-3, BR-4, BR-5
- Data Requirements: tenant, users, user_tenant, user_tenant_role, tenant_lifecycle_event, `audit_logs` (system-scoped row), tenant_setting + leave seed tables

## 3. Preconditions
- System Admin "Olivia Park" is authenticated at `admin.yourhrm.com` with a valid system-tenant JWT carrying the `SystemAdmin` role claim.
- At least one active subscription plan exists in `subscription_plan` (use a plan with `trial_days = 14`).
- The transactional email service is configured and reachable (or a test SMTP sink such as MailHog is in place).
- No tenant with subdomain `globex` currently exists; no global user with `owner@globex.com` currently exists.

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Navigate to `https://admin.yourhrm.com/tenants`, click "Create Tenant" | The Create Tenant form opens with fields: name, subdomain, plan picker, owner email, region, trial days. |
| 2 | Fill all fields with the test data and submit; observe `POST /api/v1/admin/tenants` | Request carries the system-tenant bearer; response 201 Created with body `{ tenant_id (UUIDv7), subdomain: "globex", status: "trial", created_at }`. |
| 3 | Inspect the persisted `tenant` row | One row: `subdomain = globex`, `status = trial`, `trial_ends_at` set ~14 days out, `is_system = false` (BR-5), `billing_email = owner@globex.com` (BR-4), `tenant_id` is a time-ordered UUIDv7 (FR-5). |
| 4 | Inspect `users` and `user_tenant` | A new `users` row for `owner@globex.com` exists; a `user_tenant` row links it to the new tenant; a `user_tenant_role` row grants `TenantOwner`. |
| 5 | Inspect seeded master data for the new tenant | Default leave types (Annual, Sick, Casual), a generic holiday calendar template, and a 1-step manager-approval leave workflow are present and tenant-scoped; `tenant_setting` defaults written. |
| 6 | Inspect `tenant_lifecycle_event` and `audit_logs` (system-scoped row: `UserId` null) | A `tenant_lifecycle_event` row with `event_type = 'created'`; a `audit_logs` (system-scoped row: `UserId` null) row with the acting admin `user_id`, timestamp, IP, and request payload (sensitive fields excluded) (AC-4, NFR-3). |
| 7 | Verify welcome email dispatch | A `trial_welcome` email is dispatched to `owner@globex.com` containing the tenant name, `globex.yourhrm.com` URL, and a one-time set-password link with 72-hour expiry (FR-4). Assert the dispatch/enqueue; delivery verified against the test SMTP sink. |
| 8 | Return to the tenant list | "Globex Corporation" appears with status Trial, plan Growth, and the correct creation timestamp; the subdomain renders as a clickable `globex.yourhrm.com` link (AC-4). |

## 6. Postconditions
- A fully isolated, trial-status tenant `globex` exists with an owner account, TenantOwner membership, seeded master data, a lifecycle event, an audit log entry, and a dispatched welcome email.

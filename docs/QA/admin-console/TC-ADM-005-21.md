# TC-ADM-005-21: [DEFERRED] PostgreSQL RLS isolation layer (NFR-5 third layer)

## 1. Test Objective
Verify the NFR-5 / AC-6 PostgreSQL RLS layer: a raw SQL query issued without the `app.current_tenant_id` session variable returns zero cross-tenant user rows (DB-enforced isolation independent of the application/EF layers). **DEFERRED** — this codebase enforces tenant isolation via EF Core global query filters (read) + `TenantInterceptor` (write stamping), NOT Postgres RLS. RLS is a documented deferred platform extension point (same family as the deferred RLS in US-ADM-001..004, Payroll, Leave). Application + EF-layer isolation is covered run-green by TC-ADM-ISO-010..013.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-6
- Non-Functional: NFR-5 (three-layer isolation: app + EF + RLS)
- STORY MISMATCH: AC-6/NFR-5 name Postgres RLS as an active layer; the platform implements only the app + EF layers today.

## 3. Preconditions
- Postgres RLS policies + `app.current_tenant_id` session GUC configured — NOT present in the current platform.

## 4. Test Data
| Field | Value | Notes |

| isolation layer | Postgres RLS | deferred |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open a DB session WITHOUT setting `app.current_tenant_id`; `SELECT * FROM user_tenant` | DEFERRED — once RLS lands: zero rows (RLS denies). Today: the app never issues unscoped queries; EF filters enforce isolation at the query level. |
| 2 | Set `app.current_tenant_id = <Acme>`; query `user_tenant` | DEFERRED — expected: only Acme rows. |
| 3 | Until RLS is implemented | Rely on TC-ADM-ISO-010..013 (EF query-filter + ID-injection 404). |

## 6. Postconditions
- No mutation. Stays `blocked` pending the Postgres RLS platform hardening; recommend rewording AC-6/NFR-5 to specify EF query filters as the active layer with RLS as future hardening.

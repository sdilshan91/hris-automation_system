# TC-ADM-007-11: BR-1 authorization — only TenantAdmin/TenantOwner may create/edit/manage workflows

## 1. Test Objective
Verify BR-1: only `TenantAdmin` and `TenantOwner` roles may create, edit, version, archive/restore, or delete workflow definitions. Other tenant roles (Manager, HR Officer, Employee) receive 403; unauthenticated requests receive 401. A `TenantOwner` is also permitted (not just `TenantAdmin`).

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-2/AC-3/AC-4 (write paths)
- Business Rules: BR-1 (TenantAdmin/TenantOwner only)
- Functional Requirements: FR-7 (tenant-scoped)

## 3. Preconditions
- Acme `active` with users: Dana (`TenantAdmin`), Olive (`TenantOwner`), Mike (`Manager`), Hana (`HR Officer`), Eve (`Employee`).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| valid WF payload | entity=Leave, 1 valid step | reused across roles |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Olive (TenantOwner), POST create workflow | 201; allowed. |
| 2 | As Dana (TenantAdmin), edit/archive the workflow | 200; allowed. |
| 3 | As Mike (Manager), POST create / PUT edit / archive / DELETE | 403 on every write path. |
| 4 | As Hana (HR Officer), attempt the same writes | 403 on every write path. |
| 5 | As Eve (Employee), attempt the same writes | 403 on every write path. |
| 6 | Unauthenticated (no token), attempt any write | 401. |
| 7 | Read access (GET list) for non-admin roles | Per the design, list read may be available to authorized roles, but NO write is permitted — assert reads never grant write. |

## 6. Postconditions
- Only TenantAdmin/TenantOwner mutated workflows; non-admin writes blocked (403), unauth blocked (401).

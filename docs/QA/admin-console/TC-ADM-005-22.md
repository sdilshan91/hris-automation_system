# TC-ADM-005-22: Users list pagination footer shows the real total from `totalCount` (not "1–NaN of {{total}}") (BUG-103 regression)

## 1. Test Objective
Verify the Admin → Users list pagination footer renders `Showing {start}–{end} of {total}` using the real server total. The backend user-list envelope carries the page total under `totalCount` (not `total`); the FE must bind that field and compute the range so the footer never renders `NaN` for the range end nor the un-interpolated literal `{{total}}`. Regression guard for BUG-103.

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-1 (paginated, searchable, filterable user list)
- Functional Requirement: FR-1
- Defect: BUG-103

## 3. Preconditions
- Users endpoint returns a paginated envelope `{ items, totalCount, page, pageSize }` with a total larger than one page.
- Automated: bound Karma/Jasmine spec drives the real `UserManagementService` through `HttpClientTesting`, with the real `userManagement.showing` i18n string loaded so the translate pipe interpolates.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| items | 1 user row | non-empty so the footer renders |
| totalCount | 42 | backend wire field name (NOT `total`) |
| page / pageSize | 1 / 20 | range end = min(20, 42) = 20 |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Open the Users tab | Service issues `GET /api/v1/tenant/users?page=1&pageSize=20`. |
| 2 | Backend returns `{ items:[…], totalCount: 42, page:1, pageSize:20 }` | Component binds `totalCount` -> total() = 42. |
| 3 | Inspect the pagination footer `[data-testid="pagination-range"]` | Renders `Showing 1–20 of 42`. |
| 4 | Assert the footer text | Contains `42`, `Showing 1`, `20`; never contains `NaN` or the literal `{{total}}`. |

## 6. Postconditions
- No mutation. Footer reflects the real server total and computed range.

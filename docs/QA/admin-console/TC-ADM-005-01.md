# TC-ADM-005-01: User list loads paginated, tenant-scoped, with all required columns (happy path)

## 1. Test Objective
Verify the primary success flow of AC-1: a Tenant Admin opens the Users section and receives a paginated, searchable list scoped exclusively to the current tenant. Each row shows display name, email, assigned roles, membership status (`invited`/`active`/`disabled`), last-login timestamp, and the linked employee record (if any). No users from any other tenant appear. The list is built from `user_tenant` joined to `users` and `user_tenant_role`, filtered by `ITenantContext.TenantId` (FR-1).

## 2. Related Requirements
- User Story: US-ADM-005
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1
- Business Rules: BR-1 (own-tenant only)

## 3. Preconditions
- Tenant Admin "Dana" is authenticated at `acme.yourhrm.com` with an active `user_tenant` membership and the `TenantAdmin` role; tenant Acme is `active`.
- Acme has >= 25 memberships in mixed states (some `invited`, some `active`, some `disabled`), several with multiple roles and a few linked to an `employee` record.
- A second tenant Beta exists with its own distinct users (used only to confirm absence).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| tenant | acme | resolved from subdomain / X-Tenant-Subdomain |
| page size | 20 (default) | FR-1 default |
| Beta users | beta-* | must NOT appear |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, `GET /api/v1/admin/users?page=1&pageSize=20` | 200; an array of <= 20 user summaries plus pagination metadata (total count, page, pageSize). |
| 2 | Inspect each row | Contains display name, email, assigned role names, membership status (`invited`/`active`/`disabled`), last-login timestamp, and linked employee reference when present (null otherwise). |
| 3 | Cross-check the returned set against the DB | Every returned `user_tenant` row has `tenant_id = Acme`; counts match Acme memberships only. |
| 4 | Scan for any Beta user/email | None of Beta's users or emails appear in any page. |
| 5 | Request page 2 | 200; the next slice of Acme memberships; no overlap with page 1; total count unchanged. |

## 6. Postconditions
- No data mutated. The Tenant Admin has an accurate, tenant-confined roster.

# TC-ADM-007-03: BR-2 — creating a new active workflow for an entity type auto-archives the previous one

## 1. Test Objective
Verify BR-2: each entity type may have only ONE active workflow at a time per tenant. When the Tenant Admin creates a second active workflow for the same entity type (e.g. Leave), the system automatically archives the previously active Leave workflow (`is_active = false`) so exactly one active definition remains. The archive transition is audited.

## 2. Related Requirements
- User Story: US-ADM-007
- Acceptance Criteria: AC-2
- Functional Requirements: FR-1
- Business Rules: BR-2 (one active per entity type; new active auto-archives previous)
- Non-Functional: NFR-4 (audited)

## 3. Preconditions
- Dana (`TenantAdmin`) authenticated; Acme `active`.
- Acme already has one active Leave workflow "Leave-A" (`is_active = true`).
- Plan limit allows the new active workflow (or archived ones don't count — see TC-ADM-007-09).

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| existing | "Leave-A", entity=Leave, is_active=true | pre-existing |
| new | "Leave-B", entity=Leave, is_active=true, 1 valid step | second active for same type |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, POST create active "Leave-B" for entity=Leave | 201; "Leave-B" created active. |
| 2 | GET active Leave workflow | Exactly ONE active Leave workflow: "Leave-B". |
| 3 | GET "Leave-A" | `is_active = false` (auto-archived). |
| 4 | Create active workflow for a DIFFERENT entity type (e.g. Expense) | Does NOT archive "Leave-B" — auto-archive is scoped per entity type only. |
| 5 | Inspect tenant `audit_log` | Entries for "Leave-B" create AND "Leave-A" auto-archive. |

## 6. Postconditions
- One active Leave workflow ("Leave-B"); "Leave-A" archived; audit reflects both.

# TC-ADM-002-11: Monitoring access is audited — Monitoring.Viewed and Monitoring.TenantViewed records

> **⚠ GAP-L6 / 2026-08-10 — status demoted to `draft`; the recorded `pass` was against an UNEXECUTABLE step.**
> A test step below queries **`system_audit_log`**, a table this platform deliberately does not have
> (`information_schema` returns zero rows; `IAuditLogPurgeService.cs:6`: *"this platform reuses the single audit
> table with a system action"*). The step's INTENT is satisfiable — a system-scoped row in `audit_logs` with
> `UserId` null — so the expectation has been corrected in place, but the previous verdict was earned against a
> different and impossible expectation and must be re-earned by an actual run (`/test-us`). Compare
> `TC-NTF-004-11`, which handles this correctly with an explicit conditional step.

## 1. Test Objective
Verify AC-5 / NFR-5: viewing the monitoring dashboard writes a `audit_logs` (system-scoped row: `UserId` null) record (Action `Monitoring.Viewed`), and opening a specific tenant's detail writes a `audit_logs` (system-scoped row: `UserId` null) record (Action `Monitoring.TenantViewed`) that captures WHICH tenant was viewed. Each record carries the acting system user, timestamp, and IP.

## 2. Related Requirements
- User Story: US-ADM-002
- Acceptance Criteria: AC-5
- Non-Functional Requirements: NFR-5
- Test Hints: viewing a tenant's detail is recorded in `audit_logs` (system-scoped row: `UserId` null)

## 3. Preconditions
- System Admin "Olivia Park" authenticated at `admin.yourhrm.com`.
- `audit_logs` (system-scoped row: `UserId` null) is reachable; baseline row count recorded.

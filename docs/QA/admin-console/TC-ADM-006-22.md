# TC-ADM-006-22: Branding invalid-hex error is programmatically associated with the input (aria-invalid + aria-describedby) (ISSUE-212 regression)

## 1. Test Objective
Verify the branding primary-colour hex field exposes its validation error to assistive technology (WCAG 2.1 AA — 3.3.1 Error Identification, 4.1.2 Name/Role/Value). When the entered hex is invalid, the hex `<input>` must carry `aria-invalid="true"` and an `aria-describedby` that references the id of the rendered error message element. When valid, the field must not be flagged invalid and no error element renders. Regression guard for ISSUE-212.

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-3 (primary-colour customization)
- Non-Functional: WCAG 2.1 AA (SC 3.3.1, SC 4.1.2)
- Defect: ISSUE-212

## 3. Preconditions
- Branding section rendered with a valid initial primary colour.
- Automated: bound Karma/Jasmine spec renders `BrandingSectionComponent` and queries the rendered DOM.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| valid hex | #123456 | baseline: no error, not flagged invalid |
| invalid hex | nope | triggers the error message + aria wiring |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enter a valid hex | Hex input has no `aria-invalid="true"`; no `p.cs-error` element renders. |
| 2 | Enter an invalid hex (`nope`) | `colorInvalid()` is true; the `p.cs-error` message renders and has a non-empty `id`. |
| 3 | Inspect the hex input attributes | `aria-invalid="true"` is set. |
| 4 | Inspect `aria-describedby` | Equals the `id` of the rendered error element. |

## 6. Postconditions
- No mutation (no save issued). The invalid state is announced to screen readers.

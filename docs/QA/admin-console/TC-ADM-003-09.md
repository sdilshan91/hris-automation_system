# TC-ADM-003-09: BR-3 — one active session per impersonator; second concurrent start rejected (409)

## 1. Test Objective
Verify BR-3: only one Active impersonation session is allowed per impersonator at a time. While a session is Active, a second start request by the same impersonator is rejected with 409 Conflict, and no second session/token is created. After the first session is ended/expired, a new session can be started.

## 2. Related Requirements
- User Story: US-ADM-003
- Business Rules: BR-3
- Functional Requirements: FR-4
- Test Hints: Concurrent sessions

## 3. Preconditions
- Initiator "Olivia" (SystemAdmin) has ONE Active impersonation session against tenant Acme.
- A second valid target (tenant Beta or a different Acme user) is available.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| existing session | Active, Acme/Bob | the one already running |
| second target | Beta/Carol (valid) | different tenant/user |
| reason | "Second concurrent investigation" | valid length |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | With an Active session already open, `POST /impersonation/start` for the second target | 409 Conflict — one active session per impersonator (BR-3). Message indicates an active session must be ended first. |
| 2 | Inspect side effects | No second `impersonation_sessions` row; no second token; the original session is untouched and still Active. |
| 3 | End the first session (per AC-3) | First session -> Ended. |
| 4 | `POST /impersonation/start` for the second target again | 200 — a new session is now permitted because none is Active. |

## 6. Postconditions
- At most one Active session per impersonator; a new session is allowed only after the prior one ends/expires.

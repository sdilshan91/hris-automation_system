# TC-ADM-006-13: Session policy — GET+PUT persists idle/absolute timeout + max concurrent sessions; audited

## 1. Test Objective
Verify FR-6: a Tenant Admin reads and updates the session policy (idle timeout, absolute timeout, max concurrent sessions per user). Values persist to the current tenant's session-policy fields (pre-existing columns), the change is audited before/after, and invalid values (e.g. negative timeout, idle > absolute) are rejected. The enforcement seam is the authentication middleware.

## 2. Related Requirements
- User Story: US-ADM-006
- Functional Requirements: FR-6
- Non-Functional: NFR-4 (audit)

## 3. Preconditions
- Tenant Admin "Dana" authenticated at `acme.yourhrm.com`; session-policy fields exist on the Tenant entity.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| idle_timeout_minutes | 30 | |
| absolute_timeout_minutes | 480 | 8h |
| max_concurrent_sessions | 3 | per user |
| invalid idle | -5 | reject |
| invalid relation | idle 600 > absolute 480 | reject (idle must be ≤ absolute) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Dana, `GET` session policy | 200; returns the current tenant's session policy. |
| 2 | `PUT` idle=30, absolute=480, max_concurrent=3 | 200; persisted to the current tenant. |
| 3 | `GET` again | Values equal the new settings. |
| 4 | `PUT` idle = -5 | 400; rejected; policy unchanged. |
| 5 | `PUT` idle 600 with absolute 480 | 400; rejected (idle exceeds absolute); unchanged. |
| 6 | Inspect audit | Before/after entry for the session-policy change. |
| 7 | (Enforcement seam) Note where enforced | Auth middleware reads the tenant session policy on session validation (enforcement behavior owned by Authentication module; persistence + read-back verified here). |

## 6. Postconditions
- Session policy persisted with valid values; invalid attempts rejected; audited.

# TC-ADM-010-01: Full export bundle — per-entity CSVs + audit_log.jsonl + manifest, packaged ZIP

## 1. Test Objective
Verify AC-1 / AC-2 / FR-1 / FR-2 / FR-5 / FR-6: a Tenant Admin initiates a FULL export; a Hangfire job runs and produces a ZIP bundle at `{tenantId}/exports/{export_id}/export_bundle.zip` containing one CSV per selected entity, an `audit_log.jsonl`, and a `manifest.json` with `export_id`, `tenant_id`, `tenant_name`, `export_timestamp`, `scope`, and a per-file block (filename, entity, row_count, file_size_bytes, sha256_checksum). The ExportRequest transitions Queued -> Processing -> Completed.

## 2. Related Requirements
- User Story: US-ADM-010
- Acceptance Criteria: AC-1, AC-2
- Functional Requirements: FR-1 (initiation: scope=full, context tenant), FR-2 (per-entity query + CSV + package), FR-5 (audit_log.jsonl), FR-6 (manifest contents)
- Test Hints: "Full export"

## 3. Preconditions
- Tenant Admin "Tara" authenticated at `acme.yourhrm.com`; tenant Acme is `Active`.
- Acme populated with representative rows across entities: e.g. 12 employees, 3 departments, 7 leave requests, 40 attendance records, 2 payroll runs, 12 payslips, 1+ rows in several other in-scope entities.
- No export currently in progress for Acme; Acme has < 3 exports this calendar month.
- Hangfire is operational.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| scope | full | All in-scope tenant entities |
| tenant | acme (Active) | tenant_id implicit from ITenantContext |
| employees | 12 | known row count for manifest assertion |
| payslips | 12 | known row count |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | As Tara, POST export initiation with `scope=full` | 202/200; an ExportRequest is created with status `Queued`; response confirms "Export started"; a Hangfire job is enqueued. |
| 2 | Inspect the audit log immediately after initiation | An export-initiation audit row exists (actor=Tara, tenant=Acme) — see TC-ADM-010-14. |
| 3 | Let the Hangfire job run to completion | ExportRequest transitions `Queued` -> `Processing` -> `Completed`; a file exists at `{acmeTenantId}/exports/{export_id}/export_bundle.zip`. |
| 4 | Open the ZIP and list entries | Contains one CSV per in-scope entity (e.g. `employees.csv`, `leave_requests.csv`, `payroll_runs.csv`, `payslips.csv`, ...), an `audit_log.jsonl`, and a `manifest.json`. |
| 5 | Parse `manifest.json` top-level fields | Contains `export_id`, `tenant_id` (=Acme), `tenant_name` (=Acme), `export_timestamp`, `scope` (=full). |
| 6 | Inspect a per-file manifest block | Each file entry has `filename`, `entity`, `row_count`, `file_size_bytes`, `sha256_checksum`. |
| 7 | Compare manifest `row_count` to the CSV body line count (excluding header) for employees and payslips | `employees.row_count` = 12 and `payslips.row_count` = 12 match the actual CSV data rows. |

## 6. Postconditions
- ExportRequest is `Completed`; bundle persisted at the tenant-scoped path; initiation + completion audited.

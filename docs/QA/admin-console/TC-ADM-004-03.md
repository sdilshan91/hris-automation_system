# TC-ADM-004-03: Suspension reason validation — empty / < 10 chars rejected; 10-500 boundary accepted

## 1. Test Objective
Verify FR-1's reason contract for suspension: the `reason` is mandatory and must be 10-500 chars. Empty, whitespace-only, or sub-10-char reasons are rejected (400) and NO state change occurs; a valid reason at the boundary is accepted.

## 2. Related Requirements
- User Story: US-ADM-004
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1
- Test Hints: (implicit — mandatory reason min 10 chars per AC-1)

## 3. Preconditions
- System Admin authenticated with `SystemAdmin`.
- Active, non-system tenant "Acme".

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| reason (empty) | "" | rejected |
| reason (whitespace) | "          " | rejected (trim -> 0) |
| reason (9 chars) | "too short" | rejected (< 10) |
| reason (10 chars) | "ToS breach" | accepted (lower boundary) |
| reason (500 chars) | "x" * 500 | accepted (upper boundary) |
| reason (501 chars) | "x" * 501 | rejected (> 500) |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Suspend with empty reason | 400 ValidationError; tenant remains `Active`; no lifecycle event, no audit. |
| 2 | Suspend with whitespace-only reason | 400; no state change. |
| 3 | Suspend with 9-char reason | 400; no state change. |
| 4 | Suspend with exactly 10-char reason | 200/204; tenant -> `Suspended`; reason stored. |
| 5 | (Fresh active tenant) suspend with 500-char reason | 200/204; accepted at upper boundary. |
| 6 | (Fresh active tenant) suspend with 501-char reason | 400; rejected; no state change. |

## 6. Postconditions
- Suspension is gated on a 10-500 char reason; rejected attempts leave the tenant untouched.

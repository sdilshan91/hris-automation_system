# TC-ADM-006-02: Organization profile validation — invalid/boundary inputs rejected, no partial write

## 1. Test Objective
Verify negative and boundary handling of the org profile PUT (AC-1/FR-1): required-field and format constraints are enforced server-side, an invalid request is rejected with 400 (validation problem details), and a rejected request leaves the current tenant's profile and audit log unchanged (no partial write).

## 2. Related Requirements
- User Story: US-ADM-006
- Acceptance Criteria: AC-1
- Functional Requirements: FR-1
- Business Rules: BR-4 (fiscal year start month must be 1–12)

## 3. Preconditions
- Tenant Admin "Dana" authenticated at `acme.yourhrm.com`; Acme has a known-good org profile baseline.

## 4. Test Data
| Field | Value | Notes |
|-------|-------|-------|
| empty org.name | "" | required; expect reject |
| fiscal_year_start = 0 | 0 | below range (1–12) |
| fiscal_year_start = 13 | 13 | above range |
| over-long org.name | 600 chars | exceeds column/validator max |

## 5. Test Steps
| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | `PUT` org profile with empty `org.name` | 400; validation error naming the field; profile unchanged. |
| 2 | `PUT` with `fiscal_year_start = 0` | 400; out-of-range error; profile unchanged. |
| 3 | `PUT` with `fiscal_year_start = 13` | 400; out-of-range error; profile unchanged. |
| 4 | `PUT` with `fiscal_year_start = 1` and `= 12` | 200 each; boundary months accepted. |
| 5 | `PUT` with a 600-char `org.name` | 400; max-length error; profile unchanged. |
| 6 | After each rejected PUT, `GET` profile and read audit | Baseline preserved; NO audit row written for rejected attempts. |

## 6. Postconditions
- Profile equals the baseline (after the valid boundary writes in step 4 are rolled back to baseline by test teardown); no audit rows from rejected attempts.

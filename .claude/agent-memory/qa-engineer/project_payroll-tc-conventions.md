Payroll test cases (`test-cases/payroll/`) were established by US-PAY-001 (first Payroll story; created the dir + TEST-MATRIX + the root Payroll section in TRACEABILITY-MATRIX). Payroll ADOPTS the Recruitment ID scheme (see [[project-recruitment-tc-conventions]]) rather than the single-running-counter scheme of Leave/Attendance.

- **Functional ID scheme is per-story-suffixed:** `TC-PAY-{NNN}-XX` (zero-padded story + two-digit suffix). US-PAY-001 used TC-PAY-001-01..12. The next Payroll story uses TC-PAY-002-01..NN (do NOT continue a global counter).
- **ISO ID scheme is a separate running counter:** `TC-PAY-ISO-NNN`. US-PAY-001 used TC-PAY-ISO-001..004 (the standard 4: cross-tenant read, no/invalid/mismatched tenant-context rejection, cross-tenant write block + body-injected tenant_id + foreign-component-link, tenant-scoped Redis caches). Continue this counter; reuse 001..004 for same-table operations and add ONE new ISO TC only for a genuinely distinct mutation/table. Glob existing `TC-PAY-ISO-*` for the highest before adding.
- **Three artifacts per story:** per-TC `.md` files, `test-cases/payroll/TEST-MATRIX.md`, and the root `test-cases/TRACEABILITY-MATRIX.md` (forward + backward tables, per-story Detailed Requirements Traceability, per-story Coverage Summary, the Cross-Module table row + TOTAL, and the closing-note paragraph). US-PAY-001 sized US-PAY-001 at 16 TCs.
- **Tenant isolation mechanism:** EF Core global query filters + TenantInterceptor, NOT Postgres RLS. US-PAY-001 AC-6/FR-8 say "PostgreSQL RLS policies on the payroll tables" -- ISO TCs describe the EF mechanism and note RLS as an extension point. Same caveat as all prior modules.
- **Payroll-specific recurring deferrals written CONDITIONAL (not gaps):** historical-payslip-unchanged (AC-2) + type-change-after-finalized-run (BR-7) depend on the Payroll Run/Payslip story (not built yet); structure version history (FR-7) + deactivation-with-no-active-assignment (BR-5) deferred to later Payroll stories (no employee-assignment surface yet); Redis list cache (NFR-1, key `tenant:{tenantId}:payroll:components`) written as a real test (cache-invalidation-on-write asserted); audit (NFR-5) references the Audit logging module S24; employee-affected-count for AC-5 delete-block depends on a later assignment surface (the 409 + count contract is asserted now).
- **Domain edge cases worth carrying forward:** numeric(18,2) precision (max magnitude + over-precision rounding rule + negative/non-numeric reject); deduction-exceeds-gross (BR-4); pagination default 25 / max 100 cap (NFR-3); formula safe-evaluator must reject invalid syntax, circular refs (direct + indirect cycle across the dependency graph), and unsafe code (no exec). NFR-2 fetch-all-components SLA is 200ms P95 (tighter than Recruitment's 400ms).

- **Regression TCs for a defect** attach to the OWNING story with the next free `-XX` suffix (BUG-070 → TC-PAY-002-13 under US-PAY-002; ISSUE-158 → TC-PAY-004-13 under US-PAY-004), `status: automated`, and an `@TC-...` Automation Binding block naming the exact xUnit test methods. No new US needed.
- **CtcResidualBalancer test gotcha (BUG-070):** `SalaryAssignmentServiceTests.SeedStandardStructure` builds SPECIAL as a FORMULA (`ctc - BASIC - HRA`) which SELF-ABSORBS an override — so it exercises the balancer's NO-OP (delta≤tolerance) path, NOT the delta-absorption. To integration-test real residual balancing you must seed a FIXED SPECIAL (clone the harness: `SalaryAssignmentResidualBalanceTests.SeedFixedResidualStructure`, all-Fixed BASIC+HRA+SPECIAL) so the override genuinely breaks the sum. The balancer is gated on `overrides.Count>0` in `BuildBreakdown`, so a no-override mismatch still fails `ctc_sum_mismatch`. Pure `Balance` unit tests build `CtcComponentResult` records directly and assert the tie-out invariant `sum(Earning AnnualAmount)==annualCtc` + exact residual amount + monthly=Round(annual/12, AwayFromZero).

**Why:** Reviewers/orchestrator rely on consistent IDs + the three-matrix structure for backward traceability; Payroll deliberately follows Recruitment's per-story-suffix deviation, not the Leave/Attendance running counter.

**How to apply:** Before writing the next Payroll story's TCs, use `TC-PAY-{NNN}-XX` for functional/security/perf/a11y and continue the `TC-PAY-ISO-NNN` counter. Payroll is a CRITICAL module (NFR-4 >= 85% coverage) -- ensure AC/FR/BR coverage stays >= 85%. No vault `docs/vault/modules/payroll.md` note existed at bootstrap.

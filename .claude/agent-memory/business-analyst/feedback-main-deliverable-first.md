When a task bundles **authoring** (story bodies, requirement sections) with **bookkeeping**
(traceability rows, matrix totals, STATUS corrections), do the **authoring first**.

**Why:** on F4/GAP-030 (2026-09-04) I banked all the matrix/ledger edits first as "record as you go"
progress, then ran research and setup turns. The coordinator had to interrupt: the two story files were
still untouched placeholders while four ledger files were already modified. The bookkeeping *felt* like
safe incremental progress, but it was the smaller half — and on a turn-limited run it would have been
the only half delivered. Ledger rows are worth little without the requirements they point at.

**How to apply:** identify the deliverable whose absence would make the task a failure, and land a
complete first draft of it before touching any ledger. "Record as you go" means write each *result* as
you reach it — it does not mean do the cheap items first. If research is still pending for the main
deliverable, author from the facts already verified and refine, rather than filling the wait with
side work.

US-NTF-006 Phase 1 landed the real notification **delivery infrastructure** (feature-flagged, safe with no SMTP).

**Artifacts (all under src/backend):**
- `HRM.Infrastructure/Services/SmtpEmailSender.cs` — MailKit `IEmailSender`; DI-swapped in at `DependencyInjection.cs:582` only when `Smtp:Host` non-blank, else `LogOnlyEmailSender`. `Smtp:Host` defaults **blank** in committed `appsettings.json` (never gmail); creds are user-secrets only.
- `HRM.Domain/Entities/NotificationDelivery.cs` + enums `NotificationDeliveryChannel`/`NotificationDeliveryStatus` — tenant-scoped `BaseEntity`; migration `AddNotificationDelivery`, table `notification_delivery`.
- `HRM.Api/Jobs/SendEmailJob.cs` — Hangfire, `[AutomaticRetry(Attempts=5, DelaysInSeconds={60,300,900,3600,21600})]`; success→Sent, exhausted→Failed. Idempotent (skips already-Sent).
- `HRM.Api/Notifications/RealNotificationDispatcher.cs` — now the default `INotificationDispatcher` (`Program.cs:255`, replaced `LoggingNotificationDispatcher` which stays as fallback). In-app leg → `INotificationService`; email leg → resolve email from `Users.Email` by UserId, `ShouldDeliverAsync` gate (BR-1 security types bypass), render via `IEmailTemplateService`, write delivery row, enqueue `SendEmailJob`.

**Key decisions / gotchas:**
- The `INotificationDispatcher` interface only carries a free-form `notificationType` string (no category/eventKey). `RealNotificationDispatcher.MapType()` is the **Phase-1 bridge**: string→(catalog eventKey, `NotificationCategory`, mandatory-flag). Only the 4 catalog events exist (`leave_approved`/`onboarding_welcome`/`payslip_published`/`password_reset`); unmapped types resolve no template → row marked Failed, logged, never throws.
- Email leg **opens its own DI scope and calls `tenantContext.SetTenant()`** (subdomain looked up from `Tenants`) — REQUIRED so `IEmailTemplateService.ResolveAsync` picks the right tenant's override via the global filter (unresolved context would leak another tenant's template).
- Only live caller today = onboarding outbox (`onboarding.checklist.assigned` → maps to `onboarding_welcome`). The 12 `LogOnly*` module seams are **NOT** rewired yet — that's **Phase 2+**.

**Phase 2a (US-NTF-006, branch `fix/ntf-phase2a-contract-security`) — DONE, contract widened + 2 seams rewired:**
- **`MapType` DELETED.** `INotificationDispatcher` now takes `NotificationRequest(Guid TenantId, string EventKey, string PayloadJson, Guid? RecipientUserId=null, string? RecipientEmail=null, string? NotificationType=null)`. Category + mandatory moved onto `NotificationEventDefinition` (`Category`, `IsMandatory` — non-persisted domain record, NO migration) and read via `NotificationEventCatalog.Get(EventKey)`. Dispatcher: email recipient = `RecipientEmail` ?? `Users.Email` by userId; raw-email recipients store `RecipientUserId=Guid.Empty` on the delivery row (kept entity non-nullable to avoid a migration); pref-gate only runs when a userId is present; in-app leg skips when `RecipientUserId` null.
- **New catalog events (all templates seeded by DbInitializer, no migration):** `impersonation_started` (SecurityAlerts, mandatory) · `tenant_suspended`/`tenant_termination_initiated`/`tenant_reactivated`/`tenant_restored` (SystemAnnouncements, mandatory). Existing 4: leave_approved/onboarding_welcome/payslip_published=not-mandatory, password_reset=SecurityAlerts+mandatory.
- **`RealImpersonationNotificationService`** (Infrastructure/Services, DI `:558`) replaces LogOnly: resolves tenant admins = distinct users holding role `Tenant Owner`/`Tenant Admin` (via active `UserTenants`→`UserTenantRoles`→`Roles.Name`, IgnoreQueryFilters scoped by tenantId), sends email+in-app to each. Never-throws (whole body try/catch).
- **`RealTenantLifecycleNotificationService`** (DI `:573`) replaces LogOnly: fans out to distinct billing+admin RAW emails via `RecipientEmail` override (email-only); best-effort resolves email→active-user-in-tenant for the in-app leg too. `EventType`→eventKey = `tenant_{type}`. Never-throws.
- LogOnly impersonation/lifecycle .cs files still exist (unregistered dead code — left because integration tests reference them; QA owns tests). Onboarding job has a tiny local `MapOutboxTypeToEventKey` (all→onboarding_welcome). Verified via `dotnet build HRM.Api` (0 errors); tests NOT built (QA rewrites `RealNotificationDispatcherTests`).

Shared `LeavePlaceholders` array + flat `OnboardingChecklistPlaceholders` array both declared ABOVE `_byKey` (Phase-2a NRE rule). `LeaveSample(...)` helper for preview sample-data.
- **Onboarding align — ALL THREE outbox types now payload-matched (no blank bodies):** dedicated events, all OnboardingOffboarding + not mandatory, FLAT placeholders matching each outbox payload:

  - `onboarding_task_overdue` ← `onboarding.task.overdue` (taskTitle/employeeName/dueDate/daysOverdue)
  `OnboardingNotificationDispatchJob.MapOutboxTypeToEventKey` maps all three; `_ => onboarding_welcome` is now just a fallback for future/unmapped intents. Shared flat placeholder arrays (`OnboardingChecklistPlaceholders`/`OnboardingTaskCompletedPlaceholders`/`OnboardingTaskOverduePlaceholders`) all declared ABOVE `_byKey`. No branding placeholders (payloads carry none). No migration (catalog + DbInitializer seed). Build green (0 errors); 9 relevant tests pass.
